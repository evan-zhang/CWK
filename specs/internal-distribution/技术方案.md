# 技术方案：CWK 内部可分发版

## 1. 涉及模块

- `install.sh`：增加 Python 版本检查与显式 Skill 链接安装。
- `scripts/cwk_doctor.py`：输出本地、可配置路径与实采依赖诊断。
- `scripts/cwk_collect_live.py`：公司 Skill 路径可由环境变量覆盖，子进程继承当前 Python 解释器。
- `scripts/cwk_sync_mirror_to_docdb.py`：鉴权 Skill 根目录可配置。
- 配置模板、Makefile、README、迁移文档：删除 Evan 专属路径，记录试点边界。

## 2. 数据结构变化

- 不新增业务数据结构。
- 新增运行时环境变量：`CMS_CWORK_WORKFLOW_DIR`、`CMS_AUTH_SKILL_DIR`、`OPENCLAW_SKILLS_DIR`。

## 3. 接口变化

- `scripts/cwk_doctor.py --check-only [--require-live] [--config PATH] [--json]`。
- `./install.sh --install-skill [--skills-dir PATH]`。

## 4. 运行逻辑

1. 安装检查只验证代码、Python 与模板，不读工作协同。
2. `doctor --require-live` 再验证公司 Skills 与实采授权是否就绪。
3. 显式安装 Skill 时只创建符号链接；目标冲突即停止。
4. 任何 cron、AI 专用 Agent、DocDB 写入仍由安装者在首次试点成功后自行启用。

## 5. 测试策略

- 单元测试覆盖 Python 版本与配置/路径判断。
- Shell 验证覆盖 `install.sh` 正常检查、低版本拒绝、Skill 链接冲突保护。
- 运行现有完整单元测试与 smoke 套件。

## 6. 风险点

- 同事机器上公司 Skills 的实际目录可能不同，故只能通过显式环境变量与 doctor 报告处理。
- 工作协同与 DocDB 权限由公司服务决定，代码无法替代授权申请。
- 当前仓库为私有仓库；分发对象需要已获仓库访问权。
