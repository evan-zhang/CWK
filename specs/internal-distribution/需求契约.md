# 需求契约：CWK 内部可分发版

## 1. 业务目标

让具备公司 OpenClaw 环境的技术同事，能在不复制 Evan 数据、授权或运行状态的前提下，独立安装、检查并试点运行 CWK。

## 2. 用户角色

- 安装者：公司内部、具备本机 OpenClaw 与相应业务权限的技术同事。
- 运行者：安装者自己的 OpenClaw Agent。
- 数据所有者：工作协同与知识库目标对应的授权用户。

## 3. 使用场景

1. 同事克隆发布分支后执行安装检查。
2. 同事使用自己的 `CWORK_APP_KEY`、个人 DocDB 或明确指定的团队目标运行只读试点。
3. 同事将 CWK Skill 链接到自己的 OpenClaw skills 目录，供其 Agent 按文档调用。

## 4. 功能范围

### 必须实现

- 运行时使用相对镜像目录，不含 Evan 的机器路径。
- 明确要求 Python 3.10+，并在安装/测试前给出可读诊断。
- 支持以环境变量配置工作协同、DocDB、鉴权 Skill 的安装位置。
- 提供不访问业务数据的 `doctor` 自检。
- 提供显式、可逆的 CWK Skill 链接安装选项；不自动安装 Agent、cron 或授权。
- 文档给出个人镜像与团队镜像的隔离规则及试点步骤。

### 明确不做

- 不打包、迁移或共享现有 raw、Wiki、run 输出、`.env`、本地状态或 DocDB 内容。
- 不自动创建/修改任何 OpenClaw Agent、cron 或共享知识库。
- 不替同事申请工作协同或 DocDB 权限。
- 不将多个用户的原始汇报混入同一默认镜像。

## 5. 输入

- 发布仓库副本。
- 安装者的 Python 3.10+ 与 OpenClaw 运行环境。
- 仅在实采时提供安装者自己的 `CWORK_APP_KEY` 或鉴权路由。

## 6. 输出

- 已生成的本地配置模板与 `.env` 模板。
- 可机器读取的环境自检报告。
- 可由目标 Agent 发现的 CWK Skill 链接（仅在显式启用时）。
- 可执行的 smoke 与首次实采说明。

## 7. 业务规则

- 默认目标为安装者个人 DocDB；团队目标必须显式配置项目与根目录 ID。
- `CWORK_APP_KEY` 只能来自安装者本机环境或其私有配置，不进入 Git。
- 安装默认不触发实采、云端同步或 cron。

## 8. 异常情况

- Python 版本不足、缺少公司 Skills、缺少实采授权时，`doctor` 必须返回非零并说明修复项。
- 目标 Skill 路径已有非 CWK 内容时，安装器必须拒绝覆盖。

## 9. 权限与安全要求

- 工作协同读取保持只读。
- 默认个人镜像隔离；共享镜像只由明确指定的团队目标承载。
- 不把任一既有用户的数据、授权或私有路径放入可分发配置。

## 10. 验收标准

- 在 Python 3.11 环境中，`install.sh` 与 `cwk_doctor.py --check-only` 通过。
- 在 Python 3.9 环境中，安装检查明确失败并提示最低版本。
- `--install-skill` 仅创建指向当前项目 `skill/` 的链接，不覆盖非链接目录。
- 模板和文档不含 Evan 工作区或镜像路径。
- 完整单元测试与三组 smoke 通过。

## 11. 测试场景

| 场景 | 输入 | 期望结果 |
|---|---|---|
| 正常安装检查 | Python 3.11、仅仓库代码 | 通过且不访问业务数据 |
| 低版本 Python | Python 3.9 | 非零退出并说明 Python 3.10+ |
| Skill 链接安装 | 空目标 skills 目录 | 创建链接，不创建 cron |
| 目标冲突 | 已有普通目录 | 拒绝覆盖 |
