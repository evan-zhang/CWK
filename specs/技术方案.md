# CWK RT-001 技术方案

## 1. 涉及模块

- `cwk_ai_common.py`：配置、JSON 提取、OpenClaw runner、schema 校验和确定性 fallback。
- `cwk_ai_record_understanding.py`：逐篇理解，可并发。
- `cwk_ai_event_clustering.py`：跨篇事件归并和优先级。
- `cwk_ai_enhanced_digest.py`：从结构化事件确定性渲染管理版 Markdown。
- `cwk_ai_quality_review.py`：规则版与 AI 版质量复核。
- `cwk_nightly_pipeline.py`：AI 编排、降级、manifest 与镜像发布。

## 2. 数据结构变化

- 遵循 `cwk.ai_record_understanding.v1`、`cwk.ai_events.v1`。
- 新增 `cwk.ai_daily_priorities.v1`、`cwk.ai_quality_review.v1`。
- nightly manifest 新增 `ai.enabled`、`ai.dry_run`、`ai.degraded`、`ai.models`、`ai.outputs`、`ai.stages`。

## 3. API / 接口变化

- 环境变量新增 `CWK_AI_ENABLED`、`CWK_AI_DRY_RUN`、三个模型名、并发、超时、Agent ID 和 thinking level。
- 默认 runner 使用 `openclaw agent --json`，不使用 `--deliver`；调用前检查目标 Agent 的 Skills 和工具策略。
- 每次真实调用使用独立 session ID，避免不同汇报上下文互相污染。
- 专用 Agent 必须配置 `skills: []`、`tools.profile: minimal`、`tools.alsoAllow: [read]`。

## 4. 前端页面变化

无前端改造。新增 `digest-ai-enhanced.html`，复用现有 Markdown-to-HTML renderer。

## 5. 后端逻辑变化

- 规则 stage 先执行且必须成功。
- AI stage 在规则 digest 后执行；失败不会触发 `require_ok`。
- 单篇失败生成 fallback 产物，便于后续 stage 和追溯。
- 增强 digest 只消费通过 schema 校验的结构化 JSON。
- AI 发布文件使用独立文件名，不覆盖规则版 daily 文件。

## 6. 测试策略

- `make smoke`：规则版兼容。
- `make smoke-ai`：离线 dry-run 全链路。
- `unittest`：JSON 提取、schema、证据追溯、降级和秘密扫描。
- 真实模型 pilot 不进入 CI，由运维命令显式执行。

## 7. 风险点

- OpenClaw CLI JSON envelope 版本变化：集中在 common adapter 解析。
- 模型输出不稳定：严格 JSON 提取和 schema 校验，失败 fallback。
- 过度归并：保留 `record_ids`、置信度和待复核信息。
- 隐私：不落 prompt、不投递消息、不提交 run 产物。
- nightly 时长增加：并发和 timeout 均可配置。
