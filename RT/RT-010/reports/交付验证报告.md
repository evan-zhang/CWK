## 已确定的交付契约

### 1. 实体先约束、意图后排序

- 明确解析为单一实体后，候选必须先限制在完整 entity-family postings；
- 人类 Markdown 实体页及其 30 条展示上限不参与机器 scope；
- 所有返回结果必须提供可审计 `scope_support`，scope 外结果不得进入 Top-K；
- `ambiguous / unsupported_multi_entity / unknown / resolved_empty` 均
  fail-closed，不回落全库 BM25；
- 实体已识别但 scope/证据为空时，固定返回
  `status=resolved_empty`、`confidence=none`、`results=[]`、
  `global_fallback_used=false`。

### 2. Entity catalog 与 registry

- 仓库 `config/entity-family-registry.json` 是唯一规范来源；
- `wiki/_system/entity-family-registry.json` 只是可选本地实验覆盖；
- 跨类型合并必须由 registry 显式批准并通过 raw quote 回读校验；
- 括号派生的裸通用名称默认是 `generic_candidate`，不能自动扩大 hard scope；
- `posting_provenance` 的每条 approved edge 必须携带：
  `approved_family_registry / entry_id / decided_by / decided_at /
  decision_ref / registry_version / evidence_refs[]`，不能只在 family/surface
  级保留审批信息；
- registry 决策字段及证据属于 catalog semantic core，任何变更都必须改变
  `catalog_sha256`。

### 3. Semantic hash 与快照绑定

- `catalog_sha256` 只覆盖语义内容：families、surfaces、postings、边级
  provenance、registry version/applied 决策；
- anchor cache 内容、cache hit/miss、build duration、时间戳、输出路径等
  构建态字段不进入 semantic hash；cold/warm 构建必须得到相同 hash；
- 稳定逻辑 `entity_catalog_registry_source` 必须同时写入：
  1. search index payload；
  2. `index-meta.json`；
  3. `manifest.json`；
- registry source 只能是 `repo:...` / `mirror:<relative>` 等逻辑标签，
  不能暴露本机绝对路径；
- payload 中 registry source 参与 index SHA；catalog 的授权语义由其
  registry version/applied 决策及证据进入 `catalog_sha256`，再由 payload
  的 catalog SHA 绑定。

### 4. Bound snapshot fail-closed

- payload 声明的 catalog 缺失、不可读、内部 schema/hash 校验失败或 SHA
  不匹配时，实体查询不得退化为 unscoped 全库检索；meta/manifest 是构建
  审计副本，不作为查询运行时的重复授权源；
- 可读但不可信的 catalog 只允许用于“是否命中已登记 surface”的安全检测，
  不参与 ranking；
- catalog 不可读时，NFKC 后 ASCII 实体形态、引号/分隔符名称以及去除管理
  意图词后剩余 `>=2` 字 CJK 名称均 fail-closed；
- 通用非实体事实问题仍可使用既有 unscoped BM25，避免 catalog 故障导致
  整体查询不可用；
- `--require-catalog` 是额外门禁，不是绕过上述默认安全规则的开关。

### 5. 实体—意图证据闭包

- `source_integrity` 与 `query_support` 分开计算；“文本存在于 raw”不等于
  “文本回答了该实体的进展/计划/风险”；
- entity 与 intent 必须由同一可引用结构片段建立 link，不允许跨兄弟标题、
  列表项、表格行、blockquote 或无界段落拼接；
- link 使用原 raw 坐标，并携带 anchor/intent offset、snippet、block kind、
  heading path、relation、distance 与 raw SHA；
- 最终 evidence 必须覆盖它声称支持的 entity-intent link；
- Top-K 裁剪后重新计算 intents/support/confidence，不能引用已裁掉结果；
- 复合管理意图部分有证据时最多 `medium`；全部无合法 link 时返回
  `resolved_empty / no_query_evidence_in_scope`；
- `high` 只允许在最终可引用结果集中 scope、source 与全部请求意图均验证
  通过时出现。

### 6. Local-First 派生物边界

以下路径均为本地派生物或本地实验覆盖：

- `wiki/_system/entity-catalog.json`
- `wiki/_system/entity-catalog.json.gz`
- `wiki/_system/entity-catalog-meta.json`
- `wiki/_system/entity-anchors-cache.json`
- `wiki/_system/entity-family-registry.json`

它们必须同时满足：

- 不进入 `changed_relative_paths`；
- 不被 `cwk_sync_mirror_to_docdb.iter_items` 选中；
- 已存在于 retry queue 的旧路径被识别为 stale 并清理；
- 不上传 DocDB，不作为 cloud/shadow 查询依赖。

search index 的 manifest/meta 仅携带 catalog 绑定摘要用于本地快照审计；
不等于恢复 Cloud-First，也不授权同步 catalog 正文或 cache。

## 真实问题验收

`TBS 项目进展、下一步计划、风险` 只作为已知故障防回归，不用于证明总体
准确率。冻结 commit 的验收要求是：

- 所有自然语言变体解析到同一已批准 TBS family；
- 返回结果全部属于 TBS scope，`global_fallback_used=false`；
- 进展、计划、风险分别只能由 TBS 的局部 raw 证据支持；
- BP 系统、晨报或其他项目的相邻风险/计划不得拼接为 TBS 证据；
- 任一意图缺证据时必须显式列为 missing，且不得给 `high`；
- 不要求固定 report_id 或固定排名。

总体泛化验证采用动态分层实体抽样、性质测试与代码冻结后的未来索引盲测；
不建立大型固定题库，不围绕 TBS 调特殊权重。

当前隔离快照实测：该复合问题解析为同一 TBS family
`9703e450fd7e850a`，`scope_precision=1.0`，进展/计划/风险均有局部 raw
证据，`confidence=medium`，`global_fallback_used=false`。四类 TBS 回归
查询的 Top-8 结果共 24 条 entity-intent link，均通过 raw SHA、原始坐标和
最终 evidence 闭包核验；此前
被复现的 BP 相邻表格行、晨报及远端子章节风险均未再借给 TBS。
