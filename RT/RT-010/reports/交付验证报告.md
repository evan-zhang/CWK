     `wiki/_system/entity-anchors-cache.json` 幂等重用；
   - 单一 raw 内 `(family, surface)` 命中聚合为一条 provenance
     记录（含 `match_count`），杜绝 provenance 爆炸；
   - `suppress_shorter_overlaps` O(n log n) 排序 + 单遍扫描，与朴素
     O(n²) 参考实现在 200 轮随机输入下位偏差 = 0。

4. **查询层 `scripts/cwk_wiki_query.py`**
   - 新增 `EntityResolution`、`resolve_entity`；六态：
     `unscoped / resolved / ambiguous / unsupported_multi_entity /
     unknown / resolved_empty`；
   - 明确解析时对候选做 **scope 硬过滤**、剔除实体 token、禁用
     `nav_bonus`、每条 result 附带 `scope_support`；
   - `ambiguous / unknown / resolved_empty / filters_removed_all /
     no_query_evidence_in_scope` 均返回结构化安全空结果，
     `global_fallback_used=false`；
   - `intents` 检测 progress/plan/risk/owner 并按逐意图 verified 判定；
   - **三桶排序 + 丢弃 bucket_3**（scoped 管理型查询）：
     `bucket_1` = raw 验证 + 至少支持一条 requested intent；
     `bucket_2` = raw 验证但无 requested intent 命中；
     `bucket_3` = 未验证——**从可引用结果中剔除**并通过
     `scope.dropped_unverified_rows` 上报计数。桶内保持 BM25 顺序；
   - **有界评估池**：scoped + intents_requested 时评估 `max(top_k*4,32)`
     个 scope 内候选，再做桶排序 / 丢弃 / trim 回 `top_k`，杜绝
     >top_k 的高 BM25 未验证行遮蔽真正的 bucket_1 证据；
   - **置信度锚**：scoped-resolved 情况优先锚在 bucket_1 首行；若无
     bucket_1 且查询携带管理意图，直接 fail-closed 为
     `resolved_empty / no_query_evidence_in_scope`；
   - `support` 三支：`source_integrity`（**所有**返回行都需 verified）
     / `scope_integrity` / `query_support`；`confidence` 高置信度
     还必须 `resolution_kind ∈ {exact, approved_alias}` 且三支同时
     verified；
   - `entity_catalog_sha256` 与索引不匹配时 fail-closed，CLI 新增
     `--require-catalog` 强制要求 catalog；
   - 模块内 catalog 缓存按 `(path, mtime_ns, size)` 键失效，重复查询
     ≪200 ms。

## Follow-up hardening pass（独立审计 blocker A–G）

上一轮交付通过后，独立审计（含 parent 逻辑复核）指出 7 项 **可复现** 的
残留漏洞。本节记录每一项的实际改动、验证条件与剩余限制。所有 receipts
均来自本次 hardening 提交的 diff（`scripts/cwk_wiki_query.py`
±541 行 / `tests/test_wiki_entity_scope.py` ±548 行）。

### A. 结构越界（`compute_entity_intent_links`）

- **问题**：旧 `bounded_window` 无条件把 `distance ≤ 256` 的 anchor 与
  intent 关联；`_blocks_share_heading` 允许跨兄弟 heading；`_same_
  sentence` 未把 `\n` 视为结构断点；扁平化 Markdown（无换行的 `##
  风险`）造成整行被视为一个 paragraph。
- **修复**：
  1. 移除 `bounded_window`；跨块只允许 `heading_ancestor` 或
     `same_leaf_section`（后者要求两个 paragraph block heading_path
     完全相同、且区间内无 heading/list_item/table_row/blockquote
     插入、且距离 ≤ `_INTENT_LINK_WINDOW`）。
  2. `_heading_is_ancestor`：仅当 anchor 本身为 heading block 且其
     heading_path 是 intent block heading_path 的前缀时成立；paragraph
     anchor 不再自动跨 heading。
  3. `_same_sentence` 拆分正则改为 `(?<=[。！？!?；;])\s*|\n+`，
     单个 `\n` 立即作为结构断点。
  4. `_INLINE_HEADING_SPLIT_RE` 预处理：任何行内 `## …` 标记（前面
     不是 newline / `#`）会在 parse 前插入换行，使 `parse_raw_blocks`
     能识别为 heading block。
- **测试**：`FinalHardeningStructuralLeakageTests` 覆盖 6 个场景
  （sibling headings / 相邻列表项 / 相邻表格行 / blockquote 边界 /
  扁平化行内 `##` / 单换行 + 列表项）；全部 pass。
- **实际反例复核**：
  - “日报 TBS 待办 + 独立知识库风险”→ `resolved_empty /
    no_query_evidence_in_scope`（inline shell 试跑，无结果泄漏）。
  - “BP 六大目标里 TBS 只作为过程细节”→ 同样 `resolved_empty`。

### B. Strong title 边界伪造

- **问题**：`_title_contains_family_surface` 直接对 `doc.title`
  （摘要衍生）做 `casefold() in` 子串判定；伪造的摘要标题即可窃取
  strong linkage；`AB` 也会命中 `TABLE`；`ALPHA` 会命中 `ALPHABETA`。
- **修复**：
  1. 新增 `_extract_raw_h1`，只用 raw envelope 的 `^# …` 作为 H1。
  2. Strong linkage 走 `entity_catalog.find_exact_anchors` +
     `suppress_shorter_overlaps`——与 scope catalog 走同一套边界规则；
     长度 < 2 的表面完全不计入。
  3. `_evaluate_row` 把 `raw_text` 传入 title / scope_support 检查，
     不再落到 summary 层。
- **测试**：`FinalHardeningTitleBoundaryTests` 覆盖伪造摘要 H1、`AB`
  in `TABLE`、`ALPHABETA` 三种情形；全部 pass。

### C. 迭代完备性

- **问题**：旧循环在 “有一条 intent-supporting 行” 时即 break；复合
  intent（progress+plan+risk）里只要有 progress 就停止，风险行躲在
  rank 41 后。
- **修复**：
  1. 收集 `verified_now × intent_support`，只有当
     `intents_requested_set.issubset(supported_intents)` 且
     `len(verified_now) >= top_k` 才 break。
  2. Bucket 排序后的 top_k trim 改为 “**多样化贪心**”：先按
     bucket/linkage 顺序填 top_k，再对超出 top_k 但能覆盖新 intent 的
     行，尝试替换掉 “删除后不损失任何已覆盖 intent” 的现有行。
- **测试**：`FinalHardeningIterationCompletenessTests` 用 40 个仅
  progress-verified 的干扰行 + 1 个 rank 41+ 的 risk-verified 行；
  执行结果 `evaluated_pool_size > 32`（超过一轮 batch）、risk 进入
  `intents.verified`、`IC000000000000200` 在返回列表中。

### D. Empty status 语义

- **问题**：`if scope_active and resolved and results:` 守卫在
  bucket_1 + bucket_2 全部为空、bucket_3 被丢弃后跳过 `resolved_empty`
  逻辑，最终以 `confidence=none / results=[]` + `resolution=resolved`
  漏出。
- **修复**：把 `not results` 加进 `anchor_missing` 判定；不再依赖
  `results` 非空的守卫。任何 bucket filter 完全清空的路径都直接返回
  `resolved_empty / no_query_evidence_in_scope`。
- **测试**：`FinalHardeningEmptyStatusTests` 构造 3 个 in-scope 但
  quote 不匹配 raw 的行；返回 `resolved_empty`、`filter_reasons =
  ['no_query_evidence_in_scope']`、`postings_size > 0`。

### E. Catalog binding 对 bare-entity 也 fail-closed

- **问题**：`entity_management_query = intent AND entity_shape`。裸
  `ALPHA` 无 intent，catalog 缺失 / hash mismatch 时被降级为 unscoped
  BM25 fallback。
- **修复**：新增 `_query_looks_bare_entity`（**严格** 版本：仅
  ASCII 缩略语 或 括号引用专有名词；长 CJK 短语不进入，避免误伤如
  `基础事实` 这类事实查询）。fail-closed 触发条件扩展为
  `require_catalog OR entity_management_query OR bare_entity`。
- **测试**：`FinalHardeningCatalogBindingTests` 构造有效 catalog +
  剥离 `entity_catalog_sha256` 的旧格式 index：`ALPHA` 查询返回
  `unknown / results=[] / global_fallback_used=false`；平行的
  `内容概况` 事实查询仍保持 `unscoped / resolved / resolved_empty`
  之一。

### F. High confidence 门禁强化

- **问题**：`any(r.get("entity_linkage") == "strong") AND all intents
  verified` 让 “strong 但沉默” + 独立 local intent 行也能升 high。
- **修复**：门禁变成 “存在 strong row 且该行 **自己** intent_support
  覆盖全部 requested intents”；任何 strong-quiet 行都不再帮助升 high。
- **测试**：`FinalHardeningHighGateTests` 显式复现 strong-title-quiet
  + local-only-progress 两行组合；结果 `confidence != "high"`。
- **真实 TBS receipt**：`TBS 项目进展、下一步计划、风险` 现在报
  `medium`（不是 `high`），因为在真实语料里 strong-title 行并未同时
  覆盖 progress+plan+risk 三个 intent。

### G. summary_candidate 引言与 link 可审计性

- **问题**：目录里存了 `summary_candidate.quotes` 但查询层没有 raw-
  verify；intent link 只有 block kind 与 heading_path，缺 raw offset
  和 snippet。
- **修复**：
  1. `_scope_support_for` 收集 catalog 里的 `quotes[]`，用
     `normalized_contains(quote, raw_evidence_haystack)` raw-verify；
     未通过的直接丢弃；结果暴露为
     `scope_support.candidate_quotes / _verified / _total`。
  2. Intent link 记录扩展 `anchor_offset / anchor_snippet /
     intent_offset / intent_snippet`；仍保留 `surface / relation /
     distance / raw_sha256 / anchor_block / intent_block /
     anchor_heading_path / intent_heading_path`。
- **测试**：`FinalHardeningLinkProvenanceTests` 覆盖 “link 记录含
  offsets/snippets” 与 “未 raw-verify 的 candidate quote 被丢弃”。

## 剩余限制（本次 hardening 后仍存在）

  伪 heading、`【】` 装饰性小标题等仍走 paragraph 路径。若日后
  发现新的扁平化模式，需要在同一处扩展正则或迁移到基于 tree-sitter
  的解析器（本 RT 不引入外部依赖）。

  在每次审计运行时重生成——不设固定 rank / 固定 report_id 判定。

  intents”，在真实语料上会更保守（例：`TBS 项目进展、下一步计划、
  风险` 现在稳定报 `medium`）。这是刻意的：strong-quiet + local-only
  组合被证明会误升 high。若日后 corpus 出现 title 中同时含
  “进展/计划/风险” 的整合行，可自然回到 `high`。
