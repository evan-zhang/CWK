2. **机器实体目录 `scripts/cwk_entity_catalog.py`**
   - `wiki/summaries/*.md` 的 `## 候选实体` 段落为主要来源；
   - `raw/**/*.md` 为次要来源，仅允许已批准 surface 通过精确锚点扩展 postings；
   - 同 type 家族规则：`exact_normalized`、`parenthetical_acronym`、
     `controlled_generic_suffix`、`compound_alias`（`A+suffix` 与
     `A+B` 两种子规则）；
   - 跨 type 合并**必须**由版本化数据文件
     `config/entity-family-registry.json` 显式批准，且每条合并携带
     `evidence.report_id`；
   - 注册表加载优先级：仓库内 `config/entity-family-registry.json`
     → 本地镜像 `wiki/_system/entity-family-registry.json`
     （测试通过 `registry_paths=[...]` 覆盖）；
   - 家族合并流程：**同 type 四条规则** → **注册表跨 type 合并** →
     **第二轮 compound_alias**（利用注册表新增的 entity_types 吸收同类
     compound 家族）。任何未在注册表 members 中显式列出的 same-surface
     兄弟家族保持独立、按查询时 ambiguous 处理，或由 operator 追加
     一条 evidence 的注册表条目——不再存在“自动扩散”的跨 type 合并；
   - **自研 Aho-Corasick** 多模式扫描 raw，采用 casefold + 表面感知
     边界规则（ASCII 拒绝相邻 ASCII 字符、CJK 依靠最长匹配抑制）；
   - `raw_sha256` 索引的**匿名锚点缓存**
     `wiki/_system/entity-anchors-cache.json` 幂等重用；
   - 单一 raw 内 `(family, surface)` 命中聚合为一条 provenance
     记录（含 `match_count`），杜绝 provenance 爆炸；
   - `suppress_shorter_overlaps` O(n log n) 排序 + 单遍扫描，与朴素
     O(n²) 参考实现在 200 轮随机输入下位偏差 = 0。

3. **索引绑定 `scripts/cwk_wiki_search_index.py`**
   - `build_index` 在写索引前调用 `entity_catalog.build_catalog`，
     把 `catalog_sha256 / catalog_schema / registry_version` 写进
     索引 payload、`index-meta.json` 与 `manifest.json`；
   - 索引 chunks 与 catalog / meta 均加入 `changed_relative_paths`
     便于 nightly 同步；
   - 索引 sha256 计算包含 `entity_catalog_sha256`，任一变化都
     生成新索引版本。

4. **查询层 `scripts/cwk_wiki_query.py`**
   - 新增 `EntityResolution`、`resolve_entity`；六态：
     `unscoped / resolved / ambiguous / unsupported_multi_entity /
     unknown / resolved_empty`；
   - 明确解析时对候选做 **scope 硬过滤**、剔除实体 token、禁用
     `nav_bonus`、每条 result 附带 `scope_support`；
   - `ambiguous / unknown / resolved_empty / filters_removed_all /
     no_query_evidence_in_scope` 均返回结构化安全空结果，
     `global_fallback_used=false`；
   - `intents` 检测 progress/plan/risk/owner 并按逐意图 verified 判定；
   - **三桶排序 + 丢弃 bucket_3**（scoped 管理型查询）：
     `bucket_1` = raw 验证 + 至少支持一条 requested intent；
     `bucket_2` = raw 验证但无 requested intent 命中；
     `bucket_3` = 未验证——**从可引用结果中剔除**并通过
     `scope.dropped_unverified_rows` 上报计数。桶内保持 BM25 顺序；
   - **有界评估池**：scoped + intents_requested 时评估 `max(top_k*4,32)`
     个 scope 内候选，再做桶排序 / 丢弃 / trim 回 `top_k`，杜绝
     >top_k 的高 BM25 未验证行遮蔽真正的 bucket_1 证据；
   - **置信度锚**：scoped-resolved 情况优先锚在 bucket_1 首行；若无
     bucket_1 且查询携带管理意图，直接 fail-closed 为
     `resolved_empty / no_query_evidence_in_scope`；
   - `support` 三支：`source_integrity`（**所有**返回行都需 verified）
     / `scope_integrity` / `query_support`；`confidence` 高置信度
     还必须 `resolution_kind ∈ {exact, approved_alias}` 且三支同时
     verified；
   - `entity_catalog_sha256` 与索引不匹配时 fail-closed，CLI 新增
     `--require-catalog` 强制要求 catalog；
   - 模块内 catalog 缓存按 `(path, mtime_ns, size)` 键失效，重复查询
     ≪200 ms。

   - 唯一条目：`TBS` 家族显式桥接 `system+project+product`，evidence

     并强制索引升级；不含 TBS 特定权重、rank 或 boost。

6. **审计驱动的第二轮加固**（独立评审 5 条 blocker 全部落地）：
   - **B1**：`intents.verified/missing`、`query_support`、`confidence`
     严格从**最终 citeable 结果**（bucket 排序 + drop bucket_3 + top_k
     trim 之后）重新计算，杜绝“评估池验证到了、但被 trim 掉的行”
     污染顶层字段；
   - **B2**：将固定 32-row 评估池升级为**确定性迭代批次**
     `max(top_k*4, 32)`，在 scope 内一直评估直到既有 ≥`top_k` 条
     verified 行、又有至少一条 bucket_1（intent-supporting）行，
     或 scope 耗尽；仍空则 `resolved_empty / no_query_evidence_in_scope`；
   - **B3**：持久化索引缺少 `entity_catalog_sha256`（RT-010 之前的
     旧索引）时，管理意图 + 实体形态查询**无论**
     `require_catalog=False` 也 fail-closed 为 `unknown / catalog_
     index_hash_mismatch_or_missing`，避免旧 CLI 悄悄引用未绑定的
     scope；
   - **B4a**：`_row_has_strong_entity_linkage` 收紧为**只有 title/H1
     命中家族 surface** 才是 report-level strong；`summary_candidate`
     仅证明摘要提到实体、不再自动允许任意 verified 引文支撑意图；
   - **B4b**：新增 `parse_raw_blocks`（heading / paragraph / list_item /
     table_row / blockquote / 扁平化 `：` 软标题）+
     `compute_entity_intent_links`，为每条 verified 意图产出结构化
     `entity_intent_link` provenance：`anchor_kind, surface,
     anchor_block, intent_block, relation ∈ {same_block, same_sentence,
     same_heading_subtree, bounded_window (<=256), title_report_level},
     distance, raw_sha256`；
   - **B4c**：候选实体引文（`证据：>`）在 catalog 中重新落盘
     （`summary_candidate.quotes`），查询侧可先 verify 引文与 raw 一致
     再决定是否允许结构化链接；
   - **B4d**：`entity_linkage` tier 升级为 `strong | local | weak`，
     排序次序 `strong > local > weak`，桶内保持 BM25 序；
   - **B4e**：`high` confidence 现在额外要求 “所有 requested intents 在
     citeable 集合中都有 verified 链接” **且**至少一条返回行是 strong
     tier（title/H1 命中）；仅局部 raw 链接的场景最多 `medium`；
   - 新增 7 条 blocker 专项 synthetic 测试：post-trim 意图重算 /
     40-distractor + 迟到证据 / 旧索引 fail-closed / summary_candidate
     ≠ 报告级强链接 / same-block + heading-subtree 接受 / 扁平化 md
     解析 / BP 六大目标偶发提及被拒绝 / 兄弟段落通用词不影响支持度 /
     title-report-level 接受 / 第二次实体出现可提供本地链接。
