# RT-004 技术方案

## 架构

```text
自然语言问题
  → 主题/实体导航召回
  → summary 词面召回（中文 n-gram + BM25）
  → report_id 合并与过滤
  → 回读 raw 并验证/截取原文
  → Evidence Packet（Markdown/JSON）
  → OpenClaw Agent 基于证据回答或拒答
```

## 实现

- 新增 `scripts/cwk_wiki_query.py`：零第三方依赖的确定性检索 CLI。
- 导航层：索引 topic/entity 页面标题和正文，从页面提取关联 `report_id` 给对应 summary 加权。
- 事实层：对 summary 建中文 2/3 字 n-gram 与英文/数字 token 的 BM25 索引。
- 证据层：优先读取 summary 内 `证据：>` 引文并在 raw 中做去空白逐字校验；没有结构化引文时，从 raw 正文选择与问题最相关的段落。
- 过滤层：`--from-date`、`--to-date`、`--writer`、`--kind`。
- 输出层：Markdown 供人/Agent 阅读，JSON 供测试与后续工具使用。

## 安全与兼容

- 只读 `wiki/` 与 `raw/`，默认输出 stdout；不会改写知识库。
- 不调用模型，不读取凭据，不依赖 sandbox。
- 保留现有 `cwk_cloud_wiki_*` 和 nightly 行为。

## 验证

- 合成 fixture 单元测试覆盖排序、过滤、证据校验和拒答。
- 真实 698 篇镜像运行验收查询，保存到本地 `runs/`。
- 运行现有 test suite 与 wiki smoke test，确认无回归。
