# RT-024 技术方案：安全审计、可观测性与容量基准

## 1. 模块

- `cwk_audit.py`：schema validation、append、hash chain、checkpoint、verify、replay。
- `cwk_metrics.py`：allowlisted metrics、tenant health、bounded exporter spool。
- `cwk_pr001_benchmark.py`：合成 fixture、runner、sample writer、report aggregator。
- `contracts/rt024/schemas/`：event/checkpoint/verify/health/benchmark contracts。

## 2. 审计存储

- tenant security events 写独立 append segment；中央索引只保存 opaque event
  refs 和安全类别，tenant 用户无权读取。
- `event_hash = SHA256(domain || len(prev_hash) || prev_hash || JCS(event_without_hash))`。
- segment 封口生成 checkpoint：first/last event、count、root/hash、writer version、
  previous checkpoint hash。更正只追加 correction event。
- 文件用安全 dirfd、O_NOFOLLOW、0o600、fsync；并发写由单 writer/lock 序列化。
- verify 从 genesis/checkpoint 重算，并验证 event schema、tenant binding、顺序、
  重复 ID 和断链。

## 3. 事件与 replay

事件 payload 采用类型化 allowlist：只允许 before/after SHA、epoch、状态枚举、
受限 evidence refs、query hash/length/intent、授权 report key。replay 输出历史
状态图和差异，不调用 writer、不修改权威状态。

## 4. Metrics 与 health

- counter/gauge/histogram label schema 固定 tenant opaque ID、component、operation、
  result enum、model ID hash；禁止 query/report/path/URL 作为 label。
- tenant health 从本租户事件/指标聚合；API 强制 `AgentContextSnapshot` 或 admin
  context，普通 tenant 不接裸 tenant_id。
- exporter 是异步 consumer；超时、抛错和队列满不会阻塞 producer。drop/backlog
  自身写本地低基数指标。
- critical audit 与 optional metrics 分通道；不能用 exporter 成功替代本地 audit。

## 5. Benchmark

### 5.1 数据集

确定性 seed 生成 10 tenant × 10,000 report、共享/独有证据、不同 grant、
multi-space、archive/review、撤权与恶意条目。每次生成输出 dataset SHA 与统计，
并校验无生产数据来源。

### 5.2 测量维度

- component：Broker core / real sandbox E2E。
- cache：cold / warm。
- disposition：index / archive_no_index / review / explicit combination。
- concurrency：至少 1、低并发、中并发三个记录在 manifest 的档位；数值由
  runner config 明确，不在契约预填。
- operation：allow query、deny query、SHA failure、revoke logical deny、每个
  cleanup consumer ack。

### 5.3 统计

保存原始 monotonic durations 与结果码；报告 count/error/timeout、min/max、
P50/P95/P99 和吞吐。机器/进程/Gateway/commit、缓存预热、并发、dataset SHA
全部绑定。样本不足或 E2E 未走真实 transport 时结果标 invalid/not_measured。

## 6. Gate receipt 校验

VG receipt 的唯一格式与路径由中央契约
`PR/PR-001-multitenant-knowledge-spaces/contracts/gates/` 冻结：
`cwk.pr001.verification_gate_receipt.v1` schema + `gate_registry_v1.json`。
registry 是**冻结配置**，本身不含状态：某 gate 的 `receipt_path` 不存在即
NOT RUN；存在则状态就是该 receipt 内部的 `status`/`conclusion`。

runner 启动前按 registry 的 `receipt_path` 读取 VG-B、VG-C、VG-D 的 JSON receipt，
并验证：schema 合法、`gate_id`/`feeder_rt` 与 registry 冻结映射一致、
`status=pass`、`feeder_rt_independent_pass=true`、`receipt_sha256` domain-separated
重算匹配、`artifacts[].sha256` 与磁盘一致、commit/build 兼容。缺任一项退出稳定错误，
不生成"正式基准"报告。

硬约束：RT-024 **只消费，不创建、不补写、不猜测**任何 VG receipt，也不得从
Markdown 叙述推断 gate 状态。若 receipt `synthetic=true` 或
`conclusion=conservative_unknown`，基准报告必须显式标注该限制，不得升级为
生产可用结论。开发期小样本 smoke 必须标 `mode=smoke`，不得冒充 baseline。

## 7. 测试策略

- audit property/attack tests：bit flip、delete/reorder/duplicate、cross-tenant
  splice、crash at append/fsync/checkpoint。
- redaction corpus：raw、完整 query、URL、path、token-like、控制字符和 Unicode。
- metrics fault injection：slow/dead exporter、queue saturation、restart、corruption。
- benchmark self-check：dataset determinism、sample count、clock monotonicity、
  percentile recompute、core/E2E separation、production-root refusal。
- full integration/regression：VG-B/C/D chain、Wiki smoke、全库 tests。

## 8. 风险

- 审计 hash chain 不是外部不可否认日志：checkpoint 完整性证明范围需在报告
  明确；不宣称超出本机 threat model。
- 高基数指标引发容量问题：schema allowlist 与 cardinality budget 双门禁。
- benchmark 受机器噪声：记录环境、预热和样本；不伪造 SLA。

## 9. 回滚

停 exporter/runner，保留 audit segments/checkpoints；数据面 adapter 可降为本地
安全 spool。不得删除审计事实或让 rollback 隐藏篡改告警。
