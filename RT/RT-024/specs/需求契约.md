# RT-024 需求契约：安全审计、可观测性与容量基准

## 1. 业务目标

让多租户数据链的关键安全决策可追溯、篡改可检测、租户健康可见，并以真实
实现链测得后续 RT-026 go/no-go 所需的性能、容量和撤权时间基线。

## 2. 用户角色

- tenant 用户：只读取自身非敏感健康摘要。
- 宿主管理员/安全审计员：读取中央追加式事件与完整性结果，不通过查询入口
  模拟 tenant。
- 数据面组件：提交结构化事件/指标，不传 raw/完整 query/secret。
- 独立验收 Agent：篡改、串扰、日志注入、exporter 故障和基准复现。

## 3. 功能范围

### 必须实现

- OBS-001：追加式 audit event，覆盖 binding、tenant 状态、profile pointer、
  grant/lease/revoke、route/projection、query allow/deny/evidence 和管理员操作。
- OBS-002：每个事件有 schema、event ID、tenant opaque ID、actor hash、类型、
  时间、关联 ID、before/after 摘要、evidence refs、prev/event hash；无正文。
- OBS-003：hash chain 与周期 checkpoint 可检测删除、插入、重排、篡改和
  tenant chain 交叉；replay 可重建关键状态变化序列但不成为权限 SoR。
- OBS-004：tenant health 包含最近采集、canonical、grant、route、space、
  query、模型成本、锁/队列/限流/配额、恢复状态的聚合值。
- OBS-005：tenant 用户只能读取自己摘要；中央事件和他租户统计不可见。
- OBS-006：结构化日志和错误扫描无 raw/AppKey/credential/full query/temp URL/
  原始 Agent ID/绝对路径；query 只记 hash、长度、意图和授权 report IDs。
- OBS-007：metrics/exporter/dashboard 故障不阻塞数据面；本地安全审计失败的
  fail-closed 范围明确且可测试。
- OBS-008：生成 10 tenant × 10,000 report 的确定性合成数据，不使用生产
  raw/identity/secret。
- OBS-009：分别测量 warm/cold、Broker core、真实沙箱 E2E、至少三个并发档、
  各 disposition、撤权逻辑拒绝与全部派生清理时间。
- OBS-010：基准报告记录机器/OS/Python/Gateway build、commit、数据规模、
  缓存、并发、配额、方法、样本量、错误率和分位数；没有实测不写数值。

### 明确不做

- 预先规定“达标数字”、自动调优生产、恢复/切换、采集真实用户数据。
- 日志原文检索、全租户普通 dashboard、把 audit 作为 grant/profile SoR。

## 4. 输入

- 上游结构化 event adapter，只接受允许字段和 opaque refs。
- metrics observation，只接受数值/枚举/哈希/受限标签；禁止高基数 query、
  report title、raw URL、absolute path 作为 label。
- benchmark config：seed、tenant/report 数、并发档、warm/cold、duration/sample
  count、component/E2E mode；禁止 credential/生产 root。
- gate receipts：VG-B/C/D 必须绑定当前或兼容 commit；缺失即不运行正式基准。
  唯一格式与路径来自中央契约 `contracts/gates/`
  （`cwk.pr001.verification_gate_receipt.v1` + `gate_registry_v1.json`）。
  按 registry 的 `receipt_path` 机读 JSON；registry 是冻结配置不含状态，
  `receipt_path` 不存在即该 gate 为 NOT RUN。RT-024 **只消费，不创建、不补写、
  不猜测**任何 VG receipt，也不得从 Markdown 叙述推断状态。

## 5. 输出

- `cwk.rt024.audit_event.v1`、`audit_checkpoint.v1`、`audit_verify_report.v1`。
- `cwk.rt024.tenant_health.v1` 与 admin-only aggregate（无 tenant 正文）。
- `cwk.rt024.benchmark_manifest.v1`、sample stream 和 benchmark report。
- 每份输出 canonical JSON + SHA；报告清楚区分 measured/derived/not_measured。

## 6. 业务规则

1. 事件只追加；修正通过新 correction event 引用旧 event，不原地覆盖。
2. hash 采用 domain separator + JCS bytes；checkpoint 独立持久化并可离线验。
3. tenant chain 和中央 security chain 均不得让 tenant A 推断 B 的事件数/时间。
4. audit replay 仅复核历史，不覆盖 Access Ledger/Profile/Route SoR。
5. metrics label 使用 allowlist；未知 label 拒绝，避免正文和高基数泄漏。
6. exporter 采用有界异步队列；满队列丢 metrics 时计数并报警，不拖垮数据面。
7. 基准 raw 全合成，seed 固定且 manifest 记录；禁止读取 production root。
8. core 与 E2E 数值分开，warm/cold 分开，不用一个 P95 代替所有链路。
9. 撤权分别记录事件接收→Broker deny、事件接收→各 cleanup consumer ack；
   不把两者混成一个时间。

## 7. 异常情况

- audit event 含 forbidden field、控制字符、绝对路径、完整 query/raw。
- chain 中间事件被改、删、复制、重排，checkpoint 被替换或跨 tenant 拼接。
- A 使用 B context 读 health，未知 tenant 枚举，统计标签串扰。
- exporter 卡死/超时/抛错/队列满/重启；本地 spool 满盘或损坏。
- benchmark config 试图指向 production root、样本不足、warm/cold 标注错误、
  E2E 未走真实 VG-D transport。

## 8. 验收标准

- AC-024-01：VG-B/C/D receipt 验证失败时正式基准拒绝启动。具体包括：
  `receipt_path` 缺失（NOT RUN）、schema 不合法、`status != pass`、
  `feeder_rt_independent_pass=false`、`receipt_sha256` 独立重算不匹配、
  `artifacts[].sha256` 漂移、commit/build 不兼容。receipt `synthetic=true` 或
  `conclusion=conservative_unknown` 时基准报告必须显式标注该限制。
  静态检查证明 RT-024 未写入任何 `gate-receipts/**/receipt.json`。
- AC-024-02：关键事件类型可 replay，篡改/删除/重排 100% 被 verify 报告发现。
- AC-024-03：日志/审计/metrics/spool 扫描禁止内容命中为 0（schema 字段名
  例外须人工列明）。
- AC-024-04：A 无法读取或推断 B health/event；错误不存在性等价。
- AC-024-05：exporter/dashboard 失效时数据面测试仍完成；积压有界且可恢复。
- AC-024-06：10×10,000 合成基准按 manifest 完成，core/E2E、warm/cold、并发、
  disposition 分开报告，真实样本数非 0。
- AC-024-07：撤权逻辑拒绝与各 cleanup 延迟分别报告，未测项标 not_measured。
- AC-024-08：报告不预填目标或将测量结果伪装成业务 SLA。
- AC-024-09：全库回归、Wiki smoke、secret scan、回滚验证通过，独立验收 PASS。

## 9. 黑盒测试矩阵

| 场景 | 操作 | 期望结果 |
| --- | --- | --- |
| 正常审计 | 依次 binding/profile/grant/query/revoke | replay 顺序与 refs 一致 |
| 篡改 | 改一字节/删除/重排/复制事件 | verify 明确失败并定位 opaque event |
| 日志注入 | reason/query 含 CRLF/ESC/path/token-like | 拒绝或脱敏，无原文落盘 |
| tenant 隔离 | A 请求 B health/猜 ID | 等价拒绝，无 B 统计 |
| exporter 故障 | timeout/crash/queue full | 数据面完成，drop/backlog 指标可见 |
| 审计满盘 | 本地 audit spool 不可写 | 需强审计的安全操作 fail closed |
| core 基准 | fake-free real Broker core 多并发 | 生成带环境/样本/分位数报告 |
| E2E 基准 | 真实 VG-D 沙箱链 | 单独生成 E2E 报告，不混 core |
| 撤权测量 | 注入 authority revoke | 分别输出 deny 与 cleanup 时间 |
| 生产路径注入 | config 指向现有 production root | runner 拒绝启动 |
