### A-03 CLI slot 激活：强制执行顺序

RT-012 dispatcher 每次加载**全部** `FROZEN_PROVIDER_SLOTS`。若先把
`cwk_tenant_cmd_profile` 追加进 slot tuple 而 provider 文件尚不存在，dispatcher 在加载阶段
即失败，会**破坏所有既有 CLI 命令**。因此以下三步顺序不可交换，slot commit 绝不能早于
provider 文件落地：

- [ ] A-03a（**先**）：落地 `scripts/cwk_tenant_cmd_profile.py`——ABI-valid 的
  `CommandProviderV1` 实现，默认 **fail-closed**（依赖未就绪时返回稳定 error code，不
  `sys.exit`、不抛裸异常），并配套其单元测试。此步**不触碰**
  `FROZEN_PROVIDER_SLOTS`，因此现有 CLI 完全不受影响。
- [ ] A-03b（**后**）：独立的 RT-012 compatibility commit，**只**在 slot tuple 追加一行
  `cwk_tenant_cmd_profile`，并追加 tenant CLI ordinal 1 / stage-03 append-only evolution
  receipt 与 migration note。精确 diff 限制：不得改 dispatcher 逻辑、搜索路径、错误语义、
  provider ABI，不得修改中央 policy/schema/helper/guard 或旧 SHA 表。
- [ ] A-03c（**再后**）：全量 CLI 回归——core/binding 既有命令零漂移、新 profile 命令可达、
  provider 缺失/ABI mismatch/duplicate command/symlink/CWD/PYTHONPATH 注入全部 fail closed。
  A-03c 未通过则回退 A-03b，保持 A-03a 状态（provider 存在但未挂载），既有 CLI 仍可用。
