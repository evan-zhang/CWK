# RT-019 技术方案：Knowledge Profile 提案、确认与版本生命周期

> 状态：planned。RT-020/021 尚未实现时，真实 preview/route/space 均保持 fail closed。

## 1. 模块

- `cwk_profile_sampler.py`：eligible corpus snapshot、stratification、联合 manifest。
- `cwk_profile_proposal.py`：zero-tool AI runner、chunk 聚合、proposal/decision/impact validator。
- `cwk_knowledge_profile.py`：immutable store、六状态、pointer CAS、rollback。
- `cwk_space_id.py`：`SpaceIdFactoryV1`，以 CSPRNG 128-bit 生成 RFC 4648 小写、无 padding 的 `sp_...` 候选；执行 tenant-scoped occupied-set 检查与有界碰撞重试。
- `cwk_tenant_cmd_profile.py`：CommandProviderV1 CLI adapter。
- Wave-0 `cwk_pilot_admission_api.py`：neutral shared ABI，RT-019 零漂移消费；不在本 RT
  fork schema/runtime 或实现 production adapter。
- `contracts/rt019/schemas/`：proposal job/result/item、decision、impact manifest、**profile preview receipt**（`cwk.profile_preview_receipt.v1`）等 RT-owned schema。RT-019 是 `PreviewProviderV1` ABI 与 preview receipt schema 的**唯一 owner**；RT-020 只作为零漂移 consumer，不得在 `contracts/rt020/schemas/` 重定义同名 receipt。

## 2. 数据布局

```text
tenants/<tenant_id>/
├── config/profile/
│   ├── manifests/<manifest_id>.json
│   ├── proposals/<proposal_id>.json
│   ├── decisions/<decision_id>.json
│   ├── versions/<profile_version>.json
│   ├── impacts/<profile_sha256>.json
│   ├── events/<event_id>.json
│   └── active-pointer.json
├── runs/profile/<job_id>/manifest.json
├── retries/profile/<job_id>.json
└── locks/profile.registry.lock
```

所有 leaf opaque/validated，0600/0700、dirfd/O_NOFOLLOW、CAS/fsync；ref 是相对 opaque ID，不暴露宿主机路径。

## 3. Corpus snapshot 与联合 manifest

1. 调用 RT-017 冻结的公共只读 ABI `AccessLedger.list_profile_eligible(*, snapshot)`
   （`cwk.profile_eligibility.v1`）获取 tenant 的 `ProfileEligibleRecord` 序列。这是本 RT
   获取候选语料的**唯一**合法入口：不得从 index/view 推断，不得读取 ledger 私有 grant
   目录，不得修改 `cwk_access_ledger.py`，也不得放宽 `list_query_eligible`（后者仍只
   放行 `pilot|active`，`profile_pending` 的普通查询依旧关闭）。
2. 对返回记录再次逐条检查 lease/auth_epoch，并用 RT-014 public reader 按
   `report_key + canonical_sha256` 回读并验证 canonical SHA；分层所需的时间、source、
   author、report type、activity 均来自该 canonical 读取，而非 eligibility 记录。
   返回的 `canonical_sha256` 已由 RT-017 CanonicalVersionProvider 点查并通过同一 public
   reader 验证；本次回读是 consumer-side 二次完整性门禁，不替代 provider 的验证。
3. 以 report key group 去重，冻结 corpus snapshot SHA。
4. 若 group 数 <120，原子写 job terminal receipt，立即结束，不启动 AI。
5. 按 policy v1 计算 holdout/sample size；在每个 strata 内用 `HMAC(seed, domain || LP(group_identity))` 排序，保证可复现。
6. 先分配 holdout group，再 samples；构建 chunks；写前再次 ACL。若 tenant 为
   `pilot`，以 constructor-bound `purpose=profile_workflow` 取得新的 PilotAdmission，
   拒绝 deny/unavailable/expiry/revision 回退/policy 或 snapshot 漂移，再原子发布唯一
   manifest；`profile_pending/active` 跳过该调用。

联合 manifest 的 `sample_manifest_ref` 与 `holdout_manifest_ref` 是同一 opaque ref。实现 semantic validator，不修改 v1 schema 历史文件。

## 4. Proposal runner

Runner 通过受控子进程/沙箱抽象，启动时显式清空网络、文件、工具与继承环境；只注入固定 prompt hash、model ID 和当前 chunk evidence bundle。原文包裹为 data，不拼成指令。

每个 chunk 产生 partial proposal，先 validate 后存不可变 partial hash；final 聚合只读取 validated partial。任一 chunk 失败不会产出 final Profile。禁止日志写 evidence body，只记录 chunk ID/hash/token counts（若 provider 提供）。

## 5. Proposal/decision/Profile 边界

- Proposal item ID 由 manifest SHA + item canonical payload domain-separated hash 生成。
- AI 对 space 只输出 slug/purpose 建议；宿主机 `SpaceIdFactoryV1` 在 proposal/decision 校验后用 CSPRNG 128 bit 分配候选 `sp_...`，并把 ID 纳入 Profile SHA。AI、slug 或标题都不能决定 ID。
- Decision 对 proposal item ID 与 proposal SHA 签定；edit 产生 normalized after value 和新 impact analysis，不改 proposal。
- `KnowledgeProfile v1` 只由 accepted/edited non-deferred items构造；高影响 completeness validator 必须全通过。
- Profile Service 只在 proposal 与用户决定通过后为新 space 分配候选 ID。RT-021 激活时验证该 ID 未占用并原子注册；冲突必须重新生成新 Profile 版本，不能原地修改已哈希 ID。
- Profile SHA 使用已有 RT-011 helper，不自行重写 hash 算法。
- impact manifest 是 opaque report/space refs 列表 + reason，不含 raw；供 RT-020/021 消费。

## 6. Preview ABI 与激活

RT-019 提供 Protocol 与 `NullPreviewProvider`；ProfileRegistry 的 `activate` 要求通过 verifier 的 receipt。RT-020 将实现 provider，不通过 monkeypatch/private token 注册。

**单一所有权**：`PreviewProviderV1`（ABI + `API_VERSION`）与 `cwk.profile_preview_receipt.v1` schema 在本 RT 冻结后即为跨 RT 唯一定义。RT-020 按位复用同一 schema 文件与 Protocol，禁止 fork、扩展、收窄或以同名 schema 重定义；任何字段变更必须回到 RT-019 发新版本并附 migration note。RT-020 拥有的是 preview **result set**（受 receipt `result_set_sha` 绑定的被预览条目集合）与 activation receipt，与本 receipt 是不同对象。

`PreviewProviderV1.preview` 的冻结签名为 `preview(*, tenant_snapshot, profile_ref, joint_manifest_ref, deadline_at, provider_version)`；`deadline_at` 必须进入执行快照，`provider_version` 必须等于 provider 自报版本并绑定 receipt，禁止从全局变量补参。

```text
proposal → decisions complete → profile proposed
→ provider preview receipt → profile preview
→ user confirmation bound to receipt → confirmed
→ activation receipt CAS → active; prior active → superseded
```

在 RT-020 前，Null provider 使真实流程停在 proposed；测试 fake receipt 带 `synthetic=true`，registry 的 production mode 必须拒绝 synthetic。

## 7. CLI compatibility 修订

RT-012 dispatcher 每次加载**全部** `FROZEN_PROVIDER_SLOTS`；若 slot tuple 中出现尚未落地的
provider 文件，dispatcher 在加载阶段即失败，**所有既有 CLI 命令一并被破坏**。因此 slot commit
必须严格晚于 provider 文件，顺序不可交换：

1. **先落地 provider 文件**：`scripts/cwk_tenant_cmd_profile.py` 实现 ABI-valid 的
   `CommandProviderV1`，默认 **fail closed**（依赖未就绪时返回稳定 error code，不 `sys.exit`、
   不抛裸异常），并配套单元测试。此步**不触碰** `FROZEN_PROVIDER_SLOTS`，既有 CLI 零影响。
2. **再做独立 compatibility commit**：**只**在 slot tuple 追加一行 `cwk_tenant_cmd_profile`，
   并追加 tenant CLI ordinal 1 / stage-03 append-only evolution receipt 与 migration note。
3. **最后全量 CLI 回归**：回归不通过则回退第 2 步，保留第 1 步状态（provider 存在但未挂载），
   既有 CLI 仍可用。

验收断言：

- diff 不包含 dispatcher 逻辑/搜索路径/API/error code/provider ABI 变化，也不修改中央
  policy/schema/helper/guard 或旧 SHA 表；
- provider 从 trusted scripts absolute path 加载，symlink/CWD/PYTHONPATH 注入拒绝；
- provider 缺失、ABI mismatch、duplicate command fail closed；
- core/binding 既有 commands/output 零漂移回归，新 profile 命令可达；
- 新 provider 命令均通过稳定 CommandSpec，不调用 `sys.exit`。

## 8. 生命周期与 rollback transaction

每个 version immutable。激活/回滚持有 registry lock，并以 active-pointer SHA 做 CAS：先准备 event 与目标状态文件，fsync，再原子替换 pointer；recovery 根据 journal 完成或恢复到旧 pointer，永不出现两个 active。

rollback verifier 只接受 pointer history 中最近 superseded；旧版本内容/profile SHA/manifest refs 必须完整。事件追加后不能删除。

## 9. 安全与错误

- 全层 deepForbidden + recursive scan；任何 forbidden key 即拒绝整个 proposal/profile，而非只删除字段。
- evidence ref 必须在联合 manifest samples；holdout 访问只允许 PreviewProvider。
- user actor 从可信 host context，不从请求正文自报。
- 错误返回 stable code + opaque IDs，不含正文、路径、tenant existence 或模型原始输出。

## 10. 测试与回滚

- property tests 覆盖 sampling size/overlap/determinism/chunk coverage。
- zero-tool harness 对恶意 raw 与 hostile model output 做黑盒攻击。
- transaction crash injection 覆盖 manifest/proposal/decision/pointer/rollback。
- CLI compatibility 精确 diff guard。
- 回滚实现仅切 pointer；不删版本/decision/manifest。若要停用 RT-019，保留全部不可变产物并禁用 provider slot/调用，但不得破坏 dispatcher。
