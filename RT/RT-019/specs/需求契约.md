# RT-019 需求契约：Knowledge Profile 提案、确认与版本生命周期

> 状态：planned。本文冻结 RT-019 的行为、数据、权限和黑盒验收标准。

## 1. 业务目标

基于每个 tenant 自己有权访问的报告，生成可解释、可编辑、可拒绝、可预览、可版本化和可回滚的知识治理方案；AI 只提出 proposal，用户是高影响决定的最终主体。

## 2. 用户角色

- Tenant owner/user：描述职责、确认/拒绝/编辑/暂缓建议、请求回滚。
- Knowledge Profile AI：只在 zero-tool sandbox 输出 JSON proposal。
- Profile Service：抽样、验证、版本与 pointer 的权威实现。
- PreviewProvider：RT-019 冻结 ABI；RT-020 提供真实实现与 receipt。
- 平台管理员：诊断/恢复；不能替用户通过普通入口秘密扩权。

## 3. 语料 eligibility 与抽样

候选语料**只能**通过 RT-017 冻结的公共只读 ABI
`AccessLedger.list_profile_eligible(*, snapshot)`（`cwk.profile_eligibility.v1`）获取。
RT-019 **不得**修改 `cwk_access_ledger.py`、不得放宽 `list_query_eligible`
（它仍只放行 `pilot|active`），也不得直接扫描 ledger 私有目录（如
`tenants/<id>/access/grants/`）或从 index/view 推断授权。该 ABI 已在 ledger 侧保证
tenant 状态 ∈ `{profile_pending, pilot, active}`、grant `active`、lease 未过期、
`auth_epoch` 匹配，并只返回 opaque 授权事实（无正文/路径/credential）。
其中 `canonical_sha256` 必须已经由 RT-017 注入的 `CanonicalVersionProviderV1` 点查并
经 RT-014 public `read_version` 验证；RT-019 仍需按下述步骤二次回读，且不得从 grant/
view/private catalog 重新推断 current SHA。

在此之上，RT-019 再逐条校验：

- 记录来自上述 ABI，且 `tenant_status` 允许 profile 作业；
- RT-014 canonical 可按 report key + SHA 完整回读；
- report/version 去重后唯一；
- 不属于 staged-only event、revoked/revalidation_due/granted/discovered 或其他 tenant；
- 抽样前后重读 auth_epoch/lease；快照变化则本次任务 fail closed，不生成 manifest。
- 若 tenant status=`pilot`，构造注入 `PilotAdmissionProviderV1` 并固定
  `purpose=profile_workflow`；在 corpus/manifest 生成前与 manifest/proposal/Profile
  持久化边界前重验。deny/unavailable/过期/revision 回退或两次快照漂移零下游产物。
  `profile_pending/active` 不调用该 provider，不改变其既有状态规则。

抽样规则：

- 候选少于 120 → `insufficient_authorized_sample`，零下游产物。
- 候选不少于 120：`holdout_size = clamp(floor(N * 0.15), 20, 30)`；`sample_size = min(200, N - holdout_size)`，且 sample 必须 100～200。
- 使用时间、source、author、report type、activity 的确定性多维分层；固定 corpus snapshot + random_seed + policy version 重放结果一致。
- samples 与 holdout 以 `(report_key, canonical_sha256)` 为 identity，必须零重叠；同 report 的不同 version 不得分散到两集合造成泄漏，按 report key group 分配。

## 4. 联合 SampleManifest 契约

仅写一个 `cwk.sample_manifest.v1` immutable file，包含 samples、holdout、strata、chunk layout、seed、created_at。附加语义：

- `actual_sample_size == len(samples)`；所有 chunk report keys 与 samples 完全一一覆盖；
- holdout 不出现在 chunk layout；samples/holdout report key group 零重叠；
- 所有条目仍是 active grant snapshot；manifest 写前后二次 ACL；
- ref 为 tenant-scoped opaque ref，不是绝对路径；SHA 为 NFC + RFC8785 JCS UTF-8 文件字节 hash；
- Profile 的 `sample_manifest_ref == holdout_manifest_ref`，均指该文件，`sample_manifest_sha256` 覆盖整份文件。

## 5. Proposal 契约

Proposal 至少包含：

- 推荐 spaces（AI 只提议 slug/purpose；通过校验后由宿主机 `SpaceIdFactoryV1` 以 CSPRNG 分配候选 opaque `space_id`，本 RT 不创建 durable space）；
- entity 粒度、confirmed alias 候选、merge/split；
- attention 来源/对象/类型；routing/archive rules；常见 query；review threshold；
- 每项 `proposal_item_id`、类别、建议值、至少一个真实 evidence ref、出现数、覆盖率、影响报告数、代表样例 refs、impact level；
- `sample_manifest_sha256`、prompt template SHA、model ID、proposal version/status。

禁止字段：tenant/agent/binding/credential/path/grant/shared object、shell/command/tool、任意 prompt template、URL/token、原始完整正文。Evidence refs 必须属于 samples 且 ACL 二次校验通过；引用 holdout 或非样本即整项拒绝。

`SpaceIdFactoryV1.allocate(*, tenant_snapshot, occupied_space_ids) -> str` 只接受可信 tenant snapshot 与不可变 occupied set；用 CSPRNG 128-bit 生成 RFC 4648 小写、无 padding 的 `sp_...`，最多 32 次碰撞重试，耗尽返回稳定 `space_id_exhausted`。它不读取 slug/title/AI 输出决定 ID；RT-021 必须复用同一模块与 ABI。

Proposal job 状态：`planned → sampling → proposing_partial → validating → proposed`，或终止于 `insufficient_authorized_sample | proposal_error | acl_snapshot_changed | cancelled`。这些是 job 状态，不得添加到 Profile 六状态。

## 6. AI 安全契约

- zero-tool sandbox：无网络、文件系统、shell、sub-agent 或宿主机工具；输入只有分批 evidence bundle + 固定 prompt；输出只允许 stdout JSON。
- 原文显式标记为 untrusted data；其中命令、路径、credential、规则改写或工具请求不得执行。
- chunk 输出必须逐份 schema/ACL/evidence validate，最终聚合也再次 validate；partial 不可激活。
- bad JSON、超限、未知字段、禁止字段、伪造 evidence、模型超时/拒绝均进入 `proposal_error`，不产生 Profile。

## 7. 用户决策与高影响门禁

操作固定为 `accept/reject/edit/defer`。每条 decision 记录：item ID、actor（可信宿主机上下文）、action、before/after（脱敏结构化值）、reason、evidence refs、impact count、created_at、decision SHA。

高影响至少包括 merge、split、ignore/archive 类别、覆盖多报告的 include/exclude。必须展示影响数量和至少 3 个代表样例；未显式 accept/edit 的高影响项不得进入 confirmed。`defer` 与无响应都不等同 accept。

编辑后的值必须重新跑 schema、禁止字段、evidence/ACL 和影响分析；用户不能通过编辑加入 tenant/credential/path/grant 或任意 tool。

## 8. Profile 生命周期

唯一状态：`draft → proposed → preview → confirmed → active → superseded`；不存在 `rolled_back`。

- RT-019 可创建 draft/proposed，记录 decisions，并准备 preview；真实 `preview → confirmed → active` 需要 RT-020 PreviewReceipt/ActivationReceipt。
- Profile content/version immutable；pointer 用 CAS 原子切换。
- `profile_sha256` 严格沿用 RT-011 domain-separated 公式，绑定 normalized proposal、联合 manifest SHA、prompt template SHA、model ID。
- 每版本生成 impact manifest，列出 reroute/reindex affected report/space 的 opaque refs；不在本 RT 执行。
- rollback 只允许切回最近一个 superseded version：追加 `profile_pointer_rollback`，原子把当前 active → superseded、目标 superseded → active；不删除/覆盖历史。

## 9. PreviewProviderV1

```python
API_VERSION = "cwk.preview_provider.v1"
def preview(*, tenant_snapshot, profile_ref, joint_manifest_ref,
            deadline_at, provider_version) -> PreviewReceiptV1
def verify(receipt: PreviewReceiptV1, *, expected_profile_sha,
           expected_manifest_sha, expected_holdout_set_sha) -> None
```

- 本 RT 是 `PreviewProviderV1` ABI 与 `cwk.profile_preview_receipt.v1` schema 的唯一 owner；RT-020 只能零漂移消费同一 Protocol 与 schema 文件，不得重定义同名 receipt。
- RT-019 默认 NullPreviewProvider 永远返回 `preview_unavailable`；测试可注入 fake，但必须标记 synthetic。
- Receipt 必须绑定 tenant/auth/profile/manifest/holdout set、provider/version、result set SHA、created/expires 和完整性 hash。
- `deadline_at` 必须为受限未来时刻并进入 preview snapshot；`provider_version` 必须匹配 provider 自报版本。缺失、漂移或隐式全局取值均拒绝。
- 没有 RT-020 实际 receipt 不得 active；fake receipt 不能用于生产状态。

## 10. CLI 契约

`cwk_tenant_cmd_profile.py` 通过 CommandProviderV1 提供至少：`knowledge-init`、`profile-status`、`profile-decide`、`profile-preview`、`profile-activate`、`profile-rollback`。

- 不接受 AppKey、agent_id、绝对路径、raw prompt、任意 model command。
- JSON 输出不含正文/路径/credential；稳定 exit code。
- 必须先通过 RT-012 compatibility commit 激活 frozen slot；仅 provider 文件存在但 dispatcher 不可达视为 FAIL。

## 11. 异常策略

- 样本不足：明确终态、建议采集更多已授权报告，不生成任何 Profile。
- ACL/lease/auth_epoch 在 sampling/proposal/commit 任一点变化：任务失败，删除临时 AI 输入，持久 manifest/Profile 不发布。
- AI/JSON/evidence 失败：proposal_error，不 fallback 自动规则并假装 AI proposal。
- pointer CAS 冲突：返回 conflict，重读后由用户重试；不覆盖 active。
- rollback 目标不是最近 superseded、SHA 损坏或 receipt 不匹配：fail closed。

## 12. 验收标准

- AC-019-01：N≥120 时生成 100～200 samples +20～30 holdout，确定性可复现且 report group 零重叠。
- AC-019-02：N<120 明确 `insufficient_authorized_sample`，零 manifest/proposal/profile/AI 调用。
- AC-019-03：候选只经 `list_profile_eligible(*, snapshot)` 取得且只含 active grant；
  lease/auth epoch 变化、revoked 与其他 tenant 永不入样。静态检查证明 RT-019 未修改
  `cwk_access_ledger.py`、未调用其私有成员、未直接读取 ledger 私有 grant 目录。
- AC-019-04：联合 manifest 唯一，两个 Profile refs 相等且 SHA 覆盖 samples+holdout；chunk 完整。
- AC-019-05：恶意 raw 无法触发工具；bad JSON、禁止字段、错误 evidence/holdout 引用全部拒绝。
- AC-019-06：高影响项未接受不得 confirmed/active；accept/reject/edit/defer 均有不可变审计和影响样例。
- AC-019-07：Profile SHA/版本/pointer 原子、历史不可变；仅最近 superseded 可 rollback。
- AC-019-08：没有真实 PreviewReceipt 不得 active；synthetic receipt 明确标记且不能升级生产。
- AC-019-09：profile CLI provider 通过显式 RT-012 compat slot 可达，dispatcher 安全属性和既有命令零回归。
- AC-019-10：不创建 route/index/space 文件，不读取 staged event body，不修改 nightly/生产开关。
- AC-019-10a：只有 RT-017 完整 Stage-01 独立 PASS 后才启动；eligibility 的 SHA 经
  CanonicalVersionProvider + public read_version 双重验证。`pilot` Profile workflow 在
  manifest/proposal/Profile 持久化边界重验；deny/unavailable/expiry/revision 回退/
  snapshot 漂移均零产物，`profile_pending/active` 调用次数为 0。

## 13. 测试场景

- Corpus N=0/119/120/129/200/230/1000；strata 稀疏、同 report 多 version、seed replay。
- ACL revoke/expiry/auth epoch race；canonical missing/corrupt；cross-tenant candidate injection。
- AI prompt injection、bad JSON、extra fields、fake evidence、holdout leak、oversize output、timeout。
- Decision 并发、edit injection、影响样例不足、pointer CAS、rollback chain/损坏。
- CLI missing slot/provider、duplicate command、trusted path、stable error、secret/path scan。
- 全量 RT-011～019、Wiki lint/smoke、legacy regression。
