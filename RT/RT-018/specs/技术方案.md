# RT-018 技术方案：宿主机 Tenant Scheduler

> 状态：planned。实现不得把本文中的计划接口误写成已存在事实。

## 1. 模块

- `cwk_job_provider.py`：frozen dataclass、Protocol、registry、schema/semantic validation、idempotency helper。
- `cwk_collector_job_provider.py`：RT-017 `TenantCollectorWorker` adapter。
- `cwk_tenant_scheduler.py`：tick、stagger、fair queue、lease、retry、circuit、quota、recovery 与 manifest。
- `contracts/rt018/schemas/`：job spec/result/state event/run manifest/recovery decision。

## 2. Registry 设计

```python
registry = JobProviderRegistryV1([
    CollectorJobProviderV1(...),
])
scheduler = TenantScheduler(..., providers=registry)
```

- Registry 不接受字符串 module path，不自动 import，不扫描目录。
- 构造时校验 exact API version、provider name/version grammar、job kinds 唯一、callable signature。
- Provider 加入由可信 composition root 负责：RT-018 测试 factory 只加入 collector；RT-026 以后可显式组合 RT-021 provider。
- Provider 集合及每个版本 SHA 写入启动 receipt，防止运行时替换。

## 3. Durable 布局

```text
tenants/<tenant_id>/
├── state/scheduler-v1.json
├── runs/scheduler/<tick_id>/<job_id>.json
├── retries/scheduler/<job_id>.json
├── locks/scheduler.writer.lock
└── logs/scheduler/                 # only redacted structured events
runtime/
└── scheduler-v1/                   # global resource counters/heartbeat only
```

业务状态只在 tenant 子树。`runtime/scheduler-v1` 不保存 report、cursor、credential、job input 或租户业务结果；丢失后可从 tenant 状态重建。

## 4. 幂等 key

```text
LP(x) = uint32_be(len(utf8(NFC(x)))) || utf8(NFC(x))
job_key_bytes = b"cwk-job-v1\0" || LP(provider_name) || LP(provider_version)
                || LP(job_kind) || LP(tenant_id) || LP(trigger_id)
                || LP(input_ref) || LP(policy_version)
idempotency_key = "jk_" + base32(sha256(job_key_bytes))[:26]
```

`base32` 固定为 RFC 4648 小写、去 padding、字符集 `[a-z2-7]`；禁止直接保留库函数默认大写输出。

`job_id` 可随机 opaque，idempotency_key 决定重复计划收敛。测试包含边界拼接碰撞对（`ab|c` vs `a|bc`）。

## 5. Tick 算法

1. 读取 Registry 候选 tenant，按 opaque tenant ID 稳定排序。
2. 对每 tenant 验证状态/配额/revision；不合格仅记录 reason code。
3. 计算稳定 stagger window；调用 provider `plan(snapshot)`。
4. 以 CAS enqueue 未存在的 idempotency key。
5. deficit round-robin 选择可运行 tenant；获取 tenant writer lock。
6. execute 前重读 tenant status/revision/auth_epoch 和 deadline；若为 `pilot`，调用构造期
   绑定 `collector_run` 的 shared provider，验证第一次 PilotAdmission snapshot。
7. 写 `leased → running`，调用 provider；校验 JobResult。
8. 提交终态/manifest 前重读 tenant；若为 `pilot` 再取一次 PilotAdmission，拒绝
   revision 回退、policy/hash/snapshot 漂移，再原子提交；`active` 两次都跳过。
9. 释放 lock，继续其他 tenant；任何异常不得退出主循环。

## 6. 单写锁与租约

- tenant writer lock 是 OS advisory lock + durable lease record 双层；lease 绑定 scheduler instance opaque ID、pid hash、boot ID hash、acquired/expires。
- 获取失败立即返回 `already_leased`，不长时间阻塞线程。
- stale lease 只有在进程/boot/expiry 证据一致时才回收；回收前调用 provider `recover`。
- Scheduler 自身不跨 tenant 持有多个 writer lock，避免锁顺序死锁。

## 7. Fairness、quota 与 circuit

- tenant 每 tick 获得 deficit credit；执行成本按 resource class 权重扣减；等待 tenant 的 credit 可累积到有界 cap。
- priority 只改变同 tenant 队列顺序，不跳过跨 tenant fairness。
- 并发限制分 `source_io/ai/derived_io`；首期 collector 用 `source_io`。
- circuit 状态持久化 tenant+provider+class：closed → open → half_open → closed/open；阈值和 backoff 来自版本化 policy，测试不把未经 RT-024 测量的数值宣称生产 SLA。

## 8. Recovery

- 启动扫描 tenant scheduler state，不扫描 shared raw。
- queued/retry_wait 重新排队；running/leased 先核对 result receipt，再调用 provider recover。
- 若 provider 能证明结果已提交，写 succeeded；否则只在 idempotency contract 允许时重排。
- corruption、未知 schema/version、状态逆转全部 fail closed 到 review/permanent_failed，不重写历史文件。

## 9. 安全

- Provider context 只含 layout/factories/clock/cancellation，不含 credential material；Collector provider内部使用 Broker。
- structured log allowlist；异常映射稳定 reason，不打印 `repr(exc)`。
- dirfd/O_NOFOLLOW、0600/0700、CAS/fsync；拒绝 symlink、hardlink、absolute、traversal、TOCTOU。
- 不启动 daemon/cron；测试通过显式进程入口或 library 调用。
- `PilotAdmissionProviderV1` 只构造注入，不读 env/CWD/private release config；Null
  provider 对 `pilot` 返回稳定 `unavailable`。RT-018 不实现 production adapter。

## 10. 测试策略与 VG-B handoff

- deterministic fake clock、fake provider、crash hooks 覆盖状态机。
- 多进程锁与重启测试验证 single writer。
- 双 tenant fault matrix 验证任何 A 故障下 B receipt 仍完成。
- manifest snapshot + secret/path scan。
- RT-018 独立 PASS 后，VG-B 再接 fake CWork → RT-017 Worker → RT-014/015 → Scheduler 完整链；receipt 归 PR gate，不由本 RT 自封。

## 11. 回滚

停止调用新的 Scheduler 即完成运行回滚；不修改 legacy nightly。保留 tenant job/result/receipt 供审计，不能删除 succeeded 或 revoke 事实。未来重新启用时先执行 recovery，不把旧 running 盲目视作成功。
