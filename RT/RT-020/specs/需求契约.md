# RT-020 需求契约：Holdout 预览、Router 与决策日志

> 状态：planned。本文是 Preview/Router 的编码和黑盒验收权威契约。

## 1. 业务目标

用户在激活知识方案前能看到未参与 proposal 的 holdout 效果；激活后每篇已授权报告获得可解释、可重放、可审计的 `index/archive_no_index/review` 决策，并能随证据/Profile/用户纠正变化安全重路由。

## 2. 角色

- Tenant user：查看 preview、确认或拒绝激活、纠正 route。
- PreviewProvider：只读取联合 manifest holdout 与 proposed Profile。
- Router：固定优先级决策，不拥有 grant 或 raw。
- Profile Registry：验证 preview/user/profile 绑定后原子激活。
- RT-021 Projector：后续消费 RouteDecision v2；本 RT 不写投影。

## 3. Holdout 预览

输入必须绑定：tenant/auth snapshot、proposed profile version/SHA、联合 manifest ref/SHA、holdout set SHA、PreviewProvider name/version、请求时间/deadline。

PreviewProvider 只能读取 `manifest.holdout`；如果任何 holdout report 出现在 samples/chunk/proposal evidence，整次 preview fail closed。逐篇输出：

- report key + canonical SHA 的 opaque ref；
- proposed disposition、candidate/committed spaces、reason codes、confidence；
- summary sample、entities、可回答问题、archive reason、不确定项的脱敏/受控 preview；
- evidence refs 与 per-item result SHA；
- 不把完整 raw、路径、credential 或其他 tenant 内容写入 receipt/log。

AI/派生失败不能从 holdout 删除失败样本后伪造成功；receipt 必须列出 total/succeeded/review/failed counts 和完整 result-set SHA。

## 4. 激活契约

Profile active 前同时需要：

1. profile SHA/联合 manifest SHA 完整；
2. PreviewReceipt 绑定相同 profile/manifest/holdout，未过期且 provider 受信；
3. 用户 confirmation 绑定该 receipt SHA、主体、时间和决定；
4. ActivationReceipt 绑定前述三者、影响清单、旧/new active pointer；
5. 激活 commit 前后二次检查 tenant status、auth_epoch 和 Profile pointer revision。

若 tenant status=`pilot`，还必须通过构造期绑定
`purpose=profile_workflow` 的 `PilotAdmissionProviderV1`：preview/result set 发布前、
activation commit 前各取 fresh snapshot；deny/unavailable/expiry/revision 回退或
policy/snapshot 漂移都拒绝，不能半激活。`profile_pending/active` 不增加该依赖。

任一不匹配/过期/synthetic-in-production/并发变化都拒绝。激活 transaction 把新 Profile 置 active、旧 active 置 superseded、pointer 原子更新，并排队 reroute；不能半激活。

## 5. Route 输入资格

- tenant status/profile/grant 均为当前可用；grant 必须 active、lease 未过期；canonical 按 SHA 可回读。
- route snapshot 固定 tenant auth_epoch、Profile version/SHA、grant revision/lease 与 canonical SHA；写 decision 前重检。
- `pilot` 在 route/route-diff/projection-request current pointer 持久化前重验
  `profile_workflow` admission；失败不写 decision，也不提交半 journal。
- v1 不读取 staged event body。合法 event change 只产生 opaque trigger；若正文不可用则进入 review，而不是猜测 archive/index。
- 不从 Wiki/index/space membership 推断权限或事实。

## 6. 决策顺序

严格顺序：

1. 权限/完整性/状态安全先决条件；
2. 用户显式 include/exclude/纠正规则；
3. confirmed entity/alias；
4. 结构化 source/type 规则；
5. AI 分类（仅前述不足时）；
6. threshold/conflict 合并。

规则之间冲突、低置信、新类型、AI bad JSON/timeout/禁止字段一律 `review`。AI 失败绝不解释为 `archive_no_index`。Router 不能返回 delete。

## 7. RouteDecision v2

Required：schema、decision_id、route_job_key、tenant_id、report_key、canonical_sha256、disposition、space_ids、confidence、reason_codes、evidence_refs、profile_version、profile_sha256、grant_snapshot_ref、decided_by、decided_at、decision_sha256。

语义：

- evidence refs 非空且属于本 report/profile 的已授权证据；不能引用 holdout 之外的 preview 数据扩权。
- index → committed space_ids 1..32、全部在 active Profile 且唯一；archive/review → space_ids=[]。
- `decided_by ∈ {user_rule,confirmed_entity,structured_rule,ai,composite,user_correction}`。
- confidence 只是分类度量，不能绕过冲突/权限；用户纠正也必须有 evidence/reason。
- decision SHA 用 domain-separated JCS，写后不可覆盖。

Review metadata 可记录 candidate space IDs、conflict set 和 required action；Archive metadata 只记录最小 change cursor/hash。两者都不建立 committed space membership。

## 8. 重路由与 diff

触发：canonical SHA、active Profile、confirmed entity、space config signal、user correction、grant revoke/reactivate、合法 event-change signal。

- 同一 route_job_key 重放返回同一 decision，不追加重复 log。
- 输入变化生成新 decision 与 `RouteDiffV1`，记录 old/new decision IDs、disposition、space sets、reason/profile/canonical changes 和 timestamp。
- `index → archive/review` 或 space 退出只发 cleanup/projector 事件，不由 Router 删除投影。
- `archive/review → index` 发 projection request。
- revoke 直接 fail closed 并交给 RT-015 cleanup；不写一个可误解为仍可查询的新 route。

## 9. 幂等键

严格采用 intake 中 LP + domain-separated SHA 公式；LP 长度为 unsigned 32-bit big-endian。所有字符串先 NFC、UTF-8；SHA 字段要求小写 hex。非法类型/超长无法编码即 contract error。

测试必须包含无分隔符会碰撞的 adversarial tuples，并证明两个公式结果不同；相同规范输入跨进程/重启完全一致。

## 10. 异常与安全

- Profile/manifest/receipt/SHA 损坏：拒绝激活/路由，不自动修复。
- ACL 在 preview/route 中变化：对应结果废弃；不泄漏 title/count/space membership。
- AI raw prompt injection：zero-tool classifier，只输出 schema JSON；禁止工具/路径/tenant/credential字段。
- route log CAS/满盘：不发布 partial decision，不发送 projection。
- 错 tenant/space/report/path 注入、inactive/unknown space、slug 作为 space ID 全部拒绝且错误不泄漏存在性。
- 完整 raw、query、event body、URL、credential、绝对路径不进 log/receipt。

## 11. 验收标准

- AC-020-01：Preview 只用 20～30 holdout，samples/holdout 零重叠；receipt 完整绑定 Profile/manifest/result set。
- AC-020-02：缺/错/过期/synthetic production preview、用户 confirmation 或 SHA 任一不匹配都不能 active。
- AC-020-03：优先级严格为用户确定性规则 > confirmed entity > structured > AI；冲突/低置信/AI 失败均 review。
- AC-020-04：一篇可 index 到多个 active spaces；index 至少一个 space，archive/review 无 committed membership。
- AC-020-05：RouteDecision v2 evidence required；v1 历史不修改；schema+semantic validator 拒绝所有跨字段违规。
- AC-020-06：domain-separated keys 对边界字符串无碰撞，重放不重复，输入变化生成不可变 diff。
- AC-020-07：Profile rollback 恢复上一版 pointer并重放目标版本 route；历史 decision/diff 不覆盖。
- AC-020-08：冷归档不触发 AI summary/index，变化后可重新 route；Router 从不物理删除。
- AC-020-09：ACL/revoke/in-flight profile change fail closed；A/B route/log/review/archive 完全隔离。
- AC-020-10：不写 Wiki/index/space registry，不读取 staged body，不修改生产开关/nightly。
- AC-020-10a：`pilot` preview、activation 与 route 持久化边界均经
  `profile_workflow` fresh snapshot；deny/unavailable/expiry/wrong purpose/tenant/hash、
  revision 回退与 snapshot 漂移零部分产物。`profile_pending/active` 调用 0 次，RT-020
  不实现或读取 production adapter。

## 12. 测试场景

- Preview：valid、holdout leak、missing item、partial AI failure、result tamper、receipt expiry/mismatch。
- Route：各优先级、multi-space、conflict、threshold boundary、AI timeout/bad JSON、archive/review。
- Re-route：body/profile/entity/user correction/space/revoke triggers；duplicate/reorder/crash replay。
- Attack：tenant/report/path/slug/space injection、receipt replay、fake evidence、prompt/log injection、symlink/TOCTOU。
- Transaction：activation/pointer/route log/diff 在每个 fsync/CAS 边界 crash。
- 回归：RT-011～020、全量 unittest、Wiki lint/smoke、legacy tests。
