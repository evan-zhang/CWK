# RT-020 技术方案：Holdout 预览、Router 与决策日志

> 状态：planned；v2 schema、模块与测试尚未创建。

## 1. 模块

- `cwk_profile_preview.py`：RT-019 冻结的 `PreviewProviderV1` 的真实实现、holdout reader、preview result set 生成与 activation binding。
- `cwk_router.py`：route snapshot、rule engines、zero-tool classifier、semantic validator。
- `cwk_route_log.py`：immutable decision/diff、idempotency index、reroute queue/recovery。
- `contracts/rt020/schemas/`：route_decision.v2、preview **result set**、activation receipt、route diff、review/archive metadata、projection request。
- Wave-0 `PilotAdmissionProviderV1`：构造注入、purpose 固定 `profile_workflow`；RT-020
  只消费 central runtime/schema，不 fork、不读 production allowlist。

### 1.1 Preview 单一所有权

- `PreviewProviderV1` ABI（`API_VERSION = "cwk.preview_provider.v1"`，含 `preview(...)`/`verify(...)` 签名）与 profile **preview receipt schema** 的唯一 owner 是 RT-019（`contracts/rt019/schemas/`）。
- RT-020 是纯 consumer：按位复用 RT-019 冻结的 receipt schema 与 ABI，零漂移；**不得**在 `contracts/rt020/schemas/` 下重定义同名 preview receipt，也不得扩展/收窄其字段。若需要新增字段，必须回到 RT-019 走版本化 schema 变更并同步 migration note。
- RT-020 独占拥有的产物是：`route_decision.v2`、preview **result set**（受 receipt 的 `result_set_sha` 绑定的被预览条目集合，与 receipt 本身是不同对象）、`activation receipt`、route diff、review/archive metadata、projection request。
- 契约测试必须断言 RT-020 加载的 preview receipt schema 文件 SHA 等于 RT-019 冻结版本；出现分叉即 FAIL。

## 2. RouteDecision v2 migration

- v1 文件与 validator 保持原样；v2 放在 RT-020 自有目录。
- Router 新写只产 v2；reader 显式区分版本，v1 只作为历史输入且在进入 RT-021 前经 v1→v2 migration adapter 补齐可证明 evidence，否则进入 review。
- v2 JSON Schema 使用 conditional `if/then` 表达 disposition 基础约束；Python semantic validator继续验证 active Profile space、evidence ownership、grant/profile snapshot、decision hash。
- migration 不可猜测缺失 evidence；无法证明的 v1 决策不得自动 index。

## 3. Preview 流程

```text
load proposed profile + joint manifest
→ verify refs/SHA and samples∩holdout=∅
→ ACL snapshot all holdout items
→ per-item route/preview in zero-tool boundary
→ validate each output + second ACL
→ immutable result set（RT-020 owner）
→ PreviewReceipt(profile, manifest, holdout_set, result_set)（RT-019 冻结 schema，RT-020 只填值）
→ user confirmation
→ pilot-only fresh admission recheck
→ ActivationReceipt + Profile pointer transaction
```

Holdout reader通过 RT-014 public API，不读取 shared 目录。失败项仍计入 receipt；不能通过过滤失败样本提高成功率。

若 tenant 为 `pilot`，preview/result-set 发布前与 activation commit 前分别取 fresh
PilotAdmission；两次 policy revision 必须单调且 policy/snapshot 不漂移。route pipeline
在提交 immutable decision/diff/projection request 前同样重验。`profile_pending/active`
不调用；Null/deny/expiry 直接回到稳定拒绝且无部分产物。

## 4. Router pipeline

Router adapters均返回 typed candidate，不共享可变状态：`ExplicitRuleEngine`、`ConfirmedEntityMatcher`、`StructuredRuleEngine`、`SafeAIClassifier`、`DecisionCombiner`。Combiner对来源按固定 rank 合并；同 rank 冲突或跨 rank 的 explicit exclude/include conflict进入 review。

AI 只获得最小 evidence bundle和 active Profile分类字段，无工具/网络/文件；bad output产生 reason `ai_contract_failure`，不会覆盖已有确定性命中。

## 5. Keys 与 hashes

实现公共 `_lp_nfc_utf8` 并限制单字段长度；所有 key helper frozen/test-vector 化：

- route_job_key：domain `cwk-route-job-v1` + tenant/report/canonical/profile；
- projection_key：domain `cwk-projection-job-v1` + route job/space/projector version；
- decision ID：随机 opaque，不以 SHA 充当外部对象 ID；decision SHA 用 `b"cwk-route-decision-v2\0" + JCS(record_without_sha)`。

测试向量写入契约 fixture，供 RT-021 复用；RT-021 不重实现 key 算法。

## 6. Durable 布局

```text
tenants/<tenant_id>/
├── routes/decisions/<report_key_hash>/<decision_id>.json
├── routes/current/<report_key_hash>.json
├── routes/diffs/<diff_id>.json
├── routes/review/<decision_id>.json
├── routes/archive/<decision_id>.json
├── runs/preview/<preview_id>/...
├── retries/router/<route_job_key>.json
└── locks/routes/<report_key_hash>.lock
```

路径只用 opaque/hash leaf；current pointer是可重建引用，不覆盖 decision。CAS/fsync 顺序：decision/diff durable → current pointer → downstream event；崩溃 recovery 按 journal补齐，不生成重复事件。

## 7. Activation transaction

RT-020 通过 RT-019 ProfileRegistry 公共 transaction API提交 receipt；若现有 API 不足，只能新增 versioned接口，不访问私有文件。transaction journal绑定 old/new pointer SHA、profile/preview/user confirmation/impact SHA。恢复时要么保持旧 active，要么完整切新 active，不能同时 active。

## 8. Reroute 与 downstream interface

`RouteChangeProviderV1` 输出 immutable `ProjectionRequestV1/CleanupRequestV1`，只含 tenant/report/canonical/profile/space/decision/projection key等 opaque refs，无 raw。RT-021 显式消费；当前未注册 consumer 时请求持久等待，不丢失，也不把 RT-020 视为投影成功。

Profile rollback遍历该 Profile impact manifest/现有 current route refs，以目标 Profile重新计算；不复用旧 decision作为当前而跳过新 snapshot check。

## 9. 安全与测试

- nofollow/dirfd、0600/0700、CAS、deep forbidden、stable opaque errors。
- property tests验证 disposition/space cross-field、优先级、key无歧义、reroute收敛。
- hostile model/raw/receipt/profile/manifest、ACL race、crash injection、multi-tenant isolation。
- v1 migration测试证明缺 evidence时fail-to-review。

## 10. 回滚

停用Router consumer后保留所有 decisions/diffs/requests；Profile rollback按RT-019事件切 pointer并重算。不得删除 canonical、grant、Profile、route history；RT-021 可从目标 route log重建派生物。
