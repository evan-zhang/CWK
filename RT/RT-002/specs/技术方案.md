# RT-002 Shadow Mode 技术方案

## 1. 涉及模块

- 新增 `scripts/cwk_action_center.py`
- 新增 `tests/test_action_center.py`
- 输出到现有 run 目录，不修改 nightly 默认流程。

## 2. 数据结构变化

新增 `cwk.action_cards.v1`：

- `report_id`
- `primary_type`
- `role` / `underlying_role`
- `mandatory`
- `source_labels`
- `summary` / `new_since_last_seen`
- `recommendation` / `draft_text`
- `allowed_actions`
- `requires_role_review`
- `evidence_refs`

## 3. API / 接口变化

Shadow Mode 无后端写 API。CLI 接口：

```bash
python3 scripts/cwk_action_center.py --run-name <run>
```

## 4. 前端页面变化

- 单文件 HTML，自包含 CSS/JS。
- 按责任类型过滤。
- 卡片按钮打开操作预览弹层。
- 用户可编辑意见，但确认按钮只保存页面内预览状态。

## 5. 后端逻辑变化

- 结构化字段优先、关键词补充的责任分类。
- 不确定角色进入人工复核。
- AI understanding 缺失时规则降级。
- 输出前做 secret gate。

## 6. 测试策略

- 纯函数单测覆盖六类分类和操作集合。
- fixture 生成完整 JSON/MD/HTML。
- 安全测试断言 HTML 不含网络写能力。
- 运行现有 `make test` 回归。

## 7. 风险点

- CWork 节点字段尚未形成稳定公开 schema，因此首阶段角色识别必须保守。
- HTML 中的“确认”仅代表确认预览，文案必须避免误导为已提交。
- Phase 2 前必须逐项核实真实 CWork 写接口和权限。

## 8. 2026-08-12 日报分流技术补充

- 在日期完整性补采完成后，将 `*-date-complete/collected-raw` 合并为当轮只读分析输入；主采集目录优先，补采目录只补充缺失 `report_id`。
- `cwk_action_center.py` 为卡片增加 `effective_change_type`、`views` 与 `business_date`，输出 `view_counts`。
- 当前业务日期的 `historical_backfill` 归一为 `effective_change_type=new`；旧日期历史回填保持 historical。
- 更新判定以 `change_type=updated` 为准；只有基线分类缺失时才用严格布尔意义的 `hasNewReply=true` 兜底，移除 `source_lane=reply_chain` 和陈旧 reply flag 的更新推断。
- `action-center.html` 使用“今日处理 / 近期变更”两个主页签；持续未闭环在今日页签内以 `<details>` 折叠。
- `cwk_human_digest.py` 使用同一分类原则生成三段 Markdown；`cwk_daily_html.py` 将这三段渲染为相同的双页签阅读视图。
- nightly 显式传入 `--report-date`，保证历史重建可复现，不依赖机器当前日期。

## 9. 2026-08-12 本人关系标记技术补充

- 新增 `scripts/cwk_person_relation.py`，集中解析 `Record Simple Info` 与 `Node / Opinion Chain`，输出 `relationship_status`、`relationship_role`、`visible_only`、`relationship_evidence`。
- `cwk_action_center.py` 加载 `Record Simple Info`，通过 `--owner-emp-id/--owner-name` 接收本人身份；员工 ID 优先，姓名只作为配置后的兼容匹配。
- `cwk_human_digest.py` 使用相同关系模块，避免每日简报和行动中心产生不同结论。
- `cwk_nightly_pipeline.py` 从 CLI、配置或 `CWK_OWNER_EMP_ID/CWK_OWNER_NAME` 读取身份，并传递给两个页面生成器。
- 配置缺失或节点数据不完整时采用 `unknown` 保守降级；只有节点详情包含 `nodeList` 完整响应时才允许负向判定。
- 页面标记是阅读辅助，不修改 CWork 权限、已读状态或任何业务数据。
