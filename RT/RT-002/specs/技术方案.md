# RT-002 Shadow Mode 技术方案

## 1. 涉及模块

- 新增 `scripts/cwk_action_center.py`
- 新增 `tests/test_action_center.py`
- 输出到现有 run 目录，不修改 nightly 默认流程。

## 2. 数据结构变化

新增 `cwk.action_cards.v1`：

- `report_id`
- `primary_type`
- `role` / `underlying_role`
- `mandatory`
- `source_labels`
- `summary` / `new_since_last_seen`
- `recommendation` / `draft_text`
- `allowed_actions`
- `requires_role_review`
- `evidence_refs`

## 3. API / 接口变化

Shadow Mode 无后端写 API。CLI 接口：

```bash
python3 scripts/cwk_action_center.py --run-name <run>
```

## 4. 前端页面变化

- 单文件 HTML，自包含 CSS/JS。
- 按责任类型过滤。
- 卡片按钮打开操作预览弹层。
- 用户可编辑意见，但确认按钮只保存页面内预览状态。

## 5. 后端逻辑变化

- 结构化字段优先、关键词补充的责任分类。
- 不确定角色进入人工复核。
- AI understanding 缺失时规则降级。
- 输出前做 secret gate。

## 6. 测试策略

- 纯函数单测覆盖六类分类和操作集合。
- fixture 生成完整 JSON/MD/HTML。
- 安全测试断言 HTML 不含网络写能力。
- 运行现有 `make test` 回归。

## 7. 风险点

- CWork 节点字段尚未形成稳定公开 schema，因此首阶段角色识别必须保守。
- HTML 中的“确认”仅代表确认预览，文案必须避免误导为已提交。
- Phase 2 前必须逐项核实真实 CWork 写接口和权限。
