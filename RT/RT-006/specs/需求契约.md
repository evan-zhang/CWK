# RT-006 需求契约

## 1. 业务目标

修复 Cloud-First v2 的 P0/P1 阻断项，让云端可逐步成为 CWK 的唯一持久主库，同时保留可验证证据、完整性门禁、回滚和恢复能力。

## 2. 用户角色

- Evan：通过 OpenClaw 查询工作协同历史，并优先获得云端证据链接。
- CWK nightly：采集、raw 晋级、Wiki 编译、索引发布、云端同步和完整性验收。
- 查询器：在 local/cloud/shadow 模式下召回候选并验证原文证据。
- DocDB：个人知识库中的持久对象存储、版本管理和预览入口。

## 3. 使用场景

- 新汇报进入后，raw、summary、索引和云端对象按一致顺序更新。
- Agent 启动时获取轻量索引，只拉取 Top-K raw 证据。
- 云端暂时不可用时，shadow/local 模式仍可回滚或明确拒答。
- 运维人员可检查源端、本地、云端三方集合和哈希是否一致。
- 本地目录为空时，可从云端恢复并通过 lint/smoke。

## 4. 功能范围

### 必须实现

- manifest 安全合并修复与回归测试。
- raw 默认拒绝上传、显式授权上传开关。
- 持久化 search index 及本地查询加速。
- 云端对象映射、内容哈希和单调 `index_version`。
- 云端完整性审计和 nightly 硬门禁。
- cloud/shadow 查询、临时缓存、哈希校验和读己之写。
- 云端恢复工具和至少两次隔离目录恢复验证。
- 文档、安全决策和运维说明更新。

### 明确不做

- 本轮不删除本地 raw/wiki。
- 不启用向量数据库或 embedding 流水线。
- 不建设独立 Web UI。
- 不把 raw 上传到共享空间或扩大权限范围。
- 不降低引文验证与拒答标准。

## 5. 输入

- 本地 `raw/_system/raw-manifest.json` 和 1,450 篇 raw。
- 本地 `wiki/summaries`、`topics`、`entities` 和 Wiki manifest。
- DocDB 个人空间、根目录和版本化文件接口。
- 自然语言问题、日期/发送人/来源类型过滤条件。

## 6. 输出

- 一致的 Wiki manifest、search index 和 cloud object manifest。
- 云端 raw/wiki 对象与版本。
- local/cloud/shadow 查询证据包和云端预览链接。
- 完整性、性能、恢复与交付验证报告。

## 7. 业务规则

- raw 以 `report_id + sha256` 标识不可变内容版本。
- `source_count == len(source_hashes) == raw manifest record_count`。
- `compiled_report_ids` 等于磁盘 summary 集合；质量分区不得被 bootstrap 覆盖。
- raw 同步必须显式传入 Cloud-First 授权参数；无参数和普通 Wiki 同步不得包含 raw。
- 发布顺序：raw → summaries/topics/entities → 版本化 search-index 分片 → index meta/manifest → `cloud-objects.json`；云端对象目录是唯一提交指针，读端不得从未提交的新分片自行拼接。
- 查询缓存命中必须同时匹配 `report_id + sha256`。
- 云端证据哈希不匹配时刷新索引并重试一次；仍不匹配则不得标记为 verified。
- cloud/shadow 失败不得静默回退旧云端证据；必须显式标注降级原因。

## 8. 异常情况

- manifest 漂移：安全 merge 修复，保留质量状态并失败退出旧 bootstrap 覆盖路径。
- DocDB 限流/超时：有界重试，超限进入 retry queue 并使硬门禁失败。
- 云端对象缺失或多余：完整性门禁失败，禁止报告成功。
- 鉴权失效：cloud 查询明确失败；local/shadow 模式按配置回退。
- 缓存哈希不一致：丢弃缓存并重新拉取。
- 恢复结果哈希不一致：恢复失败，不替换任何正式本地目录。

## 9. 权限与安全要求

- raw 仅上传 Evan 的个人 DocDB 空间，不创建分享或组织授权。
- 所有 DocDB 调用通过 `cms-docdb` 脚本；已存在文件只新增版本。
- 凭据不得写入日志、manifest、测试夹具或命令输出。
- 同步器必须内置 raw deny-list，只有显式 `--allow-raw` 可解除。
- 本地持久副本删除不属于本 RT。

## 10. 验收标准

- manifest 漂移修复后 source/compiled/quality 分区全部准确且保留。
- 默认同步扫描中 raw 数量为 0；显式 `--allow-raw --only-prefix raw/` 才可出现 raw。
- search index 可重复构建、哈希稳定、查询 Top-8 与旧实现一致率 ≥99%。
- 本地持久索引热查询 P50 ≤ 0.6 秒；云端查询 P95 ≤ 8 秒；回退全扫功能仍可用。该阈值以同机实测基线确定，不再沿用未经验证的 0.2 秒目标。
- 云端对象审计 missing=0、extra=0、hash mismatch=0、retry queue=0。
- shadow 查询引文验证通过率 100%，负例保持拒答。
- 两次空目录恢复演练均通过 raw 哈希、Wiki lint 和 smoke。

## 11. 测试场景

| 场景 | 输入 | 期望结果 |
|---|---|---|
| manifest 安全修复 | 698 source + 1450 compiled | source 修复为 1450，质量分区不丢失 |
| raw 默认拒绝 | 无参数同步 | raw 不进入候选列表 |
| raw 显式允许 | `--allow-raw --only-prefix raw/` | raw 可进入候选列表 |
| 索引构建 | 现有 1,450 summaries | 生成稳定 index/meta，重复构建哈希一致 |
| 查询回归 | 既有真实问题集 | Top-K 一致率 ≥99%，引文均 verified |
| 云端缺对象 | 删除一个测试映射 | strict 审计失败 |
| 缓存过期 | sha256 变化 | 缓存失效并回源 |
| 云端断网 | cloud/shadow 查询 | 明确失败或按配置回退，不伪造 verified |
| 恢复演练 | 空临时目录 | 重建成功并通过 lint/smoke |
