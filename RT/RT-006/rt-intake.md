# RT-006：Cloud-First v2 P0/P1 可信迁移底座

## 目标

在不删除现有本地 `raw/` / `wiki/` 的前提下，修复 Opus 架构评审确认的 P0/P1 问题，使 CWK 具备安全迁移到“云端唯一持久主库 + Agent 临时索引/缓存”的技术条件。

## 边界

- 本轮允许将正确的 raw 原文上传到 Evan 的个人 DocDB 知识库，但不得共享给其他用户或组织空间。
- 已存在云端文件必须使用版本更新，禁止覆盖或创建同名副本。
- 本地事实源在双读、云端对账和恢复演练验收前必须保留，不执行删除。
- 不引入向量数据库；第一版使用持久化词法倒排索引。
- 不改变引文验证规则；答案仍必须以 raw 中连续可验证文本为事实依据。
- 不修改 CWork 汇报、审批、已读状态或其他业务数据。

## 验收

1. Wiki manifest 的 source 集合、哈希和质量分区可安全合并重建，禁止破坏已有精编状态。
2. DocDB 同步器默认拒绝 raw；只有显式 Cloud-First 开关才能上传 raw。
3. 持久化 search index 可增量重建，查询结果与现有 BM25 Top-K 高度一致且显著降低本地索引启动耗时。
4. summary→raw 具备 `report_id + sha256 + cloud_file_id/path` 的稳定引用。
5. 云端对象集合与本地 manifest 可自动对账，并作为 nightly 硬门禁。
6. 查询器支持 local/cloud/shadow 三种模式、哈希校验、临时缓存和明确降级。
7. 从云端恢复到空目录的工具与演练可验证数据完整性。
8. 全量单测、Wiki lint、smoke、性能回归与恢复演练通过。
