## 5. Blocker / Minor 汇总

### Blocker（阻塞 RT-012+ 与 G5/SG-02/SG-07）

- **Blocker-A：Python validator 不闭合 `additionalProperties: false`。**
  - 相关 schema：`canonical_report`、`tenant_view`、`access_grant`、`access_observation`、`route_decision`、`query_request`、`knowledge_profile`、`sample_manifest`、`profile_pointer_rollback`、`capability_probe`、`security_defaults`、`verified_shared_extensions` 12 个都写了 `additionalProperties: false`；`scripts/cwk_pr001_contracts.py` 只对 `canonical_report / query_request / knowledge_profile` 做显式 forbidden 列表拦截，对其他 schema 无兜底；对 canonical 也没兜底未知顶层字段。
  - `validate_canonical_envelope.author` 只强制 `source_user_id: str`，接受 `author.tenant_id / author.agent_id / …` 嵌套注入。
  - `validate_sample_manifest.samples` 不去重 `report_key`；`access_grant.roles` 无 `uniqueItems`。
  - 直接违反 PRD FR-07 line 249（“采集器和 canonicalizer 遇到未知字段默认丢入 overlay，永不写 canonical”）、DESIGN §6 C-06 与需求契约.md line 9。
  - 影响下游 RT-014（Canonicalizer）、RT-017（Collector）、RT-022（Broker）：若这些 RT 使用 RT-011 冻结的 Python validator 作为唯一守卫，未知字段会被写入 canonical / 传入 query，导致 tenant overlay 泄漏进 canonical、身份字段随请求体潜入 broker。
  - 复现：
    ```python
    body = {"schema":"cwk.canonical_report.v1", ..., "attacker_field":"x", "author":{"source_user_id":"u","tenant_id":"t_..."}}
    body["canonical_sha256"] = C.canonical_sha256({k:v for k,v in body.items() if k!="canonical_sha256"})
    C.validate_canonical_envelope(body)     # → passes
    C.validate({"schema":"cwk.query_request.v1","query":"q","space_selector":["sp_ok01234567"],"meta":{"agent_id":"root","credential_ref":"secret://x","path":"/etc/passwd"}})
    # → passes; CLI validate --file … exits 0
    ```

- **Blocker-B：能力探针 `is_authoritative` 判据过弱；任意 caller 可伪造 verified 并让 aggregate 返回 exit 0。**
  - `EvidenceBundle.is_authoritative` 仅检查 `kind == "controlled_environment_receipt"`、`refs` 非空、`refs[0]` 不以 `fixture://` 开头。**没有签名、没有 issuer allowlist、没有 evidence SHA/manifest 校验、没有独立审核 receipt 引用。**

  - 复现（CLI）：手写 8 个非 forbidden probe 的 `controlled_environment_receipt` evidence（refs=`['urn:fake']`, `unique_report_key_pairs=500`），`probe run --evidence …` → `probe aggregate …` 返回 **exit 0**，`all_verified=true`，`verified` 列出 8 个 probe。

  - 影响：SG-02 / SG-07 / G5 前置门禁失去机器可信性；RT-023 / VG-D 的 receipt 无法与实现方 receipt 区分；rt-intake.md 声称的 “fixture/mock 证据永不升级” 只覆盖字面 `fixture://` 前缀，实际形同虚设。

- **Blocker-C：`compare-user-views` 把 tenant-overlay-only 字段建议为 `candidate_verified_shared`。**
  - `_is_url_field` / `_is_identity_field` 只针对 URL / 身份路径过滤；`lane / read_status / todo_status / roles[] / allowed_actions[] / reply_overlay[] / node_overlay[] / attachment_permissions[]` 都无兜底。
  - 复现：50 条 common envelope（B 侧 `lane` 与 A 侧一致），`compare(a, b)` → `suggested_verified_shared` 含 `lane / read_status / todo_status / roles[] / allowed_actions[] / node_overlay[]` 6 项。
  - `--threshold` 无 clamp：`--threshold 0.0` / `-1.0` 通过，match_rate=0 也照升。

### Minor

- **Minor-1**：`cwk_pr001_cli.py probe`（无子命令）返回 exit 0 而非 exit 4；argparse `--help` re-invocation 覆盖了 `return EXIT_USAGE`。CLI 契约说 “使用错误 exit 4”。
- **Minor-2**：`profile_sha256_recipe` 只由 `compute_profile_sha256` 硬编码实现，`cwk pr001 conformance` 覆盖不到下游 RT 是否复用同一实现；跨 RT 一致性靠人工审。
- **Minor-3**：实现方 `交付验证报告.md` §5 wiki_smoke `overall=FAIL` 没有醒目标注 “NOT RUN due to isolated worktree”；容易被误读为 RT-011 破坏 wiki。
- **Minor-4**：`_safe_path` 只脱敏错误路径尾部，仍保留最后两段目录名（例如 `secret_dir/file.json`）；虽然不违反字面“无绝对路径”，但在 tenant_id/secret_dir 命名的情境下仍有轻度信息泄漏。可与 Blocker-B 的 evidence 脱敏一起处理。
- **Minor-5**：JCS 数字格式化在 RFC 8785 边界与 ECMA-262 不完全一致：
  - `1e-6` → 应 `0.000001`，实际 `1e-06`；
  - `1e-7` → 应 `1e-7`，实际 `1e-07`（RFC 8785 不允许指数前导零）；
  - `1e21` → 应 `1e+21`，实际 `1000000000000000000000`（`is_integer()` shortcut 打破 ECMA-262 §7.1.12.1 step 10）；
  - 大整数（如 `2**60`）以精确 int 输出，未经过 IEEE-754 double。
  - RT-011 payload 目前不含这些边界，但 `canonical_json_bytes` 暴露为通用工具，跨实现 hash 会分歧。
- **Minor-6**：NFC 键碰撞：Python 源里 `{"é(composed)":1, "é(decomposed)":2}` 会在 NFC 前重复；`nfc_normalize` 之后 last-wins → 输出 `{"é":2}`。RFC 8785 不要求 Unicode normalization；RT-011 显式加了 NFC 前置。任何输入含合成/分解形态双写的键会被静默合并。跨实现容易分歧。
