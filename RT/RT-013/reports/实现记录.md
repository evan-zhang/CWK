## 2. 关键设计决定

### 2.1 一 agent 一 tenant

`BindingRegistry.bind` 在写入前把 raw_agent_id HMAC 后查 `current/<hash>.json`
（含双写期间的 secondary 副本）。如果任一记录处于 `active|suspended`，抛
`BindingConflictError` (EXIT_CONFLICT)。这保证任何时候一个 agent 都只映射到
一个 tenant；`rebind-agent` 命令内部是「revoke_out + bind_in」两步，两次都
持锁并各自 emit 一份 receipt。

### 2.2 raw_agent_id 永不落地

`BindingRecord` 只存 `agent_id_hash`（HMAC-SHA256 hex）；`AgentContext` 仅
持有 snapshot；`__repr__` 抹掉全 hash 只保留前 8 位；`redact()` 用于日志。
测试 `test_bind_raw_id_not_stored` 直接读磁盘证明。

### 2.3 credential material 生命周期

- `CredentialRefStore` 永远只写 `reference_uri`（`secret://<opaque>`），不
  接触 material；
- `CredentialBroker.lease(...)` 打开 backend 读 material，装入
  `CredentialLease.env["CWORK_APP_KEY"]`，只把 `CWK_INSTANCE_ROOT` 之外的
  白名单 env 传下去；
- `with lease` 退出时 zero-out material `bytearray`、清空 env dict；
- `lease.receipt()` 只含 `lease_id/reference_uri/credential_epoch/purpose/
  tenant_id/agent_id_hash`；**test_receipt_and_record_contain_no_material**
  逐字节扫描整个 instance root 确保 material 不落到任何文件。

### 2.4 broker fail-closed（不回退 `.env`）

- purpose × tenant status 通过 `_PURPOSE_ALLOWED_STATUSES` + RT-012
  `TENANT_OPERATION_MATRIX` 双重校验；
- backend 缺 material → `CredentialBackendError` → EXIT_IO；
- 特别测试 `test_broker_never_falls_back_to_process_env` 与
  `test_broker_never_reads_repo_env_file` 明确拒绝任何 fallback。

### 2.5 rotation 无「新旧混合状态」

- `BindingSecretStore.pointer.json`：`stable | dual_write | finalizing`；
  material 存 `binding-secrets/material/<epoch>.material`（不进 audit/receipt）；
- `BindingRegistry` 在 dual_write 期间：`resolve()` 双探（current →
  secondary）；所有 mutating API 抛 `BindingConflictError`
  (`_refuse_mutations_during_rotation`) — 从根源避免 mixed 状态；
- `rotate_secret()` 一次性完成 begin → finalize：finalize 时把 old-epoch
  hash 记录归档到 `tombstone/<old_epoch>/`；操作者必须 re-bind
  受影响的 agent（这也满足 DESIGN §C-03 "轮换必须一次性重算全部记录并
  推进所有 tenant auth_epoch"）。
- credential rotation 同理：`rotation.state=dual_write` 时 broker 拒
  lease；`finalize` 原子 pointer swap；旧 reference 归档到
  `credentials/tombstone/<epoch>/<tenant_id>.json`。
- 每次 rotation 都 `bump_auth_epoch` 每个受影响 tenant，令下游缓存失效。

### 2.6 dispatcher 扩展的唯一手法

不改动 `cwk_tenant_cli.py` 的加载策略、ABI 校验、CWD/PYTHONPATH 忽略、
`_safe_env_snapshot`、错误处理任何一行；只把 `FROZEN_PROVIDER_SLOTS` 中
RT-012 源代码里以注释形式预留的 `"cwk_tenant_cmd_binding"` 激活。
RT-012 独立验收 §4.7 / §8 明示该动作允许；这是当前设计给出的唯一扩展点，
若不足够，本 RT 需在报告中阻塞，而不是偷偷改 dispatcher — 本 RT 未触碰
dispatcher 的其它任何 API。

### 2.7 tenant 状态跃迁不在本 RT

RT-012 只暴露 `init_tenant`；`draft → profile_pending → pilot → active` 等
业务跃迁属 RT-026。测试为验证 `AgentContext.resolve()` / `Broker.lease()` 的
purpose × status 组合，用一个 **测试专属** helper `_promote(...)` 直接 CAS
写租户 record — 这是测试范围内的操作，生产命令面不包含 promote API。

### 2.8 conservative_unknown 全部保守

- `TRUSTED_AGENT_SOURCES = frozenset({'admin_cli', 'gateway_authenticated_context'})`：
  `gateway_authenticated_context` 目前只是白名单标签，仓库里没有一个 caller
  构造它 — RT-023 完成真实通道后再由独立审核批准使用；
- 未接 loopback HTTP + 请求体自报 agent_id；`AgentContext.from_untrusted / from_request_body / from_env / from_argv / from_body` 家族显式不存在（
  单元测试 `test_agent_context_has_no_from_untrusted_family` 验证）；
- 未启用 SG-02/SG-07/G5/G7；本 RT 不修改 RT-011 冻结的
  `security_defaults.json` / `verified_shared_extensions_v1.json`。

## 3. 已知约束 / 妥协

1. **rotation 后需要 re-bind**：HMAC 不可逆，无法把 old-hash 记录重新映射到
   new-hash。RT-013 选择 fail-closed 语义（tombstone 老 hash，操作者
   re-bind），既满足 "一次性重算 + auth_epoch 推进" 也避免出现 "旧 hash
   到 new material" 的 zombie 记录。若要 seamless rotation，需要独立 PR
   引入一个受审计的 raw_agent_id 中间缓存 — 属未来工作。
2. **在 dual_write 期间冻结 mutation**：为消除 "在 begin 之后到 finalize
   之前，新 binding 落到旧 hash 还是新 hash" 的分歧，RT-013 在整个 rotation
   窗口内拒绝任何 bind/revoke/suspend/reactivate（只允许 read + finalize）。
   这与 "rotation 中不能命中新旧混合状态" 一致。
3. **backend 只提供 env_ref + file_ref**：生产 backend（Keychain / KMS）由
   独立 PR 引入并做独立审核；两个内置 adapter 都不适合生产 AppKey
   存储，明确只用于测试。

## 4. 命令一览（新的 CLI 接口）

```
cwk-tenant bind-agent --tenant-id t_… --agent-id <raw> --actor admin
cwk-tenant rebind-agent --agent-id <raw> --new-tenant-id t_… --actor admin
cwk-tenant revoke-agent --agent-id <raw> --actor admin
cwk-tenant suspend-agent --agent-id <raw> --actor admin
cwk-tenant reactivate-agent --agent-id <raw> --actor admin
cwk-tenant list-bindings [--tenant-id t_…]
cwk-tenant show-binding --agent-id <raw>
cwk-tenant set-credential --tenant-id t_… --reference-uri secret://… --backend env_ref --actor admin
cwk-tenant disable-credential --tenant-id t_… --actor admin
cwk-tenant rotate-credential --tenant-id t_… --phase {begin|finalize} \
    [--new-reference-uri secret://…] [--new-backend env_ref|file_ref] --actor admin
cwk-tenant rotate-binding-secret --phase {begin|finalize} \
    [--material-file /path/to/0o600/file] --actor admin
cwk-tenant doctor:binding
```

- material 从不出现在 argv；`--material-file` 只读 0o600 regular file，
  拒 symlink / 短材料；读完 zero-out `bytearray`；
- 输出全 machine-readable JSON；错误只回显 exception class name 与
  redact 后短消息（≤256 char）；
- exit code 完全沿用 RT-012 `{0,2,3,4,5,6}`。
