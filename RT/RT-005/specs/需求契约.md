# RT-005 需求契约

## 1. 业务目标

把当前“698 篇可检索、其中 168 篇为兜底摘要”的 Wiki，升级为可持续精编、状态透明、无需 Docker 的稳定知识问答底座。

## 2. 用户角色

- Evan：通过 OpenClaw 对话查询工作协同知识。
- CWK nightly：采集、物化、编译、聚合与同步的自动任务。
- `cwk-ai-reviewer`：只接收文本并返回结构化 JSON 的无工具模型工作进程。

## 3. 使用场景

- 新 raw 进入后自动生成可导航摘要。
- 历史兜底摘要按有界批次逐步替换为 AI 精编摘要。
- 用户查询时可判断结果来自 AI 精编还是兜底，并最终回读 raw 取证。
- 运维人员无需 Docker 即可运行摘要精编。

## 4. 功能范围

### 必须实现

- 无 Docker、无工具权限的 reviewer 运行策略及代码预检。
- 单篇及批量兜底精编。
- nightly 可配置精编开关与有界数量。
- 质量状态、失败队列和验证报告。

### 明确不做

- 独立 Web UI、向量数据库、Neo4j。
- 自动回答中的自由推断。
- CWork 或 DocDB 的未授权业务写操作。

## 5. 输入

- `raw/YYYY-MM/YYYY-MM-DD/{report_id}-{title}.md`
- Wiki manifest 中的 `fallback_report_ids`
- 精编模型：`newapi/BD-MiniMax`，必要时可用 allowlist 内的 `newapi/BD-glm`

## 6. 输出

- `wiki/summaries/{report_id}.md`
- Wiki manifest 的质量分层与失败队列
- nightly/批处理运行 manifest
- 交付验证报告

## 7. 业务规则

- `compiled_report_ids` 仅表示存在可导航摘要。
- `ai_refined_report_ids` 与 `fallback_report_ids` 必须互斥并覆盖所有已编译摘要。
- 模型证据必须是 raw 中连续、可验证的原文。
- 新摘要优先于历史精编；历史精编必须有界运行。
- 模型失败不得删除原兜底摘要。

## 8. 异常情况

- 模型超时/格式错误：保留兜底，进入失败队列。
- Docker 不可用：不影响无 sandbox reviewer。
- reviewer 获得任何工具权限：预检拒绝运行。
- 原文含 secret-shaped 值：跳过模型，不发送源内容。

## 9. 权限与安全要求

- reviewer `sandbox.mode=off`，同时 `tools.profile=minimal` 且 `allow/alsoAllow` 均为空。
- reviewer `skills=[]`，deny 保留对 exec/write/message/session 等能力的禁止。
- 模型调用不使用 `--deliver`，不向任何会话外发。
- 临时 prompt 调用后删除。

## 10. 验收标准

- 无 Docker daemon 时 tiny JSON smoke 成功。
- 单篇 fallback 精编成功且 manifest 质量状态变化正确。
- nightly 命令能透传 `--refine-fallbacks`。
- 全量单测与 Wiki lint 通过。
- 真实问题仍返回 verified raw evidence。

## 11. 测试场景

| 场景 | 输入 | 期望结果 |
|---|---|---|
| 无工具 reviewer | tiny JSON prompt | 无 Docker、无工具调用，返回合法 JSON |
| 单篇精编 | 一个 fallback report_id | 摘要被替换，fallback -1，refined +1 |
| nightly 有界精编 | refine=true, limit=1 | 只处理至多 1 篇，不阻断后续阶段 |
| 模型失败 | 超时/非法 JSON | 保留旧摘要并记录 failure |
| 可信问答回归 | Token 异常问题 | 返回 verified raw evidence |
| 无答案 | 随机不存在项目 | `confidence=none` |
