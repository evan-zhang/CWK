# 技术方案

## 存储模型

```text
raw/YYYY-MM/DD/{report_id}-*.md                 最新完整快照（兼容现有查询）
raw/_system/timelines/{report_id}/snapshots/    以 raw SHA-256 命名的不可变原始快照
raw/_system/timelines/{report_id}/events/       以事件身份 SHA-256 命名的不可变 JSON 事件
raw/_system/timelines/{report_id}/manifest.json 当前时间线目录与统计
```

事件来源只允许：`record-simple-info.replyList`、`node-detail.nodeList`。所有无法结构化的字段仍完整留在快照中。

## 增量与一致性

- 现有指纹继续用 `updateTime`、`replyCount`、`hasNewReply` 等字段选出候选。
- 每次成功获取详情后，raw 晋级器以字节 SHA-256 归档快照；相同快照不重复写入。
- 事件身份由 `report_id + event_kind + actor + occurred_at + canonical payload hash` 组成；状态变化因此成为新事件。
- 时间线文件路径加入 `changed_relative_paths`，从而被 Cloud-First raw 同步器纳入。
- 审计从 latest raw 提取应有事件，并检查事件目录存在；它不把“汇报文件存在”误认为“意见链完整”。

## 调度

推荐生产节奏：5 分钟只读增量轮询 + 每夜完整性对账。高频任务必须在本地夹具、只读实采、重试演练和资源预算确认后才启用。
