# RT-Lite: RT-069 - 自助令牌页面

> profile: Spec-Lite | execution_mode: collaborative

## 方案（给人看）

- 做什么：登录后在 `/tokens` 看自己的令牌、签一支新的、吊销。
- 为什么：发令牌是试跑前最后一个还要登服务器敲命令的环节。
- 代价：签发这个高价值动作出现在网页上，所以它的身份要求必须比命令行更严，而不是更松。
- 这次故意不做什么：不做"管理员替别人签"、不做建库、不改鉴权判定。
- 用户怎样算成功：同事自己就能拿到令牌；任何人都签不出别人的令牌。
- 建议：定论。

## 守住铁律的办法

RT-047 定下的铁律是：令牌的主人只能由**当场核实过的 Key**推导，不接受手填。
页面化最容易在这里破功——做成"管理员替同事签"，主人就退化成一句声明。

所以签发同时要求两件事：

1. **会话说你是谁**（RT-065 的登录态，来自玄关核实）；
2. **你当场粘贴的 Key 解析出同一个人**。

两者必须指向同一主体。于是：会话被盗签不出令牌（没有 Key），
拿到别人的 Key 也签不出（会话对不上）。管理员同样签不出别人的令牌。

## 其余约束（都是既有规则的延用）

- 明文只在签发那次返回一次；登记表只存摘要；列表连派生标识都不给。
- 签出的是 `authz=grants` 令牌：能查什么跟随成员表，加减权限不用重签。
- 不是任何库的成员时拒签，并说清下一步该找谁。
- 同一个用途标识只能有一支有效令牌；每人有效令牌数有上限。
- 吊销：自己的随时可撤，别人的只有管理员能撤，立即生效。

## 顺带补上的缺口

`admins` 字段从 RT-061 起就存在，却没有任何方式往里加人——代码里的"管理员"分支
现实中永远走不到。本 RT 补了 `kb_authz.py admin-add / admin-remove`。
刻意只做命令行：**"谁能管所有库"不该从网页发出去**。

## 验证

- `tests/test_rt069_token_page.py`（20 条）：没会话签不出、光有会话也签不出；
  别人的 Key 在我的会话里签不出、我的 Key 在别人会话里也签不出；被拒的 Key 不回显；
  签出的令牌主人是本人、跟随成员表、快照取当时的成员资格；
  明文只回一次且不入库、列表里拿不到明文与派生标识；
  只看得到自己的令牌（管理员额外看全部但仍签不出别人的）；
  自己的能撤、别人的不能撤、管理员能撤、撤不存在的是 404；
  没有成员资格时给出"先找管理员"的指引；同用途冲突；每人上限；
  缺页面标记头拒绝；管理面上四条路由全 404；明文下不给页面。
- `tests/test_rt061_authz_store.py` 新增 6 条：管理员的增删、权力范围、只有管理员能授予、
  服务不能当管理员、未报到的人不能当管理员、留回执。
- **反向验证**：不核对身份一致 → 3 条红；不要求当场给 Key → 1 条红；
  允许撤别人的 → 1 条红；列表泄露派生标识 → 1 条红。
- 浏览器实看：错误 Key 被拒的提示、签发成功后明文只显示一次、列表与吊销按钮、输入框自动清空。

## 变更记录

## 遗留事项
