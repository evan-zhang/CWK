# RT-023 需求契约：可信沙箱传输、客户端与真实空间集成

## 1. 业务目标

建立从真实沙箱到 Host Query Broker 的不可伪造身份链和受控传输；沙箱可
提交无身份字段的查询，或先通过独立只读 `resolve_slug` 把用户可读 slug
解析为 opaque `space_id`；tenant/Agent/路径/凭据完全由宿主控制面解析。
使用真实 RT-021 索引完成 VG-D，不以 mock 替代。

## 2. 用户角色

- 沙箱 Agent：调用受控 Tool 或本机受限 client，不能选择身份/tenant。
- Gateway：在 Tool 元数据注入受控身份并生成可验证 capability receipt。
- Host adapter：验证 metadata/peercred、映射 binding、调用 RT-022。
- 宿主机管理员：管理 root-owned trust store 和 UDS peer mapping。
- 独立验收 Agent：在真实沙箱链发起伪造与越权攻击。

## 3. 功能范围

### 必须实现

- TRN-001：首选 OpenClaw controlled Tool；身份只来自 Gateway 控制元数据，
  request body 中任何身份/tenant/path/credential 字段均拒绝。
- TRN-002：Tool 能力不合格时，仅允许 UDS `0600` 后备；使用 kernel
  `SO_PEERCRED/getpeereid/LOCAL_PEERCRED` 与 host registry 映射身份。
- TRN-003：交付 production trust-store 与 `CapabilityReceiptVerifier`；
  支持 key ID、算法、有效期、撤销、target、audience 和重放防护。
- TRN-004：真实 `SpaceIndexProvider` 只访问已解析 tenant 的 active space
  投影，返回稳定 index version；不读取全局/shared raw。
- TRN-005：`list_spaces` 只返回当前 tenant active/queryable 的 opaque
  `space_id`、slug 和显示名；`resolve_slug(slug)` 只在同一可信 tenant 上下文
  解析严格 RT-021 slug，返回 opaque ID；不存在、他 tenant、disabled 与无权
  必须是等价安全错误，歧义拒绝。slug 输入是严格 lowercase ASCII 字节匹配：
  实现不得执行 `lower()`/`casefold()`/NFC/NFKC/NFKD/去空白/字符替换等任何
  归一化；大小写变体、Unicode 同形与兼容性变体必须直接拒绝，而不是归一后接受。
- TRN-006：sandbox client 不持有 AppKey、shared raw、host root、agent ID
  或 tenant ID；错误输出脱敏。
- TRN-007：真实 capability receipt 可由独立 verifier 离线复核；过期、错
  signer/key/target/audience、篡改、重放和被撤销 key 全部拒绝。
- TRN-008：在真实沙箱链上交付可被 VG-D 消费的攻击面与证据，覆盖身份伪造、
  空间越权、双 ACL、in-flight revoke、canonical SHA、Prompt injection 与 sandbox
  destroy 隔离。VG-D 本身在 RT-023 独立 PASS 之后执行，其 receipt 是 RT-024/
  RT-026/G6 的输入，**不是 RT-023 的完成前置**。
- TRN-009：可实现专用 non-production `PilotAdmissionProviderV1` sandbox adapter，
  但它与 RT-026 production factory、release switch/G7/allowlist source 完全分离，只能
  用于本 RT 的注入/deny/expiry 测试。VG-D/G5 production claim 不得引用该 adapter；
  production adapter 的唯一 owner 为 RT-026。

### 明确不做

- loopback HTTP、自报身份、共享目录挂载、沙箱内采集/存储。
- 自动创建 Skill、生产部署、真实用户 enablement、AppKey/cron 变更。
- 任何 mock-only VG-D 或“能力探针可运行”即视为 verified 的升级。
- 由 sandbox/client/env/CWD 提供 pilot allowlist，或让 test/fake admission provider
  进入 production trust/composition root。

## 4. 输入契约

### 4.1 Tool 调用

- request body 只允许 RT-022 QueryRequest v2、`list_spaces` 的空参数对象，或
  `resolve_slug` 的严格 `{slug}` 对象；slug 不能混入 QueryRequest，且解析结果
  只能返回当前 tenant 的 opaque `space_id`。
- 身份 metadata 必须在 Gateway 控制层注入，adapter 接收时与 body 分离；
  body 同名字段即使值相同也拒绝。
- metadata 至少包含不可变调用 ID、受控 Agent identity、Gateway instance/
  build、issued-at、audience；adapter 立即 HMAC identity，原值不得落盘。

### 4.2 UDS 后备

- socket 固定在 instance runtime 子树，由安全 dirfd 创建，mode `0600`，
  拒绝 symlink/hardlink/路径覆盖。
- peer uid/gid/pid（平台可得字段）来自 kernel；host mapping 必须证明该
  credential 唯一对应一个已绑定 Agent。共享 uid 无附加隔离证明时拒绝。
- client frame 有长度上限、版本、nonce、deadline；无身份字段。

## 5. Production trust-store 与 receipt

`cwk.rt023.trust_store.v1` 由宿主机管理员管理，root/服务账号只读，不从
CWD、PYTHONPATH、请求体或普通环境变量加载。每个 entry 包含：`signer_id`、
`key_id`、`algorithm`、public-key/verifier reference、`not_before/not_after`、
允许 targets/audiences、状态 `active/revoked`。v1 只允许经审计库实现的
Ed25519 或等价外部 KMS/HSM verifier，禁止自制对称生产签名。

`cwk.rt023.capability_receipt.v1` 至少包含：schema、receipt ID、signer/key、
algorithm、target、audience、issued/expires、nonce、Gateway build、能力摘要、
evidence SHA、canonical envelope SHA 和 signature。签名覆盖 domain separator
与除 signature 外的 JCS bytes。nonce/receipt ID 在有效期内只能消费一次。

## 6. 输出契约

- query：原样返回 RT-022 evidence bundle/error，不增加身份或路径字段。
- list_spaces：稳定排序的 tenant-scoped descriptors 与 `as_of/index_version`。
- resolve_slug：返回单个 tenant-scoped opaque `space_id` 与 mapping revision；不存在、无权、disabled 或他 tenant 使用等价错误。
- capability：probe 只有 production verifier 通过且真实 evidence receipt
  存在时才可从 `conservative_unknown` 升 `verified`。
- VG-D receipt：记录环境/build、真实 transport、identity source、攻击矩阵、
  Broker/index/canonical versions 和证据哈希；不含 secret/原始 Agent ID。

## 7. 业务规则

1. OpenClaw Tool 为首选；UDS 是受限后备，不是同时暴露的第二公共入口。
2. 身份映射在 query/list_spaces/resolve_slug 共用同一 adapter；不得一个入口可信、另一
   入口自报。
3. slug 仅在 host 解析，Broker 只接 opaque space ID。
4. capability receipt 验证顺序：schema → trust-store entry → key 状态/时效 →
   target/audience → envelope SHA → signature → nonce replay → evidence binding。
5. 敌意 raw 只作为 evidence data；不能改变 Tool 名称、参数、身份或触发
  新工具调用。
6. 销毁沙箱只能中断该 client；宿主 collector/scheduler/Broker 数据不删。
7. VG-D 对 active tenant 必须证明 admission 调用 0 次；若测试 pilot，则
   non-production adapter 的结果只能作为 scoped test evidence，不能升级 G5 或
   `capability_activated`。RT-023 不读取 RT-026 私有配置，也不签发生产 admission。

## 8. 验收标准

- AC-023-01：真实 Tool metadata 或合格 UDS peercred 不能被沙箱伪造。
- AC-023-02：请求 body 身份/tenant/path 字段在 adapter 边界即拒绝。
- AC-023-03：A 只能 list/resolve/query A 的 spaces；不存在、disabled、无权与他 tenant slug 返回等价错误，冲突不能解析到 B。`resolve_slug` 对大小写变体、NFKC/NFC/NFKD 变体、含空白与同形字符的 slug 全部拒绝，且拒绝路径与"不存在"等价，不做任何归一化后匹配。
- AC-023-04：沙箱内扫描不到 AppKey、shared raw、host path 和其他 tenant。
- AC-023-05：production trust-store 正反例与重放/撤销测试全部通过；测试
  signer 不可用于 verified。
- AC-023-06：真实 SpaceIndexProvider + RT-022 双 ACL + SHA 回读通过。
- AC-023-07：Prompt injection/敌意 raw 不能触发越权 Tool 或更改参数。
- AC-023-08：RT-023 自身由独立验收 Agent 在真实 transport/verifier/provider 上判定
  PASS；任何 mock-only 结果不得标 completed。VG-D 在此 PASS **之后**由 wave 集成
  验收者执行，不作为 AC-023-08 的前置条件。
- AC-023-09：全库回归、Wiki smoke、secret scan、socket/文件权限通过。
- AC-023-09a：non-production PilotAdmission adapter 与 production factory 物理/类型/
  composition 隔离，sandbox/body/env 不能提供 policy；active VG-D 路径 admission 0 次，
  pilot fake 路径明确 synthetic 且不能关闭 VG-D/G5 production admission 条件。

## 8a. RT-023 拥有的 PR-001 receipt（生产者义务）

RT-023 是两份 PR-001 级 receipt 的**唯一生产者**；二者都不是 RT-023 的完成条件，
而是 AC-023-08 独立 PASS 之后的产出物。

| receipt | schema | 路径 | 任务 | 生产阶段 | 消费者 |
| --- | --- | --- | --- | --- | --- |
| `gateway-identity-transport` 能力激活 | `cwk.pr001.capability_activation_receipt.v1` | `PR/PR-001-multitenant-knowledge-spaces/capability-receipts/gateway-identity-transport/receipt.json` | T023-13 | T023-11 独立 PASS 之后、T023-12a 的 VG-D 之前 | 仅 RT-026 |
| RT-023 安全门 | `cwk.pr001.security_gate_receipt.v1` | `PR/PR-001-multitenant-knowledge-spaces/security-receipts/RT-023/receipt.json` | T023-14 | `rt_independent_acceptance` | RT-026（go/no-go）、G6（final acceptance） |

**与 `cwk.rt023.capability_receipt.v1` 的区别（禁止混用）**：§5 定义的
`cwk.rt023.capability_receipt.v1` 是**运行时每次调用**的签名传输凭据，由 production
`CapabilityReceiptVerifier` 按 §7.4 顺序逐次校验，带 nonce 防重放、生命周期以秒计、
永不入库为仓库证据。本节的 `cwk.pr001.capability_activation_receipt.v1` 是**仓库级
PR-001 能力激活记录**，写在固定 `capability-receipts/` 路径、只被 RT-026 消费。
它**不是一次性写入**：schema 要求 `expires_at` 与 `sequence`，有 30 天上界并按归档链续签，
到期即失效。

**首次激活与续签的字段义务不同（以 `capability_activation_receipt_v1.schema.json` 为准，
逐字对齐，禁止在此处收紧或放宽）**：

| 字段 | `sequence = 1`（首次激活） | `sequence = k > 1`（续签） |
| --- | --- | --- |
| `sequence` | 必填，恒为 `1` | 必填，为 `k` |
| `expires_at` | 必填 | 必填 |
| `previous_receipt_sha256` | **禁止出现**（present 即 INVALID） | **必填**，且等于 `archive/` 中 `sequence = k-1` 那份归档件**重算**出的 sha256 |
| `renewal_probe_ref` | **禁止出现**（present 即 INVALID） | **必填** |

即：首次激活**没有**前序 receipt 可引用，也**没有**续签探针可指向，因此这两个字段在
`sequence = 1` 上是硬禁止字段，而**不是**"可选"或"留空"。把它们写成空串、`null`、
占位 hash 或自指 hash 一律 fail closed。只有 `sequence > 1` 才**同时**要求两者。
两者 schema ID、domain separator（
`cwk-capability-activation-receipt-v1\0`）与存放位置均不同，任何一方都不能代替另一方。

- **真实生产条件**（逐条见闭包图 `production_conditions`）：存在专用非生产 sandbox
  pilot Agent（sandbox 开启、最小 Tool allowlist，所需 Gateway 重启发生在 Life 触发
  回合之外）；至少一条真实受控 transport 端到端承载真实 query（OpenClaw 受控 Tool
  plugin factory，或能把单一凭据唯一映射到单一绑定 Agent 的合格 UDS `SO_PEERCRED`
  后备）；Agent identity 由 Gateway 控制面注入且可证明无法从请求 body 伪造，沙箱读
  不到 CWK 实例根、凭据、shared raw 或任何其他 workspace；production trust store 与
  `CapabilityReceiptVerifier` 从固定 root-owned 路径加载，使用真实 Ed25519 或外部
  KMS/HSM verifier，全链路无 test-only signer。
- **缺失即不签发**：若 Tool metadata 无法证明不可伪造且无合格 UDS 后备，RT-023 状态
  为 blocked 并**完全不生成激活 receipt**；mock-only 或 `conservative_unknown` 结果
  绝不得记为 `capability_activated`。
- **独立验证**：两份 receipt 的 `verifier` 必须是 T023-11 的独立验收 Agent，
  且严格不等于实现 Agent（`producer`）。
- **无环**：VG-D 既不是激活 receipt 的前置，也不得作为其 `evidence_refs` 角色；VG-D 是
  RT-026 的同级独立输入。顺序恒为
  T023-11 独立 PASS → 激活 receipt → T023-12a 的 VG-D → RT-026。
- **有界有效期与续签**：`expires_at - created_at` 必须满足 `0 < Δ ≤ 2592000s`
  （30 天，闭区间上界），比权威能力更短——陈旧 trust-store 声明等于静默认证绕过。
  过期后禁止原地覆盖，须归档旧 receipt 并基于**新的真实探测**续签。

## 9. 黑盒测试矩阵

| 场景 | 操作 | 期望结果 |
| --- | --- | --- |
| Tool 正常 | A 沙箱查询 A space | 返回 A evidence；receipt 可离线验证 |
| body 伪造 | A body 写 B agent/tenant | adapter 拒绝，Broker 未调用 |
| metadata 伪造 | 沙箱尝试覆盖 Gateway metadata | 受控层忽略/拒绝，identity 仍为 A |
| UDS 假 peer | 未登记 uid/pid 或共享 uid | fail closed，不回退 body identity |
| list/resolve 越权 | A 猜 B slug/space ID，或解析不存在/disabled slug | 等价拒绝，不泄露存在性；QueryRequest 未被构造 |
| slug 变体 | 对已存在 slug 提交大写/混合大小写、NFKC/NFC/NFKD 变体、含前后空白或同形字符 | 全部拒绝且与"不存在"等价；实现不得归一化后解析成功 |
| receipt 篡改 | 改 target/audience/expiry/signature | verifier 拒绝，probe 不升级 |
| receipt 重放 | 重复 nonce/receipt ID | 第二次拒绝 |
| key 撤销 | 使用 revoked key receipt | 拒绝 |
| 撤权竞态 | retrieval 后 revoke A | 无 evidence 返回 |
| Prompt injection | raw 指令要求调用工具/换 tenant | 仅作为数据，不触发工具 |
| 沙箱销毁 | query 中/后销毁 A sandbox | 宿主数据面和 B 不受影响 |
