# RT-023 技术方案：可信沙箱传输、客户端与真实空间集成

## 1. 架构

```text
sandbox client
  -> OpenClaw controlled Tool metadata (preferred)
     OR UDS kernel peercred (fallback, mutually exclusive)
  -> IdentityAdapter -> AgentContextSnapshot
  -> list_spaces / RT-022 QueryBroker
  -> RT-021 SpaceIndexProvider -> RT-014 EvidenceReader
```

Transport adapter 与 request parser 分层；任何 body 字段都不能写入
`IdentityAdapter` 的 identity 输入。

## 2. 模块

- `cwk_gateway_tool_adapter.py`：受控 Tool metadata 验证与调用边界。
- `cwk_query_uds.py`：仅后备的 socket server/client、peercred 和 framing。
- `cwk_capability_trust.py`：trust-store loader、production verifier、replay store。
- `cwk_space_index_provider.py`：RT-021 real provider 与 list/slug resolver。
- `cwk_sandbox_query_client.py`：无 credential/identity 的薄 client。
- `contracts/rt023/schemas/`：trust store、receipt、space list、VG-D receipt。
- 专用 non-production PilotAdmission adapter：仅在 test composition root 构造，绑定
  `query_broker`；不得出现在 production factory/trust store，也不得读取 RT-026 policy。

若需要正式 Skill，只在独立 Skill Workshop 流程生成；这些模块不伪装成 Skill。

## 3. IdentityAdapter ABI

```python
class IdentityAdapter(Protocol):
    def context_from_tool(self, *, controlled_metadata, request_id) -> AgentContextSnapshot: ...
    def context_from_peer(self, *, peer_credential, connection_id) -> AgentContextSnapshot: ...

class CapabilityReceiptVerifier(Protocol):
    def verify(self, receipt_bytes: bytes, *, expected_target: str,
               expected_audience: str, now) -> VerifiedCapability: ...
```

Tool adapter 必须从 Gateway SDK 的 server-controlled metadata object 取值；
不能从普通 mapping 合并 body。UDS adapter 通过已连接 socket 的 kernel API
读取 peer credential，再查询 host-only mapping；映射结果唯一才返回 context。

## 4. Trust-store/verifier

- loader 用 dirfd/O_NOFOLLOW 打开固定 host path，校验 owner、mode、canonical
  JSON 和完整性；不搜索 CWD/PYTHONPATH。
- verifier 对 JCS envelope 加 domain separator，调用审计过的 Ed25519 库或
  外部 KMS/HSM verifier adapter；禁止复用 `_TEST_PROBE_SIGNING_SECRETS`。
- key rotation 允许旧 key 在明确 overlap 窗口内验证，但新 receipt 只能用
  active key；revoked key 无宽限。
- replay store 以 receipt ID/nonce + expiry 持久化，crash 后仍能拒绝重放。
- RT-011 probe integration 使用版本化 adapter/migration note；旧 v1 test
  HMAC 路径仅测试可见，production mode 导入即拒绝。

## 5. Controlled Tool 与 UDS

### Tool

- 注册 `query`、`list_spaces`、`resolve_slug` 三个最小 operation；operation 固定，
  用户不能指定任意 host callable。`resolve_slug` 是独立只读入口，只接受严格
  `{slug}` 对象，不能与 QueryRequest 合并，返回值只有当前 tenant 的 opaque
  `space_id` 与 mapping revision。
- Gateway 限制 payload bytes、deadline、concurrency；host 再次限制。
- metadata audience/instance/build 与 trust receipt 一致。

### UDS 后备

- 仅当 Tool capability 结论不可用且 peer identity 唯一可证时启用。
- socket mode `0600`，安全目录，长度前缀 frame，最大 bytes，read/write
  deadline，单连接有界请求数。
- Linux 用 `SO_PEERCRED`；macOS 使用 `getpeereid`/`LOCAL_PEERCRED` 等可用
  kernel API。若只能获得共享 uid，必须有独立 OS uid/受控进程映射证据，
  否则 feasibility 结论为 blocked。

## 6. Real SpaceIndexProvider

- 从 context tenant root 读取 RT-021 registry、membership 和 index manifest；
  禁止接受 caller path。
- list_spaces 只返回 active/queryable space 的 opaque `space_id`、slug 与显示名。
- `resolve_slug` 对输入执行严格字节级校验，不做任何归一化：不 lower/casefold、
  不 NFC/NFKC/NFKD、不去空白、不替换连字符或同形字符。输入必须逐字节等于
  RT-021 冻结的 slug 语法（`^(?=.{1,32}$)[a-z](?:[a-z0-9-]*[a-z0-9])?$`，保留字
  `all/shared/raw/system/archive/review` 拒绝）。任何大小写变体、NFKC/NFC 变体、
  全角或 Unicode 同形输入一律直接拒绝，绝不归一化后再匹配。
- slug 唯一性只在已存的严格 lowercase ASCII 字节上判定；registry 侧不存在
  casefold 索引。歧义、不存在、disabled、他 tenant 与无权返回同一等价安全错误。
- retrieve 仅接 RT-022 已计算 allowset，返回 Candidate 不含 raw。
- manifest/index SHA 与 version 校验失败时 query unavailable，绝不全局 fallback。

## 7. 验证策略

1. contract/unit：trust store、receipt、replay、framing、permissions、slug
   （含大小写变体、NFKC/NFC 变体、前后空白、保留字、超长的全部拒绝用例）。
2. integration：真实 RT-021 provider + RT-022 Broker + canonical reader。
3. real sandbox attacks：body/metadata/peer spoof、A→B、path/space enum、Prompt
   injection、destroy sandbox、receipt expiry/revoke/replay。
4. VG-D：验收 Agent 独立生成攻击 payload并验证真实 receipt；mock suite 仅为
   前置，不计 gate。

PilotAdmission 验证与 transport 验证正交：VG-D 的 production transport/identity 结论
不得借用 non-production admission adapter。active tenant 的 Broker path 应验证 admission
0 次；pilot fake path 仅验证构造注入、两次调用和 fail-closed，不形成 G5 readiness。

## 7a. PR-001 receipt 生成机制（T023-13 / T023-14）

两份 PR-001 receipt 都由 T023-11 的**独立验收 Agent**在 RT-023 独立 PASS 之后写入，
均为 evidence-only 变更，不触碰 runtime，也不改动 Gateway 配置。

- **三种 receipt 严格区分**，domain separator 互不可换：
  | 对象 | separator | 生命周期 | 存放 |
  | --- | --- | --- | --- |
  | `cwk.rt023.capability_receipt.v1`（运行时传输凭据） | RT-023 自有 | 秒级、每次调用、nonce 防重放 | 不入库，只在 transport 内流转 |
  | `cwk.pr001.capability_activation_receipt.v1`（能力激活） | `cwk-capability-activation-receipt-v1\0` | ≤ 30 天，可归档续签 | `capability-receipts/gateway-identity-transport/` |
  | `cwk.pr001.security_gate_receipt.v1`（安全门） | `cwk-security-gate-receipt-v1\0` | 无 TTL；registry 路径唯一，重验即整份替换（无归档链） | `security-receipts/RT-023/` |
- **写入顺序**：冻结被测候选 commit → T023-11 独立验收 → PASS → 在随后的
  evidence-only commit 中写 receipt。`tested_subject_commit` 必须是该 evidence-only
  commit 的**祖先**，且与 receipt 自身 `evidence_refs`/`artifacts` 一致；**不要求**
  等于 RT-026 最终 HEAD。
- **evidence_refs / artifacts**：仓库相对普通文件，拒绝绝对路径、`..`、任一分量
  symlink、hardlink、目录、特殊文件；逐条 sha256 与磁盘匹配。任何 evidence 角色都
  不得指向 VG-D receipt（无环约束）。
- **报告引用是单向的，且两类报告的时序相反**：
  - `reports/独立验收报告.md` 被 receipt 以 `independent_acceptance_report` 角色
    **按 sha256 绑定**，必须在 receipt 签发**之前**冻结并**永不再编辑**；它**不引用**
    `receipt_sha256`，也不引用 receipt 路径。
  - 只有**不被绑定**的 `reports/交付验证报告.md`（交付/状态件）可在 receipt 写入
    **之后**追加其路径与 `receipt_sha256`。
  receipt 不反向哈希报告。被绑定的报告一旦在 receipt 之后被编辑，其 sha256 即与
  receipt 记录值不符，等于自毁该 receipt。
- **续签（仅激活 receipt）**：旧 receipt 原字节移入
  `capability-receipts/gateway-identity-transport/archive/<旧 receipt_sha256>.json`，
  新 receipt `sequence` 递增 1、`previous_receipt_sha256` 指向该归档项，且必须基于
  **新的真实探测**（真实 transport + 真实 trust store）。禁止原地覆盖。
- **不生成的情形**：blocked 时不写文件；RT-026 见不到 receipt 即 NOT_RUN / NO_GO。

## 8. 风险与阻塞

- Gateway SDK 可能不暴露不可覆盖 metadata：阻塞 Tool 路径，不能猜接口。
- 同一 OS uid 下 UDS 无法区分 sandbox：阻塞后备路径，不能依赖 body token。
- crypto dependency：必须锁定版本、来源和安装检查；无 verifier 时 fail closed。
- Tool/UDS 双入口漂移：运行时只启用一种，验收 receipt 记录实际路径。

## 9. 回滚

禁用 operation/关闭 UDS、撤销 trust entry、卸载 client；Broker feature flag
保持关闭。回滚演练验证 legacy/collector 不受影响，历史审计不删除。
