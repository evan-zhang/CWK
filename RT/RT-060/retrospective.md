# RT-060 复盘

## 目标达成了吗

达成。首页回归产品介绍，深度内容进了文档中心五页（快速开始 / 架构与部署 / API 参考 /
扩展开发 / 常见问题），已部署到 OPS 并从局域网逐条路由复验。

## 做对了什么

- **把"简洁"写成判据**。首页不得出现命令、接口字段或 SVG——这类东西最容易在后续迭代里
  一点点漏回首页，靠自觉守不住，靠判据能守住。
- **API 文档与服务端契约用代码连起来**。判据不只检查字段齐全，还直接 import
  `contract.py` 比对查询长度与 `top_k` 上限。文档写错比没有文档更糟：照着它写的调用
  会被服务端拒绝，而且要等某个同事踩到才会发现。现在服务端一改，测试就红。
- **内容搬家时改判据的位置而不是删判据**。RT-059 的 12 条失败全是"内容不在首页了"，
  逐条指向新页面，意图一条没丢。
- 路由只认注册过的 slug，路径穿越和未知页都是 404——文档站最容易被顺手写成
  「按路径找文件」，那是另一类问题的开始。

## 踩到什么

- 判据里留过一个指向不存在模块的占位（`from contract_probe import ...`），
  被自己跑测试时抓到。半成品判据比没有判据更危险：它看起来是绿的。
- 局域网复验第一轮有三条路由报 502，重试即好——是服务重启期间的时序，不是代码问题。
  但当时没能立刻分辨，说明重启后应该先探健康再逐条验证。

## 留给下一次

- 文档页与 `docs/cwk-kb-access-setup.md`、`docs/ADAPTER-CONTRACT.md` 内容重叠，
  长期应择一为准、另一处引用它。现在是两份表述，改一处要记得同步另一处。
- 没有站内搜索，页数再多就需要。
- 「用户自己上传的文件」是产品问题不是工程问题：功能放在哪一层、谁为内容负责、
  库的粒度是个人还是团队，都要先定，再决定写不写适配器。
