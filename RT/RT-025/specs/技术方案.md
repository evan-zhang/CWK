# RT-025 技术方案：加密备份与 Clean-room 恢复

## 1. 模块

- `cwk_backup_crypto.py`：AEAD/key-provider ABI、nonce/key 生命周期、zeroization
  best effort、错误脱敏。
- `cwk_backup.py`：一致性 snapshot、分类器、segment writer、encrypted manifest。
- `cwk_restore.py`：preflight/plan、selective staging restore、重建、verify、publish。
- `contracts/rt025/schemas/`：manifest/receipt/plan/verify/measurement。
- `tests/fixtures/rt025/`：唯一 tracked 测试输入目录；仅含合成、非生产、无真实
  凭据数据的 fixture。产生 RT-025 security receipt 时，该目录必须非空并存在于
  `tested_subject_commit`。

## 2. Crypto ABI

```python
class BackupKeyProvider(Protocol):
    def create_data_key(self, *, backup_id, context) -> WrappedDataKey: ...
    def unwrap_data_key(self, *, wrapped_key, context) -> SecretBytes: ...

class BackupCryptoProvider(Protocol):
    algorithm: Literal['AES-256-GCM']
    def encrypt(self, *, key, nonce, aad, plaintext) -> bytes: ...
    def decrypt(self, *, key, nonce, aad, ciphertext) -> bytes: ...
```

参考实现使用锁定版本的审计加密库，不自制 primitive。AAD 绑定 schema、backup
ID、segment ID、sequence、classification、tenant-scope hash 和 plaintext SHA。
nonce 每 data key 唯一；重复检测即中止。

## 3. Bundle 格式

- 外层 envelope：schema、backup ID、crypto algorithm、wrapped-key reference、
  encrypted-manifest SHA/length、created-at、tool version；不含 tenant 详情。
- inner manifest：按 restore order 排序的 segment entries、逻辑 IDs、依赖、
  classification、plain/cipher hashes、length、schema/store versions、snapshot
  epochs 和 optional/rebuildable 标记。
- segment 使用长度前缀与 sequence；所有路径由 restore target + validated
  logical ID 构造，不保存 source absolute path。

## 4. Snapshot 与分类

每个上游 store 提供 read-only snapshot/version token；backup coordinator 在
短一致性屏障内冻结 token，再流式读取。Classifier 对所有发现文件/records
必须匹配矩阵 allowlist；unknown、symlink、hardlink、device 或 path escape 拒绝。

staged event evidence 单独 classification，正文与 manifest 同时加密；只包含
snapshot 时仍未清理的 tenant-private 项。scheduler state/retries/run manifests
包含但标 `restore_action=quarantine_paused`；locks 永不包含。

## 5. Restore 流程

1. 验证 target 是显式、新建、空目录且不为 workspace/repo/home/root。
2. 加载外 envelope，unwrap key，在内存验证/解密完整 manifest。
3. 生成 tenant-selective plan，验证全部依赖/segment/schema/hash 后才写。
4. 在 target 内 staging 子树按顺序恢复；每项写后重读 SHA/schema。
5. tombstone/intent recovery 先于 grant queryability；binding/credential 写为
   disabled/rebind-required；staged evidence quarantine；scheduler paused。
6. 从 route/profile/grant/canonical 重建 membership/index/cache；不复制旧 cache。
7. 执行 SHA、ACL、A/B、revoke、profile/space、audit chain 和 Broker receipts。
8. 仍保持 feature flags off，原子发布 clean-room pointer和 restore receipt。

## 6. Selective restore

selector 先转换为 tenant ID hash set；plan 过滤所有 tenant-scoped records，并
只加入这些 tenant 引用的 canonical objects。全局 catalog 输出最小子集，不
保留未选 tenant 引用计数或名字。audit 导出使用 tenant-specific events；中央
cross-tenant checkpoint 以不泄漏方式重新封口并注明 selective lineage。

## 7. Verification（RT-025 自验 + VG-E 输入）

本节产出的是 RT-025 自身独立验收所需的等价性证据，同时作为后续 VG-E 的输入。
VG-E 在 RT-025 独立 PASS 之后由 wave 集成验收者执行，不在本 RT 内签发。

- before snapshot 生成固定 allow/deny/query/revoke/SHA fixture receipt。
- after restore 使用相同 QueryRequest 与身份映射测试；credential-dependent
  操作保持 disabled，query 仅在显式测试 enable receipt 下临时打开。
- 比较外部 decision code、report/evidence SHA、tombstone与 profile/space；
  index version 可重建变化但必须在 receipt 中声明且安全结果等价。
- 测量 monotonic backup/restore duration、snapshot timestamp→completed 的
  recoverable point，记录数据量/环境，产生 RTO/RPO receipt。

## 8. 测试策略

- tracked fixture 只从 `tests/fixtures/rt025/` 读取；该目录不充当 restore target，
  也不得保存真实备份、真实 tenant 内容或真实凭据。每次 clean-room E2E 的运行时
  target 由 `mktemp`（或等价安全 API）在仓库外单独创建，测试结束后的清理仍按
  精确目标与授权边界执行。
- crypto known-answer/round-trip/wrong-key/nonce reuse/tamper/truncate/swap/replay。
- filesystem attack：symlink/hardlink/FIFO/TOCTOU/path traversal/non-empty target。
- classification coverage：矩阵逐行、unknown default deny、secret corpus scan。
- selective A/B、tombstone revival、staged quarantine、scheduler pause、credential
  rebind、audit chain、derived rebuild。
- clean-room E2E + 恢复前后等价对照（VG-E 输入）、全库/Wiki regression 和 rollback。

## 9. 风险

- 外部 key provider 未选：production provider 缺失时实现可测试但 RT-025 不得
  completed；fake crypto 既不计入 RT-025 独立验收，也不计入后续 VG-E。
- selective audit lineage：需明确不证明未选 tenant 的完整性，也不泄露计数。
- 大对象内存：segment streaming；manifest 设置条目/字节上限。

## 10. 回滚

失败时不发布 staging；清理由验收临时目录的明确路径执行。源 instance 与
backup 永不修改；任何清理 clean-room 的动作先列出精确目标并保留 receipt。
