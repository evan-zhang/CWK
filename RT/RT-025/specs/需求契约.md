# RT-025 需求契约：加密备份与 Clean-room 恢复

## 1. 业务目标

在不携带明文凭据、不依赖原机路径、不复活撤权的前提下，将多租户权威数据
恢复到全新目录；派生物从权威状态重建，并产出可供后续 VG-E 消费的"恢复前后安全
行为等价"证据。VG-E 本身在 RT-025 独立 PASS 之后作为独立 wave 集成回执执行。

## 2. 用户角色

- 备份管理员：触发备份但不能读取 key material 或 tenant raw。
- 恢复管理员：在 clean-room 选择全量或 tenant 子集恢复。
- 外部 Key Provider：包装/解包 data key；密钥不进入 bundle。
- 独立验收 Agent：篡改、错误密钥、A-only、撤权和 query 等价攻击。

## 3. 功能范围

### 必须实现

- BKR-001：backup bundle 使用认证加密、每 bundle/segment 唯一 nonce/data key、
  外部 KEK 包装；key 与数据物理/权限分离。
- BKR-002：inner manifest 记录逻辑对象、schema/version、tenant scope、明文
  SHA、密文 SHA、长度、依赖、classification 和 restore order；无绝对路径。
- BKR-003：按下表执行 include/exclude，未知数据类别默认拒绝备份而非猜测。
- BKR-004：支持 full 与 tenant-selective restore；A-only restore 不生成 B 的
  metadata、view、profile、space、index、audit tenant view 或 scheduler state。
- BKR-005：恢复顺序固定为安全配置/tenant/binding refs → ledger/tombstone →
  canonical/catalog → views/staged evidence → profile/route/space → audit/scheduler →
  重建派生 → 验证；失败不开放数据面。
- BKR-006：恢复后 canonical SHA、catalog、active grant 数、tombstone、profile
  SHA、space IDs 和 audit chain 与选定 snapshot 一致。
- BKR-007：错误 key、bit flip、truncate、segment swap/replay、manifest 缺项、
  unknown schema 全部 fail closed，目标不出现可查询的部分恢复。
- BKR-008：Broker/collector/Scheduler 默认 disabled/paused；credential ref 在
  secret backend rebind receipt 前不可解析。
- BKR-009：恢复后重新执行 allow/deny/revoke/in-flight/SHA/query 与 A/B 隔离
  receipt，并以稳定格式输出恢复前/后对照证据；后续 VG-E 只消费该证据做比较，
  不构成 RT-025 的完成前置。
- BKR-010：记录真实 backup duration、restore duration、snapshot age、数据量、
  环境与 RTO/RPO；不预填承诺值。

### 明确不做

- AppKey、access token、binding HMAC secret、private signing key、backup key、
 完整 query、临时 URL、cache/temp/log 原文备份。
- 原地恢复、覆盖 production、自动查询开放或自动重放 scheduler retries。

## 4. 权威/可重建/敏感备份矩阵

| 数据类别 | 分类 | 备份 | 恢复行为 |
| --- | --- | --- | --- |
| Instance/Tenant Registry、epoch、状态 | 权威/敏感元数据 | 加密包含 | 恢复到安全状态；原状态作为证据，数据面仍关闭 |
| Binding records、`agent_id_hash`、binding epoch | 权威/敏感 | 加密包含 | 恢复记录；原始 Agent ID 不存在，外部 secret 复核前不可用 |
| Credential refs/secret pointers/rotation metadata | 权威/高度敏感指针 | 加密包含指针，绝不含值 | 标 `rebind_required`；管理员重新绑定 secret backend |
| AppKey/token/HMAC secret/private key/backup key | Secret material | **排除** | 绝不恢复；缺少即保持 fail closed |
| Canonical objects、version catalog | 权威/敏感正文 | 加密包含 | 按 SHA 验证后发布到 clean-room |
| Access Ledger、lease、revoke intent/tombstone/outbox | 权威/安全关键 | 加密包含 | tombstone 优先；in-flight intent 向前恢复，不复活 grant |
| Tenant View overlay | 权威 tenant-private | 加密包含 | 仅选定 tenant；ACL/SHA 验证前不可读 |
| Staged event evidence body + manifest/cleanup state | 权威、临时、高度敏感 | 未清理且 snapshot 内的项加密包含 | 恢复至 tenant quarantine；非 query/AI/index 输入，继续 cleanup/review |
| RT-016 migration crosswalk、reconciliation、review entries | 权威/迁移证据/敏感元数据 | 加密包含 | 校验 source/canonical SHA 与状态；供 RT-026 数据/query diff，缺失即恢复失败 |
| Profile/proposal/decision/pointer/rollback events | 权威/敏感 | 加密包含 | SHA/状态图验证；active pointer 不自动触发作业 |
| Route decision log、space config/registry | 权威 | 加密包含 | 验证 opaque space ID/slug uniqueness；供重建使用 |
| Space membership、Wiki/summary/entity/search index | 可重建派生 | 默认排除 | 从 route/grant/profile/canonical 确定性重建并比对 manifest |
| Cache、临时文件、query result/full query | 可丢弃/敏感 | 排除 | 不恢复 |
| Audit events/checkpoints/replay roots | 权威安全记录 | 加密包含 | 验 chain；tenant-selective 输出不得泄露未选 tenant |
| Metrics/tenant health/exporter spool | 可重建/运行态 | 默认排除；仅保留聚合 baseline receipt | 从恢复后事件重建，不恢复高基数 spool |
| Scheduler state、retry queue、run manifests、locks | 运行权威/敏感 | state/retries/manifests 加密包含；locks 排除 | 恢复为 paused quarantine；人工审核后新 lease 才可重放，旧锁不恢复 |
| Gate receipts、schema/version manifests、trust public refs | 权威发布证据/安全配置 | 加密包含 | 验签/验 SHA；private signing material 排除，功能保持关闭 |

## 5. 输入

- 显式 instance root（安全 dirfd 验证）、snapshot ID、tenant selector、外部
  key provider reference、空 clean-room target。
- tenant selector 缺省必须显式选择 `all`；空列表非法，防止误认为全量。
- key provider 返回 opaque wrapped-key/unwrap result，不把 key 放 argv/log/env
  dump/manifest。
- 仓库内 tracked 测试输入的唯一精确 owner 路径为 `tests/fixtures/rt025/`；其中
  只能包含合成、非生产、无真实凭据数据的 fixture。产生 RT-025 security receipt
  时，该目录必须非空且存在于 `tested_subject_commit`。
- `tests/fixtures/rt025/` 绝不是运行时 restore target。正式 clean-room 演练仍须用
  `mktemp`（或等价安全 API）在仓库外创建独立临时目录，并继续满足“显式、新建、
  空目录且不为 workspace/repo/home/root”的约束。

## 6. 输出

- `cwk.rt025.backup_manifest.v1`（加密 inner manifest + 最小公开 envelope）。
- `backup_receipt.v1`、`restore_plan.v1`、`restore_receipt.v1`、
  `restore_verify_report.v1` 和 RTO/RPO measurement receipt。
- receipt 记录选定 tenant 集合的 hash、对象分类计数、bytes、schema versions、
  source snapshot/commit 与验证结论；不记录 secret/正文/绝对路径。

## 7. 业务规则

1. snapshot 在一致性屏障下读取；各权威 store 的版本/epoch 写入 manifest。
2. 认证加密必须使用审计库的 AEAD（首选 AES-256-GCM）与外部 key provider；
  禁止自制 XOR/裸 AES/HMAC-only encryption。
3. 外层公开 envelope 不泄露 tenant 名称/数量/对象标题；inner manifest 加密。
4. restore 先生成 plan 并验证全部 segments/key/schema/dependencies，再写目标。
5. 写入 staging target，全部验证通过后原子发布 clean-room pointer；失败清理
  staging，不产生可查询半成品。
6. selective restore 的 canonical 可包含 A 需要的共享对象，但不得产生 B
  grant/view/profile/space/scheduler/audit tenant metadata。
7. tombstone/intent 优先于旧 active grant；恢复不得将 revoked 变 active。
8. 派生索引全部从权威状态重建；manifest 中旧派生 hash 仅作验证参考。
9. 恢复后需管理员提供新的 enable receipt；无 receipt Broker/Scheduler 永远关。

## 8. 验收标准

- AC-025-01：矩阵每行有实现策略和自动化 include/exclude 断言，未知类别拒绝。
- AC-025-02：bundle/manifest/argv/log/temp 扫描无 secret、绝对路径、临时 URL。
- AC-025-03：wrong key、bit flip、truncate/swap/replay 均 fail closed，目标无
  可查询半成品。
- AC-025-04：A-only restore 不出现任何 B metadata/index/audit health/scheduler。
- AC-025-05：staged evidence 仍 quarantine；scheduler retries paused；credential
  refs rebind 前 fail closed。
- AC-025-06：SHA/grant/tombstone/profile/space/audit chain 验证一致，派生可重建。
- AC-025-07：恢复后 allow/deny/revoke/query/SHA 与恢复前等价，由 RT-025 自身的
  独立验收 Agent 判定 PASS。VG-E 在此 PASS **之后**由 wave 集成验收者执行，
  其 receipt 供 RT-026/G6 消费，不作为 AC-025-07 的前置条件。
- AC-025-08：Broker/Scheduler/collector 默认关闭，无法被 restore 参数绕过。
- AC-025-09：真实 RTO/RPO 及方法/环境/数据量有记录，无虚构数字。
- AC-025-10：全库回归、Wiki smoke、secret scan、回滚通过，独立验收 PASS。

## 9. 黑盒测试矩阵

| 场景 | 操作 | 期望结果 |
| --- | --- | --- |
| 全量恢复 | 合成 A/B snapshot → 空目录 | 权威一致、派生重建、数据面关闭 |
| A-only | 只选 A | 无 B metadata/index/audit health/scheduler |
| 错 key | 不匹配 KEK/DEK | 验证失败，目标未发布 |
| 篡改/截断 | bit flip/删尾/交换 segment | fail closed，receipt 标 invalid |
| 撤权复活 | snapshot 含旧 grant+tombstone | 恢复后 deny，tombstone 有效 |
| staged evidence | 恢复未决 tenant-private body | 仅 quarantine，Broker/index 不可见 |
| scheduler retry | 恢复待重试 job | paused，不自动调用 CWork |
| credential ref | 恢复 pointer 无 secret | `rebind_required`，解析 fail closed |
| 路径迁移 | 不同 clean-room 根 | 无原机绝对路径依赖 |
| 等价对照（VG-E 输入） | 恢复前后 query/deny/revoke/SHA | 安全结果等价，差异有明确 blocker；对照证据以稳定格式输出供后续 VG-E 消费 |
