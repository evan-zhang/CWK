# RT-Lite: RT-065 - 同事安全报到与控制台薄登录态

> profile: Spec-Lite | execution_mode: collaborative

## 方案（给人看）

- 做什么：让同事能**安全地**用自己的业务 Key 确认「我是谁」，进入人员目录；
  并在控制台留下一份**很薄的登录态**（浏览器知道现在坐着的是哪个人）。
  不新建用户名密码，不另起一套账号产品——身份仍只向玄关借，权限仍用现有成员表。
- 为什么：没有报到，成员表里基本只有管理员；没有登录态，就做不成用户/成员管理界面，
  更做不成自助建库。局域网现在是明文，Key 不能经普通网页传。
- 代价：内网站点要能加密访问（或等价安全通道）；控制台从「只认管理密钥」变成
  「也能认出已报到的人」；运维要管证书或反代。
- 这次故意不做什么：自助建库/上传；切到按成员表判权（可在报到验证后另开短 RT）；
  邮箱注册、密码、OAuth；复制工作协同里的权限；访问审计正文（可另立）。
- 用户怎样算成功：同事在加密页面提交本人业务 Key → 系统经玄关核实 → 人员目录出现此人；
  之后打开控制台能看到「当前用户：某某」，且**不保存 Key**；未报到/假 Key 进不去。
- 建议：**定论做**；加密方式选下面推荐项（方案甲）。

## 加密报到：三种做法（请选一个）

### 方案甲（推荐）：内网 HTTPS + 控制台「报到 / 登录」页

在现有控制台（或紧挨着的报到页）前面加 HTTPS（常见是反代挂证书）。
同事用浏览器打开加密地址 → 粘贴本人业务 Key 一次 → 服务端只在内存里拿去问玄关 →
通过则写入人员目录，并给浏览器一份短时会话（证明「已报到的某人」）。
**Key 不落盘、不进日志、不进令牌库。**

- 好处：和产品主线一致；一次做好，成员管理、自助建库都能复用这套登录态。
- 代价：要准备内网证书（或公司已有的通配/内网 CA）并改发布方式。
- 适合：正式给同事用。

### 方案乙：暂时只走 SSH / 本机命令报到，网页登录后做

同事自己在能碰服务器的环境里跑报到命令（Key 只进自己机器的环境变量，不经明文网页）。
网页端先不做粘贴 Key，只做「管理员已报到的人」的会话——但同事仍难自己完成第一步。

- 好处：改动小、不碰证书。
- 代价：普通同事用不起来；「按人授权」仍然卡死。
- 适合：只想先搭会话骨架、同事很少且都有服务器权限——**不推荐作为主路径**。

### 方案丙：一次性加密通道（例如短期安全隧道），不改长期 HTTPS

为报到单独开临时加密入口，用完可关。

- 好处：证书/反代可以后补。
- 代价：运维折腾、同事体验差、以后每个新人都要再开一次。
- 适合：紧急给一两个人报到——**不推荐当常态**。

**推荐选甲。** 乙、丙不能替代「加密报到」这个产品目标。

## 薄登录态长什么样（选甲之后）

1. **报到**：HTTPS 页提交 Key → 玄关核实 → 人员目录有此人（已有 `enroll` 逻辑，改成走安全入口）。
2. **登录**：同一页或相邻页，再次用 Key 核实（或报到成功直接建会话）；浏览器拿到短时会话。
3. **控制台**：除原有「管理密钥」运维入口外，增加「已登录的人」视角——至少能显示当前用户是谁。
4. **铁律**：身份禁止手填；会话里只存人员主体与过期时间一类字段，不存 Key。
5. **管理员**：你已在目录里；本 RT 不要求先做完整用户管理页，但要能证明「第二个人也能报到并被认出来」。

## 假设与现状

- 现状依据：`kb_identity` / `kb_authz enroll` 已能用 Key 向玄关解析人员；卡点是明文 HTTP。
  控制台今天靠管理密钥解锁，没有「当前用户」。
- 关键假设：同事能从自己电脑打开内网 HTTPS 地址；业务 Key 仍只由本人持有。
- 已验证过：同一人两把 Key，玄关侧人员 ID / 真名一致——所以「Key 绑定到人」站得住。

## 实现备注（批准后再写细）

- 优先复用现有核实与人员目录写入，不平行发明第二套身份表。
- 会话存放与过期、HTTPS 终止位置（反代 vs 进程内）在实现阶段按运维约束选定，方案门只锁定「必须加密 + 薄会话 + Key 不落盘」。
- 管理密钥入口保留，避免运维在会话坏掉时锁死。

## 验证（批准后）

- 假 Key / 空 Key / HTTP 明文入口（若仍暴露）不得完成报到。
- 真 Key：人员目录出现对的人；刷新控制台仍显示该用户直至过期；登出后消失。
- 日志与审计中不得出现 Key 原文。
- 浏览器按真实 HTTPS 地址点通一遍。

## 变更记录

- 用户能感到什么：同事终于能以本人名义进入系统门口；控制台能认出是谁在用。

## 遗留事项（本 RT 成功后另开）

- 控制台成员管理页（加减谁能看哪个库）。
- 切换到按成员表判权。
- 自助建库 / 上传（含导入时来源权限检查）。
- 检索/问答访问审计（时间 / 令牌 / 库 / 结果）。
