# RT-021 需求契约：多知识空间 Projector 与索引

> 状态：planned。本文冻结 space 管理、投影、清理与黑盒验收标准。

## 1. 业务目标

将当前 tenant 有权访问并被 RouteDecision v2 判定为 `index` 的报告，投影到一个或多个专题空间；每个空间可有自己的摘要、主题、实体和搜索索引，但全部事实回链同一个 RT-014 canonical SHA。

## 2. 角色

- Tenant owner：经可信 host context 创建/rename/disable/re-enable 自己的 spaces。
- Platform admin：执行受审计的恢复/诊断，不通过普通查询越权。
- Profile activation：携带用户 confirmation，可原子请求创建 Profile 中的新 spaces。
- Projector：消费 RT-020 projection/cleanup request，生成可重建派生物。
- Access Ledger：授权/撤权唯一 SoR；Projector 不从 route/index 推断权限。

## 3. SpaceRecord 契约

Required：schema、space_id、slug、display_name、purpose、status、created_by_subject_hash、created_via、profile_version/SHA、record_revision、created_at、updated_at、record_sha256。

- `status ∈ {active,disabled}`；禁止其他别名、delete/terminal state。
- `created_via ∈ {profile_activation,tenant_owner,platform_admin}`，且必须绑定可信 actor/confirmation receipt ref。
- `space_id` 随机 128-bit opaque、永不复用；Profile 流程接受 RT-019 `SpaceIdFactoryV1` 已写入 Profile SHA 的候选 ID，直接 owner 创建由 Registry 使用同一算法生成；AI/slug/标题不能提供 ID。slug 只用于 UI/CLI 解析。
- slug grammar、唯一性、不可复用、32 个上限按 intake；reserved：`all/shared/raw/system/archive/review`。
- rename 原子更新 mapping、写 old-slug tombstone 和 receipt；space_id及所有 membership/projection不变。
- disabled space 不接受新 membership/route projection，也不被默认检索；disable 触发派生清理，但保留 record、raw、grant、route history。
- re-enable 需要 actor、reason、active Profile包含该 space或新的确认 receipt；之后从 route log重建。
- 禁止字段：parent_space_id、child_space_ids、ancestors、descendants、mount/path、tenant root、credential、grant、raw。

## 4. 创建与权限规则

- AI proposal只提出配置；没有用户 confirmation/actor receipt时不能写 SpaceRegistry。
- tenant_owner只能管理自己tenant；platform_admin操作也必须显式tenant、actor、reason并审计，不能接受请求体自报agent identity。
- 在 profile activation transaction中，所有新 spaces须预校验slug/上限/候选ID未占用/receipt；任一失败则Profile activation与space创建全部不提交。候选ID碰撞时必须生成新Profile版本，禁止修改已哈希Profile里的ID。
- 不提供跨tenant move/copy/clone space；不提供nested space。

## 5. SpaceMembership v1

每条 committed membership required：membership_id、tenant_id、space_id、report_key、canonical_sha256、route_decision_id/SHA、route_job_key、projection_key、profile_version/SHA、status、created_at、membership_sha256。

- 仅 RouteDecision v2 `disposition=index` 且space_id在其 committed `space_ids`内可创建。
- 创建前/提交前二次验证 tenant active/pilot、space active、grant active+lease、canonical SHA、Profile/route snapshot。
- 若 tenant 为 `pilot`，构造注入 `PilotAdmissionProviderV1` 并绑定
  `purpose=profile_workflow`；创建前与 current membership/projection/index pointer 提交前
  各验证 fresh snapshot。deny/unavailable/expiry/revision 回退或两次 snapshot 漂移均
  不提交；`active` 调用 0 次。
- 一报告可属于多个space；每个membership引用相同canonical SHA，不含body/raw副本。
- `(tenant,space,report,canonical,profile,route decision)` 幂等；重放不重复。
- route退出/revoke/disable/Profile rollback时，current membership移除并写immutable removal receipt/history；不删除route/canonical/grant。

## 6. Projection 契约

每个 membership 可生成：summary、topics、entities、search document、daily/action/risk view（仅Profile启用的类型）。ProjectionManifest required：

- tenant/space/report/membership/decision/profile/canonical opaque refs；
- `projection_key`（严格复用RT-020 helper/test vector）；
- generator name/version、artifact types、每artifact SHA/size/relative opaque ref；
- source snapshot、created_at、manifest SHA、status。

规则：

- 派生输出把“canonical事实”与“space-specific为何重要/解释”分栏；事实字段不得被space prompt改写成独立事实。
- artifact不得包含完整raw副本、credential、绝对路径、临时URL或另一个tenant数据。
- 同一report多space可有不同解释/摘要，但canonical ref/SHA一致；冲突时消费者须回退canonical。
- 生成失败保留membership/route/raw并标记derived incomplete；不能把失败改成archive/delete。

## 7. Entity/Search 适配

- `cwk_entity_catalog.py` 和 `cwk_wiki_search_index.py` 多租户路径只从 tenant + opaque space_id 派生。
- entity family/alias policy来自active Profile或tenant config，不读取/写入仓库级全局 registry作为多租户权威。
- search index只含active membership；构建候选不扫描shared raw。
- 索引条目带canonical/profile/decision/membership SHA；完整性不匹配则拒绝发布。
- RT-010实体硬范围、RT-007时间线、RT-008关系与legacy Wiki接口回归保持。

## 8. Archive/Review views

- `archive_no_index` 不创建space membership、summary/entity/search、日报；只保存tenant-scoped最小metadata/change cursor/reason/canonical ref。
- `review` 不创建committed membership；candidate spaces只能存在review metadata。
- 两者都不是权限来源，默认不可由未来Broker召回；冷归档查询必须由RT-022显式disposition预算。
- revoke触发`archive_metadata/review_queue` cleanup；成功后各自ack。

## 9. Cleanup consumers

### 9.1 Revoke

消费RT-015 cleanup outbox的 `space_index`、`review_queue`、`archive_metadata`：先确认Ledger已fail closed，再删除/取消本tenant相关current membership、projection、index/cache entry、review/archive metadata，写每consumer cleanup receipt，全部durable后ack。其他tenant共享canonical不变。

### 9.2 Route/Profile/Space变化

- route space退出/index退出：按RT-020 CleanupRequest精确清理，幂等。
- Profile rollback：以目标Profile重放route，清理不再存在的membership/artifact并补建目标版本。
- space disable：清空该space current membership/派生/index，保留record/history/canonical/grant；re-enable从权威route log全量重建。
- crash/retry不得留下可检索的孤儿；逻辑deny先于物理清理。

## 10. Deterministic rebuild

输入只有：active/allowed tenant状态、SpaceRegistry、active Profile、RT-020 current route/immutable log、RT-015 active grants、RT-014 canonical public reader。派生index/cache不是输入SoR。

相同输入与generator版本重建得到相同membership set、manifest keys和index logical hash；物理文件顺序/mtime不参与hash。遇到缺失/corrupt/unknown version进入review并不发布partial current pointer。

## 11. 异常与安全

- slug大小写/Unicode/路径/保留词/重复/旧slug reuse/超32/nesting全拒绝。
- wrong tenant/inactive space/slug冒充ID/unknown decision/v1无证据decision拒绝且不泄漏存在性。
- grant/profile/auth变化、revoke intent、canonical/route SHA mismatch在提交前fail closed。
- disk full/projector crash/index publish failure不发布current pointer；其他tenant/space可继续。
- dirfd/O_NOFOLLOW、0600/0700、CAS/fsync；防symlink/hardlink/TOCTOU、log/temp/cache串扰。

## 12. 验收标准

- AC-021-01：space只能由可信主体/confirmation创建；AI proposal不能直接创建；状态、slug、上限、no-nesting全部严格。
- AC-021-02：同report进入2+spaces时所有membership/projection引用同一canonical SHA，磁盘无raw副本。
- AC-021-03：RouteDecision v2/active grant/active space/Profile四门禁齐全；v1缺证据不能自动index。
- AC-021-04：summary/topic/entity/search manifest完整绑定generator/profile/route/membership/canonical并可完整性验证。
- AC-021-05：revoke、route退出、Profile rollback、space disable清除current派生与index，保留canonical/grant历史/route历史；其他tenant不受影响。
- AC-021-06：archive/review默认无membership/index/日报；只保留最小tenant metadata并可清理。
- AC-021-07：全量rebuild确定性、可从权威输入恢复；corrupt/partial不发布current index。
- AC-021-08：tenant entity policy不依赖仓库级全局registry；RT-007/008/010与Wiki smoke全部回归。
- AC-021-09：路径/slug/tenant/space/symlink/hardlink/TOCTOU/cache/log/temp攻击泄漏为0。
- AC-021-10：不实现沙箱/query/transport，不修改nightly/cron/install/release flag；Projector provider未被生产注册。
- AC-021-11：`ProfileSpaceSnapshotProviderV1` 生产 adapter 交付且零漂移——所用
  Protocol 与 `cwk.profile_space_snapshot.v1` schema 文件字节等同 RT-022 owner 版本，
  `contracts/rt021/schemas/` 未重定义同名 schema。adapter 只读、只接受可信
  `AgentContextSnapshot`（裸 `tenant_id=` 抛 `TypeError`），单次调用返回一致快照；
  `default_space_ids ⊆ queryable_space_ids`，`membership_versions`/`index_versions`
  键集合精确等于 `queryable_space_ids`；0 space 时仍返回非空 `profile_sha256`；
  返回值不含 slug/标题/正文/绝对路径/credential/Agent ID/他租户标识。
- AC-021-11a：`pilot` 的 membership/projection/index current publish 在生成前与提交前
  通过 `profile_workflow` fresh snapshot；deny/unavailable/expiry/wrong binding、revision
  回退和两次 snapshot 漂移零部分发布。`active` 调用 0 次，RT-021 不实现 production adapter。

## 13. 测试场景

- Space：create/rename/disable/re-enable、reserved/uppercase/Unicode/duplicate/old reuse/33rd/nesting/actor spoof。
- Projection：single/multi-space、same canonical、new version、generator failure、partial publish、rebuild。
- Cleanup：revoke/route exit/profile rollback/disable、crash every step、duplicate/reordered task/ack。
- Isolation：A/B same report、A revoke/disable/disk full不影响B；path/cache/log/temp scan。
- Snapshot adapter：0 space 仍带 profile SHA、Profile pointer 读取中途切换、space
  disable/rename 竞态、键集合缺/多、`default ⊄ queryable`、裸 `tenant_id=`、
  返回值 deep-forbidden scan、与 RT-022 fake provider 的契约互换验证。
- Regression：RT-007/008/010、Wiki lint/smoke、RT-011～021、全量unittest。
