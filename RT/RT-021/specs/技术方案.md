# RT-021 技术方案：多知识空间 Projector 与索引

> 状态：planned；模块、schema、索引与测试尚未实现。

## 1. 模块与所有权

- `cwk_space_registry.py`：SpaceRecord、slug map/tombstone、actor/receipt、状态与上限。
- `cwk_space_projector.py`：membership、projection、current pointer、rebuild、cleanup consumers。
- `cwk_projector_job_provider.py`：RT-018 JobProviderV1 adapter。
- `cwk_space_snapshot_adapter.py`：RT-022 冻结的 `ProfileSpaceSnapshotProviderV1`
  生产 adapter（只读，零漂移消费 RT-022 的 Protocol 与 schema）。
- `cwk_entity_catalog.py`、`cwk_wiki_search_index.py`：RT-021独占tenant/space适配。
- `contracts/rt021/schemas/`：space record/change、membership/removal、projection/index manifest、cleanup/rebuild receipt。
- Wave-0 `PilotAdmissionProviderV1`：RT-021 只以 `profile_workflow` constructor-bound
  consumer 使用；central runtime/schema 零漂移，不实现 production adapter。

## 2. SpaceRegistry布局与事务

```text
tenants/<tenant_id>/config/spaces/
├── records/<space_id>.json
├── slugs/<slug>.json
├── slug-tombstones/<slug>.json
├── events/<event_id>.json
├── receipts/<receipt_id>.json
└── registry-pointer.json
```

create/rename/status change持有registry lock，以revision/CAS提交。Create先验证actor receipt、Profile activation、全量slug set和count≤32；一次activation的多个space用journal all-or-nothing。Rename先写tombstone和新map，再更新record/pointer；recovery保证旧slug不会映射到其他ID。

ID 复用 RT-019 `cwk_space_id.SpaceIdFactoryV1`：CSPRNG 128 bit 后做 RFC 4648 小写、无 padding base32。Profile activation 使用已绑定 Profile SHA 的候选 ID 并检查未占用；直接 owner 创建也通过同一 factory 生成。slug 不作为目录以外的事实 key，slug map 文件内容只指向 space_id。所有记录 deep-forbidden hierarchy/path/credential/grant/raw。

## 3. Projection布局

```text
tenants/<tenant_id>/
├── knowledge-spaces/<space_id>/
│   ├── memberships/current/<report_key_hash>.json
│   ├── memberships/history/<membership_id>.json
│   ├── projections/<projection_key>/manifest.json
│   ├── summary/ topics/ entities/ views/
│   └── current-index.json
├── indexes/<space_id>/<index_version>/...
├── views/archive/<report_key_hash>.json
├── views/review/<report_key_hash>.json
├── runs/projector/<run_id>/manifest.json
└── locks/spaces/<space_id>.lock
```

任何路径leaf只用validated opaque/hash。Projection artifact不存canonical body；需要事实时在生成时经RT-014 public reader读取，输出只保留必要派生与evidence refs。

## 4. Projector pipeline

1. 校验ProjectionRequest/RouteDecision v2/route key测试向量。
2. 读取tenant/space/Profile/grant/canonical快照；拒绝disabled/unknown/expired/revoked。
   tenant=`pilot` 时在生成任何 staging artifact 前验证第一次 `profile_workflow`
   admission；tenant=`active` 跳过。
3. 对每space计算projection_key；获取tenant+space+report细粒度lock。
4. 若同key已完整提交则幂等返回。
5. 在staging生成summary/topic/entity/search docs与manifest；每artifact hash。
6. 提交前二次ACL/Profile/space/route recheck；`pilot` 再取 fresh admission，拒绝
   revision 回退、policy/hash/snapshot 漂移或 deny/unavailable/expiry。
7. 原子发布projection、membership、index segment，再切current pointers。
8. 写receipt并通知JobProvider；失败不切pointer。

跨space不共享可变artifact，但都引用同canonical SHA；不得把一个space目录硬链接/软链接到另一个tenant或shared raw。

PilotAdmission 第二次失败必须删除/隔离 staging 并保持全部 current pointers 不变；不能
先提交 membership 再发现投影未获准。Null provider 只对 `pilot` 形成稳定 unavailable。

## 5. Index与entity适配

- 每space独立compact index，key含tenant/space/profile/index version；不扫描shared raw。
- Search doc只保存可检索派生和report/canonical refs；publish前按membership active集合构建。
- Entity catalog factory显式接收tenant/space/Profile policy；legacy调用仍保持现状，多租户调用禁止fallback全局registry。
- Index manifest logical hash按sorted normalized docs JCS计算，排除mtime/absolute path。

## 6. Cleanup state machine

```text
received → logical_hidden → artifacts_removed → indexes_rebuilt
         → receipt_committed → outbox_acked
```

- 一收到revoke即从current pointer/next search generation排除，物理删除异步。
- 每阶段幂等并以cleanup key CAS；crash从最后durable阶段继续。
- outbox每个consumer分别receipt/ack；不得在任一artifact仍可检索时提前ack。
- route/profile/disable cleanup使用同一engine但不ack Ledger outbox；保留各自trigger receipt。

## 7. Rebuild

Rebuilder创建全新generation，不就地修改current index：枚举SpaceRegistry active records + RT-020 current routes，交叉active grants，逐个RT-014 read/verify，生成membership/projections/index。全部完成且second snapshot一致后原子切generation pointer；旧generation随后按保留策略清理。

同权威输入+generator version的logical hashes必须相同。任何snapshot变化重试新generation，不把混合版本发布。

## 7.1 `ProfileSpaceSnapshotProviderV1` 生产 adapter

RT-022 已冻结注入式 ABI `ProfileSpaceSnapshotProviderV1.snapshot(agent_snapshot)`
与 `cwk.profile_space_snapshot.v1` schema，**RT-022 是唯一 owner**。RT-021 交付其
生产 adapter（`cwk_space_snapshot_adapter.py`），按位复用同一 Protocol 与 schema 文件，
禁止 fork、扩展、收窄或以同名 schema 重定义；字段变更必须回到 RT-022 发新版本。

adapter 语义：

- 只接受可信 `AgentContextSnapshot`；不接受裸 `tenant_id=`、slug、instance root
  或 credential。
- 单次调用内一致读取：先取 RT-019 active Profile pointer 得到 `profile_sha256` /
  `profile_version`，再从 SpaceRegistry 取该 Profile 声明的 active space records，
  拼出 `default_space_ids` / `queryable_space_ids`（稳定排序、唯一、各自 ≤32，
  且 `default ⊆ queryable`），最后逐 space 取 membership 版本与 `current-index.json`
  的 index version，键集合精确等于 `queryable_space_ids`。
- 读取过程中 Profile pointer 或 space 状态发生变化则重读；无法得到一致快照即
  抛出稳定错误，由 Broker 映射为 `access_denied`。
- **0 space 不是特例**：Profile active 但无可查询 space 时仍返回非空
  `profile_sha256` 与空的 `default_space_ids`/`queryable_space_ids`。
- 返回值只含 opaque ID/版本/hash，deep-forbidden 拒绝 slug、标题、正文、绝对路径、
  tenant root、credential、Agent ID 与其他 tenant 标识。
- adapter 是纯只读，不创建/修改 space、membership、index 或 Profile。

## 8. RT-018 Provider

`ProjectorJobProviderV1`的JobSpec只含projection/cleanup/rebuild request opaque ref，不含raw/credential/path。RT-021测试显式注入Registry；RT-026 composition root决定未来pilot注册。RT-021不能修改Scheduler ABI、nightly或cron。

## 9. 安全与测试

- Actor/slug/space semantic tests，schema deep-forbidden no nesting。
- A/B同canonical、多space、ACL/Profile/space race、index corruption、disk/crash/CAS。
- revoke/route/rollback/disable全cleanup矩阵和early-ack负向测试。
- no raw copy扫描：artifact内容、inode/link、路径、secret、URL、body-size/signature检查。
- RT-007/008/010/Wiki回归与完整unittest。

## 10. 回滚

Projector/Index可删除current派生后从route log重建；SpaceRegistry、Profile、route、grant、canonical与cleanup receipts不删除。停止provider注册即停新作业；legacy entity/search路径保持。若回滚到旧generation，必须先验证其对应Profile/grant仍有效，否则保持查询关闭。
