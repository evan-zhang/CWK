## 3. 原子写六步顺序（不得重排）

`cwk_atomic_file.write_atomic(parent_fd, name, data)`：

1. `os.open(temp_name, O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW|O_CLOEXEC, 0o600, dir_fd=parent_fd)`；
2. 循环 `os.write` 直到全部写完（EINTR/short-write 都处理）；
3. `os.fchmod(fd, 0o600)`（umask 硬化）+ `_fsync_fd(fd)`（macOS 用 `F_FULLFSYNC`，其他平台 `os.fsync`）；
4. `os.rename(temp_name, name, src_dir_fd=parent_fd, dst_dir_fd=parent_fd)`；
5. `_fsync_fd(parent_fd)`；
6. 返回 `AtomicWriteReceipt(name, sha256, size)`。

任一步失败：`unlink_at(parent_fd, temp_name, missing_ok=True)` 后 re-raise。
`exclusive=True` 时在步骤 1 前 lstat 已存在直接拒 `AtomicFileError code=exists`。

## 4. CAS

```
current_bytes = read_file(parent_fd, name)
current_sha = sha256(current_bytes)
if current_sha != expected_previous_sha256:
    raise RevisionConflict
write_atomic(parent_fd, name, new_bytes)
```

Registry 层在整个 CAS 周期持有 `exclusive_lock(parent_fd, ".<tenant_id>.lock", blocking=True)`，
锁文件与租户记录同目录，进程死亡时 kernel 自动释放。

## 5. 状态机与操作矩阵

```
draft            → profile_pending
profile_pending  → pilot | suspended | offboarded
pilot            → active | suspended | offboarded
active           → suspended | offboarded
suspended        → profile_pending | pilot | active | offboarded  (需新 receipt/verifier)
offboarded       → (terminal)
```

`assert_valid_transition(from,to)` 是纯策略函数；RT-012 不暴露任意状态跃迁 API，
只有 `init_tenant` 会写 `draft`。RT-026 才允许 enable/disable/release（新 provider 模块）。
`suspended` 恢复时调用者必须提供 verifier 数据（RT-013+ 决定接口）；RT-012 拒绝无 verifier
的调用（`VerifierRequired` 保留类）。

操作权限矩阵（`TENANT_OPERATION_MATRIX`）：

- `draft` : {admin_configure}
- `profile_pending` : + credential_resolve, sampling_collect_bounded, profile_ai, profile_confirm
- `pilot` : + collector_run, scheduler_run, query_broker
- `active` : + 与 pilot 相同
- `suspended` : {admin_configure}
- `offboarded` : ∅

## 6. Provision 事务

`init_tenant`：

1. 生成 opaque `tenant_id` + `txn_id`；
2. `exclusive_lock(reg_tenants_fd, ".<tid>.lock")`；
3. 若记录已存在 → `TenantExists`；
4. 写 `provision-journal/<tid>.<txn>.journal`（含 action/actor/reason/started_at/frozen_children）；
5. `TenantLayout.initialize()` 创建 15 子目录；
6. 构造 record + receipt；receipt 的 `receipt_sha256` = canonical sha 去掉自身字段后重算，
   record 的 `provisioning.last_receipt_sha256` 引用该值；两者互相锁定；
7. `write_atomic(reg_tenants_fd, "<tid>.json", record_bytes, exclusive=True)`；
8. `write_atomic(rcpt_fd, "<tid>.<txn>.receipt", receipt_bytes, exclusive=True)`；
9. `unlink_at(jfd, "<tid>.<txn>.journal", missing_ok=True)`；
10. 写只读投影 `config/tenant.projection.json`。

崩溃恢复：`recover()` 遍历 `provision-journal/`：

- 有匹配 receipt → 事务已完成，只需 unlink journal；
- 无匹配 receipt 且 record 已存在 → journal 是旧残留（step 9 崩溃），unlink journal；
- 无匹配 receipt 且 record 不存在：仅当整个 tenant 树全部是**空**冻结子目录时才回滚，
  否则保留（说明 RT-013+ 已写入业务数据）；
- 各目录 orphan `.cwk-tmp-*` 一并清理。

## 7. Dispatcher 加载策略

- `_TRUSTED_SCRIPTS_DIR = Path(__file__).resolve().parent` — 绝不使用 `os.getcwd()`；
- `_load_provider(name)`：
  1. `name` 匹配 `^[a-z][a-z0-9_]{0,63}$`；
  2. `<TRUSTED>/scripts/<name>.py` 必须存在且不是 symlink；
  3. `importlib.util.spec_from_file_location` 精确文件加载；不走 `sys.path`；
  4. import 抛异常 → `_ProviderLoadError`（fail closed）；
  5. 校验 `API_VERSION == "v1"`、`PROVIDER_NAME`/`PROVIDER_VERSION` 匹配正则、
     `list_commands()` 返回 `Sequence[CommandSpec]`；
  6. 命令名冲突 → 立即失败。
- 已损坏 provider slot 不影响其他 provider — 但 RT-012 目前只有一个 core provider；
  RT-013+ 加入 provider 时也要通过完全相同的 gate。
- 环境变量白名单：只把 `CWK_INSTANCE_ROOT` 放入 `CommandContext.env`；其他环境不传递。

## 8. Doctor 输出

`cwk.rt012.layout_doctor_report.v1`：`checks[]` 每项 `{name, severity, status, detail}`。
零 issue → exit 0；至少一 issue → exit 2（`EXIT_CONTRACT`）。
Doctor **仅**：

- 校验 root 存在 / 非 symlink / 权限；
- 顶层 children 缺失 / symlink / non-dir / mode；
- registry ↔ tenant 树一致性（record 存在但 tree 缺失，或反之）；
- 单租户：record 校验 / 15 子目录存在 / 权限 / symlink / 投影 revision 漂移 / quota
  scheme；
- provision-journal 残留。

Doctor **不**：读 credential、读 tenant view、读 access ledger、发起 CWork
请求、执行任何 mutation。

## 10. 稳定退出码

| Code | 名字 | 含义 |
| ---- | ---- | ---- |
| 0 | `EXIT_OK` | 成功 |
| 2 | `EXIT_CONTRACT` | schema / 状态机 / 策略违反 |
| 3 | `EXIT_CONFLICT` | CAS / revision / duplicate 冲突 |
| 4 | `EXIT_USAGE` | 缺子命令 / 未知命令 / 缺参数 / 缺 env |
| 5 | `EXIT_IO` | 缺文件 / 权限 / 磁盘错 |
| 6 | `EXIT_INTERNAL` | 未预期异常（打印类名，无 traceback） |

## 11. 失败模型

- **`CWK_INSTANCE_ROOT` 缺失 / 相对 / 编码变体 / 符号链接** → `InstanceRootError` → CLI EXIT_USAGE。
- **`tenant_id` 非 opaque** → `TenantIdError` → CLI EXIT_CONTRACT。
- **CAS 冲突 / duplicate init** → `RegistryConflict` / `TenantExists` → CLI EXIT_CONFLICT。
- **schema 违规** → `SchemaError` → CLI EXIT_CONTRACT。
- **磁盘 / 缺文件** → `TenantNotFound` / `AtomicFileError` → CLI EXIT_IO。
- **未预期** → dispatcher 兜底 `EXIT_INTERNAL`，只打印异常类名，绝不打印 traceback / 绝对路径。
