## 冻结的 RT-012 契约清单

`PR/PR-001-multitenant-knowledge-spaces/contracts/rt012/schemas/`：

- `tenant_record.schema.json` — `cwk.rt012.tenant_record.v1`：`draft`/`profile_pending`/
  `pilot`/`active`/`suspended`/`offboarded`；`credential_ref` / `active_profile_version`
  只能 `null`；`auth_epoch` / `record_revision` `[1, 2^53-1]`；`quota` 结构冻结（值全 null）；
  `provisioning.last_receipt_id`/`last_receipt_sha256`；`state_history` 追加式；
  `additionalProperties:false` + `unevaluatedProperties:false`。
- `provision_receipt.schema.json` — `cwk.rt012.provision_receipt.v1`：`txn_[a-z0-9]{26}`、
  `action ∈ {tenant_init, record_revision_bump, auth_epoch_bump}`、`receipt_sha256`
  hex 64 char。
- `instance_layout.schema.json` — `cwk.rt012.instance_layout.v1`：冻结的 7 项 root child、
  15 项 tenant child、4 项 knowledge-space child。
- `layout_doctor_report.schema.json` — `cwk.rt012.layout_doctor_report.v1`：结构化 check
  条目，`severity ∈ {info, warn, error}`、`status ∈ {ok, issue}`。
- `command_spec.schema.json` — `cwk.rt012.command_spec.v1`：ABI 描述。

- RT-012 **只读** RT-011 冻结 helper：`TENANT_ID_REGEX`、`SPACE_ID_REGEX`、
  `IJSON_MAX_SAFE_INT`、`SHA256_HEX_REGEX`、`strict_json_loads` / `strict_json_load_path`、
  `canonical_json_bytes` / `canonical_sha256`、`ContractError`、
  `load_security_defaults` / `load_verified_shared_extensions_v1`、
  Draft 2020-12 subset engine（`_validate_schema` 私有函数供 registry schema 校验复用）。
- RT-012 **未修改** RT-011 的 14 张 v1 schema、`security_defaults.json`、
  `verified_shared_extensions_v1.json`、`ADR-0001`、`cwk_pr001_*` Python 文件；
  独立 fixture SHA / secret scan / `git diff --check` 保证零漂移。

## 稳定退出码

沿用 RT-011 命名但显式增加 `EXIT_CONFLICT=3`（CAS/duplicate 冲突）与
`EXIT_INTERNAL=6`（兜底），完整集合为
`{EXIT_OK=0, EXIT_CONTRACT=2, EXIT_CONFLICT=3, EXIT_USAGE=4, EXIT_IO=5, EXIT_INTERNAL=6}`。
Dispatcher 保证所有 handler 返回值必须在集合内，否则强制转 `EXIT_INTERNAL=6`。
