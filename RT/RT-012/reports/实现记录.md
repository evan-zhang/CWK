## 2. 关键设计要点

### 2.1 权威 tenant record 单一来源

`registry/tenants/<tenant_id>.json` 是**唯一**权威 record。
`config/tenant.projection.json` 只是带 `record_revision` 与 `record_sha256` 的只读投影，
没有 `credential_ref` / `auth_epoch` 之类会漂移的字段。RT-012 从不写第二个 tenant
config 文件。

### 2.2 CAS 用 on-disk sha 而非 canonical sha

`TenantRecord` 现在同时携带 `on_disk_sha256`（用于 `cas_write` 比对）与
`canonical_sha256()`（用于 receipt / 审计）。这样：

- 使用者可以直接 read → mutate → CAS，无需再手工序列化；
- receipt / 审计使用规范 JSON sha，稳定不受美化格式影响。

### 2.3 dirfd + O_NOFOLLOW 一致性

所有 `write_atomic` / `read_file` / `mkdir_at` / `unlink_at` / `child_exists` 都要求
`parent_fd`；`InstanceLayout` / `TenantLayout` 不返回路径字符串，只暴露 dirfd context
manager。这样 caller 无法绕过 containment 校验。

### 2.4 rollback 严格边界

`recover()._rollback_uncommitted_tenant_tree` 只在：

1. 存在匹配 `txn` 的 journal；
2. 无匹配的 commit receipt；
3. 无 tenant record；
4. tenant 树只包含冻结的 15 个子目录且每个子目录都是空的；

才 rmdir。任一条件不满足即保留。任何 recursive glob / `rm -rf INSTANCE_ROOT` 都不
允许，即使人工调用也会因 `_validate_leaf` 而拒。

### 2.5 dispatcher provider 加载

只从 `<repo>/scripts/<name>.py`（`Path(__file__).resolve().parent`）绝对路径读取；
恶意 CWD + PYTHONPATH（`test_rt012_cli.ProviderFailClosedTests.test_malicious_cwd_provider_ignored`
证实）不会污染 dispatcher。broken/incomplete provider fail closed（EXIT_USAGE），不
partial load。

### 2.6 状态跃迁 API 缺席

RT-012 **不暴露**任意 `transition_to(state)`。生产状态跃迁属 RT-013（binding）/ RT-019
（profile）/ RT-026（release）。RT-012 只提供 `init_tenant`（写 `draft`）与两个 CAS bump。
`assert_valid_transition` 是纯策略函数，任何调用者都可以查询“这条边是否合法”，但
本 RT 不提供把它作为副作用调用的入口。

- 读入 RT-011 helper 时未修改任何私有状态（`_CUSTOM_HANDLERS` 未 pop / append）；
- 复用 `_validate_schema` 私有引擎校验 RT-012 自有 schema（tenant_record /
  provision_receipt）；这是唯一使用 RT-011 私有 API 的地方，属可控依赖；
- 若 RT-011 之后 bump `_validate_schema` 参数，RT-012 会在 unit test 立即失败。
