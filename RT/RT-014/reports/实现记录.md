# RT-014 实现记录

## 交付边界

- 单文件实现 `scripts/cwk_shared_evidence.py`，只公开
  `SharedEvidenceStore.{open, initialize, publish, read_version, recover}` 与
  `SharedEvidenceError`、`PublishReceipt`、`RecoveryReport`、`SHARED_CHILDREN`、
  `CATALOG_KEY_REGEX`；未新增 CLI/HTTP、未修改 tenant CLI dispatcher、未修改
  `cwk_instance.py` / `cwk_atomic_file.py` / RT-013 任何模块。
- 冻结 4 张 JSON schema 至 `PR/.../contracts/rt014/schemas/`：
  `report_version` (cwk.report_version.v1)、`catalog_head`、`publish_receipt`、
  `recovery_report`。
- 冻结 opaque `catalog_key = r_<base32(sha256(domain-sep + report_key.utf8)[:16])>`；
  `report_id` / `source_namespace` 从不出现在文件系统路径上。
- 冻结 8 项稳定错误 code：`contract / not_initialized / not_found / sha_mismatch /
  canonical_drift / catalog_conflict / corrupt_catalog / orphan_object /
  report_key_mismatch`（共 9 个；`SharedEvidenceError._CODES` 为唯一枚举）。

## 发布顺序（严格不可重排）

1. RT-011 `validate_canonical_envelope`（含 30+ forbidden 深扫 + canonical_sha256
   recompute）；
2. `compose_report_key` + `_catalog_key`；`canonical_json_bytes` 序列化；
3. 打开 `shared/` 与 `locks/` 目录 FD，取 per-report `_flock_with_retry`
   （包装 `exclusive_lock`；对 macOS `O_CREAT|O_NOFOLLOW` 高并发下 spurious ENOENT
   做小范围重试，语义仍与阻塞 flock 等价）；
4. `_read_head` + `_read_entries` 严格校验 head schema、head 字节 JCS 往返、
   jsonl entry_count 一致性、jsonl 每行 JCS 往返；
5. 若同 `canonical_sha256` 已在 catalog：`_reverify_object_on_disk` 复核 SHA/schema
   后返回 `is_new_version=False`；
6. 否则 `new_object_id` → mkdir shard → `write_atomic(exclusive=True)` 发布对象文件；
7. `cas_write(catalog.jsonl)`（全文件重写）+ `cas_write(catalog.head)`；两者均带
   `expected_previous_sha256`。

## 读取顺序（严格不可重排）

`_read_head` → `_read_entries` → `head.catalog_jsonl_sha256 vs jsonl 字节 sha`
一致 → 找到目标 entry → entry.report_key 一致 → 打开对象文件 →
`sha256(bytes) == entry.object_bytes_sha256` → strict JSON parse →
`validate_canonical_envelope` → `canonical_json_bytes(payload) == raw` →
`payload.canonical_sha256 == 请求 sha` →
`compose_report_key(payload.namespace, payload.report_id) == 请求 report_key` →
返回 dict。

## 恢复行为

`recover()` 只清理 `.cwk-tmp-*` 孤儿并对现有 catalog↔object 做只读一致性检查；
永不删除或改写对象/ catalog；对孤儿对象、缺失对象、SHA 不符、corrupt catalog
以结构化 `RecoveryReport` 返回，字段完全 opaque。

## 已知边界与后续 RT 接口

- 对上层的接口是 `SharedEvidenceStore` 的 5 个方法与 3 个 dataclass；后续
  RT-015 / RT-016 / RT-017 应严格通过这套接口写入证据，不得绕过。
- `recover()` 只报告问题，不做任何删除；orphan / missing / sha_mismatch /
  corrupt_catalog 情况的 GC 或人工处置属于 RT-024 / RT-025 的运维面。
- 本 RT 从未接触 audit 目录；审计写入统一由 RT-024 完成。
- `catalog_key` 依赖 domain-separated SHA-256；任何未来的迁移必须新增 schema
  版本，绝不能在 v1 语义下修改 domain 分隔符。
