## 冻结的 RT-014 契约清单

`PR/PR-001-multitenant-knowledge-spaces/contracts/rt014/schemas/`：

- `report_version.schema.json` — `cwk.report_version.v1`：DESIGN §6.2 的 catalog entry 结构。
  必填 `schema/report_key/canonical_sha256/object_id/first_seen_at/source_updated_at/normalizer_version`；
  `report_key` 严格匹配 `SOURCE_NAMESPACE_REGEX + ":" + REPORT_ID_REGEX`；`object_id` `OBJECT_ID_REGEX`；
  `canonical_sha256` hex 64；`additionalProperties:false` + `unevaluatedProperties:false`；
  顶层 forbiddenProperties 覆盖 `tenant_id/agent_id/credential_ref/lane/read_status/reply/node/
  attachment/temporary_url/path/mirror_root/auth_epoch/binding_epoch` 等泄漏字段。
- `catalog_head.schema.json` — `cwk.rt014.catalog_head.v1`：单文件 head 指针。字段：
  `schema/catalog_key/report_key/entry_count/latest_object_id/latest_canonical_sha256/
  catalog_jsonl_sha256/head_revision/created_at/updated_at`；`catalog_key` 匹配 `^r_[a-z2-7]{26}$`；
  `entry_count >= 1`；`head_revision >= 1`；`additionalProperties:false` + `unevaluatedProperties:false`。
- `publish_receipt.schema.json` — `cwk.rt014.publish_receipt.v1`：`report_key/canonical_sha256/
  object_id/catalog_key/is_new_version/is_new_report/catalog_revision/catalog_head_sha256`。
- `recovery_report.schema.json` — `cwk.rt014.recovery_report.v1`：`schema/staging_orphans_removed
  /catalog_dirs_scanned/objects_verified/catalog_issues`；`catalog_issues[].code ∈
  {orphan_object, missing_object, sha_mismatch, corrupt_catalog}`；只报告 opaque
  `catalog_key/object_id`。

## 与 RT-011 / RT-012 契约的关系

- RT-014 **只读** RT-011 的公开导出：
  - Byte 契约：`canonical_json_bytes`、`canonical_sha256`、`new_object_id`、`OBJECT_ID_REGEX`、
    `SHA256_HEX_REGEX`、`SOURCE_NAMESPACE_REGEX`、`REPORT_ID_REGEX`、`compose_report_key`、
    `parse_report_key`、`nfc_normalize`、`strict_json_loads`、`strict_json_load_path`。
  - Schema 校验：`validate_canonical_envelope`（含深扫）；本 RT 不重复实现深扫逻辑。
  - Draft 2020-12 subset engine（`_validate_schema`）供本 RT catalog head / entry /
    receipt / recovery 4 张 schema 使用。
  - 错误类：`ContractError`（被包装为 `SharedEvidenceError(code="contract")`）。
- RT-014 **只调用** RT-012 的公开原子/dirfd API：`cwk_atomic_file` 的 `open_dir_nofollow`、
  `mkdir_at`、`write_atomic`、`cas_write`、`read_file`、`exclusive_lock`、`recover_orphans`、
  `child_exists`、`unlink_at`、`fsync_dir`、`FILE_MODE`、`DIRECTORY_MODE`；
  `cwk_instance.InstanceLayout.child_fd("shared")` 与 `TENANT_ID_REGEX/SPACE_ID_REGEX/
  validate_tenant_id`（本 RT 不使用 tenant/space；仅确认继承 RT-012 目录）。
- RT-014 **未修改** RT-011 / RT-012 / RT-013 任何文件；`git diff --check` 干净；不接触
  `cwk_tenant_cli.py` dispatcher，也不接触 RT-013 binding/credential 模块。

## 稳定错误 taxonomy

`SharedEvidenceError.code` 取值集合：

| code | 语义 |
| --- | --- |
| `contract` | envelope / catalog / head schema 校验失败，或字节非 JCS |
| `not_initialized` | shared/ 下 RT-014 子目录尚未创建 |
| `not_found` | 请求的 `(report_key, sha)` 在 catalog 内不存在 |
| `sha_mismatch` | 对象文件字节 SHA 与声明不符 |
| `canonical_drift` | JCS 往返后字节不等于对象文件内容 |
| `catalog_conflict` | CAS 冲突：catalog.head / jsonl 上次快照失效 |
| `corrupt_catalog` | head 与 jsonl SHA 不匹配，或 head 引用 entry_count 与 jsonl 行数不匹配 |
| `orphan_object` | catalog 引用的 object_id 在 objects/ 中找不到（只在 read 或 recover 报告） |
| `report_key_mismatch` | 对象 body 内 `source_namespace + report_id` 与请求 report_key 不符 |

## 非目标

- 不实现 tenant runtime、registry、credential broker、collector、scheduler、profile、
  router、projector、query broker；
- 不联网、不读 `CWORK_APP_KEY`、不修改现有 nightly/生产 cron；
- 不新增 CLI/HTTP；不修改 `cwk_tenant_cli.py` dispatcher；
- 不修改 `.serena/`、`.spec-workflow/`；
- 不写审计事件；不写 tenant 目录；不接触 `objects/` 已发布对象的删改；
- 不在 RT-014 内 “自我验收”；独立验收由后续 Opus Agent 完成，本 RT 只标 implementation_done。

6. **对象/catalog/SHA 篡改被 reader 拒绝**：`test_rt014_attacks.CorruptionTests.*`。
7. **symlink/hardlink/TOCTOU/staging prefill**：`test_rt014_attacks.SymlinkAttackTests` /
   `HardlinkAttackTests` / `StagingPrefillTests`。

10. **RT-011/012/013 全量回归 + 全 tests 通过**。
