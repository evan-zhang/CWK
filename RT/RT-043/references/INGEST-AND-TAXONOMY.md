## 一、用户到底提供什么（修订：砍掉用户名）

### 提供清单（v1 定稿）

1. **工作协同个人 Key**（一个值）——身份从 Key 自动派生
   （调 whoami 类接口拿姓名/工号，建库时写入 kb_members，用户不用自己填）
2. **回灌窗口偏好**（默认近 3 个月，可不填=用默认）

用户名不再单独提供：个人 Key 就是身份凭证，人从 Key 派生。
将来「一人多库/一库多人」时，成员身份同样从各自 Key 派生。

### 用户拿到什么（修订：两值实际是一值）

- **token**：唯一的用户特定值（平台发放）
- **OPS 地址**：预先约定的常量，写死在 Skill 安装说明里（公司系统地址性质，
  不随用户变化；变了=平台迁移，发公告，不属于用户配置）

Skill 安装 = 填 1 个 token + 1 个写死的常量。

## 二、回灌窗口/过滤器：支持什么形式

### 分层原则（关键澄清）

```
过滤器决定「收不收」（ingest 层，粗）
分类体系决定「怎么组织」（wiki 层，细）
```

「同样 100 篇汇报不同人关注点不同」**不靠少收**解决——靠分类层。
raw 宁全勿缺（资产+账本基础）；主动收窄才用过滤器。

### 过滤器形态：过滤器列表，v1 只启用两个维度

```json
// _system/source.json
{
  "source": "cwork",
  "key_ref": "CWORK_APP_KEY_<KB>",
  "filters": [
    { "type": "time_window", "start": "auto-3m" },
    { "type": "direction", "lanes": ["inbox", "outbox"] }
  ]
}
```

- **时间窗**（v1 启用）：API 原生支持，秒级窗口分页
- **方向**（v1 启用）：收件箱 / 发件箱 / 两者
- **预留维度**（架构支持、v1 不启用）：关键词、发件人、收件人、项目标签、
  相关性阈值——这些 API 不支持服务端过滤，实现为「拉回后本地判定入不入 raw」
- 过滤器只影响之后采集，不回溯删 raw（raw 只增不改红线不变）

## 三、AI 知识库核心原理：五层模型（回应「当时参考的理论要做的东西」）

### 已建成部分（公司库实物证据）

| 层 | 内容 | 状态 |
|---|---|---|
| L1 raw | 原始资产，按月分区，只增不改 | ✅ 生产 |
| L2 summaries | 每篇汇报 AI 精编页（结构化、带 frontmatter） | ✅ 1547 页（wiki 全层合计 4034：精编+实体+主题+索引，口径实测 2026-09-04） |
| L3 实体层 | entity-catalog：6119 实体族（人/项目/产品/系统/组织），每族带证据引用与合并登记 | ✅ 生产 |
| L4 主题层 | topics：跨篇主题聚类页 | ✅ 生产 |
| L5 分类层 | 每库自定义 taxonomy + categories 索引页 | ⬜ 本设计补上 |

L3/L4 就是当时按 AI 知识库理论做的「知识图谱式组织」——实体抽取、消歧合并
（family registry）、证据锚定（entity anchors）、主题聚合。个人库将按库重建
（范围=该库语料，不与公司库混）。

### 本设计新增：L5 分类层（每库一份 taxonomy）

```json
// _system/taxonomy.json
{
  "version": 1,
  "dimensions": [
    { "name": "内容类型", "values": ["汇报", "会议纪要", "审批", "公告", "讨论"] },
    { "name": "项目", "values": [], "dynamic": true },
    { "name": "自定义", "values": [], "dynamic": true }
  ],
  "focus_note": "可选：库主人的关注点，注入精编视角"
}
```

- 维度分静态（人工定取值）/动态（从内容自动枚举，如项目名——直接复用 L3 实体层
  的 project 族，不是新发明）
- `focus_note` 可选，如「重点关注项目风险与跨部门依赖」→ 注入精编 prompt

### 「同料不同库」的差异如何体现（全部在 wiki 层，存储零改动）

```
raw      相同（同源同窗）
实体层   范围不同（各自库的语料）
taxonomy 维度不同（张三偏项目进度，李四偏风险审批）
focus    精编视角不同
索引页   按各自 taxonomy 组织 categories/
```

### 生成与演化

```
建库 → 默认 taxonomy（内容类型 + 动态项目维度）
初灌 → 精编建 summaries + 实体层 + topics
     → AI 扫描全量内容提议修订 taxonomy → 库主人确认 → version+1
每篇精编 → 按 taxonomy 打标签（frontmatter）→ 生成/更新 categories/ 索引页
改 taxonomy → raw 不动不重灌 → 全量重打标签（v1）；增量（v2）
```

### 验收判据（判据纪律版）

- 抽任意 wiki 页，其分类标签必能在 taxonomy.json 找到取值
  （防「标签凭空」：坏情形=页面带 taxonomy 外标签而全绿——判据须能红）
- categories/ 索引页每条引用必落到真实存在的页面
  （防「索引空转」）
- 实体族引用的证据引用必能落到真实 raw 文件
  （防「实体幻觉」，复用现有 registry 机制）
