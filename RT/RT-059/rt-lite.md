# RT-Lite: RT-059 - 知识库服务官网 v1（产品站 + 站内控制台入口）

> profile: Spec-Lite | execution_mode: collaborative

## 方案（给人看）

- 做什么：把 RT-058 那个单页门户升级成一个像样的产品官网——讲清楚这个服务是什么、
  现在有哪几个库、能做什么、怎么接入、常见问题，并在站内保留控制台入口
  （点开跳到控制台，输 `12345678` 解锁）。
- 为什么：现在的门户只有一屏——三张库卡片、三步接入、一个按钮。它能证明"通了"，
  但拿给同事看不足以让人明白这东西是干什么的、值不值得接。
- 代价：官网要显示真实数字，就得有一个数据来源；见下面"实况数字"一节的取舍。
- 这次故意不做什么：不做真实建库、摄取、用户管理和授权签发（那是后面的阶段）；
  不做公网暴露；不引入前端框架或构建步骤，仍是零依赖的服务端渲染 + 原生 JS。
- 用户怎样算成功：从局域网打开官网，不看技术细节也能说清楚"这是什么、我要不要接";
  页面上的三个库数字与控制台里一致；点控制台入口能进去并用 `12345678` 解锁；
  官网进程仍然零数据访问（那条负向判据仍然红得起来）。
- 建议：定论——控制台保持独立进程，站内入口是链接而不是内嵌。理由见"控制台入口"。

## 站点结构

单页长滚动，锚点导航，五个板块：

1. **概览**：一句话讲清楚它是什么 + 三个库的实况文档数 + 四个服务的健康状态。
2. **能力**：检索 / AI 问答 / 原文核验三张卡，每张写清楚"能做什么"和"边界在哪"
   （例如：语料是快照不是实时；零命中会体面拒答而不是编）。
3. **接入指南**：三步 + 401/403 的语义 + 令牌纪律（不进命令行、不进日志、不进聊天）。
4. **常见问题**：为什么查不到、`no_answer` 意味着什么、为什么会 403、快照多久更新一次。
5. **管理员入口**：控制台链接 + 一句话说明需要密码。

## 不显示任何库内数据（2026-09-16 修正）

初版方案打算在官网上显示三个库的实况文档数，并为此在控制台加一个公开摘要端点。
用户当场纠正：官网是**产品介绍页**，给还没用过的人看功能和用法，不是数据看板，
不显示真实库里的东西。

于是公开端点不做了，门户保持纯静态。好处是隔离这件事不需要额外判据去守——
它本来就什么都不读。判据改为反向断言：页面上不出现统计字段、不出现任何取数调用
（`fetch(`、`XMLHttpRequest`、`/api/*`、管理密钥头），库卡片的文字必须**恰好**等于
配置里的名字和说明，多一个字都说明有人往上加了东西。

## 控制台入口：为什么是链接不是内嵌

两种做法：

- **A（采纳）**：官网与控制台仍是两个进程，站内入口是一个链接，点开跳到控制台输密码。
- B：合成一个地址，控制台成为官网里的一个区域。

B 换来的只是少一个端口号，代价是官网进程必须持有登记表和审计路径——
"公开面零数据访问"这条唯一的结构性保证就没了。不值得。

## 假设与现状

- 关键假设：公开摘要端点暴露"有哪几个库、各有多少文档"在局域网内是可接受的；
  这与门户本来就列出三个库名的现状同级，不引入新的信息类别。
- 现状依据：`scripts/kb_portal.py` 的 `PortalApp.page()`；`scripts/kb_admin.py` 的
  `_snapshot_libraries()` / `_services()`；`tests/test_rt058_kb_console.py` 的
  `PortalIsolationTests`（隔离判据）。

## 实现备注

- 改 `scripts/kb_portal.py`（页面重写、取数走浏览器）与 `scripts/kb_admin.py`
  （新增公开摘要端点）；判据加在 `tests/test_rt058_kb_console.py` 同族的新文件里。
- 不能破坏的约定：门户不导入任何数据模块；公开端点不返回令牌/审计/路径；
  控制台默认关闭与写动词占位不变；8787/8790 不受影响。
- 内部阶段：公开端点 + 判据 → 官网页面 → 本机真实浏览器点一遍 → 部署 OPS → 局域网复验。

## 遗留事项

- 公开摘要端点是新的免鉴权面；虽然只吐库名和计数，仍应纳入审计与速率考虑。
- 官网仍无"快照更新时间"可显示——索引里没有生成时间戳，需要摄取侧补元数据。
- 控制台的单一共享密钥、无每人身份、无失败锁定问题不在本 RT 范围，随用户管理那段解决。
