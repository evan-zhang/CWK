# RT-059 复盘

## 目标达成了吗

达成。官网跑在 OPS 上、局域网可达（`http://192.168.91.72:8792/`），站内有控制台入口。
它既是招揽页也是完整接入手册：五步、可复制命令、期望输出、登记模板、错误语义都在页面上。
后续又按要求补了部署拓扑图、请求链路时序图和数据来源说明。

## 做对了什么

- **范围被纠正时立刻改，并把纠正写进记录**。初版方案要在官网显示实况文档数，
  用户指出这是产品介绍页不是数据看板。公开摘要端点因此没做——少写的这部分代码，
  比写出来再删更值钱。
- **承接能力如实写**。摄取管道只注册了两个适配器，「用户自己上传的文件」没有通道，
  页面标为「尚未开通」。并加了一条判据直接读 `kb_ingest.ADAPTERS`：将来加了适配器
  而官网没跟上，测试会红——文档与代码的同步交给判据，不靠记性。
- **图在真实浏览器里看过才算完**。两处错都是肉眼抓到的：一根竖箭头等于宣称
  「令牌登记表喂给本机模型」，圈码在 12px 下糊成一个点。这两样静态检查都发现不了。
- 复制按钮走 `execCommand`：站点是普通 HTTP 不是安全上下文，新剪贴板 API 在这里不存在。
  这类"只有在真实部署形态下才暴露"的问题，本机 https 预览是测不出来的。

## 踩到什么

- RT 记录被改了范围之后一度自相矛盾：四个小节还留着"实况数字 + 公开端点"的旧表述。
  记录自相矛盾比记录过时更糟——后来的人会照着一个从未实施的方案去理解代码。
  已全篇对齐。
- 判据写糙过两次，都是我自己的锅：禁止字符串写得太宽（`2027` 撞上库名、
  `took_ms` 撞上手册必须讲的返回字段），以及注释里出现了被禁的 API 名字。
  判据要表达的是意图，不是字面黑名单。

## 留给下一次

- 首页承载了太多技术细节。小白看着累，想深入的人又找不到系统的地方——
  RT-060 把深度内容搬进文档中心，首页只留产品介绍。
- 页面五步与 `docs/cwk-kb-access-setup.md` 是同一套流程的两份表述，改一处要同步另一处。
