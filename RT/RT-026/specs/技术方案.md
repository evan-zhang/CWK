# RT-026 技术方案：试点准备、影子切换与回滚工具

## 1. 模块

- `cwk_release_switch.py`：版本化 switch、CAS transition、G7 gate、rollback，
  以及 neutral `PilotAdmissionProviderV1` 的唯一 production adapter/factory。
- `cwk_shadow_query_diff.py`：双读 runner、规范化、六层 diff、报告聚合。
- `cwk_go_no_go.py`：只读 receipt/policy verifier、hard-gate evaluator。
- `cwk_tenant_cmd_release.py`：受 RT-012 provider ABI 约束的 release CLI。
- `install.sh`：installer 的权威 owner 实现路径；只做默认关闭的兼容入口。
- `scripts/cwk_doctor.py`：doctor 的权威 owner 实现路径；只做本地检查与报告。
- `scripts/cwk_go_no_go_launcher.py`：trusted GO/NO-GO launcher 的权威 owner 实现路径
  （计划新增）；负责 OS-control evidence，不承担只读 evaluator 的门禁判定职责。
- legacy/nightly adapter：只做默认关闭的兼容入口，RT-026 独占。
- `contracts/rt026/schemas/`：switch/transition/diff/policy/go-no-go/rollback。

## 2. Switch 与状态机

switch 使用 CAS + append audit，字段包含 version/revision、mode、read_path、
component flags、allowlist hash、receipt refs、updated-at。读取异常返回内存安全
默认，不尝试修复为 enabled。

```text
off --(verified shadow prerequisites)--> shadow
shadow --(external G7 + all gates + allowlist)--> pilot
shadow|pilot --(rollback/error/expired receipt)--> off
```

production mode verifier拒绝 test signer/test fixture。`pilot` transition API 即使
被直接 import，也必须复核 G7；CLI 不是唯一安全门。

### 2.1 Production PilotAdmission adapter

RT-026 只零漂移实现 Wave-0 冻结的 neutral Protocol：provider 构造时固定
`purpose=collector_run|profile_workflow|query_broker`，公开方法仍只是
`snapshot(*, agent_snapshot)`。`ReleasePilotAdmissionProviderV1` 从当前 switch
revision、仓库外 trust store 验真的 G7、target environment/instance、component
flag 与 tenant allowlist 构造严格九字段快照，TTL 不超过 300 秒，按
`cwk-pilot-admission-snapshot-v1\0` 域分隔 JCS 重算。revision 使用持久 CAS
high-water，回退、重放或 policy/hash 漂移均拒绝。

factory 的安全默认是 Null/拒绝：off/shadow、缺失或损坏配置、过期/撤销/
错 target G7、未启用的 component 或 allowlist miss 都不产生 admitted snapshot。
测试 composition root 可注入隔离 synthetic G7 fixture 验证状态机，但 production
factory 从类型、signer 和 trust-root 三处拒绝该 fixture。adapter 不写 G7，不读
credential 真值/租户正文，也不参与 go/no-go 的 G1～G5 封闭输入聚合；
因此不引入 RT-026 → G6/G7 → RT-026 的环。

## 3. Shadow 双读

- legacy 先产生用户实际响应；new query 在隔离只读链执行，结果不回写用户。
- manifest 绑定 query corpus hash、crosswalk、legacy/new build/index/profile/
  auth snapshot 和时间窗口。
- 完整 query 不写报告；以 request ID/hash 关联受控 fixture。
- timeout/error 分开记录，不把未运行视作 match。

## 4. Diff 算法

1. 验证 RT-016 crosswalk source/canonical SHA并转换 stable report keys。
2. 规范化 decision、candidate set、hits、evidence tuples 和 refusal safety class。
3. 先判 exact；再按四个 allowlist predicate 顺序分类，每个 predicate 返回
  machine-readable evidence；否则 `blocking_unclassified`。
4. `reviewed_security_tightening` 必须验证 ledger snapshot + 独立 receipt；仅
  status label 不够。
5. aggregate 任何 blocker 即 report FAIL；不允许百分比阈值掩盖一条泄漏/SHA。

## 5. Go/No-Go evaluator

evaluator 输入只接受 schema-valid receipts/policy，不从 Markdown 文本推断 PASS。
验证 signer、target、audience、commit/build、expiry、evidence SHA 与 dependency
DAG。规则分：hard booleans（任一 false=NO_GO）与 measured thresholds（从已签
policy 加载）。报告逐项列 proof ref，不可由 `--force` 改写。

输出 `READY_FOR_G7_REVIEW` 后只生成 receipt，不写 switch、不改 tenant/cron。

evaluator 与 trusted launcher 是两个独立安全主体：evaluator 只读取封闭输入并生成
go/no-go 结论；launcher 施加评估器无权解除的 OS 写拒绝，采集 pre/post 精确清单与
真实写拒绝探针结果，并由 launcher 签发 run attestation。launcher 生成的 OS-control
evidence 供 evaluator/独立验收消费，但 launcher 本身不得代做门禁判定，evaluator 也
不得自签 launcher evidence。

## 6. CLI slot 兼容修订

- provider 实现冻结的 `API_VERSION/PROVIDER_NAME/PROVIDER_VERSION/list_commands`。
- dispatcher 兼容 commit 只把 `cwk_tenant_cmd_release` 加入固定 tuple；不得动态
  discovery、环境变量 module、CWD import 或 partial provider fallback。
- tests 对修改前后 dispatcher hash/AST 做白名单差异，除 tuple 元素外语义零
  漂移；恶意 symlink/duplicate/import error 仍 fail closed。
- 若 RT-019 profile slot 尚未按同样机制激活，doctor 报 blocker，不代为偷改。

## 7. Nightly/install compatibility

- off 模式调用路径与 legacy 基线相同；新 adapter 不读取 tenant runtime。
- shadow schedule 使用独立 fixture/config 与唯一 run ID，不修改现有 crontab。
- installer=`install.sh`、doctor=`scripts/cwk_doctor.py`；二者默认 dry-run，报告
  缺依赖/receipt/permissions，不会创建真实 secret、开启服务或重启 Gateway。
- trusted launcher=`scripts/cwk_go_no_go_launcher.py`（计划新增）。三条 owner code
  路径都必须存在于 RT-026 preflight receipt 的 `tested_subject_commit`；验证针对该
  subject 中的仓库普通文件，不接受 wrapper、别名或 evidence 路径代替。launcher 的
  仓库源路径与运行时固定 root-owned 执行路径分别记录，后者不得反向改写 owner 映射。
- 所有生产 side-effect API 在本 RT execution mode 中硬拒绝。

## 8. Rollback

`rollback()` 获取 release lock，写 rollback intent，CAS switch→off/legacy/
all-components-false/empty-runtime-allowlist，停止新 scheduler lease，写 receipt，
再清 intent。任一步 crash 后 recovery 只向 off 推进。它不删除新 evidence、
audit、backup、profile、space 或 diff。

## 9. 测试策略

- schema/state/CAS/crash recovery/default-corruption tests。
- diff property tests与每种 allowed/blocker 的双向反例；crosswalk/SHA 攻击。
- go/no-go receipt signer/expiry/build/policy/threshold/hard blocker 组合测试。
- production PilotAdmission 三 purpose、九字段/hash/TTL、revision high-water、
  default-off、G7 target/signer/revoke/expiry/replay、component flag/allowlist 与 rollback
  组合测试；正向只用隔离 synthetic G7 fixture，production factory 必须拒绝它。
- CLI AST/slot zero-drift、CWD/PYTHONPATH/symlink/duplicate provider attacks。
- full synthetic two-tenant E2E、VG-E restored E2E、legacy nightly fixture、Wiki
  smoke、full unittest、secret/production-state scan、rollback。

## 10. 风险

- legacy/new 排名实现不同：只有契约列出的 equal-key reorder 可自动接受，
  其他必须 blocker/人工决策，不扩大 allowlist。
- G7 authority 尚未存在：代码保持 production pilot transition fail closed。
- installer/nightly 高风险：限定 adapter diff，保存 off-mode 基线 receipt。

## 11. 回滚验证

在合成 shadow/pilot fixture 的每个 transition crash 点重启 recovery，均应收敛
off+legacy；复跑 legacy nightly/read smoke，确认新数据和审计仍可读但不参与响应。
