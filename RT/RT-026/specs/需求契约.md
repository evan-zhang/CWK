# RT-026 需求契约：试点准备、影子切换与回滚工具

## 1. 业务目标

把 PR-001 开发结果收敛为默认关闭、可影子核验、可判定、可一键回 legacy 的
受控试点候选包。系统的结论**上限**只有两种：`READY_FOR_G7_REVIEW`（语义严格为
"**可提交进入 G6 最终验收**"）或 `NO_GO`（另有 `INVALID` 表示输入不可验证）。
它**不能**自行部署生产，**不能跳过 G6**，也**不能**直接申请、签发或自称获得 G7 授权。

## 2. 用户角色

- release 管理员：查看状态、执行 doctor/shadow/diff/rollback/go-no-go。
- 业务/安全批准人：在 RT-026 之外签发 G7 与实测阈值 policy。
- legacy 用户：RT-026 默认行为下完全走现有 read/nightly。
- 独立验收 Agent：验证默认关闭、diff、硬 blocker、rollback 和 E2E。

## 3. 功能范围

### 必须实现

- REL-001：版本化 release switch，默认 master=false、mode=off、read=legacy、
  component flags=false、allowlist=[]；缺失/损坏配置也等价 off。
- REL-002：独立 shadow schedule/runner，不修改现有生产 cron；shadow output
  不返回给用户、不写 legacy、不提升 tenant 状态。
- REL-003：legacy/new 数据 diff 消费 RT-016 crosswalk；查询 diff 比较候选、
  hits、evidence SHA、decision/denial reason 和安全状态。
- REL-004：按 §6 只接受显式允许差异；未分类、证据变化、越权或 new 更宽松
  均为 blocker。
- REL-005：go/no-go 只消费**前置** receipt：VG-A～VG-E、G1～G5、真实 capability、
  RT-024/025 baseline、diff、回滚、回归与 secret scan；缺任一项 NO_GO。
  **精确来源**：VG receipt 取自 `contracts/gates/gate_registry_v1.json` 的
  `receipt_path`（schema `cwk.pr001.verification_gate_receipt.v1`）；
  release gate receipt 取自 `contracts/gates/release_gate_registry_v1.json` 的
  `receipt_path`，即 `release-gate-receipts/G{1..5}/receipt.json`
  （schema `cwk.pr001.release_gate_receipt.v1`），**恰好五份**。
  两个 receipt 根**互不相交**且都不得由 RT-026 创建或补写。
  **G6/G7 不是 RT-026 的输入**：G6 由新鲜独立最终验收者在 RT-026 自身独立 PASS 之后
  签发，消费 RT-026 的 go/no-go 报告作为其输入之一；G7 是 G6 之后由外部信任根与用户
  签发的**授权**（`release-gate-receipts/G7/authorization.json`），不是验证结论。
  任何要求 RT-026 预先读取或验证 G6/G7 的实现都是自依赖环，必须视为契约违规。
  `release_gate_registry_v1.json` 中 G6 与 G7 的 `direct_rt_consumers` 均为**空数组**，
  这是同一事实的机读侧证据。G7 授权文件在与不在，都必须让 RT-026 的结论保持不变。
- REL-006：实测阈值从外部批准的 versioned policy/receipt 读取；缺阈值或 signer
  不可信 NO_GO，不在代码中预填数字。
- REL-007：一键 rollback 原子关闭 master/component/schedule并恢复 legacy read；
  不删除新数据/审计/backup/diff。
- REL-008：installer/doctor 的 owner 实现路径分别冻结为仓库根相对路径
  `install.sh` 与 `scripts/cwk_doctor.py`；二者支持 dry-run 和 fixture，不部署、
  不写 production secret/config/cron。
- REL-009：`cwk_tenant_cmd_release` 经显式 RT-012 slot 兼容修订加载；provider
  ABI 与 dispatcher 安全语义零漂移。
- REL-010：合成双租户 E2E 覆盖去重、view、profile、route、multi-space、cold
  reroute、revoke、scheduler 隔离、backup/restore、query diff 和 rollback。
- REL-011：RT-026 是 neutral `PilotAdmissionProviderV1` 的**唯一 production
  adapter owner**。adapter 由 `scripts/cwk_release_switch.py` 实现，构造时绑定
  `collector_run | profile_workflow | query_broker` 之一，只从当前 release
  switch、仓库外信任根验真的 G7 authorization、target environment/instance、
  component flags 与 tenant allowlist 派生九字段短期快照。off/shadow、
  过期/撤销/错 target G7、component 关闭、tenant 不在 allowlist、坏配置或
  revision 回退全部 fail closed。adapter 不签发 G7，不读真实 credential
  值，也不改变 RT-026 go/no-go 输入仍排除 G7 的反环规则。

### 明确不做

- 真实试点、真实 key、cron 切换、Gateway restart/deploy、Cloud/DocDB 发布、GA。
- 自动接受差异、自动签发阈值/G7、删除 legacy/new 数据或审计事实。

## 6. Legacy/New 查询等价与允许差异

比较前用 RT-016 crosswalk 把 legacy ID/path 表达映射到 `report_key` 与
`canonical_sha256`；无法唯一映射直接 blocker。

必须逐层比较：

1. 请求规范化与有效时间范围；
2. 候选 report key 集；
3. 最终 hit 集与稳定排序；
4. 每个关键结论的 evidence report key + canonical SHA；
5. allow/deny/no-evidence/clarification decision；
6. 拒答 reason 的安全语义（不存在性仍不可区分）。

允许差异仅有：

- `presentation_only`：答案措辞、空白、时间/安全链接展示不同，但 decision、
  candidate/hit/evidence 完全相同。
- `crosswalk_representation`：legacy path/ID 与 new opaque key 表达不同，且 RT-016
  crosswalk 的 source/canonical SHA 均验证通过。
- `equal_sort_key_reorder`：candidate/hit 集完全相同，仅在完整规范排序 key
  **字节完全相等**的项之间顺序不同。
- `reviewed_security_tightening`：new 拒绝/过滤 legacy 曾返回的项，且 Access
  Ledger 证明该项非 active/已撤权、独立安全复核 receipt 明确接受；不能自动
  批准，也不能掩盖数据遗漏。

以下一律 blocker：new 允许 legacy 拒绝且无外部授权证据、跨 tenant 命中、
candidate/hit 无解释缺失、canonical SHA/引文事实不同、new evidence 不在 active
grant、拒答变高置信答案、排序差异不满足相等 key、任何未分类差异。

## 7. Go/No-Go 规则

### 硬性 NO_GO

- 任一 VG-A～VG-E/G1～G5 receipt 缺失、过期、错 commit/build 或 FAIL。（G6/G7 是
  RT-026 的下游，不出现在此列表；引用它们即为环依赖。）
- 任一 VG receipt 的 `receipt_path` 不存在、schema 不合法、`receipt_sha256` 重算
  不匹配、`artifacts[].sha256` 漂移、`feeder_rt_independent_pass=false` 或
  `status != pass`。
- 任一 hard gate 的 receipt `synthetic=true` / `conclusion=conservative_unknown`
  （VG-A 永久属此类），**且**其能力缺口按下面 §7.1 判定为 **OPEN**。
  此类 receipt 无论缺口是否闭合，都必须作为**显式生产 blocker / scoped evidence** 列出，
  不得被 RT-026 结论掩盖，也不得靠同名 Markdown 叙述放行。
- 任一被 closure map 要求的 activation receipt 缺失、schema 不合法、
  `receipt_sha256` 重算不匹配、artifact 漂移、`synthetic=true`、`owner_rt` 与 closure map
  不符、`owner_rt_independent_pass=false` 或 `conclusion != capability_activated`。
- Gateway identity/transport/authority 仍 `conservative_unknown`。
- 任一跨 tenant 泄漏、secret leak、blocking query/data diff、SHA/ACL/restore/
  rollback 失败、全库/Wiki/nightly fixture 回归失败。
- release 默认不是 off/legacy/empty allowlist，或可绕过 G7 开 pilot。
- RT-024/025 baseline 不可复现，或批准 threshold policy 缺失/验签失败/超限。
- 现有单用户 nightly/read path 在 off/rollback 后与基线不一致。

### 7.1 synthetic gate 的闭合判定（fail-closed，但不是死角）

VG-A 是**永久** synthetic。若规则停在"任一 synthetic hard gate ⇒ 无条件 NO_GO"，
则即便 RT-017/RT-023 后来交付真实能力，`READY_FOR_G7_REVIEW` 也永不可达——那是设计死角。
RT-026 机读 `contracts/gates/synthetic_closure_map_v1.json` 判定缺口状态：

- **VG-A 永不升级、永不重跑、永不重解释**：已签发 receipt 不得就地编辑或重签；
  RT-026/G6/G7 都不得把 `synthetic=true`/`conservative_unknown` 读成更强结论
  ——**缺口闭合之后也不行**；VG-A 的 `rerun_allowed=false`，receipt 永久冻结、archive 恒空。
- **缺口只能由单独 owner 的 capability activation receipt 闭合**
  （`cwk.pr001.capability_activation_receipt.v1`，与中央计划 §5.1 SG-00 对应）：
  `cwork-authority-source`（owner **RT-017**）与 `gateway-identity-transport`
  （owner **RT-023**），路径为 `capability-receipts/<capability_id>/receipt.json`，
  **不在 `gate-receipts/` 下**，domain separator 也不同，两族 receipt 无法互换。
- **闭合是合取**：`status=pass` ∧ `synthetic=false` ∧ `owner_rt_independent_pass=true`
  ∧ `conclusion=capability_activated` ∧ `receipt_sha256` 重算一致 ∧ 全部
  `artifacts[].sha256` 与磁盘一致。任一不成立 ⇒ **OPEN ⇒ NO_GO**。
  完整判定还包含：`verifier` 存在且 ≠ `producer`；`consumers` 恰为闭包图/registry
  为该 receipt 声明的消费者数组（schema 中没有 `consumer_rt` 标量）；
  `closes_gate_ids` 恰为闭包图映射集合；`tests_run > 0` ∧ `tests_failed = 0` ∧
  skipped 有界；`evidence_refs` 覆盖该 capability 的全部 `required_evidence_roles`
  且非空；每个 evidence/artifact 是安全的仓库相对普通文件（拒绝绝对路径、`..`、
  任一分量 symlink、末段 symlink、hardlink、目录、特殊文件）；`created_at` 为严格
  RFC3339；无多余字段与深层禁用字段。
- **有界 TTL**：闭包图为每个 capability 冻结 `max_validity_seconds`
  （`cwork-authority-source` 7776000s / 90 天；`gateway-identity-transport` 2592000s /
  30 天）。RT-026 对链上**每一份** receipt 校验 `0 < expires_at - created_at <= max`，
  上界为**闭区间**（正好等于上界有效，多一秒无效），且**不使用评估器自己的时钟**做该
  判定。该界只存在于冻结配置中，receipt 无法自行放宽其 TTL。当前 current receipt 已过期
  ⇒ 缺口重新 OPEN ⇒ NO_GO。
- **可续签、不可原地覆盖**：activation receipt 与 VG 链同形——`sequence`、
  `previous_receipt_sha256`、`capability-receipts/<capability_id>/archive/<旧 sha256>.json`。
  RT-026 **只读 current**，并校验整条链；owner 只能在其 RT 验收仍有效且完成新的真实探测
  之后续签。RT-026 不得触发、代写或修复任何续签。
- **subject 绑定是祖先规则**：`tested_subject_commit` 须是引入该 receipt 的
  evidence-only commit 的祖先，且与该 receipt 自身证据一致；**RT-026 不得要求它等于
  自己的最终 HEAD**，也不得据此把诚实证据判为陈旧。任何关于"过期 / 错误 commit / 错误
  build"的结论都必须来自上述可机读校验，不得凭叙述断言。
- **闭合之后**该 synthetic gate 不再单独构成**永久** blocker，但仍以 scoped evidence
  与显式生产 caveat 出现在报告中。
- **VG-B～VG-E** 若为 synthetic，不得借用 VG-A 的映射，只能靠**非 synthetic 重跑**
  （先按字节归档被取代 receipt 到 `gate-receipts/VG-{X}/archive/{其 receipt_sha256}.json`，
  再发布新的 current receipt），或先修订 closure map 显式映射。
- **VG-B～VG-E 链校验**：RT-026 走**唯一一条前缀链**——`sequence` 从 1 起、archive 与
  current 恰好占满 `1..N`、current 位于链尾、`supersedes_receipt_sha256` 逐级链接、
  每个归档文件名等于其自身重算 hash、全链 `gate_id` 一致——并拒绝 gap / fork / orphan /
  cycle。`created_at` 递增只作**辅助**校验，不得作为唯一排序证据。空 / 无 current /
  无 archive 仍为 `NOT_RUN`，不是失败。
- **archive 精确成员关系**：链校验之外，RT-026 还必须对 `gate-receipts/VG-{X}/archive/`做一次**整目录枚举**，并要求其成员**恰好**等于链上被取代的 receipt 集合（文件名 = 自身
  `receipt_sha256` + `.json`）。多余 JSON、隐藏项（`.` 开头）、任意位置的 symlink、
  hardlink、非普通文件（FIFO / 设备节点 / socket）、嵌套子目录一律判**失败**。
  这条不能由 `sequence` 恰好占满 `1..N` 推出：不带 `sequence` 的条目对链校验不可见。
  同一条闭合要求适用于 `capability-receipts/<capability_id>/archive/` 与
  `security-receipts/`（后者无归档链，其闭合就是"每个 `*.json` 恰好落在已声明的
  `receipt_path` 上"）。
  **VG-A 例外且必须按例外处理**：它由冻结配置中的静态哈希
  `7058a91a1a5d48a8daca2967b77e7cb64cea578fb66ee3b69f3c12ff3e918657` 钉住，无 `sequence`、
  无 supersedes，archive 必须缺席或为空。RT-026 必须拒绝任何替代的 VG-A current receipt
  与任何 VG-A 归档 / 轮换，且**不得**为了补链字段而修改 VG-A receipt 的字节。
- **RT-026 只聚合**：不得创建、补写、猜测任何 activation receipt，不得轮换或归档任何
  gate receipt，不得修改 closure map。文件不存在 = NOT RUN = fail closed，
  永远不得解释为"已激活"或 `N/A`。
- **当前状态**：两份 activation receipt 都不存在 ⇒ VG-A 缺口 OPEN；十份安全门 receipt
  也都不存在 ⇒ 每个 SG 条目 `NOT_RUN` ⇒ 结论为 NO_GO。这是现状陈述，不写进 closure map
  或 security registry（配置不得携带时点观测）。

### `READY_FOR_G7_REVIEW`

只有全部 hard gate（VG-A～VG-E、G1～G5）为 PASS、**每个 synthetic hard gate 的能力缺口
按 §7.1 判定为 CLOSED**、所有 diff 为 exact/允许且需要人工复核者已有 receipt、
实测指标满足批准 policy、rollback 演练成功时才可输出。即便如此，所有 synthetic gate
仍须以 scoped evidence + 显式生产 caveat 列出。此结论不启用 tenant，
不等于 G6/G7/M4/生产 GO。

### 三段顺序（不可交换，禁止环）

```text
VG-A~VG-E + G1~G5 receipts
  → RT-026 go/no-go 报告（结论上限 READY_FOR_G7_REVIEW）
  → RT-026 由独立验收 Agent 判定 PASS
  → 新鲜最终验收者签发 G6（消费上面全部产物）
  → G6 之后才进入 G7 release readiness 授权
```

`READY_FOR_G7_REVIEW` 是 **G6 之前**的 RT-026 自身结论，表示"可提交给 G6 最终验收"；
release readiness 的 G7 授权发生在 G6 签发之后，由 RT-026 之外的业务/安全批准人执行，
且必须有 Evan（用户）**显式授权**，永不可由 RT-026 推断或自动产生。
RT-026 既不签 G6 也不签 G7。

**禁止的表述与行为（逐条 fail closed）**：

- 把 `READY_FOR_G7_REVIEW` 写成或读成 `G7_AUTHORIZED`、`RELEASE_APPROVED`、
  `GA_READY`、"已获 G7"、"可直接进入 G7" 或任何等价物；
- 以"RT-026 已 PASS"为由**跳过 G6**、把 G6 与 G7 合并为一步、或倒置两者顺序；
- 在 RT-026 内部签发、代签、补写或推断 G6 / G7 receipt；
- 把 G6 或 G7 列为 RT-026 的输入（二者是**下游**，见 §3 与 §5）。

## 8. Release switch 状态规则

- `off`：legacy read；所有新 component false；allowlist 为空。
- `shadow`：legacy read 仍为用户响应；new chain 只读/对账；不得调用生产 writer。
- `pilot`：只有 external G7 receipt + allowlist + tenant pilot 状态 + 全 gate 才能
  进入；本 RT 验收只用隔离合成 fixture，不切真实 tenant。
- 任一错误、receipt 过期或 rollback 请求都原子进入 `off`。

## 9. CLI 契约

provider 建议只暴露：`release:status`、`release:doctor`、`release:shadow`、
`release:diff`、`release:go-no-go`、`release:rollback`。所有 mutation 默认
`--dry-run` 或要求显式确认 token；不得提供无 G7 校验的 `enable-production`。
dispatcher slot 激活必须是显式兼容修订并有零漂移/恶意 provider 测试。
