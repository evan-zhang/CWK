## 二、关键设计决策

1. **grant_key 与 view_key 同源**：`H("cwk-access-ledger-grant-key-v1",
   tenant_id, report_key)[:128 bit] → base32-lower(26 chars)`。同一
   (tenant, report_key) 的 grant 与 view 记录复用同一 opaque ID，
   避免 report_id 出现在任何路径中。
2. **On-disk grant record 是 RT-015 envelope + 嵌套 RT-011 access_grant.v1**：
   保证 RT-011 冻结契约不被扩展；查询后仍可提取 v1 payload 交给
   下游 broker/consumer。
3. **撤权先写 intent journal**：从 `_write_intent` 完成的瞬间，
   `check_query_eligibility` 一律返回 `AccessDenied(revocation_in_progress)`
   —— 即便 grant record 尚未标记 revoked。这是“逻辑拒绝先行”的核心。
4. **auth_epoch 双重锚定**：snapshot.tenant_auth_epoch 必须与 live
   tenant.auth_epoch 相等，且 grant.auth_epoch 必须与 live 相等。
   revoke 触发 `TenantRegistry.bump_auth_epoch` → snapshot 立即失效。
5. **Authority adapter 默认 fail-closed**：真实权威源在 RT-015 范围外；
   测试 `FakeSigningAuthority` 只能通过 module-private token 注册；
   HMAC 签名 + `hmac.compare_digest` 常量时间比较。
6. **Cleanup outbox 幂等**：`outbox_id = stable_hash(txn_id)`，重跑
   revoke / recover 都得到 byte-identical outbox 文件；消费者按
   consumer 列表逐次 ack，最后一个 ack 后 unlink。
7. **View overlay 双 ACL**：`read_view` 与 `upsert_overlay` 都在 IO 前后
   各调用一次 `check_query_eligibility`；这直接实现 DESIGN §5 C-13
   的“in-flight revoke 拒绝旧证据”要求。
8. **Log injection 双层防护**：mutation API 立即 `_validate_actor_reason`
   → 严格可打印 ASCII；schema pattern `\A[\x20-\x7e]+\Z` 再校验。
9. **错误 opacity**：`AccessLedgerError.__str__` 只暴露 `code` +
   `grant_key`（opaque）；`AccessDenied` 只显示 `"access denied"`，
   `reason` 保留在属性上供测试使用但不进入 `__str__`。
10. **零漂移测试自动化**：`FrozenFilesZeroDriftTests` 通过 `git show
    HEAD:<path>` + `hashlib.sha256` 对比现文件；后续 RT 亦可复用。

## 三、明确的边界（防止越界）

- **不迁移 legacy timeline payload**。RT-016 只能对 legacy timeline 做
  hash / crosswalk / review；不可通过 RT-015 的 `TenantViewStore` 把
  full reply/node 正文塞入 tenant view。RT-011 `cwk.tenant_view.v1`
  是唯一契约，`reply_overlay/node_overlay` 只允许 IDs + 可选
  `content_sha256`。
- **不接入真实 authority、真实 Broker、真实 Scheduler、真实 Space
  Projector、真实 Cache**。RT-015 只交付逻辑授权/撤权消费者契约（写
  outbox），实际清理动作由 RT-021/022/024 落地。
- **不修改 RT-011~014 冻结物**。修改任何被 `FrozenFilesZeroDriftTests`
  覆盖的路径都会立即断言失败。
- **不自认完成 G3 / VG-A / M3 / 生产迁移**。RT-015 只是 VG-A 的输入之一。

## 五、剩余风险

- **真实 authority 集成**：`_FailClosedAuthority` 无法被替换而不修改
  代码；RT 系列的下一步（很可能 RT-017 或 RT-020）需要设计一个真实
  authority 适配器契约。RT-015 已定义 `cwk.rt015.authority_receipt.v1`
  与 `AuthorityAdapter` 抽象基类，接口稳定。
- **Cleanup consumer**：真正的 space_index / cache 清理还没实现。
  RT-021 / RT-022 需要消费 `iter_cleanup_outbox` 并 `ack_cleanup_task`。
  RT-015 已在 outbox 中固定 3 类消费者，如未来新增
  (review_queue / archive_metadata)，schema 已预留。
- **Tenant view v2**：如果 legacy timeline payload 需要迁移，需要
  新一轮 RT-011 级独立审核后新增 `cwk.tenant_view.v2` 或
  `verified_shared_extensions_v2`；RT-015 明确拒绝在 v1 上偷渡。
- **Recovery 报告的 inconsistencies**：目前只写 opaque prefix；后续
  可扩展到 RT-024 审计导出。
