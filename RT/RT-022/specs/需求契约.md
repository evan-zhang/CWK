# RT-022 需求契约：Query Broker 授权核心

## 1. 业务目标

为沙箱查询提供宿主机授权核心。在任何检索或证据回读之前，将可信 Agent
固定解析到一个 tenant，并以 active grant、space membership 和请求快照
执行两次 ACL，输出可验证 evidence bundle；不暴露共享文件系统或对象存在性。

## 2. 用户角色

- 普通沙箱 Agent：只提交无身份字段的查询内容。
- Host Query Broker：执行授权、检索编排、二次 ACL、SHA 回读和审计。
- tenant 管理员：配置 tenant/profile/space，但不能通过 Broker 模拟用户。
- 独立验收 Agent：从公开入口做正常、异常和恶意黑盒验证。

## 3. 功能范围

### 必须实现

- QBR-001：只接受传输层给出的 `AgentContextSnapshot`；请求体的
  tenant/agent/path/credential/profile/epoch 字段全部拒绝。
- QBR-002：按 binding、tenant 状态、pilot allowlist、active profile、
  space 所属关系建立不可变 `req_snapshot`；其中 Profile/space 事实只来自
  QBR-011 的注入式 provider，不来自磁盘布局推断。
- QBR-003：候选域严格等于 active grant 与 active space membership 的
  交集；未授权标题、数量、时间和 report ID 不进入检索器。
- QBR-004：Top-K 回读前重新读取 binding、tenant、grant/lease 并比较
  `binding_epoch/auth_epoch/profile_sha`；变化即拒绝该请求的全部证据。
- QBR-005：按 catalog 指定 SHA 回读 canonical，并验证内容 SHA；只输出
  当前 tenant 仍有权访问的 evidence bundle。
- QBR-006：实现 tenant/epoch/profile/space/filter/index-version 绑定的
  安全缓存；每次命中仍复核授权。
- QBR-007：交付 `QueryRequest v2` 与强语义 validator；v1 不修改。
- QBR-008：`index/archive_no_index/review` 各自独立预算；冷归档不得扫描
  shared raw；对默认和显式预算在 server-policy clamp 后均必须满足
  `archive_limit * 2 <= index_limit`。
- QBR-009：稳定、脱敏、存在性等价的错误 envelope；内部 reason 仅进入
  受控审计，不写外部消息。
- QBR-010：消费 RT-015 cleanup outbox 的 cache 清理任务并幂等 ack。
- QBR-011：冻结并只通过**构造注入**使用 `ProfileSpaceSnapshotProviderV1`
  （`API_VERSION = "cwk.profile_space_snapshot_provider.v1"`，方法
  `snapshot(agent_snapshot) -> ProfileSpaceSnapshotV1`）。单次调用一次性返回
  `profile_sha256`、`profile_version`、`default_space_ids`、`queryable_space_ids`、
  `membership_versions`、`index_versions`、`as_of`、`snapshot_sha256`；
  **即使 0 个 space 也必须携带 `profile_sha256`**。Broker 禁止 per-space 回调、
  禁止 import 或读取 RT-019/RT-021 的私有模块与磁盘布局。RT-022 是该 ABI 与
  `cwk.profile_space_snapshot.v1` schema 的唯一 owner，本 RT 只实现 fake provider；
  RT-021 后续实现生产 adapter 并零漂移复用同一 Protocol/schema。
- QBR-012：零漂移消费 Wave-0 neutral `PilotAdmissionProviderV1`。provider 在构造期绑定
  `purpose=query_broker`，公开方法仅 `snapshot(*, agent_snapshot)`。request schema/
  semantic validation 失败时调用 0 次；tenant=`active` 调用 0 次；`pilot` success 与
  cache hit 恰好调用 2 次：第一次在 Profile snapshot、检索和 cache lookup 前，第二次
  在 fresh binding/tenant/grant/Profile 复核后、EvidenceReader/readback/返回前。

### 明确不做

- OpenClaw Tool/UDS、真实 Gateway identity、`list_spaces`、slug 解析、沙箱
  安装或 Skill；由 RT-023 实现。
- 最终自然语言回答、任意 host path/raw path 读取、跨 tenant/管理员旁路。
- 物理删除 canonical、修改 grant/profile/space 或启用生产。

## 4. 输入契约

### 4.1 `cwk.query_request.v2`

- `schema`：固定 `cwk.query_request.v2`。
- `query`：NFC 后 1～4000 个字符，去除首尾空白后不得为空；控制字符拒绝。
- `space_selector`：可缺省；缺省表示“由服务端读取当前 tenant 的 active
  Profile 所声明的默认 active/queryable space 集”，不得扩大到 Profile 外空间。若出现，必须是 1～32 个唯一 opaque `space_id`；
  空数组非法。slug 不属于该字段。
- `include_dispositions`：可缺省，缺省等价 `['index']`；若出现必须非空、
  唯一，且仅可取 `index/archive_no_index/review`。
- `disposition_budgets`：可缺省；缺省时从只读 server policy 为每个有效
  disposition 生成并写入快照。若出现，其键集合必须与有效 dispositions
  **完全相等**，每项含 `limit`、`timeout_ms`、`concurrency`，均为正整数
  且不得超过 server policy；clamp 后的所有生效预算仍须满足
  `archive_limit * 2 <= index_limit`。若本次未请求 `index`，比较项使用相同
  server policy/scope 下的 index ceiling，仅用于上限校验，不启动 index 检索。
  v2 禁止顶层 `limit`。
- `time_filter`：可缺省或 null；对象至少一个端点非 null；RFC3339/UTC
  规范化后必须 `from <= to`。
- schema `additionalProperties:false`，并做 deep-forbidden scan。

### 4.2 可信上下文

调用 Broker 必须同时提供由传输适配器生成的不可变上下文；它不属于 JSON
request。缺失、过期、类型伪造或字段与 live binding 不一致均拒绝。

## 5. 输出契约

成功输出 `cwk.rt022.evidence_bundle.v1`，至少包含：`request_id`、有效
`space_ids`、有效 dispositions 与预算快照、`as_of`、`req_snapshot_hash`、
`index_versions`、按稳定顺序排列的 evidence items。每个 item 至少含
`report_key`、`canonical_sha256`、授权 `space_ids`、安全 source link 或
source ID、作者/时间、受限引文和证据校验状态；不含 tenant 路径、原始
Agent ID、credential、完整 query 或未授权候选。

内部 `QuerySnapshot v1` 除既有字段外必须包含 `tenant_status`、
`admission_policy_revision` 与 `pilot_admission_snapshot_sha256`；后两项在 `active` 时
严格为 null，在 `pilot` 时来自第一次已验证 snapshot。它们进入 req snapshot hash、
cache key 和审计 hash，不进入外部身份字段。

失败输出 `cwk.rt022.query_error.v1`，外部 `code` 仅允许：

- `request_invalid`
- `access_denied`
- `query_unavailable`
- `evidence_unavailable`
- `rate_limited`
- `internal_error`

未知对象、他租户对象、已撤权对象和无 membership 必须映射为相同
`access_denied` 形态、状态码、字段集合与近似时序预算；错误不含 ID/path/reason。

## 6. 业务规则

1. 顺序不可交换：可信身份 → binding/tenant/profile 快照 → space 校验 →
   grant∩membership → retrieval → 二次 ACL → SHA readback → bundle/audit。
2. 缺省 `space_selector` 只展开为 QBR-011 provider 返回的 `default_space_ids`；
   显式 `space_selector` 必须是 `queryable_space_ids` 的子集，否则按存在性等价的
   `access_denied` 拒绝。不得枚举全局或该 Profile 未声明的空间。
   `default_space_ids ⊆ queryable_space_ids`，且 `membership_versions`/`index_versions`
   的键集合必须精确等于 `queryable_space_ids`；不满足即视为 provider corruption
   并拒绝整次请求。`queryable_space_ids` 为空时仍按正常授权语义得到空候选域，
   返回与未授权完全等价的 `access_denied`，不得暴露“该 tenant 无 space”。
3. request 合法且 tenant=`pilot` 时，先调用一次 PilotAdmission；deny/unavailable/
   过期/错 tenant/purpose/hash/revision 回退时在 1 次调用后拒绝，Profile provider、
   retrieval 与 cache 均不得调用。`active` 完全跳过该 provider。
4. 任一 Top-K 在二次校验时发现快照变化，整次请求 fail closed；不得返回
   “其余仍通过”的部分答案。
5. disposition 检索器彼此隔离预算；一个超时不扩大其他预算。
6. `archive_no_index` 只读其专属派生索引，绝不退化为 shared raw 全扫描。
7. cache key 至少含 tenant、tenant status、binding/auth epoch、profile SHA、排序后的
   space IDs、query/filter hash、disposition budgets、index versions、admission policy
   revision 与 pilot snapshot SHA。Broker 维护 `(tenant_id,purpose)` revision high-water；
   回退拒绝，deny/unavailable 结果不得缓存。
8. 审计只记录 query hash/长度/意图、授权 report IDs、决策和快照 hash。
9. 二次 ACL 与 fresh Profile snapshot 完成后，`pilot` 必须调用第二次 PilotAdmission；
   deny、revision 回退、policy/hash/snapshot 漂移时丢弃整次请求，不调用 EvidenceReader，
   不返回部分 bundle。cache hit 也必须完整执行两次。

## 7. 异常与攻击场景

- 身份字段、report ID、绝对路径、traversal、symlink、credential 注入。
- 缺省与空 `space_selector` 混淆、空 dispositions、预算键缺失/多余/超限。
- `from > to`、非 UTC/非法日期、空白 query、超长 query、控制字符。
- stale binding/auth/profile、lease 过期、in-flight revoke/rebind/rollback。
- A 的 cache key/query hash 碰撞尝试命中 B；缓存命中后撤权。
- fake index 返回未授权 report、重复项、越租户 metadata、损坏 SHA。
- 对存在/不存在/已撤权/他租户对象做错误与时序探测。

## 8. 验收标准

- AC-022-01：所有 QBR-001～012 均有实现和自动化测试映射。
- AC-022-02：双租户恶意夹具下跨租户泄漏为 0，未授权候选不进入 provider。
- AC-022-03：撤权/rebind/profile change 在二次 ACL 前注入时请求整体拒绝。
- AC-022-04：v2 交叉字段语义的正反例全部可机读验证；v1 字节零漂移。
- AC-022-05：三类 disposition 预算独立；默认/显式预算 clamp 后均满足 archive 半额不变式，冷归档无 shared raw 扫描。
- AC-022-06：对象存在性四种状态返回等价外部错误。
- AC-022-07：SHA 篡改或 catalog/object 不一致无 evidence 输出。
- AC-022-08：现有 Wiki smoke、RT-010 实体范围与全库回归通过。
- AC-022-09：独立验收明确 PASS 后才允许进入 RT-023 真实集成。
- AC-022-10：`ProfileSpaceSnapshotProviderV1` 冻结且只经构造注入；静态检查证明
  Broker 未 import `cwk_knowledge_profile.py`/`cwk_space_registry.py`/
  `cwk_space_projector.py`，也未读取其私有目录。0-space 返回值仍带非空
  `profile_sha256` 并进入快照与 cache key，外部错误与未授权等价；provider 返回
  键集合不符、`default ⊄ queryable`、未知 space ID、含 slug/路径/正文/credential
  或二次调用漂移时，请求整体 fail closed 且无部分 bundle。
- AC-022-10a：invalid request 与 `active` 的 PilotAdmission 调用均为 0；`pilot`
  success/cache hit 恰好 2 次。第一次 deny 只调用 1 次且 Profile/retrieval/cache 0 次；
  第二次 deny、revision 回退或 policy/snapshot 漂移无 EvidenceReader/部分 bundle。
  deny/unavailable 不缓存，QuerySnapshot/cache key/high-water 绑定冻结的 admission 字段。

## 9. 黑盒测试矩阵

| 场景 | 输入/注入 | 期望结果 |
| --- | --- | --- |
| 正常默认 | 缺省 selector/dispositions/budgets | 仅展开本 tenant active Profile 的默认 active spaces，index 默认预算写入快照 |
| Profile 子集 | tenant 另有 active space 但不在 active Profile 默认集 | 缺省 selector 不召回该空间及其候选 |
| 正常显式 | 两空间、两 disposition、完整预算 | 各自预算检索，bundle 仅含 active grant∩membership |
| 空选择器 | `space_selector=[]` | `request_invalid` |
| 时间倒置 | `from > to` | `request_invalid`，provider 未被调用 |
| 预算错配 | 多余/缺失 disposition key | `request_invalid` |
| 显式预算越界 | clamp 后 `archive_limit * 2 > index_limit` | `request_invalid`，任何检索器未调用 |
| 候选投毒 | fake provider 返回未授权 report | 二次 ACL 拒绝整次请求，无 report 泄漏 |
| 撤权竞态 | retrieval 后 bump auth epoch | `access_denied`，无部分 bundle |
| 缓存串扰 | A/B 同 query、同空间文本 | cache 物理/逻辑隔离，B 不命中 A |
| SHA 篡改 | object bytes 与 catalog SHA 不符 | `evidence_unavailable`，无正文 |
| 存在性探测 | unknown/revoked/other-tenant/absent | 相同外部错误 envelope 与字段 |
| 冷归档 | 显式 archive budget | 不访问 shared raw 枚举器，预算不超 policy |
| 注入 | tenant/path/agent/report/credential 字段 | validator 拒绝，审计脱敏 |
| 零空间 Profile | provider 返回 0 space + 非空 `profile_sha256` | `access_denied`，与未授权字节等价；快照/cache key 仍含 profile SHA |
| provider 缺 profile SHA | 0 space 且 `profile_sha256` 缺失/空 | provider corruption，整次请求拒绝 |
| provider 键集合不符 | `index_versions` 缺键或多键、未知 space ID | provider corruption，检索器未调用 |
| provider 越界默认集 | `default_space_ids ⊄ queryable_space_ids` | provider corruption，整次请求拒绝 |
| provider 漂移 | 二次 ACL 时 profile SHA/space/index 版本变化 | `access_denied`，无部分 bundle |
| provider 泄漏 | 返回值含 slug/路径/正文/credential/他租户 ID | 拒绝整次请求，审计仅记 opaque reason |
| invalid request admission | schema/语义不合法 | admission 0 次，`request_invalid` |
| active admission | active tenant 正常或 cache hit | admission 0 次，既有双 ACL 正常执行 |
| pilot first deny | 第一次 deny/unavailable/expired/wrong binding | admission 1 次；Profile/retrieval/cache/EvidenceReader 均 0 次 |
| pilot second deny | 检索后二次 deny/revision 回退/policy 或 snapshot 漂移 | admission 2 次；丢弃整请求，无 EvidenceReader/部分 bundle |
| pilot cache hit | 已有合法 cache value | 仍恰好 2 次 admission，cache 不复用旧准入结论 |
