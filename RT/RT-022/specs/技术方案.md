# RT-022 技术方案：Query Broker 授权核心

## 1. 涉及模块

- `cwk_query_contracts.py`：v2 schema loader、语义 validator、稳定错误与
  evidence bundle validator。
- `cwk_query_broker.py`：授权 pipeline、snapshot、预算编排、安全缓存、
  cleanup consumer。
- `cwk_wiki_query.py`：仅增加无任意路径参数的 raw-loader 库适配。
- `contracts/rt022/schemas/`：`query_request_v2`、`query_error_v1`、
  `evidence_bundle_v1`、`query_snapshot_v1`、**`profile_space_snapshot_v1`**
  （`cwk.profile_space_snapshot.v1`，RT-022 唯一 owner，RT-021 零漂移消费）。
- Wave-0 `cwk_pilot_admission_api.py`：central neutral ABI；RT-022 只消费并构造注入
  `purpose=query_broker`，不拥有/复制其 runtime/schema，也不实现 production adapter。

## 2. 数据结构与版本决策

### 2.1 QueryRequest v2

采用新版本而非修改冻结 v1。JSON Schema 负责类型、枚举、长度和
`additionalProperties:false`；`validate_query_request_v2_semantics()` 负责：

- 缺省 selector/dispositions 的唯一语义与空数组拒绝；
- effective disposition 集与 budget 键集合完全相等；
- server policy 上限和 `archive.limit <= floor(index.limit/2)`；若只查询
  archive，则用 policy 的 index default 计算上限；
- RFC3339 转 UTC 后 `from <= to`；
- NFC、非空白 query、控制字符和 deep-forbidden；
- 生成规范化 immutable request，不把客户端原 JSON传给下游。

### 2.2 请求快照

`QuerySnapshot` 包含 opaque tenant ID、`agent_id_hash`、binding/auth epoch、
profile SHA、排序 space IDs、disposition budgets、filter hash、membership/index
versions 和开始时间。其中 `profile_sha256`、space IDs 与 membership/index versions
全部来自 §3.1 `ProfileSpaceSnapshotProviderV1.snapshot()` 的单次返回值，并附带
该返回值的 `snapshot_sha256`（即 §3.1 表中冻结的字段名，`ProfileSpaceSnapshotV1` 中**不存在** `profile_space_snapshot_sha256` 这一字段）；
Broker 不从磁盘或其他 RT 的私有布局补齐这些字段。
另必含 `tenant_status`、`admission_policy_revision`、
`pilot_admission_snapshot_sha256`；后两项对 active 为 null，对 pilot 为第一次准入
snapshot 的值，并进入 snapshot hash/cache key。
持久化/日志仅记录 domain-separated JCS SHA，不记录原始 query。

### 2.3 Evidence bundle

item 以 `(source_namespace, report_id, canonical_sha256)` 稳定排序；引用长度
和总 bundle 字节受 server policy 限制。bundle 生成前后均校验 schema，且
只从已通过二次 ACL 的内存对象构造。

## 3. 公开 ABI

```python
class ProfileSpaceSnapshotProviderV1(Protocol):
    API_VERSION = "cwk.profile_space_snapshot_provider.v1"
    def snapshot(self, agent_snapshot) -> ProfileSpaceSnapshotV1: ...

class SpaceIndexProvider(Protocol):
    def retrieve(self, *, snapshot, request, disposition, budget) -> Sequence[Candidate]: ...

class EvidenceReader(Protocol):
    def read_verified(self, *, report_key, canonical_sha256) -> VerifiedEvidence: ...

class AuditSink(Protocol):
    def append(self, event: QueryAuditEvent) -> None: ...

class QueryBroker:
    def query(self, *, agent_context, request_payload) -> EvidenceBundle: ...
    def consume_cleanup(self, *, tenant_id, outbox_id) -> CleanupResult: ...
```

`PilotAdmissionProviderV1` 不在本 RT 重定义；构造时 purpose 固定为 `query_broker`，
调用仅 `snapshot(*, agent_snapshot)`。Broker 对返回的 exact 9 fields、TTL≤300s、domain
hash、tenant/purpose、revision 与 admitted 做 consumer-side 验证。

Provider 不得接收 instance root/raw path/credential；Candidate 必须含 report key、
space ID、disposition、index version 和 canonical SHA，不含正文。AuditSink 故障
按策略写本地安全 spool；若安全审计无法落盘且策略要求强审计，则 fail closed。

### 3.1 `ProfileSpaceSnapshotProviderV1`（并行 ABI 闭包）

RT-022 与 RT-019/021 并行开发，因此 Broker **不得**读取 Profile/Space 的私有磁盘布局，
也不得 import `cwk_knowledge_profile.py` / `cwk_space_registry.py` / `cwk_space_projector.py`。
Broker 只通过**构造注入**的单一 provider 拿到 Profile 与 space 视图：

```python
API_VERSION = "cwk.profile_space_snapshot_provider.v1"

class ProfileSpaceSnapshotProviderV1(Protocol):
    API_VERSION = "cwk.profile_space_snapshot_provider.v1"
    def snapshot(self, agent_snapshot: AgentContextSnapshot) -> ProfileSpaceSnapshotV1: ...
```

**所有权**：RT-022 是本 ABI 与 `cwk.profile_space_snapshot.v1` schema 的唯一 owner；
RT-021 后续实现生产 adapter，只能按位复用同一 Protocol 与 schema 文件，不得 fork、扩展、
收窄或以同名 schema 重定义。字段变更必须回到 RT-022 发新版本并附 migration note。

**调用语义（冻结）**：

- 单次调用一次性返回全部所需事实，Broker **禁止** per-space 回调或 N+1 查询；
  原 `SpaceIndexProvider.list_active_spaces/versions` 两个方法被本 provider 取代，
  `SpaceIndexProvider` 只保留 `retrieve`，避免同一事实出现双 owner。
- 唯一入参是可信 `AgentContextSnapshot`；不接受 `tenant_id=` 裸 kwarg、slug、
  instance root、raw path 或 credential。
- 返回值 immutable，且在本次请求生命周期内被冻结进 `req_snapshot`；二次 ACL 阶段
  重新调用一次并逐字段比对，任何漂移即整次请求 fail closed。

`ProfileSpaceSnapshotV1`（`cwk.profile_space_snapshot.v1`）字段：

| 字段 | 语义 |
| --- | --- |
| `schema` | 固定 `cwk.profile_space_snapshot.v1` |
| `profile_sha256` | 当前 active Profile SHA；**即使 0 个 space 也必须携带**，不得为空或省略 |
| `profile_version` | active Profile 的 opaque 版本标识 |
| `default_space_ids` | Profile 声明的默认可查询 active space opaque IDs，稳定排序，可为空数组 |
| `queryable_space_ids` | Profile 声明的全部可查询 active space opaque IDs，稳定排序，可为空数组 |
| `membership_versions` | `space_id → opaque membership 版本`，键集合必须精确等于 `queryable_space_ids` |
| `index_versions` | `space_id → opaque index 版本`，键集合必须精确等于 `queryable_space_ids` |
| `as_of` | RFC3339 UTC |
| `snapshot_sha256` | 对上述字段做 domain-separated JCS 的完整性 hash |

**不变式（由 Broker 侧 validator 强制，provider 不可信）**：

- `default_space_ids ⊆ queryable_space_ids`；两者元素唯一、稳定排序、各自 ≤32；
- `membership_versions` 与 `index_versions` 的键集合精确等于 `queryable_space_ids`，
  不多不少；缺键、多键或未知 space ID 视为 provider corruption，拒绝整次请求；
- 空 space 集**不是**特例路径：`profile_sha256` 仍必须存在并进入快照与 cache key；
  随后按正常授权语义得到空候选域，映射为与未授权完全等价的 `access_denied`，
  不得返回可区分“该 tenant 没有 space”的外部信息；
- 无 active Profile、Profile 非 `active` 状态或 provider 抛出 → `access_denied`；
- 返回值中出现正文、标题、slug、路径、tenant root、credential、agent ID 或其他
  tenant 的 ID 即视为 provider corruption，拒绝整次请求。

**禁止字段**：raw body、title、slug、绝对路径、tenant root、credential/token、
原始 Agent ID、其他 tenant 的任何标识。

本 RT 只实现 **fake provider**（仅测试可用，含 0-space、缺键、多键、越权 ID、
漂移等敌意夹具）；fake provider 不得用于 VG-D 或生产。

## 4. 处理流程

1. schema + semantic validation，拒绝身份/路径字段；失败时 PilotAdmission 0 次。
2. 由 `AgentContextSnapshot` 读取 live binding 和 tenant；验证状态/epoch。
   `active` 跳过 PilotAdmission；`pilot` 在任何 Profile/retrieval/cache 操作前获取并验证
   第一次 `query_broker` admission，失败时这些下游调用均为 0。
3. 调用注入的 `ProfileSpaceSnapshotProviderV1.snapshot(agent_snapshot)` 一次，
   校验 §3.1 全部不变式；缺省 selector 展开为 `default_space_ids`，显式 selector
   必须是 `queryable_space_ids` 的子集（否则 `access_denied`）。profile SHA、
   membership/index versions 一并冻结进 req snapshot。
4. 从 ledger 取 active grants，与 membership 做交集，构造 provider allowset。
5. 分 disposition 在独立 semaphore/deadline 下检索；provider 输出必须是
   allowset 子集，否则视为 provider corruption 并拒绝整次请求。
6. 对去重 Top-K 逐项重新读取 binding/tenant/grant/lease/profile/membership，
   与快照逐字段比较。
7. `pilot` 获取第二次 admission；拒绝 revision 回退、policy hash/revision/snapshot
   漂移与 deny/unavailable/expiry。失败丢弃全部 candidates；cache hit 也走步骤 2～7。
8. EvidenceReader 按指定 SHA 回读并验证；任何不一致拒绝整次请求。
9. 构造 bundle、写脱敏审计，再返回。

## 5. 缓存设计

- key bytes 使用 domain separator + length-prefix/JCS，禁止字符串 `+` 拼接。
- key 覆盖 tenant、binding/auth epoch、profile SHA、space IDs、query/filter hash、
  budgets、index versions、tenant status、admission policy revision 与 pilot snapshot SHA。
- value 不含未二次 ACL 的 raw；跨 tenant 不共享 evidence/answer cache。
- 命中后仍重走步骤 2～7；deny/unavailable 不缓存。Broker 对 `(tenant_id,
  "query_broker")` 维护 revision high-water，观测回退立即拒绝；cleanup outbox 以 `(outbox_id, consumer='cache')`
  幂等清理并 ack。

## 6. 稳定错误

内部异常先映射为六个外部 code；外部 message 固定，不插值 ID/path/reason。
unknown/revoked/other-tenant/absent 的 payload 字节结构一致。错误 audit event
可记录 opaque reason enum，但不得保存完整 query 或正文。未经识别的异常映射
`internal_error` 并清理 traceback 的用户可见输出。

## 7. 测试策略

- schema/semantic property tests：缺省、空、交叉字段、UTC、边界整数、深层
  forbidden、canonical round-trip。
- fake provider 黑盒：投毒候选、重复、跨 tenant metadata、超预算、超时。
- deterministic race hooks：在 retrieval/二次 ACL/readback/cache hit 各点注入
  revoke、rebind、profile rollback、space disable。
- error-equivalence：比较 code、字段、序列化长度分桶和受控时间预算。
- 回归：RT-013～015、RT-021 契约、RT-010/Wiki smoke、全库 unittest。

## 8. 风险与控制

- v1 客户端歧义：Broker 外部入口只接受 v2；若保留 v1 adapter，必须显式
  转换成 v2 immutable request 并对每个默认值写 receipt。
- AuditSink 可用性与可用性冲突：以配置化强审计策略 fail closed；不得静默
  丢审计。
- disposition fan-out 放大：每类独立 semaphore，外层总 deadline 取最小值。
- provider 泄漏：Broker 只传 allowset，不传全量 grant；返回子集再验证。

## 9. 回滚方案

禁用 Broker flag；删除新增模块和 v2 schema。v1、legacy CLI、index、grant、
canonical 均不迁移、不删除。
