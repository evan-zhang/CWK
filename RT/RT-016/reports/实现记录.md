## 1. 交付摘要

RT-016 落实 DESIGN §12 M2/M3 与开发计划 §9 中“不动 legacy 树、只写
RT-016 自有命名空间、通过 RT-014/RT-015 公开 writer 完成影子迁移与
数据对账”的目标。实现包含：

- 一份纯函数式 `LegacyRawDecomposer`：合成 legacy Markdown/JSON
  → `(CanonicalEnvelope, TenantViewEnvelope, AccessObservation)`
  三元组 + 结构化 `decompose_report`；一律 fail-closed，不
  truncate、不猜测。
- 一份 `ShadowImporter`：`publish (RT-014) → observe (RT-015 initial_status=granted)
  → durable crosswalk (RT-016 自有 namespace) → append-only manifest`
  的严格顺序；per-crosswalk `flock` + CAS 保证幂等与并发安全；
  fake authority 情境下可选完成 `promote_to_active + upsert_overlay`
  端到端。
- 一份 `MigrationReconciler`：以 RT-016 durable crosswalk 为 new-side
  全集，对每条 crosswalk 调 RT-014 `read_version` 校验；与合成
  legacy 树的递归 SHA-256 交叉分类为
  `both_equal / only_legacy / only_new / new_undecomposable`；输出
  严格 schema 校验过的 `ReconciliationReport`。
- 五份新 schema（RT-016 独占，全部 `additionalProperties:false +
  unevaluatedProperties:false + deepForbiddenProperties`）：
  `decompose_report.schema.json`、`migration_crosswalk.schema.json`、
  `review_entry.schema.json`、`migration_manifest_entry.schema.json`、
  `reconciliation_report.schema.json`。
- 六份测试文件（共 75 项 targeted tests）覆盖 schema、decomposer、
  importer、reconciler、attack surface；含 `FrozenFilesZeroDriftTests`
  比对 RT-011~015 冻结文件的 HEAD SHA-256。

## 3. 关键实现要点

### 3.1 三类哈希严格区分

- `legacy_source_sha256 = SHA-256(raw_bytes)`：磁盘原始字节，无
  规范化。
- `canonical_sha256`：`_C.canonical_sha256(envelope_without_canonical_sha256)`；
  RT-011 recipe 内部 = `sha256(canonical_json_bytes(nfc_normalize(...)))`。
- `object_bytes_sha256 = sha256(canonical_json_bytes(full_envelope))`：
  envelope 完整 JCS 字节（含 canonical_sha256），等于 RT-014 catalog
  的 `object_bytes_sha256`。

三者永不宣称相等；`test_rt016_decomposer.HappyPathTests.test_three_hashes_are_distinct`
与 `test_rt016_importer.ImportOneHappyPathTests.test_hash_fields_distinct`
直接断言。crosswalk 和 review 都同时保存三者。

### 3.2 观察永不升 active

`LegacyRawDecomposer.decompose` 始终生成
`AccessObservation(initial_status="granted",
observation_source="legacy_raw_decomposition")`。RT-015 冻结的
`cwk.access_observation.v1` schema 只允许 `discovered/granted`，
即使 caller 试图伪造也会被 RT-011 拒绝。

`ShadowImporter.import_one` 从不主动调用 `promote_to_active`；仅在
caller 显式传入合法 `authority_receipt` 时才转入 fake authority 端到
端路径（tests only）。

### 3.3 RT-015 tenant view fail-closed blocker（明确边界）

生产路径下，legacy raw 观察产生的 grant 状态是 `granted`；而
`TenantViewStore.upsert_overlay` 要求 `active` grant + 未过期 lease
+ tenant.status ∈ {pilot, active} + snapshot 匹配 + canonical 存在
+ 二次 recheck。真实 authority integration 目前仍
`conservative_unknown`（RT-011/RT-015 结论），所以 RT-016 在无
`authority_receipt` 场景下：

- 完成 canonical 发布 + observation 记录 + crosswalk 落盘；
- crosswalk 中的 `tenant_view_envelope` 字段完整保存 RT-011
  `validate_tenant_view` 通过的 overlay 内容（供未来 replay）；
- `tenant_view_written = False`；
- `tenant_view_deferred_reason = "no_authority_receipt_available"`。

`test_rt016_attacks.Rt015InsufficientAuthorityBlockerTests` 锁定该
契约。**RT-016 不修改 RT-015 冻结物；不实现 privileged bypass；
不宣称完成 M3/G3/VG-A/生产迁移。**

### 3.4 幂等 + 崩溃安全

- `crosswalk_key = base32(sha256(domain, tenant_id, view_key,
  legacy_source_sha256))[:16]`：同一 legacy 源永远映射到同一 key；
  重复 import 命中 `_find_existing_crosswalk_for_legacy` → 直接
  返回既有 receipt。
- 每个 crosswalk 有独立 `flock`（`cw.<crosswalk_key>.lock`），CAS
  写入（`_A.cas_write(expected_previous_sha256=None)`）；同一
  crosswalk 已存在且内容漂移（canonical_sha256 / object_id /
  grant_key 变化）→ `LegacyImportError(code="corrupt")`，永不
  静默覆盖。
- Manifest jsonl 用 `mf.<run_id>.lock` 串行化，追加式 CAS 写；
  按 `(legacy_source_sha256, outcome)` 去重。
- 崩溃点：
  - publish 之后 observe 之前 → RT-014 canonical 已落盘，重跑
    走 idempotent publish + observe。
  - observe 之后 crosswalk 之前 → RT-015 grant 已 `granted`（幂等），
    重跑走 idempotent observe + crosswalk 写入。
  - crosswalk 之后 manifest 之前 → `_find_existing_crosswalk_for_legacy`
    命中，`_append_manifest_entry` 按 (sha, outcome) 幂等追加。
- `recover(actor, reason)` 幂等清理 staging/rt016 与每个 tenant
  子目录下的 `.cwk-tmp-*` 孤儿；不修改 durable crosswalk / review /
  manifest。

### 3.5 macOS ENOENT 竞态处理（不改 RT-015）

RT-014 已在 `cwk_shared_evidence._flock_with_retry` 中记录了 macOS
上 `os.open(..., O_CREAT|O_NOFOLLOW|O_CLOEXEC, dir_fd=…)` 在高
争用下可能瞬时抛 `FileNotFoundError` 的行为。RT-015 的
`AccessLedger.observe` 直接使用 `_A.exclusive_lock` 而没有内部
重试。

RT-016 通过在 `ShadowImporter.import_one` 内部对
`self._ledger.observe(...)` 进行有界（最多 16 次、jitter 上限
50 ms）重试包裹绕过该竞态；重试仅捕获 `FileNotFoundError`，其他
`AccessLedgerError` 立刻抛为 `LegacyImportError(code="ledger_denied")`。
本改动完全在 RT-016 侧，未修改 RT-015 任何字节。

`test_rt016_attacks.ConcurrentImportTests` 显式记录并断言该运行时
契约：并发工作者可能各自看到 `FileNotFoundError` 或
`LegacyImportError(code="ledger_denied")`（accepted transient race
tokens），但必须至少一个成功且所有成功者返回相同 `crosswalk_key`；
串行后续调用必须回到同一 key。

### 3.6 路径安全

- `LegacySource` root 必须是绝对路径且非 symlink，否则
  `LegacyImportError(code="path_containment")`。
- 子树按 `O_DIRECTORY | O_NOFOLLOW` 递归；文件名 grammar
  `[A-Za-z0-9_.\-]{1,255}`；symlink 与 `nlink > 1` 静默跳过（防止
  跨 inode 攻击）。
- 单文件 32 MiB 安全上限；超过抛 `LegacyImportError(code="contract")`。
- `legacy_path_hint` 只用于 `sha256(domain + hint)` 做 opaque
  tie-breaking；无论 caller 传什么字符串都无法穿透 RT-016 之外
  目录。

### 3.7 零 legacy 写入 / 零漂移

- `LegacySource` 只做读取；从未 open with `O_WRONLY|O_RDWR|O_CREAT`。
- `LegacySource.snapshot()` 在 batch 导入前捕获，`verify_no_drift()`
  在批量导入结束或 reconcile 开始时复核；任何路径 / 字节变化直接
  `LegacyDriftDetected`。
- `MigrationReconciler.reconcile` 内部再走一次 `verify_no_drift`；
  失败设 `zero_drift_verified=False` 但仍出报告，供上层 gate 决策。
- `test_rt016_schemas.FrozenFilesZeroDriftTests.test_no_drift_from_head`
  以 `git show HEAD:<path>` 比对 RT-011~015 冻结模块 / schema /
  security defaults / verified shared extensions 与当前 worktree
  SHA-256；本 RT 交付时 test PASS。

### 3.8 forbidden field 扫描

每份 schema 的 `customKeywords.deepForbiddenProperties` 覆盖：

- 凭据：`app_key / app_secret / credential_ref / credentials /
  agent_id / agent_id_hash / cookie / session_token / authorization /
  prompt_template`。
- 宿主路径：`absolute_path / mirror_root / cwork_root /
  instance_root`（+ review/reconciler 加 `path`）。
- 正文与临时 URL：`canonical_body / body_text / reply_body /
  node_body / html / raw_body / full_content / opinion / message /
  attachment_url / preview_url / short_url / presign_url /
  download_url`（review/reconciler 严格于 crosswalk，额外拦截
  `body / content / reply / replies / node / nodes / attachment /
  attachments / temporary_url`；crosswalk 因合法保存
  `tenant_view.attachment_permissions[].temporary_url` 而不能
  deep-forbid `temporary_url`，Python 层的 `_C.validate_tenant_view`
  已保证 URL 只能在 attachment_permissions 数组下且不能出现在
  canonical 中）。
- 授权 epoch：`auth_epoch / binding_epoch`。

`test_rt016_attacks.ForbiddenFieldScanTests` 在 crosswalk 文件文本
上直接检查 `app_key / credential_ref / cookie / session_token`
关键词与绝对路径样本不出现。

## 6. 关键设计决定回顾

| 决定 | 理由 |
| --- | --- |
| RT-016 自有 subtree 在 `registry/rt016-crosswalk/`（而非扩展 RT-012 `REGISTRY_CHILDREN`） | 不改 RT-012 冻结 allow-list，仍能通过 `layout.child_fd("registry")` + 自有 `_openat_dir_nofollow` 打开 |
| crosswalk_key 按 (tenant, view_key, legacy_source_sha256) 派生 | 幂等/去重的最小键；overlay-only diff 情形下同 canonical 允许多 crosswalk |
| Observation 只写 granted | 严格遵循 RT-015 `cwk.access_observation.v1` 与安全语义（迁移观察不代表授权批准） |
| 生产路径不写 tenant view | RT-015 view store 要求 active grant + lease；无 authority receipt 时无法安全升 active，故记录 deferred_reason 保留完整 envelope 供未来 replay |
| Reconciler 用 crosswalk 作为 new-side 全集 | 不新增 RT-014 enumerate API；每条走 `read_version` 完成完整校验 |
| macOS ENOENT 竞态在 RT-016 侧兜底 | 不修改 RT-015 冻结物；测试显式声明 accepted transient race tokens |

## 8. v1.1 remediation

RT-016 独立验收 Agent 在 commit `c6a740a` 报告 `Verdict = PASS,
Minor=2, Info=2`；本次 remediation 关闭三项（Minor-1 / Minor-2 /
Info-1），Info-2 保留（低风险信息级）。所有改动严格限于 RT-016
自有代码 / schema / 测试 / 文档；未修改 RT-011~015 任何冻结物，
未修改 legacy 数据面模块，未修改 `RT/index.yaml`。

### 8.1 Minor-1 → read 层跨字段完整性绑定

**原报告观察**：`read_crosswalk` 只做字节级 JCS round-trip
（`_canonical_bytes(payload) != raw`），无法检测 JCS-preserving 的语义
篡改（例如把 top-level `canonical_sha256`、`object_id`、
`observe_grant_key`、`view_key` 改为无关值，然后重新 JCS 序列化写回）。

**修复**：新增 `_load_crosswalk_payload` + `_validate_crosswalk_integrity`
两个内部函数（`scripts/cwk_legacy_raw_import.py`），把以下所有读路径
统一走同一整套完整性链路：

- `ShadowImporter.read_crosswalk(...)`
- `ShadowImporter.iter_crosswalks(tenant_id)`
- `ShadowImporter._find_existing_crosswalk_for_legacy(...)`
- `ShadowImporter.import_one` 内 crosswalk 写入前的 CAS 冲突分支

链路顺序（任一失败抛 `LegacyImportError(code="corrupt")`，前置不透
出 Python 内建异常）：

1. UTF-8 解码
2. `strict_json_loads`（同时拦截 duplicate JSON key）
3. RT-016 crosswalk schema
4. RT-011 `validate_tenant_view`（嵌套 tenant_view_envelope）
5. 字节 JCS round-trip：`_canonical_bytes(payload) == raw`
6. **跨字段一致性绑定**：
   - `payload.canonical_sha256 == publish_receipt.canonical_sha256 ==
     tenant_view_envelope.canonical_sha256 ==
     decompose_report.canonical_sha256`
   - `payload.object_id == publish_receipt.object_id`
   - `payload.catalog_key == publish_receipt.catalog_key`
   - `payload.catalog_revision == publish_receipt.catalog_revision`
   - `payload.report_key == publish_receipt.report_key`
   - `payload.object_bytes_sha256 == decompose_report.object_bytes_sha256`
   - `payload.legacy_source_sha256 == decompose_report.legacy_source_sha256`
   - `tenant_view_envelope.tenant_id == payload.tenant_id`
   - `tenant_view_envelope.report_key == payload.report_key`
   - `payload.report_key == compose_report_key(payload.source_namespace,
     payload.report_id)`
   - `payload.view_key == payload.observe_grant_key ==
     compute_grant_key(payload.tenant_id, payload.report_key)`
   - `payload.crosswalk_key ==
     compute_crosswalk_key(payload.tenant_id, payload.view_key,
     payload.legacy_source_sha256)`
7. 额外：文件名 crosswalk_key == payload crosswalk_key；父目录
   tenant_id == payload tenant_id（防重命名 slot 攻击）。

RT-016 v1 写入的每一个正当 crosswalk 都持有以上全部字段（crosswalk
schema 一直要求这些字段必填），因此不存在“无可验证完整性绑定的旧
记录”被静默接受的可能——即便存在，也会在 read 时立即被绑定检查抛
`corrupt`，绝不静默通过。

### 8.2 Minor-2 → source_namespace 幂等键

**原报告观察**：同一 tenant 下同一 raw 字节，在两个不同
`source_namespace` 之间被视为幂等命中，第二次调用静默返回第一次
crosswalk（记在第一次 namespace 下）。

**修复**：

- `compute_review_id(tenant_id, source_namespace, legacy_source_sha256,
  run_id)` 增加 `source_namespace` 参数，纳入域分隔哈希材料 →
  不同 namespace 产生不同 review_id。
- `review_entry.schema.json` 新增必填字段 `source_namespace`；
  `_write_review(source_namespace=...)` 与 payload 一并存储；
  既有 review 命中时交叉核验 tenant/ns/sha/run_id/review_id 与调用
  参数完全一致，否则抛 `corrupt`。
- `_find_existing_crosswalk_for_legacy(..., source_namespace, ...)`
  filter 键新增 `source_namespace`；只有 tenant + ns + sha 三者
  同时匹配才返回既有记录。
- `_find_existing_review(..., source_namespace, ..., run_id)` 改为
  按预期 review_id 精确定位（无需 scan），并对读到的 payload 做
  绑定字段交叉核验。

同一 raw + 不同 ns → 两条独立 crosswalk（不同 crosswalk_key /
view_key / canonical_sha256，各自记正确的 source_namespace）；同一
raw + 同一 ns → 仍幂等（同一 crosswalk_key，manifest 去重）。

### 8.3 Info-1 → JSONDecodeError → LegacyImportError(code="corrupt") 包装

**原报告观察**：`read_crosswalk` 遇到结构性 JSON malformed 时抛裸
`json.JSONDecodeError` / `UnicodeDecodeError`，未包装为
`LegacyImportError`。

**修复**：`_load_crosswalk_payload` / `_load_review_payload` 与
`iter_manifest` 内所有 JSON 解析都用统一的 try/except，捕获
`json.JSONDecodeError` / `UnicodeDecodeError` / RT-011 `ContractError`
（duplicate JSON key），一律包装为
`LegacyImportError(code="corrupt")`，携带可选 `crosswalk_key /

## 9. v2 anchor remediation（本次追加）

RT-016 v1.1 独立验收后 acceptance 报告在 `a2789ef` 发现一个协调篡改
Major 及若干关联问题：v1 crosswalk 的整体字节被替换为“另一条合法

### 9.2 Bound reader（唯一合法的 finder / CAS 入口）

1. 拒绝任何非 v2 crosswalk（v1 不含 source_kind + path_hash，无法
   参与 v2 幂等或对账 PASS）；

写入前的 CAS 冲突分支现均只走这一入口——调用者要么明确声明

`MigrationReconciler.reconcile(*, anchor, run_id, source)` 完全重写：

1. 无 anchor 一律 `LegacyImportError(code="contract")` — 绝不回退到

2. 用 LegacySource dirfd 只读遍历，按每个 `.md` 的 rel-path 计算

5. 磁盘 SHA-256 与 crosswalk `legacy_source_sha256` 比对（不等 →

### 10.1 idempotency 强化（fix 1）

`ShadowImporter.import_one` 与 CAS 冲突分支在 v2 slot 命中既有
crosswalk 后，MUST 调
`_verify_crosswalk_matches_fresh_decompose(payload, raw_bytes=...,
decomposer=self._decomposer, evidence_store=self._evidence)`。该 helper：

1. 用 caller 的 raw_bytes + `run_started_at` 走 fresh
   `LegacyRawDecomposer.decompose(...)`；
2. 逐字段比对 `canonical_sha256 / object_bytes_sha256 / report_key /
   report_id / source_namespace / source_kind / legacy_path_hash /
   legacy_source_sha256 / view_key / observe_grant_key / v2
   crosswalk_key`；
3. 对 `tenant_view_envelope` 做 **canonical projection** JCS bytes 比对
   （`canonical_tenant_view_projection` 只剔 `observed_at` 一个纯
   观测时钟字段）；
4. 用重新算的 `(report_key, canonical_sha256)` 调 RT-014 公共
   `SharedEvidenceStore.read_version()`；
5. RT-014 返回 envelope 重 JCS 序列化后与本次 fresh envelope 逐字节
   比对。

任何一步失败 → `LegacyImportError(code="corrupt")`。协调篡改（把 A
的 crosswalk 字节替换为 B 的自洽 payload、或把 A 的 crosswalk 中的
overlay 静默替换为 B 的 lane/read_status/todo_status）在 import_one /
import_batch 都 fail closed。
