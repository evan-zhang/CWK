## 四、真实攻击结果（包含用户显式追加的协调篡改类）

以下所有断言均由**本 verify Agent 独立编写**（`/tmp/rt016_blackbox.py`），

### 4.1 Minor-1 remediation：JCS-preserving 单字段跨字段绑定

对每次同一 legitimate crosswalk 依次执行 20 组“JCS 保留但语义跑偏”
的单字段篡改，每组同时验证 `read_crosswalk` 与 `iter_crosswalks` 两条
读路径；再加 3 组“文件名/父目录/写路径 CAS 冲突分支”攻击，合计 40
断言，全部收敛为 `LegacyImportError(code='corrupt')`。

**顶层字段（每项验证 read + iter，20 断言）**：
`canonical_sha256` / `object_id` / `object_bytes_sha256` /
`catalog_key` / `catalog_revision` / `view_key` /
`observe_grant_key` / `legacy_source_sha256` / `report_key`；
外加 `publish_receipt.{canonical_sha256, object_id, catalog_key,
catalog_revision, report_key}` /
`tenant_view_envelope.{canonical_sha256, tenant_id, report_key}` /
`decompose_report.{canonical_sha256, object_bytes_sha256,
legacy_source_sha256}`。

**写路径与命名/目录攻击（20 断言中的最后 3 组）**：

- `minor1_filename_key_mismatch` ✓ — 把 JCS-保序的 payload 换名到
  另一 `crosswalk_key` 文件下，`read_crosswalk` 抛 `crosswalk_key
  inside payload disagrees with file name`（code=corrupt）。
- `minor1_wrong_tenant_dir_read` ✓ — 把 payload 复制到另一 tenant
  的 `crosswalks/` 下，`read_crosswalk(tenant_id=other)` 抛
  `crosswalk tenant_id disagrees with parent directory`
  （code=corrupt）。
- `minor1_find_existing_surfaces_corrupt` ✓ — 篡改现有 crosswalk 后
  重复 `import_one`（相同 raw + namespace），`_find_existing_crosswalk_for_legacy`
  经 `_load_crosswalk_payload` 抛 `publish_receipt.canonical_sha256
  disagrees with top-level canonical_sha256`（code=corrupt）。

**结论**：v1 acceptance 报告的 Minor-1 “read 层不检测 JCS-preserving
跨字段篡改”**在 v1.1 remediation 中已闭合**。任何单字段篡改（无论
顶层还是三处嵌套 embedding 的对应字段）都被 `_validate_crosswalk_integrity`
拦截。基线 `baseline_untampered_read_ok` 断言表明合法 crosswalk 仍能
通过完整绑定链（`canonical_sha256` 四处同源、`view_key ==
observe_grant_key` 同源、cross-derivation 正确）。

### 4.6 用户请求追加的协调篡改攻击（Variant A + B）

**攻击定义**：攻击者在临时合成 crosswalk 中**同步**改写 top-level +

`_validate_crosswalk_integrity` 全部十项跨字段一致性检查。

#### Variant A（协调指向 RT-014 catalog 中**不存在**的 canonical）

- 前置：一条 legitimate crosswalk（`legacy_source_sha256=A`,
  `canonical_sha256=C_A`, `report_key=R`）。
- 攻击：把 top-level `canonical_sha256` 与
  `object_bytes_sha256` 改为 `1"*64` / `2"*64`；同步覆盖
  `publish_receipt.canonical_sha256`、
  `tenant_view_envelope.canonical_sha256`、
  `decompose_report.{canonical_sha256, object_bytes_sha256}`。
- `coord_A_read_crosswalk_accepts_coordinated_tamper` ✓ —
  `read_crosswalk` 返回被篡改的 payload **不抛异常**（预期，
  remediation 只做“字段间自洽”，不做“字段与 RT-014 catalog 实际内容
  一致”）。
- `coord_A_reconciler_only_new_on_missing_canonical` ✓ —
  `MigrationReconciler.reconcile` 通过 RT-014
  `read_version(R, "1"*64)` → `SharedEvidenceError(code=not_found)` →
  分类 `only_new`；`both_equal_count == 0`。
- `coord_A_reconciler_flags_canonical_missing` ✓ —
  `failure_samples` 明确包含 `{"classification": "canonical_missing"}`。

**结论 A**：协调篡改指向不存在的 canonical 时，**RT-014 read_version
层能补捕**（与 v1 acceptance 报告对 Minor-1 的“下游 RT-014 层补捕”
论证一致）。read 层单独不检测但 reconciler 会翻车。

#### Variant B（协调指向 RT-014 catalog 中**真实存在**的另一 canonical）

  `report_key` 与 `view_key`。
- 探针确认（预运行）：`read_version(R, C2)` 成功返回真实 envelope，
  因为 C2 是同一 report_key 下的合法第二版本。
- 攻击：把 `cw1` 文件的 top-level `canonical_sha256` /
  `object_bytes_sha256` / `object_id` / `catalog_key` /
  `catalog_revision` 全部改成 `cw2` 的值；把 `publish_receipt` /
  `tenant_view_envelope` 直接深拷贝为 `cw2` 的；把 `decompose_report`
  深拷贝 `cw2` 的但保留 `legacy_source_sha256 = A1`（这是让攻击
  存活的关键：top-level `legacy_source_sha256` 与
  `decompose_report.legacy_source_sha256` 都保持 `cw1` 原值，才能满足
  `_validate_crosswalk_integrity` 的
  `decompose_report.legacy_source_sha256 == top-level` 检查）。
- `crosswalk_key` / `view_key` / `report_key` 均不变（因为
  `view_key = compute_grant_key(tenant, report_key)` 且
  `crosswalk_key = compute_crosswalk_key(tenant, view_key,
  legacy_source_sha256)` — 输入未变，导出键不变），文件名无需
  改动。

**结果**：

- `coord_B_read_crosswalk_accepts_full_coordinated_tamper` ✓ —
  `read_crosswalk(cw1.crosswalk_key)` 返回被篡改 payload；`canonical_sha256
  == C2`，`legacy_source_sha256 == A1`；`_validate_crosswalk_integrity`
  的十条检查全绿（`_C.validate_tenant_view` 也过，因为嵌套 envelope
  是 `cw2` 的合法拷贝且顶层 `tenant_id / report_key` 与其一致）。
- `coord_B_reconciler_reports_both_equal_for_lie` ✓ —
  `reconcile(tenant, run_id, source=legacy_tree_with_raw1+raw2)`
  给出 `both_equal_count == 2`（`only_new_count == 0`）。
  伪 cw1 通过 `read_version(R, C2)` 成功、
  `recomputed_object_bytes_sha256 == cw1.object_bytes_sha256`（因为
  两者都被改成 `C2` 的值）、`legacy_shas[A1] == [raw1_file]` 命中，
  被判为 `both_equal`。真 cw2 也是 `both_equal`。**总数字上没有异常
  ——但语义上伪 cw1 声称“raw1 → C2”，这是纯粹的谎言（真实是
  raw1 → C1）**。
- `coord_B_no_failure_sample_flags_lie` ✓ —
  `failure_samples` 为空；`canonical_missing` /
  `canonical_sha_mismatch` / `object_bytes_sha_mismatch` 均未触发。
- `coord_B_reconciler_still_catches_truly_bogus_canonical` ✓ —
  对照实验：把伪 cw1 的所有 canonical 字段再改成 `"3"*64`（不存在
  的 canonical）后，reconciler 立刻回落到 `canonical_missing`
  分类（`only_new_count == 1`）。证明 reconciler 的失败模式判定是
  实测有效的，唯一的盲区就是“coordinated 指向真实第二版本”。

**结论 B**：**这是一个 remediation 之后仍存在的残余深度防御缺口**。
详见 §五 Minor-3。

#### Minor-3（新增 · 本 verify Agent 应用户请求追加显式覆盖）：跨字段协调篡改在 read 与 reconcile 双侧的残余缺口

**观察**：v1.1 remediation 的 `_validate_crosswalk_integrity` 仅校验
crosswalk **payload 内部**的自洽（顶层字段与嵌套 `publish_receipt` /
`tenant_view_envelope` / `decompose_report` 相应字段一致，且能重推
`report_key` / `view_key` / `crosswalk_key` 三条 domain-separated
派生）。它**不**校验：

- crosswalk 声明的 `canonical_sha256` 是否真的对应
  `read_version(report_key, canonical_sha256)` 返回的 RT-014
  catalog 内容；
- crosswalk 声明的 `legacy_source_sha256` 是否真的能被
  `LegacyRawDecomposer.decompose` 重演出声明的 `canonical_sha256`。

`MigrationReconciler.reconcile` 补捕了第一条（通过
`SharedEvidenceStore.read_version`）；但对第二条它**只做“存在性 +
`object_bytes_sha256` 复核”**，不重跑 decomposer。当攻击者具备
`registry/rt016-crosswalk/<tenant>/crosswalks/` 的写权限，并且同一
`report_key` 下已经合法发布过第二个 canonical 版本时，即可构造
Variant B（§4.6）——payload 自洽、read_crosswalk 静默通过、reconciler
判为 `both_equal` —— 但这个 `both_equal` 语义上是**错误映射**
（crosswalk 声称 legacy A1 → canonical C2，实际 legacy A1 → canonical
C1）。

**可复现步骤（100% 复现率，见 `/tmp/rt016_blackbox.py` §Variant B）**：

```python
# 1) publish legitimate v1 and v2 of same report_id.
r1 = importer.import_one(tenant_id=tid, source_namespace="cwork",
    raw_bytes=sample_raw(report_id="2070777", body="V1"), ...)
r2 = importer.import_one(tenant_id=tid, source_namespace="cwork",
    raw_bytes=sample_raw(report_id="2070777", body="V2"), ...)
cw1 = importer.read_crosswalk(tenant_id=tid, crosswalk_key=r1.crosswalk_key)
cw2 = importer.read_crosswalk(tenant_id=tid, crosswalk_key=r2.crosswalk_key)

# 2) coordinated rewrite: cw1's file becomes fully consistent with cw2's canonical
#    while keeping cw1's own legacy_source_sha256.
cw1_path = <registry>/rt016-crosswalk/<tid>/crosswalks/<cw1_key>.json
payload = json.loads(cw1_path.read_bytes())
payload["canonical_sha256"] = cw2["canonical_sha256"]
payload["object_bytes_sha256"] = cw2["object_bytes_sha256"]
payload["object_id"] = cw2["object_id"]
payload["catalog_key"] = cw2["catalog_key"]
payload["catalog_revision"] = cw2["catalog_revision"]
payload["publish_receipt"] = deepcopy(cw2["publish_receipt"])
payload["tenant_view_envelope"] = deepcopy(cw2["tenant_view_envelope"])
d2 = deepcopy(cw2["decompose_report"])
d2["legacy_source_sha256"] = cw1["legacy_source_sha256"]  # 关键
payload["decompose_report"] = d2
cw1_path.write_bytes(canonical_json_bytes(nfc_normalize(payload)))

# 3) read layer accepts (no LegacyImportError).
importer.read_crosswalk(tenant_id=tid, crosswalk_key=r1.crosswalk_key)
    # → returns tampered payload silently

# 4) reconciler classifies as both_equal for the lie.
report = reconciler.reconcile(tenant_id=tid, run_id=..., source=<legacy_tree>)
    # → both_equal_count == 2, only_new_count == 0, failure_samples == []
```

**冲击评估**：

- **攻击面**：需要
  `registry/rt016-crosswalk/<tenant>/crosswalks/` 目录写权限（0o700，
  RT-012 `DIRECTORY_MODE`），且同 report_key 下已经存在合法多版本
  canonical——若攻击者已在该目录内，本身已在信任边界内部。此攻击
  不越过 tenant 边界（`payload.tenant_id` 必须匹配父目录，
  Minor-1 §4.1 已验证），不越过 report_key 边界（`publish_receipt.report_key`
  必须匹配 `top-level report_key`），不产生凭据/URL/绝对路径泄漏。
- **数字不出错**：`both_equal_count` 数值**未被虚增**（两条 crosswalk
  对应两条 legacy raw，都被判 both_equal）。真正的错误是**逐条 crosswalk
  的 legacy→canonical 映射语义**——`failure_samples` 与
  `reconciliation_report` schema 目前不暴露单条映射，所以观测层不会
  发现异常。
- **潜在后果**：
  - RT-025（clean-room restore 演练）如按 crosswalk 反查 canonical，
    可能恢复到错误版本。缓解：RT-025 加密备份应覆盖
    `registry/rt016-crosswalk/`，攻击者需先破坏备份签名；另外可
    强制“恢复时重跑 decomposer 与 crosswalk 交叉核对”。
  - RT-026（legacy vs new 试点切换 diff）如按 crosswalk 直读，可能
    错报“无 diff”。缓解：RT-026 diff 引擎本身若在两侧独立重跑
    decomposer 会自然发现不一致。
- **与 spec 承诺关系**：
  - `rt-intake §六` 只承诺“读时逐字节复核，任何漂移抛 corrupt”——
    v1.1 的绑定链把这条落实到“字节 + 内部自洽”，但确实**未**承诺
    “内容与 RT-014 catalog / decomposer 的跨制品一致”。
  - `MigrationReconciler` docstring 只承诺 `both_equal` 语义为
    “crosswalk 声明与 RT-014 read_version + object_bytes_sha256
    复核 + 磁盘 raw SHA-256 一致”——**没有**承诺“crosswalk 声明的
    canonical 就是从这份 raw 重解码得到”。
  - 因此本项**并不违反字面 spec**，属于**深度防御残余**。

**建议**（不阻塞 remediation 合入）：

1. `read_crosswalk` 保持现状；将“cross-artefact 一致性”下沉给
   `MigrationReconciler`。
2. `MigrationReconciler.reconcile` 增加可选 `verify_by_redecompose=True`
   参数：命中 both_equal 时对 `legacy_source` 重跑
   `LegacyRawDecomposer.decompose(raw_bytes=…)`，比较结果的
   `canonical_sha256` 与 `crosswalk.canonical_sha256`；不一致时
   降级为 `canonical_sha_mismatch` 分类并写入 `failure_samples`。
3. 或者：`ReconciliationReport` 中把 `failure_samples` 扩展为逐条
   `both_equal` 采样（含 opaque `crosswalk_key` + `sha_verified=true/false`
   flag），让审计层能事后 spot-check。
4. RT-025 加密备份策略应显式声明覆盖 `registry/rt016-crosswalk/`
   且备份完整性受 authority-signed manifest 约束（与 v1 acceptance
   已提出的 RT-025 演练前处理保持一致）。

**Severity 判定**：**Minor**——不违反字面 spec、不越过 tenant/
report_key 边界、不泄漏凭据；但突破了 v1 acceptance 对 Minor-1
“下游 RT-014 层能补捕”的乐观假设边界（当攻击者能指向合法第二
canonical 时，RT-014 不再补捕）。属于跨 RT 深度防御建议，不作为
本次 remediation 的合入阻塞。用户明确要求在报告中如实覆盖并给出
结论，故列入。
