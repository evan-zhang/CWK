### Minor（2）

#### Minor-1：`read_crosswalk` / `iter_crosswalks` / `_find_existing_crosswalk_for_legacy` 不检测 JCS-preserving 跨字段篡改

**观察**：`read_crosswalk` 内做字节级复核 `_canonical_bytes(payload) != raw`，
这只能证明磁盘字节能 roundtrip 通过 JCS 规范化；无法证明字段之间的
语义一致性。攻击者若能写入 `registry/rt016-crosswalk/<tid>/crosswalks/<cw>.json`，
可以：

1. 解析 → `payload = json.loads(original)`
2. 篡改 `payload["canonical_sha256"] = "0" * 64` 或
   `payload["object_id"] = "o_" + "a"*26` 或
   `payload["observe_grant_key"] = "g_" + "b"*26`
3. 重新 JCS 序列化 → 写回

此后 `read_crosswalk` 与 `iter_crosswalks` **静默返回被篡改的 payload**，
不抛任何异常；下游若不再走 RT-014 `read_version` 或 RT-015
`_grants` 二次验证，则会消费到不一致的数据。

**可复现复现步骤**（复现率 100%）：

```python
cw = importer.read_crosswalk(tenant_id=tid, crosswalk_key=r.crosswalk_key)
cw_path = tmp_root / "registry" / "rt016-crosswalk" / tid / "crosswalks" / f"{r.crosswalk_key}.json"
orig = cw_path.read_bytes()
payload = json.loads(orig)
payload["canonical_sha256"] = "0" * 64
cw_path.write_bytes(canonical_json_bytes(nfc_normalize(payload)))
got = importer.read_crosswalk(tenant_id=tid, crosswalk_key=r.crosswalk_key)
assert got["canonical_sha256"] == "0" * 64   # ← silently returned
assert got["publish_receipt"]["canonical_sha256"] != "0" * 64   # ← inconsistent!
```

**冲击评估**：

- 攻击面：需要磁盘写权限进入 `registry/rt016-crosswalk/`，即已在
  trust boundary 内部。
- 下游 `MigrationReconciler.reconcile` 会调用
  `SharedEvidenceStore.read_version(report_key, "0"*64)` → RT-014 返回
  `SharedEvidenceError(code="not_found")` → 报告分类为
  `canonical_missing`。所以最终**不会**在读端产生 canonical 混淆。
- 但 rt-intake §六 明文承诺 “读时逐字节复核，任何漂移抛
  `LegacyImportError(code='corrupt')`”——语义漂移不在字节复核覆盖内，
  与承诺语气有偏差。
- 未产生：canonical/grant/view 被跨 tenant 或跨 report 错误引用；未产生
  凭据 / URL / 绝对路径泄漏；未跨越 tenant 边界。

**建议**（不阻塞验收）：`read_crosswalk` 在 payload 通过 schema 后，额外做
- 顶层 `canonical_sha256 == publish_receipt.canonical_sha256 ==
  tenant_view_envelope.canonical_sha256 == decompose_report.canonical_sha256`；
- `crosswalk_key == compute_crosswalk_key(tenant_id, view_key, legacy_source_sha256)`；
- `observe_grant_key == compute_grant_key(tenant_id, compose_report_key(source_namespace, report_id))`；
- `view_key == observe_grant_key`；
- `object_bytes_sha256 == sha256(canonical_json_bytes(nested tenant_view_envelope))` 或与
  `publish_receipt.object_bytes_sha256` 一致。

任一不一致抛 `LegacyImportError(code="corrupt", crosswalk_key=cw)`。这
将把 rt-intake §六 的承诺落到实处。

**Severity 判定**：**Minor**——下游 RT-014/RT-015 层能补捕，未违背字面
spec（字节复核确实执行），未突破 tenant 边界；仅是 read 层深度防御
不够。

#### Minor-2：跨 namespace 幂等碰撞（identical raw bytes）

**观察**：`_find_existing_crosswalk_for_legacy` 仅按
`(tenant_id, legacy_source_sha256)` 匹配。如果 caller 用**完全相同的
raw 字节**在同一 tenant 下先后传入两个不同的 `source_namespace`，
第二次调用会**静默返回第一次的 crosswalk**：

```python
r1 = importer.import_one(tenant_id=tid, source_namespace="cwk_reports",
                         raw_bytes=raw, ..., legacy_path_hint="a.md")
r2 = importer.import_one(tenant_id=tid, source_namespace="cwk_alt_ns",
                         raw_bytes=raw, ..., legacy_path_hint="a.md")
# 观察：
#   r1.view_key == r2.view_key                    (来自 cwk_reports 的 grant_key)
#   r1.crosswalk_key == r2.crosswalk_key          (同一 crosswalk 文件)
#   cw2["source_namespace"] == "cwk_reports"      (即使 caller 传的是 cwk_alt_ns)
```

`ImportReceipt` 未标记“this call hit idempotency cache from a different
source_namespace”；操作员如按 receipt 结果统计 “cwk_alt_ns 已迁移
1 份”，实际上 crosswalk 记在 `cwk_reports` 命名空间下，产生统计偏差。

**冲击评估**：

- 不违背 spec 显式条款（rt-intake / 需求契约未明确规定跨 namespace 同
  raw 应如何处理）。
- 不产生 tenant 边界越权（都在同一 tenant 内部）。
- 不产生 canonical / grant / view 数据泄露。
- 生产环境下同一 raw 文件通常只落一个 namespace，因此可观测风险很低。
- 但若 RT-026 / RT-017 引擎按 (tenant, namespace, report_id) 计算迁移
  完成率，需要额外把 crosswalk 的 `source_namespace` 与 caller 声明的
  `source_namespace` 显式对比。

**建议**（不阻塞验收）：将幂等键改为
`(tenant_id, source_namespace, legacy_source_sha256)`；如果 caller 声明
的 `source_namespace` 与既有 crosswalk 不同，要么写一条新 crosswalk，
要么抛 `LegacyImportError(code="conflict",
message="legacy raw already migrated under different source_namespace")`。

**Severity 判定**：**Minor**——设计模糊，语义偏差；不构成安全事件。

### Info（2）

#### Info-1：`read_crosswalk` 不把 `json.JSONDecodeError` 包装为 `LegacyImportError`

**用户提问回复**：JSON parse 现象是**可复现的真实行为**，但**不是安全
缺陷**：

- 复现：`cw_path.write_bytes(original[:-2] + b" \n")` → 后续
  `read_crosswalk` 抛原始 `json.JSONDecodeError: Invalid control
  character at column 3123`，未被 `LegacyImportError(code='corrupt')` 包装。
- 语义正确性：异常仍中断 read，篡改字节从不被静默采信；未产生任何
  canonical/grant/view 静默传播。
- Spec 一致性偏差：需求契约 §一 明确 “任一失败抛 `LegacyImportError
  (code='corrupt')` 或 `code='contract'`”。目前 JSON 解析错误未走
  该 taxonomy，可能给依赖 `except LegacyImportError` 的 caller 带来
  一次意外的 Python 内建异常。

**Severity 判定**：**Info**——错误 taxonomy 一致性问题，无安全或数据
影响。建议 `read_crosswalk` / `iter_reviews` / `iter_manifest` 内加
`try: json.loads → except json.JSONDecodeError: raise LegacyImportError(code="corrupt")`。

#### Info-2：unknown_reply_keys 数组回显 legacy raw 的键名

**观察**：当 legacy raw 的 `replyList[i]` 中含未知键（例如
`attachment_url`），decompose_report 的 `unknown_reply_keys` 会记录
键名字符串（不含值）。crosswalk 文件文本上因此会出现字符串
`"attachment_url"`——但**只是键名**，URL VALUE (`https://z.invalid/a.pdf`)
从不被写入。

**冲击评估**：仅泄漏 legacy raw 的 schema 形状，无用户数据；schema 形状
本身在多个位置已公开。

**Severity 判定**：**Info**——低风险信息泄漏，不修复也可接受。
