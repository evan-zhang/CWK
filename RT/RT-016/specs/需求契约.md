## 二、schema 契约

`PR/PR-001-multitenant-knowledge-spaces/contracts/rt016/schemas/` 独占：

- `decompose_report.schema.json` — `cwk.pr001.rt016.decompose_report.v1`：
  `additionalProperties:false + unevaluatedProperties:false`；必填
  `schema/decomposer_version/normalizer_version/legacy_source_sha256/
  canonical_sha256/object_bytes_sha256/body_bytes_length/
  body_truncation_would_occur/field_sources/hit_rules/
  unknown_frontmatter_keys/unknown_row_keys/unknown_reply_keys/
  unknown_node_keys/timeline_event_hash_check/decomposition_status/
  quarantine_reasons`；`decomposition_status ∈ {ok, quarantined}`；
  `quarantine_reasons` 枚举覆盖 missing / malformed / oversize / control /
  timeline / path / TOCTOU / Unicode 冲突等 25 项；
  `deepForbiddenProperties` 拦截 credential/body/temporary_url/path。
- `migration_crosswalk.schema.json` —
  `cwk.pr001.rt016.migration_crosswalk.v1`：`crosswalk_key ^cw_[a-z2-7]{26}$`；
  必填三类 hash + `publish_receipt`（结构由 Python 端二次校验为 RT-014
  publish_receipt.v1）+ `tenant_view_envelope`（由 RT-011
  `validate_tenant_view` 二次校验）+ `decompose_report`（由本 RT
  decompose_report schema 二次校验）+ `observe_grant_key`（`^g_[a-z2-7]{26}$`）+
  `observation_source ≡ "legacy_raw_decomposition"` +
  `initial_status ≡ "granted"` + `tenant_view_written` 布尔 +
  `tenant_view_deferred_reason ∈ {null, no_authority_receipt_available,
  authority_receipt_rejected, access_ledger_denied, canonical_missing,
  in_flight_revocation, not_attempted}`；`timeline_snapshot_hashes` /
  `timeline_event_hashes` 各自 unique 上限 4096；
  `deepForbiddenProperties` 拦截 credential / canonical_body /
  reply_body / node_body / auth_epoch / binding_epoch / cookie 等。
- `review_entry.schema.json` —
  `cwk.pr001.rt016.review_entry.v1`：`review_id ^qe_[a-z2-7]{26}$`；
  `migration_status ∈ {review, undecomposable}`；`quarantine_reasons`
  至少一项；`deepForbiddenProperties` 严于 crosswalk（额外拦截
  `reply / node / attachment / temporary_url` 等），因为 review
  永远不应携带这些字段。
- `migration_manifest_entry.schema.json` —
  `cwk.pr001.rt016.migration_manifest_entry.v1`：一行一 JSON；
  `outcome ∈ {complete, review, undecomposable}`；`entry_seq >= 1`；
  可选字段 `crosswalk_key / review_id / canonical_sha256 / view_key /
  quarantine_reasons` 依 outcome 出现。
- `reconciliation_report.schema.json` —
  `cwk.pr001.rt016.reconciliation_report.v1`：所有 count 字段 `>=0`；
  三类 rate ∈ [0, 1]；`zero_drift_verified` 布尔；
  `failure_samples[]` classification ∈ 9 类枚举；`opaque_key` 只允许
  `^[a-z0-9_.:/\-]+$`；`deepForbiddenProperties` 与 review 相同。

## 三、错误 taxonomy（`LegacyImportError.code`）

| code | 语义 |
| --- | --- |
| `contract` | schema / 字段 / JCS / 类型违反（含 unknown source_kind / bad run_id 等） |
| `not_initialized` | RT-016 或依赖子目录尚未创建（例如未调用 `initialize()`） |
| `not_found` | 请求的 tenant / crosswalk / review 子目录不存在 |
| `conflict` | 内部并发冲突（保留字段，当前实现不主动触发） |
| `state` | 非法状态迁移（保留字段） |
| `io` | 底层 I/O 出错（打开子目录、fstat 失败） |
| `corrupt` | crosswalk / review / manifest 字节漂移或 schema 反向复核失败 |
| `log_injection` | actor / reason 含控制字符或超长 |
| `path_containment` | LegacySource root 是 symlink / 不是目录 / 子路径穿透 |
| `legacy_drift` | Pre-scan 与 re-scan 不一致 |
| `duplicate_report_id` | 保留：预留给未来强隔离；当前依 RT-014 catalog 语义处理 |
| `authority_deferred` | 保留：预留给未来 tenant view 强制 upsert 流程 |
| `ledger_denied` | RT-015 observe / promote 失败被 RT-016 视作 fail-closed 的对外错误 |
| `canonical_missing` | 保留 |
| `internal` | RT-016 自身不变量被打破（例如 opaque_id 长度失败） |

## 五、v2 anchor-bound identity（自 RT-016 v2 remediation）

### 5.1 v2 identity 五元组

RT-016 v2 records 的 identity 材料严格为
`(tenant_id, source_namespace, source_kind, legacy_path_hash,
legacy_source_sha256)`，由独立 domain separator
`cwk-rt016-crosswalk-key-v2` / `cwk-rt016-review-id-v2` 派生。v1 与 v2
opaque key 空间正交，永不碰撞。同一 raw bytes 在不同 namespace / 不同
path / 不同 source_kind 下必然得到不同 crosswalk_key / review_id /
manifest 行 identity；允许共享 RT-014 canonical，但 crosswalk / review /
manifest 记录彼此独立。

### 5.2 ReconciliationAnchor（对账契约）

`MigrationReconciler.reconcile(*, anchor, run_id, source)` 要求 caller
提供 `ReconciliationAnchor(tenant_id, source_namespace, source_kind,
decomposer_version, normalizer_version)` — 五个字段都是**运行时可信输
入**（不从 crosswalk 自述读出）。无 anchor 一律
`LegacyImportError(code="contract")`；anchor 任一字段与 crosswalk 不符
即计入 `anchor_mismatch`，绝不 `both_equal`。

### 5.3 v2 强对账流程

对每条 v2 crosswalk（顺序 fail-closed）：

1. 从 LegacySource dirfd 只读，按 crosswalk 的 `legacy_path_hash` 定位
   磁盘 bytes；未找到 → `legacy_bytes_missing`。
2. `sha256(bytes) == crosswalk.legacy_source_sha256` — 不等 →
   `legacy_source_sha_drift`。
3. 用 anchor 的 decomposer/normalizer 版本 fresh
   `LegacyRawDecomposer.decompose(...)`；`status != "ok"` →
   `re_decompose_mismatch`。
4. 逐字段比对（重新推导）：`canonical_sha256` / `object_bytes_sha256` /
   `report_key` / `view_key` / `observe_grant_key` / v2 `crosswalk_key` /
   **`tenant_view_envelope` 的 NFC+JCS bytes**（lane / read_status /
   todo_status / reply_overlay / node_overlay 任一漂移即失败）。任一
   不符 → `re_decompose_mismatch`。
5. 用重新计算的 `(report_key, canonical_sha256)` 调 RT-014 公开
   `SharedEvidenceStore.read_version()`；异常 → `canonical_missing` /
   `object_bytes_sha_mismatch` / `canonical_sha_mismatch`。
6. RT-014 返回的 envelope 重新 JCS 序列化，与自己 fresh 重算的 envelope
   JCS bytes **逐字节比对**（`read_version_bytes_mismatch`）。

只有第 1~6 全部通过才计入 `both_equal`。

### 5.4 v1 audit boundary

v1 crosswalk / review 保留可读（`read_crosswalk` / `iter_crosswalks` /
`iter_reviews` 的 audit 视图），但：

- 永远不进入 v2 importer 的幂等命中路径（v2 finder 只查 v2 slot）。
- v1 crosswalk 永远计入 `unanchored_v1_count`，绝不 `both_equal`。
- v1 review 从不参与 `only_legacy` coverage arithmetic（只有 v2 review
  才能贡献 coverage，且必须 `(legacy_path_hash, legacy_source_sha256)`
  与磁盘当前 raw 匹配才会抑制 `only_legacy`；raw SHA 漂移的 v2 review
  计入 `review_source_sha_drift` 并不抑制 `only_legacy`）。
- 允许 pre-Minor-2 shape（无 `source_namespace` 字段）通过 audit-only
  loader；这类记录也 100% 走上述 unanchored 路径。

### 5.5 idempotency 强化：finder / CAS 命中必须 fresh-decompose

`ShadowImporter.import_one` 在 finder 命中或 CAS 冲突分支重读既有
crosswalk 后，MUST 用本次 caller 的 `raw_bytes` 重新 decompose，并按
5.3 中步骤 4~6 完整比对；任何不一致 → `LegacyImportError(code=
"corrupt")`。这一步是防御“协调篡改”的关键——即使既有 crosswalk 的
bound-reader identity 与 caller 完全一致，只要其内容与 fresh
decompose + RT-014 read_version 不逐字节相等，即拒绝复用。

### 5.6 Bound readers（唯一合法读入口）

- `_load_crosswalk_payload_bound(raw, expect=_BoundReaderExpect(...))`
  用于 finder / CAS conflict。
- `_load_review_payload_bound(raw, tenant_id, filename_review_id,
  require_v2=…)` 用于 `iter_reviews` / `_find_existing_review`。
- `_load_manifest_line_bound(raw_line, tenant_id, filename_run_id,
  line_number, expected_entry_seq=…)` 用于 `iter_manifest` 与
  **`_append_manifest_entry` 的全量既有行 replay**（第三轮修复：append
  路径禁止直接 `strict_json_loads + schema` 后加入 dedupe seen）。
  强制项：strict JSON、JCS+NFC raw canonical bytes 逐字节回环、schema
  校验、tenant/run 绑定、`entry_seq` 连续且唯一、`outcome` 与
  `crosswalk_key`/`review_id` 出现关系、`complete` 记录的 v2
  `crosswalk_key` = `compute_crosswalk_key_v2(tenant, ns, kind,
  path_hash, raw_sha)`、`review`/`undecomposable` 记录的 v2 `review_id`
  = `compute_review_id_v2(...run_id)`。

三者共同强制：**filename ↔ payload id、parent-dir tenant ↔ payload
tenant、v2 identity 重推导等式**。任一不符抛
`LegacyImportError(code="corrupt")`；一条坏 review / manifest 行永远
不会被静默计入 coverage / dedupe，也永远不会先命中 dedupe 再在以后
才报错。

### 5.7 检测边界（明确不宣称）

上述保证只在“RT-016 registry 被攻击者写入 **同时** LegacySource dirfd
只读读取路径与 RT-014 SharedEvidenceStore 底层 shared/ 目录彼此独立、
未在同一时间窗口被同一攻击者篡改”的前提下成立。三方共谋不在本层
保证范围。不做任何生产系统整体不可篡改宣称；不宣称 M3/M4/M5/G3/VG-A/
真实租户切换。
