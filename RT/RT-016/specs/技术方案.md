# RT-016 技术方案：LegacyRawDecomposer + ShadowImporter + MigrationReconciler

> 目的：把 PRD FR-06/FR-20、DESIGN §12 M2/M3、开发计划 §9 RT-016 的
> “不动 legacy 树、只写 RT-016 自有命名空间、通过 RT-014/RT-015 公开
> writer 完成影子迁移与数据对账” 落地为可独立测试的库函数，不新增
> 运行时入口、不修改任何冻结模块。

## 1. 组件拓扑

RT-016 **不引入新写路径** 到 RT-011~015 的存储：

- 通过 `SharedEvidenceStore.publish` 间接写入 `shared/`；
- 通过 `AccessLedger.observe` 间接写入
  `registry/access-ledger/<tenant>/…`；
- 通过 `TenantViewStore.upsert_overlay` 间接写入
  `tenants/<tenant>/views/`，且**仅在 fake authority 端到端测试**
  下执行；生产路径永不落 view；
- RT-016 自有 durable 数据只写到 `registry/rt016-crosswalk/`；
- staging 只用 `staging/rt016/` 前缀。

## 2. 磁盘布局

```
CWK_INSTANCE_ROOT/
├── registry/
│   └── rt016-crosswalk/           (RT-016 owned, 0o700)
│       └── <tenant_id>/           (0o700)
│           ├── crosswalks/<cw_...>.json    (0o600, CAS via cwk_atomic_file)
│           ├── review/<qe_...>.json        (0o600, CAS)
│           ├── manifests/<run_id>.jsonl    (0o600, append-only, CAS)
│           └── locks/                       (0o700, flock anchors)
├── staging/
│   └── rt016/                     (RT-016 owned, 0o700)
│       └── <run_id>/              (0o700, temp workspace, cleaned by recover)
└── (unchanged) tenants/、shared/、registry/access-ledger/…
```

关键说明：

- `rt016-crosswalk` 与 `rt016` 不在 RT-012 `REGISTRY_CHILDREN` /
  `INSTANCE_ROOT_CHILDREN` allow-list 中；RT-016 通过
  `layout.child_fd("registry")` / `layout.child_fd("staging")` 打开
  父目录，然后用自己的 `_openat_dir_nofollow` helper 打开子目录，
  避免修改 RT-012 冻结常量。
- `crosswalk_key = "cw_" + base32_lower(sha256(domain \0 tenant_id
  \0 view_key \0 legacy_source_sha256)[:16])`，全局唯一 128 bit；
  同 view_key + 同 legacy raw → 同 crosswalk_key；overlay-only diff
  下同 view_key 但不同 legacy raw → 不同 crosswalk_key（两条独立
  记录，共享 canonical）。
- `review_id = "qe_" + base32_lower(sha256(domain \0 tenant_id \0
  legacy_source_sha256 \0 run_id)[:16])`；同一 raw 在同一 run 中
  幂等，跨 run 会生成新的 review 用于审计追溯（并覆盖到 manifest
  entry）。
- 每个 tenant 独立子树，`O_NOFOLLOW` 全程；不新增枚举 API。
- 每个 `<cw_key>` / `<review_id>` 都有独立 `flock` 锚；manifest
  写入使用 `mf.<run_id>.lock`，避免多写者交错行。

## 3. 数据契约

见 `PR/PR-001-multitenant-knowledge-spaces/contracts/rt016/schemas/`
与 `../需求契约.md § 二`。所有 schema 都通过 RT-011
`_validate_schema` + `_iter_deep_forbidden` 校验，不重实现 JSON Schema
引擎；嵌套字段 `publish_receipt / tenant_view_envelope /
decompose_report` 用 Python 端二次校验（RT-014 publish_receipt.v1、
RT-011 tenant_view.v1、RT-016 decompose_report.v1）。

三类哈希的确定方式：

- `legacy_source_sha256 = sha256(raw_bytes)`：原始 Markdown 磁盘
  字节，无任何解析 / 规范化。
- `canonical_sha256`：`_C.canonical_sha256(partial)`（内部 =
  `sha256(canonical_json_bytes(nfc_normalize(partial)))`），其中
  `partial` 是 canonical envelope 剔除 `canonical_sha256` 字段
  后的字典。RT-011 `validate_canonical_envelope` 会再次重算并核对，
  实现事实上的三重防护。
- `object_bytes_sha256 = sha256(canonical_json_bytes(envelope))`：
  envelope 完整字节（包含 canonical_sha256 字段）；等于 RT-014
  catalog entry 的 `object_bytes_sha256`。三者永不宣称相等。

## 4. 状态机与不变量

- `DecomposeResult.status ∈ {ok, quarantined}`。`quarantined` 时三个
  envelope 全部为 `None`，`decompose_report.quarantine_reasons` 非空；
  不允许部分产出。
- `ImportReceipt.outcome ∈ {complete, review, undecomposable}`；
  `undecomposable` 用于结构级不可读（malformed frontmatter /
  missing body / oversize），其余归入 `review`（可人工修复）。
- Crosswalk 一旦写入即不可覆盖；重复 `import_one` 只允许 CAS 校验
  内容一致后返回原 receipt；`canonical_sha256` / `observe_grant_key` /
  `object_id` 任意漂移 → `LegacyImportError(code="corrupt")`。
- Manifest jsonl 内 `(legacy_source_sha256, outcome)` 二元组一 run
  内唯一；命中重复直接跳过。
- Tenant view：
  - 生产路径（无 authority receipt）永远 `tenant_view_written=False`；
    `tenant_view_deferred_reason="no_authority_receipt_available"`；
  - fake authority 端到端成功 → `tenant_view_written=True`；
    `tenant_view_deferred_reason=None`；record_revision=1；
  - fake authority 失败（签名不匹配 / receipt binding 错 / lease
    过期）→ deferred_reason 精细分类，canonical + observation
    仍持久化；
  - **RT-016 从不自行绕过 `granted → active` 迁移，也不宣称完成
    生产迁移。**
- LegacySource：
  - `snapshot()` 记录 pre-scan hash；`verify_no_drift()` 与
    `re_scan()` 一致则通过，任何 add/remove/modify 均抛
    `LegacyDriftDetected`；
  - 迭代过程中 symlink 与 `nlink>1` 文件跳过；
  - root 若为 symlink 或非目录，构造时抛
    `LegacyImportError(code="path_containment")`。

## 5. Import 流程（crash-safe）

```
import_one(tenant_id, source_namespace, raw_bytes, run_id, ...)
├─ 校验 actor/reason (log-injection 防御)
├─ validate tenant_id/source_namespace/run_id/run_started_at/raw_bytes
├─ tenants.get(tenant_id)  # 提前 fail-close 未知 tenant
├─ open registry/rt016-crosswalk/<tenant_id>/ (create=True)
├─ _find_existing_crosswalk_for_legacy   → 幂等返回既有 receipt
├─ _find_existing_review                 → 幂等返回既有 review
├─ LegacyRawDecomposer.decompose(...)    → DecomposeResult
├─ status=quarantined:
│   ├─ _write_review(...)  (CAS + JCS bytes)
│   └─ _append_manifest_entry(outcome=review|undecomposable)
├─ status=ok:
│   ├─ SharedEvidenceStore.publish(envelope) → PublishReceipt
│   ├─ AccessLedger.observe(observation, actor, reason)  (retry macOS ENOENT)
│   │        └── grant.status = granted
│   ├─ if authority_receipt:
│   │     AccessLedger.promote_to_active(receipt)
│   │       ├── 成功 → TenantViewStore.upsert_overlay(view_envelope)
│   │       │        → tenant_view_written=True
│   │       └── 失败 → tenant_view_deferred_reason 精细分类
│   ├─ 组装 crosswalk_payload，
│   │  Python 端二次校验 tenant_view_envelope (RT-011)
│   │                    decompose_report (RT-016)
│   │                    publish_receipt (RT-014 shape)
│   ├─ flock(cw.<crosswalk_key>.lock):
│   │     if leaf exists: 校验内容一致 → 返回 existing
│   │     else: cas_write(crosswalks/<cw>.json, JCS bytes, expected=None)
│   └─ flock(mf.<run_id>.lock):
│         cas_write(manifests/<run_id>.jsonl, current + entry + b"\n",
│                   expected=current_sha)
└─ return ImportReceipt
```

- 所有 CAS 写在独立 flock 下进行，避免 macOS 上的写入交错。
- 每一步之间的崩溃：
  - publish 之后 observe 之前崩溃：canonical 已发布（idempotent），
    重跑 import_one 会重进 publish（RT-014 幂等）后继续 observe。
  - observe 之后 crosswalk 之前崩溃：grant 已 granted（幂等），
    重跑 import_one 会重进 observe（RT-015 幂等）后写 crosswalk。
  - crosswalk 之后 manifest 之前崩溃：`_find_existing_crosswalk_for_legacy`
    命中 → 返回 receipt；`_append_manifest_entry` 幂等（按
    (legacy_source_sha256, outcome) 去重）。
- `recover(actor, reason)` 幂等 sweep 每个 tenant 每个 subdir 的
  `.cwk-tmp-*` 孤儿；不修改 durable crosswalk / review / manifest。

## 6. 与 RT-015 公共 writer 的边界

- `AccessLedger.observe` 允许写入的 status 仅
  `discovered / granted`；RT-016 始终写 `granted`。RT-015 会保留
  幂等语义（同 grant 已 granted 再传 granted 直接 no-op）。
- `AccessLedger.promote_to_active` 要求 authority receipt +
  tenant.status ∈ {pilot, active}（不含 draft/suspended/offboarded）。
  生产环境下 RT-016 无 receipt，无法调用，也不会调用。
- `TenantViewStore.upsert_overlay` 要求：
  1) valid `AgentContextSnapshot`；
  2) tenant.status ∈ {pilot, active} + snapshot.tenant_status 一致；
  3) grant.status == "active" + lease 未过期；
  4) canonical 已发布；
  5) 二次 recheck 未变化。
  这些前置在 RT-016 fake authority 场景下由测试 fixture 设置完毕，
  生产路径没有 authority ⇒ 全部跳过。
- **fail-closed blocker 声明**：真实 authority integration 仍
  `conservative_unknown`；RT-016 不修改 RT-015 冻结物，也不实现
  privileged bypass；直到独立评审新增 authority 通道并冻结后，
  legacy → tenant view 的完整数据流仍以 crosswalk 内存快照的形式
  等待激活。这条 blocker 已写进 rt-intake / 需求契约 / 交付验证
  报告，验收阶段可直接命中断言。

## 7. Reconciler 流程

```
MigrationReconciler.reconcile(tenant_id, run_id, source)
├─ source.verify_no_drift()  →  zero_drift_verified ∈ {True, False}
├─ 递归扫描 legacy 树 → legacy_side: {rel_path → sha256}
├─ importer.iter_crosswalks(tenant_id) → new_side: [crosswalk...]
├─ importer.iter_reviews(tenant_id)    → review_entries
├─ for cw in new_side:
│    envelope = SharedEvidenceStore.read_version(report_key, canonical_sha256)
│    recompute object_bytes_sha256
│    if any mismatch → failure_samples.append(canonical_missing |
│         canonical_sha_mismatch | object_bytes_sha_mismatch); only_new++
│    elif no matching legacy sha → only_new++
│    else → both_equal++
├─ for legacy sha 未覆盖:
│    if in review_entries → 计为 new_undecomposable
│    else → only_legacy++; failure_samples opaque_key=H(path)
├─ 输出 ReconciliationReport (schema 校验)
└─ 空 tenant 情况下 rate 除数为 0 → 用 1.0（安全默认）
```

- Reconciler 从不修改任何 store；只做只读校验与统计。
- `failure_samples` 上限 128；每条最多 64 char 的 opaque token；
  不泄漏路径 / 正文 / 凭据。
- `zero_drift_verified=False` 不使报告失败，而是显式暴露给上层
  gate；上层可据此拒绝进入下一阶段。

## 8. Log injection 防护

- 所有 mutation API 首先 `_validate_actor_reason` → 严格 printable
  ASCII + 长度限制 → 违反 `LogInjectionDetected`。
- 所有 schema 层再次以 `\A[\x20-\x7e]+\Z` 校验（避免绕过 API 直接
  构造 payload）。
- `evidence_refs` 沿用 RT-015 的字符集限制（RT-016 只传固定前缀
  `decomposer_version:` / `normalizer_version:` /
  `legacy_source_sha256:`，全部满足 RT-015 grammar）。

## 9. 错误 opacity

- `LegacyImportError.__str__ = "[<code>] <msg> (crosswalk_key=<opaque>)"`
  或 `(review_id=<opaque>)`；从不含绝对路径、正文字节、临时 URL、
  `agent_id`、credential、tenant workspace 路径。
- Reconciler failure_samples `opaque_key` 只允许
  `^[a-z0-9_.:/\-]+$`；path hash 化后取前 32 字符即可。

## 10. 与后续 RT 的接口

- RT-017（per-tenant collector）：也会使用 `AccessLedger.observe`
  向同一 tenant 写入 grant，但走不同 `observation_source`
  （`tenant_appkey_observation`）；RT-016 不与之串行、也不共享
  crosswalk namespace，因此并发安全。
- RT-018 (scheduler) / RT-019 (profile) / RT-020 (router) /
  RT-021 (projector) / RT-022 (broker) / RT-023 (transport)：
  **完全不读 RT-016 crosswalk / review / manifest**。它们只消费
  RT-014 / RT-015 的稳定接口。
- RT-024（audit / metrics）：可选消费 RT-016 manifest jsonl 与
  crosswalk / review 统计做迁移进度可观测性，但不属 RT-016 交付
  范围。
- RT-025（clean-room recovery）：备份必须覆盖
  `registry/rt016-crosswalk/`；恢复后与 RT-014 / RT-015 一起做
  一致性检查。RT-016 提供的 `iter_crosswalks / iter_reviews /
  iter_manifest` 是无副作用只读接口，可直接被恢复演练消费。
- RT-026（试点切换 / 查询 diff）：可通过 RT-016 crosswalk +
  RT-014 read_version 校验 canonical 完整性；查询 diff 属 RT-026
  的额外工作。

## 12. 回滚

- 删除 RT-016 新增文件 → 回退整套能力；未修改 RT-011~015 任何
  冻结物。
- 已 durable 写入的 crosswalk / review / manifest 保留（属于
  RT-016 自有 namespace；后续可由 RT-025 恢复演练或独立清理
  工具处理）。
- RT-014 canonical / RT-015 grant 是不可回退语义（这是设计目标
  之一）；删除 RT-016 不会撤销既有 grant。

## 13. v2 anchor remediation：架构增量

RT-016 v1.1 独立验收（`c6a740a`）关闭了 Minor-1/Minor-2/Info-1。此后
`a2789ef` 的 v2 anchor remediation 引入了 v2 identity / v2 crosswalk /
v2 review / v2 manifest / v2 reconciliation report、以及
`ReconciliationAnchor` 与 bound reader。第二轮 remediation（本次）在
v2 结构之上继续闭合以下防御漏洞：

### 13.1 五份 v2 契约 schema

- `migration_crosswalk_v2.schema.json`（`cwk.rt016.migration_crosswalk.v2`）
  必填字段包含 `identity_version="v2"`、顶层 `legacy_path_hash`；
  crosswalk_key 由 `compute_crosswalk_key_v2(tenant, ns, kind,
  path_hash, raw_sha)` 派生。
- `review_entry_v2.schema.json`（`cwk.rt016.review_entry.v2`）；
  review_id 由 `compute_review_id_v2(tenant, ns, kind, path_hash,
  raw_sha, run_id)` 派生。
- `migration_manifest_entry_v2.schema.json`
  （`cwk.rt016.migration_manifest_entry.v2`）；dedupe 键为
  `(source_namespace, source_kind, legacy_path_hash,
  legacy_source_sha256, outcome)`。
- `reconciliation_report_v2.schema.json`
  （`cwk.rt016.reconciliation_report.v2`）；必填 `reconciliation_anchor`
  子对象（`tenant_id / source_namespace / source_kind /
  decomposer_version / normalizer_version`），并新增
  `unanchored_v1_count`、`anchor_mismatch` 等分类。

v1 版本的五份 schema 严格保留可读，但仅供 audit；`review_entry.v1`
在第二轮 remediation 中放宽 `source_namespace` 为可选，以恢复对
pre-Minor-2 shape v1 记录的 audit-only 兼容性。**任何 v1 schema 的
后续调整必须同步更新 `test_rt016_schemas._FROZEN_RT016_V1_SCHEMA_BASELINE_SHAS`
以强制走 review 流程**。

### 13.2 `ReconciliationAnchor` 与 v2 reconciler pipeline

```python
class ReconciliationAnchor:
    tenant_id: str            # 校验 RT-012 tenant_id 语法
    source_namespace: str     # 校验 RT-011 namespace 语法
    source_kind: str          # 必须 current_raw | timeline_snapshot
    decomposer_version: str   # v\d{1,4}
    normalizer_version: str   # v\d{1,4}

reconciler.reconcile(*, anchor, run_id, source) -> ReconciliationReport
```

`reconcile` 无 anchor → `LegacyImportError(code="contract")`。对每条
v2 crosswalk 顺序执行 `anchor identity` → `path_hash bytes lookup` →
`raw sha` → `fresh decompose` → `field-by-field compare` →
**`tenant_view_envelope` JCS bytes bit-for-bit compare** → `RT-014
read_version` → **返回 envelope JCS bytes bit-for-bit compare**。v1
crosswalk 永远 `unanchored_v1`。

### 13.3 Bound readers（unified fail-closed entry）

三个 bound reader helper 保证 finder / CAS conflict / audit iter 的所有
路径都强制 filename ↔ payload id / parent-dir tenant ↔ payload tenant
/ v2 identity 重推导等式的绑定：

- `_load_crosswalk_payload_bound(raw, expect)`：v2 slot 内 v1 payload
  一律拒绝；filename、payload、v2 identity、v2 recomputed key 全绑定。
- `_load_review_payload_bound(raw, tenant_id, filename_review_id,
  require_v2=…)`：filename ↔ payload.review_id；parent tenant ↔
  payload.tenant_id；v2 记录还要 `compute_review_id_v2(payload own
  fields...) == filename`；`require_v2=True` 时 v1 记录被拒。
- `_load_manifest_line_bound(raw_line, tenant_id, filename_run_id,
  line_number)`：每行 tenant_id / run_id 必须与父目录 / 文件名
  一致；未知 schema / v0 混行都 fail-closed。

### 13.4 idempotency 强化（防协调篡改）

`ShadowImporter.import_one` 与 CAS 冲突分支通过
`_verify_crosswalk_matches_fresh_decompose(payload, raw_bytes, ..., decomposer,
evidence_store)` 强制：找到 v2 slot 中的 payload 后必须

1. 用 caller 的 raw_bytes fresh `decompose(...)`；
2. 对齐所有派生字段（含 `tenant_view_envelope` 的 NFC/JCS bytes）；
3. 调用 RT-014 `read_version(report_key, canonical_sha256)`；
4. 逐字节比对返回 envelope 与 fresh envelope 的 JCS bytes。

任何步骤失败 → `LegacyImportError(code="corrupt")`。即使既有 crosswalk
的 bound-reader identity 与 caller 完全一致，只要内容与本次 raw + RT-014
不完全匹配（例如 tenant_view_envelope 中 lane 被静默植入），import 拒
绝复用；对账拒绝 PASS。

### 13.5 Frozen zero-drift 基线

`tests/test_rt016_schemas.py` 的 `FrozenFilesZeroDriftTests` 采用显式
`(path → sha256)` allowlist 基线（RT-011~015 使用 `7ba906f` 时的 SHA；
RT-016 v1 schema 使用当前 post-second-round 的 SHA）。不再对
`HEAD:<path>` 做自我比较——那种自比较在漂移已被提交后会静默通过。
测试 `test_rt016_anchor_v2.FrozenBaselineCatchesDriftTests` 是 meta-
level 校验，证明基线 dict 非空并且 SHA 比较真的能触发失败。任何未来
对冻结文件的合法修改都必须同步更新 allowlist，从而强制走 review 流程。
