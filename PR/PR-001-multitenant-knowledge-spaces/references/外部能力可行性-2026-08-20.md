## 结论

- Gateway 可信身份链在产品机制上可实现：使用 OpenClaw 原生 Tool plugin factory，从运行时 tool execution context 读取注入的 Agent ID，再构造 `AgentContext.from_trusted(source="gateway_authenticated_context")`。请求参数不能提供或覆盖 identity。
- 当前已存在的普通 Agent 没有启用 sandbox，因此还不能生成 VG-D 的真实沙箱 receipt。VG-D 需要一个专用非生产 pilot Agent、sandbox 与最小 Tool allowlist。
- Gateway HTTP `/tools/invoke` 使用 operator 级认证且允许请求体选择 Agent，不能作为沙箱的不可伪造身份通道。
- UDS peer credential 在内核层可用，但当前 Agent 共享同一 OS 用户，尚不能可靠映射 uid/pid 到 Agent；只保留后备，不作为首选。
- 工作协同目前没有已证明的权威 ACL 快照/撤权事件源。现有关系观察只能用于角色/UI 分类，不能把 grant 提升为 active。

## 实现边界

### GatewayAgentIdentityAdapter（RT-023）

- Tool 面固定为 `query`、`list_spaces`、`resolve_slug` 三个 operation；schema 只允许各自的最小字段（QueryRequest v2 / 空参数对象 / 严格 `{slug}`），递归拒绝 agent/tenant/credential/path/profile/epoch 字段。
- `resolve_slug` 是独立只读入口，slug 做严格 lowercase ASCII 字节匹配，不执行 lower/casefold/NFC/NFKC/去空白等归一化；变体一律按"不存在"等价拒绝。
- plugin factory 捕获运行时 Agent ID，只在宿主机内短暂传给 trusted AgentContext；不得进入 argv、环境、日志、socket payload 或持久化文件。
- Tool 只开放给专用 pilot Agent allowlist；sandbox 不能读 CWK instance root、credential、shared raw 或其他 workspace。

### CWorkAuthorityProvider（RT-017）

- API：`observe_visible(cursor)`、`verify_grant(report_key)`、`consume_revocations(cursor)`。
- 凭据只通过 Header 发送；不得复用会把 AppKey 放进 URL query 的 legacy client。
- 响应严格分类：`ALLOW / EXPLICIT_DENY / NOT_FOUND / TRANSIENT_UNKNOWN / AUTH_FAILURE / SCHEMA_ERROR`。
- 只有经后端确认具备权威语义的 `ALLOW` 可签发不超过 15 分钟的 grant/refresh receipt；deny/revoke 立即撤权，其余全部 fail closed。
- production provider 与 trust anchor 使用构造函数注入，不能复用 test sentinel/fake signer。

## 真实门禁所需外部条件

1. 建立专用 sandbox pilot Agent 与最小 Tool policy；任何需要 Gateway restart 的操作必须在 Life-triggered turn 外执行。
2. 工作协同后台提供权威权限快照 API，或初始快照 + 撤权事件流，并明确版本、游标、deny/not-found 语义、SLA 与审计签名。
3. 确认 production receipt signer/trust anchor 后，相关 probe 才能从 `conservative_unknown` 升级。
4. 两个非生产 AppKey 的真实 A/B 可见性和撤权测试需要单独的测试凭据与业务授权。

## 当前判定

- RT-017/022/023 的接口、fake/synthetic 安全测试和默认关闭实现可继续开发。
- 在真实 sandbox receipt 前，VG-D/G5 不得标记 PASS。
- 在权威 ACL/撤权源前，不得宣称真实 tenant 可安全激活或进入 G7/M4。
- **Wave-0 在本主题上的交付到此为止**：只读核验 receipt 已完成，结论
  `conservative_unknown`/`blocked`。剩余的是 RT-017（CWork authority）与
  RT-023（Gateway identity/受控 transport）各自的 **capability activation receipt**，
  它们不是 Wave-0 的未完成项，而是后续 RT 的交付物。
