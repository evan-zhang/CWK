# 安全威胁模型与验收门禁

> 适用范围：PR-001 多租户共享证据与专题知识空间
> 结论：首期必须使用宿主机 Query Broker；沙箱不得挂载共享 raw。

## 1. 核心安全不变量

- 共享存储不代表共享访问权限。
- `tenant_id` 只能由可信 Gateway Agent 身份映射得出，不能由请求参数提供。
- 候选召回前和任意 raw 回读前都必须校验当前有效授权。
- 权限撤销先立即逻辑拒绝，再异步清理索引和缓存。
- 评论、审批、附件在多用户一致性验证前默认属于 tenant overlay。
- 沙箱不持有 AppKey、共享 raw 路径、其他 tenant 信息或可覆盖租户范围的参数。
- 工作协同正文始终按不可信数据处理，不能改变配置、授权或工具范围。

## 2. 威胁主体和信任边界

威胁主体包括：普通租户用户、受提示注入影响的 Agent、错误/过期绑定、缺陷采集/索引/缓存任务、被盗用的宿主机服务账号，以及含恶意指令或异常路径文本的工作协同正文。

信任边界：

1. Gateway 身份认证 → Agent Binding Resolver；
2. Scheduler → Credential Broker → CWork；
3. 采集结果 → Canonicalizer → Shared Evidence；
4. Shared Evidence → Access Ledger/Tenant Projection；
5. Sandbox Agent → Host Query Broker；
6. 在线存储 → 加密备份/恢复环境。

## 3. 威胁与强制控制

### T-01：Agent/tenant 身份伪造

- 请求协议不接受 tenant、agent、mirror 或 raw 路径。
- 身份来自 Gateway 已认证上下文或等价可信 peer credential。
- unknown agent、重复绑定、过期 binding 一律拒绝；tenant 查询仅允许 `pilot/active`，其中 `pilot` 还必须命中 allowlist。`draft/profile_pending/suspended/offboarded` 的查询请求全部拒绝，不引入 `disabled` 别名状态。
- 重绑由管理员完成并审计。

### T-02：report_id 枚举越权

- 不公开无授权上下文的 `get_raw(report_id)`。
- 每次回读要求 active binding、`pilot|active` tenant（pilot 必须 allowlist）、active grant、匹配 auth epoch 和未过期 lease。
- 不能只依赖“report 已在 tenant index”。

### T-03：召回阶段串租户

- 普通查询只访问 tenant space index。
- ACL 在候选生成前执行；输出前再次执行。
- 标题、命中数量和对象存在性同样受 ACL 保护。

### T-04：路径穿越、软链接和 TOCTOU

- 外部只接受 opaque ID，不接受路径。
- 根目录和 tenant/cache/log 目录禁止软链接。
- 优先使用目录句柄和 `O_NOFOLLOW`；不能只做一次 `resolve()`。
- 测试绝对路径、`../`、URL/Unicode 编码、软链替换、硬链和临时路径覆盖。

### T-05：缓存串扰

缓存键必须含：`tenant_id + auth_epoch + profile_sha + spaces + query/filter hash + index_version`。不跨 tenant 共享答案/evidence 缓存；撤权先提升 auth epoch。

### T-06：日志、异常和临时文件泄漏

- 日志不记录 raw、AppKey、完整 query、正文或其他 tenant 信息。
- 错误不回显宿主机路径、共享 object ID 或 tenant ID。
- 临时文件位于 tenant 专属目录并清理。
- 中央安全审计仅管理员受控访问。

### T-07：AppKey 泄漏或串用

- tenant config 仅保存 `credential_ref`。
- Credential Broker 用环境白名单注入一次性进程。
- 不允许 CLI 参数、manifest、Prompt、日志、沙箱环境出现密钥。
- `draft/suspended/offboarded` tenant 不发放；`profile_pending` 仅为有界样本采集发放；失败时不回退其他 tenant 或全局 `.env`。

### T-08：工作协同内容提示注入

- raw 被明确包裹为数据。
- AI 抽取使用零工具或等价受控环境。
- 原文中的命令、路径、tenant 或 credential 字样不能触发工具或修改配置。
- AI 输出经 schema、证据和权限校验，只作为建议。

### T-09：错误共享评论、审批和附件

- 初始契约：canonical report body + tenant view overlay。
- 未证明跨身份一致的 reply/node/attachment 全部留在 overlay。
- 临时下载 URL 永不进入 canonical。
- 只有差异验证通过的字段才能升级为 shared。

### T-10：权限撤销窗口

- grant 使用 lease，不使用永久布尔权限。
- 撤权：标记 revoked → 提升 auth epoch → Query Broker 同步拒绝 → 异步清理 index/cache/space → 保存墓碑。
- 无撤权事件时，lease 到期必须重新验证；失败立即拒绝。

### T-11：并发和故障扩散

- 每 tenant 独立 collector/index lock、state 和 retry queue。
- shared object 使用原子不可变 commit；同版本并发写幂等。
- 每 tenant 配额和熔断；A 的 API 429/坏 profile/超大正文不影响 B。

### T-12：共享对象存在性侧信道

- 对外 object ID opaque；不提供 hash existence API。
- 不因不同 report_id 正文相同而合并报告身份。
- report_id 唯一性未证明前使用 `source_namespace + report_id`。

### T-13：备份和恢复泄漏

- shared raw、access ledger、profile 和 audit 加密备份。
- 备份密钥与数据分离。
- 恢复先恢复安全配置和 ACL，再 raw，再重建派生索引；通过跨租户/撤权测试后才开放查询。
- AppKey 明文不从备份恢复，只重新绑定 credential reference。

### T-14：knowledge profile 越权

- profile 只能影响知识治理和展示，不能创建 grant、改变 binding、指定路径或 tenant。
- 高影响 merge/split/archive 需用户确认。
- proposal 不自动 active；版本化、影响预览、审计和回滚。

## 4. 验收门禁

### SG-00：外部事实验证

- report_id 唯一性；
- 两用户共同可见 50–100 篇的正文/reply/node/attachment 差异；
- 可信 Gateway Agent 身份来源；
- 权限和撤权来源；
-宿主机服务账号和沙箱通信方式。

未完成时必须采用保守默认，不能声称对应字段可安全共享。

### SG-01：共享存储

- 两 tenant 同一版本 raw 对象数为 1；
- 不同版本为两个不可变版本；
- 不同 report_id 不因正文相同而合并身份；
- 普通 Agent 无法列举/探测 shared object。

### SG-02：身份与 ACL

- A 独有报告 B 不可见；共同报告指向同一 canonical object；
- tenant/mirror/report 参数注入被拒；
- unknown agent、非 `pilot/active` 查询 tenant、未命中 allowlist 的 pilot、expired binding/grant 被拒；
- 标题、数量、引文均不越权；跨租户泄漏为 0。

### SG-03：文件系统

所有路径穿越、编码变体、软链/硬链、TOCTOU、cache/log/temp 覆盖均 fail closed。

### SG-04：缓存与日志

- 缓存键缺任一安全维度时测试失败；
- 撤权后旧缓存立即不可命中；
- A/B 同 query 不交换 evidence；
- secret scan 对日志、manifest、temp、环境转储为 0 命中。

### SG-05：密钥生命周期

- 密钥不在参数、Prompt、配置、日志、沙箱或 Git；
- A 不能使用 B 的 credential ref；
- 轮换后旧密钥失效；`draft/suspended/offboarded` tenant 无法启动采集，`profile_pending` 只能启动有界样本采集；
- broker 失败不回退全局密钥。

### SG-06：撤权

建议目标：有撤权事件时逻辑拒绝 ≤60 秒、index/cache 清理 ≤5 分钟；无事件时 lease ≤15 分钟。最终 SLA 需业务确认。

### SG-07：沙箱

- 环境无 AppKey；文件系统无 shared raw/其他 tenant/宿主机路径；
- 协议无 tenant/mirror/raw path 参数；
- 沙箱销毁不影响宿主机采集；
- raw 中指令不能触发工具或越权读取。

### SG-08：故障隔离与容量

A 的死锁、超时、429、坏 profile 或超大报告不影响 B；同 tenant 双采集保持单写者；state/lock/retry 不共享。

### SG-09：备份恢复

干净环境恢复后验证 SHA、ACL、profile、跨租户和撤权回放；仅恢复 A 不生成 B 索引；记录真实 RTO/RPO。

### SG-10：试点

- 2–3 人、14 天：泄漏 0、遗漏 0、调度 14/14、密钥/禁用/撤权/恢复均通过；
- 5–10 人、30 天：调度 ≥99%、泄漏 0、撤权达标、故障不扩散、成本在预算内；
- 未通过不得全员生产。

## 5. 建议默认值

- report key：`source_namespace + report_id`。
- reply/node/attachment：验证前 tenant overlay。
- 无权威撤权事件：15 分钟 access lease。
- 查询：Host Query Broker，不使用共享 raw 只读挂载。
- 日志：query hash/长度/分类/report IDs，不存完整 query/raw。
- 冷归档：只取消知识化，不物理删除。
- break-glass：无默认全租户读取；临时、双人审批、限时、全审计。
