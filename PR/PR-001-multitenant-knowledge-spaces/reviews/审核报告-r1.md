## 3. 必须整改的 Major 决策项（不闭合则视同 Blocker）

### M1：Query Broker transport + 可信 Agent 身份必须收敛
- 首期强制 **OpenClaw 受控 Tool 调用** 为主 transport；Agent 身份由 Gateway 在 Tool 元数据中注入，请求体字段不可覆盖。
- **UDS + SO_PEERCRED**（或等价 peer credential）作为**后备本机实现**，同样不接受请求体中的 `agent_id`。
- **明确禁止**：loopback HTTP + 用户自报 `agent_id` 的弱协议，任何时候都不合门禁。
- 此决策作为 **G1 硬门禁**：ADR 与 `security_defaults.json` 必须落盘并被独立测试断言。

### M2：Legacy raw 分解器、无法反解时 fail closed、迁移对账算法
- 现有 raw 混合 canonical 字段与 tenant 视角，不能原样搬入 canonical。必须提供 `LegacyRawDecomposer` 与三元组输出（Canonical/TenantView/AccessObservation）。
- 无法反解时**不写 canonical、不写 tenant view**，进入 `review/legacy-undecomposable/` 队列 fail closed，不允许部分写入或猜测。
- 提供 `MigrationReconciler` 五分类对账（`only_legacy / only_new / both_equal / both_diff / new_undecomposable`）与对账报告，作为 M3 门禁。

### M3：100–200 篇 Knowledge Profile Proposal 全链路细化
- **分批/聚合**：单 chunk 20–30 篇，`partial_proposal_v1` → 确定性 reducer → `proposal_v1`；单 chunk 失败重试上限后整体 `proposal_error`；跳过判定不允许由 AI 决定。
- **零工具执行环境**：零文件系统/零网络/零 sub-agent；raw 明确包裹为不可信数据。
- **Prompt injection 防线**：JSON schema + 证据引用校验 + ACL + 禁止字段扫描（tenant_id/agent_binding/path/credential/shell 模板等）。
- **Sample manifest 与 proposal SHA 绑定**：`sample_manifest_v1` 不可变；`profile_sha256 = sha256(canonical_json(proposal) + sample_manifest_sha256 + prompt_template_sha256 + model_id)`；缺一拒绝激活。

## 4. Major 项（收敛后可继续）

以下项在 r1 中被识别为 Major，整改产物需在 PRD/DESIGN 或 defaults 中显式收敛：

1. **`verified_shared_extensions` 升级流程**：字段从 overlay 升级为 shared 必须经过契约探针 → 独立审核 → 版本化清单登记；临时 URL 永远禁止升级。
2. **Access Ledger 字段/状态与 SLA**：字段清单固化、状态机固化、SLA 采用“安全默认 + 后续基准替换”。
3. **Query Broker `include_dispositions`**：默认 `["index"]`；冷归档查询入口通过此字段暴露，不新增旁路 API。
4. **In-flight `auth_epoch` 复核**：Broker Top-K 阶段必须复核 `req_snapshot`，防止 in-flight 撤权穿透。
5. **RT-011 职责不过载**：拆 RT-011A（契约与探针）+ RT-011B（安全默认与 broker transport 决议，G1 硬门禁），避免一 RT 铺满 13 个脚本。
6. **Agent binding HMAC / opaque ID**：`agent_id` 明文不落盘，只保存 HMAC；`space_id` 使用 opaque ID，slug 只做 UI 映射。
7. **Break-glass 首期明确不提供**：`security_defaults.json` 中 `break_glass.enabled=false`；任何未来 break-glass 必须独立 PR。
8. **Python 版本统一**：全 PR 采用 Python 3.11+，取消 3.10 兼容表述。
9. **首期配额/性能表述**：一律“安全默认 + 后续基准替换”，未测量前不虚构 P95/RTO/RPO。
10. **知识空间 slug → opaque ID**：所有派生投影、审计、路由决策、缓存键、目录路径使用 opaque `space_id`，slug 可改名不影响持久化。
11. **冷归档查询入口**：由 `include_dispositions=["index","archive_no_index"]` 显式打开，默认关闭。
