# PR-001 开发计划独立审核（R1）

> 审核方式：干净只读 Subagent
>
> 审核范围：`PRD.md`、`DESIGN.md`、三份 `references/` 与当前 CWK 代码结构
>
> 审核日期：2026-08-19

## 1. 结论

**CHANGES REQUIRED。** PRD 与详细设计的方向正确，但原 `RT-011～RT-018` 共 8 个大 RT 不能直接用于开发。多个 RT 同时跨越身份、密钥、ACL、共享证据、调度、路由、沙箱传输、备份与试点等不同安全边界，无法做到独立实现、独立验收和安全回滚。

建议拆分为 `RT-011～RT-026` 共 16 个 RT，并增加 5 个波次集成门禁。每个 RT 必须由独立实现 Agent 编码，再由另一独立验收 Agent仅依据公开入口、产物与负向测试验收。

## 2. 当前代码事实

- `cwk_collect_live.py` 同时写正文、lane、read/todo、reply/node 等混合 Markdown，并支持 `--app-key`、全局环境和含明文密钥的临时参数文件，不能直接作为多租户 Worker。
- `cwk_raw_store.py` 按 `report_id` 维护当前 raw，更新时覆盖当前路径并用 timeline 保存旧快照；可复用哈希与晋级思路，但它不是共享不可变对象库。
- `cwk_nightly_pipeline.py` 约 1536 行，固定使用仓库级 `runs/state/mirror/.env`。应保留为 legacy façade，不应继续叠加多租户调度逻辑。
- `cwk_wiki_query.py` 仍接受任意 `--mirror-root` 和 raw 路径；沙箱不能暴露该入口。但已有 `query_mirror(..., raw_loader=...)` 注入点，可复用 RT-010 的实体硬范围与证据校验。
- `cwk_report_relation.py` 可作为访问观察输入，但接口当前是可选的，不能直接等同于权威 ACL 或撤权流。
- PRD 将 P95 冻结放在首个 RT，但真实 Broker 未实现前无法测量有意义的 P95；应在 RT-024 冻结实测基线。

## 4. 推荐 RT 拆分

### RT-011：外部契约探针与安全基线

- 输出 `ReportKey`、canonical/view/access/profile/route v1 契约；report ID、权限/撤权、可信 Agent 身份、沙箱传输能力探针；双租户恶意夹具。
- 外部事实必须标记为 `verified` 或 `conservative_unknown`；未知字段默认 tenant overlay；默认键为 `source_namespace + report_id`。
- 只做契约、探针和夹具，不写生产数据、不持有密钥、不实现 runtime。

### RT-012：Instance Layout 与 Tenant Registry

- 输出安全路径解析、原子文件 API、tenant registry、生命周期、配额、auth epoch、基础 admin/doctor。
- 路径穿越、编码变体、软/硬链接与 TOCTOU 必须 fail closed；多租户模式不得回退仓库级路径。
- 不绑定 Agent，不处理密钥、ACL、raw 或采集。

### RT-013：可信 Agent 绑定与凭据边界

- 输出 binding registry、binding epoch、credential reference、Credential Broker、轮换/禁用接口及受控 AgentContext 适配器。
- 请求体不能提供 agent/tenant；环境白名单注入；argv、配置、日志、manifest、Prompt、沙箱与 Git secret scan 均为 0。
- 不判断 report ACL，不采集正文。

### RT-014：共享不可变 Canonical Evidence Store

- 输出 Canonicalizer、opaque object store、report-version catalog、CAS/细粒度锁与校验式 reader。
- 同一 report/version 只存一份；新版本保留旧对象；不同 report 不因正文相同合并身份；故障不能产生半引用。
- 不创建 grant、不查询 CWork、不提供对象枚举 API。

### RT-015：Access Ledger、Tenant View 与撤权核心

- 输出索引化 grant ledger、lease/revalidation/revocation、tenant view、撤权事件和清理消费者契约。
- 撤权立即逻辑拒绝并提升 epoch；A 撤权不影响 B；任意 crash injection 点均不能命中旧缓存权限。
- 不负责发现权限，也不直接操作最终 space/index/cache。

### RT-016：Legacy Raw 影子迁移与数据双读核验

- 输出只读 importer、legacy current raw 与 RT-007 timeline 导入、迁移 crosswalk、续跑 manifest 和双读比较器。
- 必须区分 `legacy_source_sha256` 与规范 JSON 的 `canonical_sha256`；不得直接宣称二者相等。
- legacy 树零修改；导入后的 grant 默认为 `revalidation_due`。

### RT-017：Per-tenant Collector Worker

- 输出 CWork source adapter、`CanonicalEnvelope/TenantViewEnvelope/AccessObservation` 三路结果和 tenant-scoped state/run/retry。
- 无 argv/临时文件明文密钥；只调用只读模式；bounded list 中暂未出现不能误判为撤权。
- 单次只运行一个 tenant，不负责全局调度与知识空间投影。

### RT-018：宿主机 Tenant Scheduler

- 输出错峰计划、每 tenant 单写锁、持久重试、配额、并发控制、熔断和运行 manifest。
- A 的死锁、429、超时、坏配置或磁盘配额不得影响 B；重启后队列可恢复。
- 新建 scheduler，不在 legacy nightly 中开发。

### RT-019：Knowledge Profile 提案、确认与版本生命周期

- 输出可复现分层抽样、proposal schema、用户接受/拒绝/编辑/暂缓记录、profile 版本/SHA/影响清单/回滚与 PreviewProvider 契约。
- 样本 100～200、holdout 20～30 且不重叠；只读 active grant；AI 输出经 schema、证据与 ACL 校验；恶意 raw 不得触发工具。
- 没有真实 preview receipt 时 profile 不得激活。

### RT-020：Holdout 预览、路由器与决策日志

- 输出真实 PreviewProvider、三态多标签路由器、route decision log、review/archive metadata、reroute job/diff 和 profile 激活 receipt。
- 优先级为确定规则 > confirmed entity > AI；低置信、冲突或 AI 失败进入 review，绝不自动删除。
- 只产生路由决定与激活凭据，不创建 Wiki/索引。

### RT-021：多知识空间 Projector 与索引

- 输出 space membership、summary/topic/entity/index 投影、archive/review 视图和撤权/路由变化消费者；适配 RT-010。
- 同一报告进入 TBS/SFE 时引用同一 canonical SHA；不复制 raw；撤权或退出 index 后清除该 tenant 投影。
- 只生成 host 侧可重建派生物，不处理沙箱协议和身份。

### RT-022：Query Broker 授权核心

- 输出 AgentContext→binding→tenant/status/profile→space→ACL 前滤→二次 ACL→SHA 回读→evidence bundle；安全缓存键与审计 sink。
- tenant/mirror/path 注入、stale binding/grant、撤权竞态、缓存串扰、对象存在性探测全部拒绝；缓存命中前仍验证授权。
- 纯 host service core，不实现 UDS/OpenClaw Tool 或沙箱安装。

### RT-023：沙箱传输、客户端与真实空间集成

- 输出已验证的 UDS 或 OpenClaw 受控 Tool adapter、沙箱查询 client/Skill、peer identity 映射与真实 space index adapter。
- 协议不得包含 agent/tenant/mirror/raw path 参数；沙箱无 AppKey、shared raw、其他 tenant 或宿主机路径。
- 若 Gateway 无法提供可信身份，必须阻塞，不得退化为 loopback HTTP + 用户提供 agent ID。

### RT-024：安全审计、可观测性与容量基准

- 输出追加式审计、租户健康聚合、成本/队列/锁/授权/路由/query 指标、日志脱敏及 10 tenant × 1 万 report 合成基准。
- 日志不得包含 raw、AppKey、完整 query、临时 URL 或宿主机敏感路径；产出真实 P50/P95，不预设虚构阈值。

### RT-025：加密备份与 Clean-room 恢复

- 输出加密 backup manifest、密钥分离接口、按安全顺序恢复工具和恢复验证报告。
- clean-room 恢复后 canonical/catalog、binding、有效/撤销 grant、profile SHA 一致；撤权墓碑仍有效；无 AppKey 明文。
- 恢复后 Broker 默认关闭，必须通过 ACL/越权/撤权验证才开放。

### RT-026：试点准备、影子切换与回滚工具

- 输出 tenant allowlist、独立试点 schedule、legacy/new 双读差异、切换开关、回滚 runbook、go/no-go evaluator、安装/doctor/兼容入口。
- 合成双租户 E2E 覆盖去重、视角差异、profile、路由、多空间、冷归档重路由、撤权、故障隔离、备份恢复与 legacy 回滚。
- 只验收试点可执行性；2～3 人 14 天和 5～10 人 30 天是独立发布活动门禁。

## 5. 五个波次集成门禁

- **VG-A（RT-015 后）**：双租户 fixture → canonical store → grants/views → allow/deny。
- **VG-B（RT-018 后）**：fake CWork → collector → shared/ACL → scheduler 故障隔离。
- **VG-C（RT-021 后）**：授权样本 → profile → preview/route → 多空间投影/撤权清理。
- **VG-D（RT-023 后）**：真实沙箱身份 → Broker 双 ACL → raw 验证证据。
- **VG-E（RT-025 后）**：clean-room restore → 同一 allow/deny/query 结果与撤权回放。

## 6. 文件所有权与并行约束

- RT-011 后冻结共享 schema 版本；后续只新增版本，不能各 RT 私改。
- `cwk_collect_live.py` 只由 RT-017 修改。
- legacy `cwk_nightly_pipeline.py`、安装入口与统一 feature flag 只由 RT-026 修改。
- `cwk_entity_catalog.py`、`cwk_wiki_search_index.py` 与 Wiki projector 适配由 RT-021 独占。
- `cwk_wiki_query.py` 的 Broker/raw-loader 适配由 RT-022 独占。
- RT-016 migration 与 RT-017 collector 仅调用 RT-014/015 的公开 writer，不互改实现。
- 每个 RT 使用临时 instance root 和 fake 依赖独立验收；每个波次再跑完整 regression/smoke。
