# PR-001 第二轮审核整改记录（r2）

> 日期：2026-08-19
> 依据：`审核报告-r2.md` 与独立跨文档契约复核
> 范围：仅修订 PRD、DESIGN、开发计划与参考资料；未修改代码、cron、Cloud、DocDB、生产镜像或真实密钥。

## 1. 结论

第二轮审核确认目标架构、安全模型和 16-RT 拆分可行，但发现状态枚举、迁移哈希、路由幂等键、G/VG/M 映射及若干组件所有权不一致。本轮已按“一个规范来源、其他文档引用”的原则闭合，并保留历史审核文件作为不可变审计记录。

## 2. 阻塞项闭环

1. **Grant 状态统一**：全局使用 `discovered / granted / active / revalidation_due / revoked / purge_pending / purged`；只有 `active` 可读。Legacy 导入从 `granted` 开始，权威复核前不得升级。
2. **路由幂等键统一**：`route_job_key = tenant_id + report_key + canonical_sha256 + profile_sha256`；`projection_key = route_job_key + space_id + projector_version`。
3. **迁移双哈希**：分别保存 legacy 原始字节与 canonical JSON 的 SHA，通过确定性 crosswalk 对账，不要求二者相等。
4. **G/VG/M 三轴拆分**：G0～G7 是发布门禁，VG-A～E 是波次集成 receipt，M0～M5 是迁移阶段；三者不再按编号强行配对。
5. **指标归属**：RT-024 实测 Broker core 与真实沙箱端到端 P50/P95、容量和配额；RT-025 clean-room 恢复实测 RTO/RPO；RT-026 消费两类基线。
6. **查询授权顺序**：active grant 与 space membership 先取交集，才进入 retrieval；Top-K raw 回读前再执行第二次 ACL 与 epoch 快照复核。
7. **字段安全默认**：reply、node、attachment metadata 在双身份验证和版本化扩展批准前全部 tenant overlay；临时 URL 永远不进入 canonical。
8. **空间标识**：持久化只使用 opaque `space_id`；slug 仅为 UI 别名，由 RT-023 的可信 `list_spaces`/解析接口提供，沙箱不读 tenant 配置。

## 3. 组件边界与唯一所有权

- RT-017 Collector 只发布 envelope/事件，不直接调用尚未交付的 Router。
- RT-018 Scheduler 依赖稳定 JobProvider，不直接耦合 RT-021 Projector。
- RT-022 独占 Query Core/raw-loader 适配；RT-023 独占 transport/client 与真实 space adapter。
- RT-024 独占 Audit/Metrics；RT-025 独占 Backup/Recovery。
- `cwk_collect_live.py`、实体/搜索投影、`cwk_wiki_query.py`、legacy nightly/install/feature flag 均已指定唯一 RT owner。
- 跨 RT 只能消费冻结 schema/provider；禁止跨 security boundary 合并模块。

## 4. 迁移与发布顺序

- RT-016 只完成影子导入与数据级 crosswalk；Broker 尚不存在时不做查询 diff。
- RT-026 在 RT-022/023 可用后完成 legacy/new 候选、证据和拒答理由 diff；数据对账与查询 diff 共同闭合 M3。
- M4 真实试点必须同时满足 RT-026、VG-A～E、G6，并另获 G7 部署/密钥/调度授权。
- M5 只在 14 天试点通过后启动，属于开发计划之外的发布活动。
