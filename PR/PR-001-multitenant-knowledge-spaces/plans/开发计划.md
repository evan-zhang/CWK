# PR-001 开发计划：多租户共享证据与用户专属知识空间

> 状态：G0 PASS，RT-011 待启动
> 范围：RT-011～RT-026，共 16 个可独立实现、独立验收的 RT
> 原则：实现者不自验收；前置门禁未通过不得进入依赖 RT；默认不启用生产租户、cron、Cloud 或 DocDB 写入。

## 1. 交付目标与执行规则

本计划把 PRD 与 DESIGN 拆成四条可独立验证的能力链：

1. **租户安全链**：实例布局、可信 Agent 绑定、凭据边界、访问授权与撤权；
2. **共享证据链**：公司级不可变 Canonical Evidence Store、版本目录与 legacy 影子迁移；
3. **用户知识链**：Knowledge Profile 共创、三态多标签路由、多知识空间投影；
4. **安全查询与运行链**：宿主机调度、Query Broker、沙箱传输、审计、备份恢复与试点切换。

执行规则：

- 每个 RT 必须有独立实现 Agent、独立验收 Agent、需求契约、技术方案、测试与交付验证报告。
- 验收 Agent 只依据公开 CLI/API、产物、负向测试和 receipt 验证，不依赖实现内部函数。
- 验收失败时回到同一实现 Agent 修复，再由同一独立验收 Agent复测；通过后才能合并并进入依赖 RT。
- RT-011 冻结 v1 schema；后续 RT 只能新增版本，不得私自改写已冻结字段语义。
- 所有开发使用临时 `CWK_INSTANCE_ROOT`、fake CWork、双租户恶意夹具；禁止读取真实 AppKey 或修改现有 nightly/生产镜像。
- 任何未知权限、身份、字段归属或撤权状态一律 fail closed。
- 性能与配额不预设虚构数字；RT-024 分别测量 Broker core 与真实沙箱端到端 P50/P95、容量和配额，RT-025 通过 clean-room 恢复实测 RTO/RPO，RT-026 只消费两类基线。

## 3. RT-011：外部契约探针与安全基线

**目标**：在不写生产数据、不持有密钥的前提下，冻结系统 v1 契约并把外部未知事实显式化。

- 依赖：无。
- 输入：PRD、DESIGN、威胁模型、当前 CWork/CWK 代码、双用户脱敏样本或保守未知状态。
- 输出：`ReportKey`、`CanonicalEnvelope`、`TenantViewEnvelope`、`AccessObservation`、`KnowledgeProfile`、`RouteDecision`、`QueryRequest`、`sample_manifest_v1`、`verified_shared_extensions_vN` v1 schema/manifest；`prompt_template_sha256` 与 `model_id` 的哈希输入规约；安全默认与身份/传输 ADR；双用户字段比较器；report ID、权限/撤权、可信 Agent 身份、沙箱传输探针；双租户恶意夹具。
- 范围内：契约、探针、fixture、schema 校验器、`verified | conservative_unknown` 结论。
- 非目标：运行时、采集、租户目录、密钥、真实数据迁移、生产开关。
- 关键门禁：默认 `ReportKey = source_namespace + report_id`；同 ID 不同 namespace 不冲突；未验证字段全部进入 tenant overlay；每项外部事实均有可机读结论与证据位置；冻结 `object_id = "o_" + base32(random 128 bit)`、Access grant 七状态、RouteDecision `space_ids[]`、QueryRequest `space_selector[]`（元素为 opaque `space_id`）、NFC normalizer + RFC 8785 JCS/UTF-8 canonical JSON 和带 domain separator 的 `profile_sha256` 字节公式。
- 负向测试：跨 namespace 冲突、缺字段、未知附件/回复/审批差异、伪造 transport/identity 结果。
- 回滚：删除本 RT 新增 schema/probe/fixture；不产生数据迁移。
- Agent：`agent-rt011-impl` / `agent-rt011-verify`。

## 4. RT-012：Instance Layout 与 Tenant Registry

**目标**：提供单机共享引擎下的安全租户目录、生命周期、配额和原子文件基线。

- 依赖：RT-011。
- 输出：安全路径解析器、原子文件 API、Tenant Registry、tenant 状态机、quota/auth epoch、基础 admin/doctor CLI。
- 范围内：`CWK_INSTANCE_ROOT/tenants/<opaque_tenant_id>/` 下 state/run/lock/log/temp/config/view/space 边界。
- 非目标：Agent 绑定、凭据、ACL、raw、采集、调度。
- 关键门禁：路径穿越、绝对路径、编码变体、软/硬链接、TOCTOU 全部 fail closed；多租户模式绝不回退仓库级路径；非法生命周期跃迁拒绝；A/B 文件完全隔离。
- tenant 业务状态机与 PRD FR-02/DESIGN C-02 完全一致：`draft → profile_pending`；`profile_pending → pilot|suspended|offboarded`；`pilot → active|suspended|offboarded`；`active → suspended|offboarded`；`suspended → profile_pending|pilot|active|offboarded`；`offboarded` 为终态。状态权限矩阵也属于本 RT 的冻结契约：`profile_pending` 只允许有界样本采集和 Profile Proposal/Preview，`pilot` 只对 allowlist 开放数据面，`active` 正常开放，`draft/suspended/offboarded` 禁止凭据解析、采集、Scheduler 和查询。`provisioning/retiring` 如需使用，只能另作内部 job 状态，不能进入 `tenant.status`。
- CLI 所有权：本 RT 独占共享 `cwk_tenant_cli.py` dispatcher 与冻结的 command-provider registry；后续 RT 不得修改 dispatcher，只能新增各自 provider 模块并通过稳定接口注册命令。
- 回滚：registry 与目录创建使用事务/receipt；未完成 tenant 可安全撤销，已 active tenant 禁止静默删除。
- Agent：`agent-rt012-impl` / `agent-rt012-verify`。

## 5. RT-013：可信 Agent 绑定与凭据边界

**目标**：把不可伪造的 Agent 身份绑定到唯一 tenant，并让 AppKey 只存在于宿主机凭据边界。

- 依赖：RT-012；RT-011 的可信身份探针结论。
- 输出：Binding Registry、binding epoch、credential reference、Credential Broker、轮换/禁用接口、受控 `AgentContext` 适配器。
- 范围内：一 Agent 一 tenant、密钥引用与最小环境白名单注入、轮换/禁用、审计 receipt。
- 非目标：报告 ACL、正文采集、知识空间或查询。
- 关键门禁：请求体不得提供 agent/tenant；unknown/rebound/expired/suspended 绑定一律拒绝；失败不回退 `.env`；argv、配置、日志、manifest、Prompt、沙箱、Git secret scan 为 0；binding secret 轮换采用双写、原子 pointer 切换和旧目录墓碑，轮换中请求不得命中新旧混合状态。
- CLI 扩展：本 RT 只新增 `cwk_tenant_cmd_binding.py` provider，不修改 RT-012 冻结的 `cwk_tenant_cli.py` dispatcher。
- 外部门禁：必须在真实 Gateway 控制环境证明身份不可由用户/沙箱伪造，否则标记 `conservative_unknown`，不得宣称 SG-02 完成。
- 回滚：撤销 binding、提升 binding epoch、禁用 credential reference；不删除 tenant 数据。
- Agent：`agent-rt013-impl` / `agent-rt013-verify`。

## 6. RT-014：共享不可变 Canonical Evidence Store

**目标**：同一工作协同汇报本体只保存一份，并保留不可变版本与完整性证据。

- 依赖：RT-011、RT-012；可与 RT-013 并行。
- 输出：Canonicalizer、opaque object store、report-version catalog、CAS/细粒度锁、校验式 reader。
- 范围内：宿主机内部 canonical envelope、内容对象、版本目录、哈希校验、并发幂等。
- 非目标：grant、CWork API、tenant view、对象枚举、沙箱访问。
- 关键门禁：两 tenant 的同一 report/version 仅一个对象；新版本保留旧对象；不同 report 即使正文相同也不合并身份；catalog/staging 故障不产生半引用；canonical 中无 tenant/view/credential/path。
- 并发测试：重复提交、不同版本竞态、catalog CAS 冲突、断电/异常注入、损坏对象回读拒绝。
- 回滚：对象不可删除；仅回退新 catalog pointer，并保留孤立对象供 GC 后续审计。
- Agent：`agent-rt014-impl` / `agent-rt014-verify`。

## 7. RT-015：Access Ledger、Tenant View 与撤权核心

**目标**：建立用户—报告访问关系、用户视角 overlay 与立即生效的撤权核心。

- 依赖：RT-012～RT-014。
- 输出：索引化 grant ledger、lease/revalidation/revocation、Tenant View Store、撤权事件与清理消费者契约。
- 范围内：权威 allow/deny、用户专属 read/todo/lane/reply/node 等 overlay、auth epoch、撤权墓碑。
- 非目标：权限发现、真实 space/index/cache 清理实现、采集和查询协议。
- 关键门禁：过期/未知 grant fail closed；撤权先逻辑拒绝并提升 epoch；A 撤权不影响 B；view 不复制正文；crash injection 任一点都不能命中旧缓存权限。
- grant 状态遵循 PRD/DESIGN v1：`discovered → granted → active → revalidation_due → active|revoked`，以及 `revoked → purge_pending → purged`；只有 `active` 可读，其他状态全部 fail closed。
- 回滚：授权状态只追加/版本化；不得通过回滚恢复已撤权 grant。
- Agent：`agent-rt015-impl` / `agent-rt015-verify`。

## 8. VG-A：租户证据与授权集成门禁

必须证明：同一 canonical 可被 A/B 共享；A/B view 独立；A 撤权后逻辑拒绝与墓碑立即生效且 B 保持可用；未知 tenant/report/object 不泄露存在性。派生索引/缓存清理不属于 VG-A，统一在 VG-C 验收。receipt 通过后才能进入迁移、采集、知识与查询链。

## 9. RT-016：Legacy Raw 影子迁移与数据双读核验

**目标**：在不修改 legacy 树、不切换生产的情况下，把现有 raw 与 RT-007 timeline 影子导入新模型。

- 依赖：RT-014、RT-015。
- 输出：只读 importer、current raw/timeline 导入器、crosswalk、续跑 manifest、数据级双读比较器。
- 范围内：历史版本解析、canonical/view 拆分、迁移对账、幂等续跑。
- 非目标：真实 CWork 查询、nightly 切换、Broker、删除/搬迁 legacy。
- 关键门禁：report 数、版本链、正文、时间、来源和 crosswalk 一致；中断不发布半 catalog；重复导入幂等；legacy 树零修改；迁移 grant 默认为 `granted`，未经权威源复核不得升级为 `active`，到期或复核失败使用 `revalidation_due`。
- 哈希口径：分别保存 `legacy_source_sha256` 与 `canonical_sha256`，用确定性 crosswalk 或原始字节对象证明完整性，禁止直接宣称两者相等。
- 回滚：丢弃未发布 staging/crosswalk pointer；共享对象保留，不影响 legacy。
- Agent：`agent-rt016-impl` / `agent-rt016-verify`。

## 10. RT-017：Per-tenant Collector Worker

**目标**：将现有混合采集器拆成按 tenant 单次运行、三路安全输出的 Worker。

- 依赖：RT-013～RT-015。
- 输出：CWork Source Adapter；`CanonicalEnvelope`、`TenantViewEnvelope`、`AccessObservation` 三路输出；tenant scoped state/run/retry；legacy collector façade 兼容层。
- 范围内：只读 API、单 tenant 一次运行、增量/回复/审批观察、可恢复 manifest。
- 非目标：何时运行、全局公平调度、知识空间投影。
- 关键门禁：A/B 同报告 canonical 去重、reply/node/view 差异隔离；无 argv/临时文件明文密钥；仅调用只读模式；bounded list 中暂未出现不得误判撤权；单租户失败不污染其他 tenant。
- 代码所有权：只有本 RT 可修改 `cwk_collect_live.py`；写入必须调用 RT-014/015 公共接口。
- 回滚：legacy façade 保持可用；新 Worker 由 feature flag 隔离且默认关闭。
- Agent：`agent-rt017-impl` / `agent-rt017-verify`。

## 11. RT-018：宿主机 Tenant Scheduler

**目标**：在宿主机错峰调度租户 Worker，并保证单写者、配额、重试和故障隔离。

- 依赖：RT-012、RT-013、RT-017。
- 输出：错峰计划、每 tenant 单写锁、持久重试、并发/配额、熔断、运行 manifest。
- 范围内：Worker orchestration、恢复队列、限流、tenant suspend 感知。
- 非目标：复制采集/投影逻辑、修改或启用生产 cron、改写 legacy nightly。
- 关键门禁：A 的死锁、429、超时、坏配置、磁盘配额不影响 B；同 tenant 双触发仅一名 writer；suspended tenant 不启动；宿主机重启后队列可恢复；manifest 无密钥。
- 代码边界：新建 scheduler；`cwk_nightly_pipeline.py` 保持 legacy façade，仅 RT-026 可做最终兼容入口调整。
- 回滚：停用新 scheduler feature flag；legacy nightly 不受影响。
- Agent：`agent-rt018-impl` / `agent-rt018-verify`。

## 12. VG-B：采集与调度故障隔离门禁

必须以 fake CWork 同时运行至少两个 tenant，证明共享去重、视角隔离、单租户错误/限流/超时不扩散、重启可续跑、无明文密钥或仓库级状态回退。

## 13. RT-019：Knowledge Profile 提案、确认与版本生命周期

**目标**：让 AI 先读 100～200 篇代表性汇报，提出用户专属知识方案，用户确认后形成版本化 Profile。

- 依赖：RT-014、RT-015。
- 输出：可复现分层抽样、proposal schema、接受/拒绝/编辑/暂缓记录、Profile 六状态、版本/SHA/影响清单、追加式 `profile_pointer_rollback` 事件、PreviewProvider 契约。
- 范围内：实体颗粒度、别名、合并/拆分、关注专题、冷归档候选、抽取重点的建议与确认。
- 非目标：生产路由、索引、空间文件或未预览即激活。
- 关键门禁：训练样本 100～200、holdout 20～30 且不重叠；只读取 active grant；高影响 merge/split/archive 未确认不得推进；AI 输出经 schema、证据和 ACL 校验。
- AI 安全：分批输入、零工具运行、原文视为不可信数据；恶意 raw 不得触发命令/工具；profile 禁止 tenant/binding/credential/path/grant 字段。
- CLI 扩展：本 RT 只新增 `cwk_tenant_cmd_profile.py` provider，不修改共享 dispatcher。
- 回滚：Profile 状态仅为 `draft/proposed/preview/confirmed/active/superseded`；回滚原子切换 active pointer、同步 active/superseded 状态并追加审计事件，不存在 `rolled_back` 状态，也不删除历史决定。
- Agent：`agent-rt019-impl` / `agent-rt019-verify`。

## 14. RT-020：Holdout 预览、路由器与决策日志

**目标**：用未参与方案生成的 holdout 验证 Profile，并输出可审计的三态多标签路由决定。

- 依赖：RT-015、RT-019。
- 输出：实际 PreviewProvider、`index | archive_no_index | review` 路由器、route decision log、review/archive metadata、reroute/diff、profile 激活 receipt。
- 范围内：确定性规则、confirmed entity、AI 分类、多标签、多空间 membership 建议。
- 非目标：创建 Wiki、索引、删除 raw。
- 关键门禁：优先级为确定性规则 > confirmed entity > AI；低置信、冲突、AI 失败进入 review；一篇可进入多个 space；preview/用户确认/`profile_sha256` 全绑定后方可 active。
- 幂等键：`route_job_key = tenant_id + report_key + canonical_sha256 + profile_sha256`；`projection_key = route_job_key + space_id + projector_version`。
- 回滚：撤销 active profile pointer并重放上一版本路由；决策日志不可覆盖。
- Agent：`agent-rt020-impl` / `agent-rt020-verify`。

## 15. RT-021：多知识空间 Projector 与索引

**目标**：一份共享 raw 支撑同一用户多个独立逻辑知识空间，而不复制事实层。

- 依赖：RT-014、RT-015、RT-020。
- 输出：space membership、summary/topic/entity/search-index 投影、archive/review 视图、撤权与路由变化消费者、RT-010 实体目录适配。
- 范围内：TBS/SFE/通用等 opaque `space_id` 派生物、冷归档排除、可重建索引。
- 非目标：沙箱协议、身份、共享 raw 复制、物理删除。
- 关键门禁：同一报告进入多个 space 均引用同一 canonical SHA；无 raw 副本；撤权或退出 index 后清除 tenant 投影；停用 space 不删除 raw/grant；冷归档默认不进查询/日报。
- 回归：RT-007 时间线、RT-008 查询、RT-010 实体硬范围与现有 Wiki smoke 必须通过；tenant 的实体族规则不得继续共用仓库级 `config/entity-family-registry.json`。
- 代码所有权：`cwk_entity_catalog.py`、`cwk_wiki_search_index.py` 与 Projector 适配由本 RT 独占。
- 回滚：删除并从 route log 重建派生物；Canonical Store 与 grant 不变。
- Agent：`agent-rt021-impl` / `agent-rt021-verify`。

## 16. VG-C：Profile、路由与多空间门禁

必须证明：授权样本可生成 proposal；holdout 与训练样本不重叠；用户确认可激活 Profile；同一报告多空间只引用一份 canonical；撤权、route 退出和 Profile 回滚能清除派生索引且不删除事实层。

## 17. RT-022：Query Broker 授权核心

**目标**：在宿主机内实现不可绕过的查询授权核心，复用现有检索但不暴露任意路径入口。

- 依赖：RT-013～RT-015；可使用 fake `SpaceIndexProvider` 与知识链并行开发。
- 输出：`AgentContext → binding → tenant/status/profile → space → ACL prefilter → retrieval → second ACL → SHA readback → evidence bundle`；安全缓存键与审计 sink。
- 范围内：授权、候选过滤、二次 ACL、证据回读、缓存与错误语义。
- 非目标：UDS/OpenClaw Tool 传输、沙箱安装、最终自然语言答案组织。
- 关键门禁：拒绝 report ID 枚举、tenant/mirror/path 注入、stale binding/grant、撤权竞态、缓存串扰、对象存在性探测；先以 active grant 与 space membership 取交集，再进入 retrieval，Top-K 回读前执行第二次 ACL；缓存命中前仍复核授权；错误不回显 tenant/object/path。
- 冷归档限额：`index`、`archive_no_index`、`review` 各自有独立 limit/timeout/concurrency；`archive_no_index` 默认 limit 不高于 `index` 的一半且不能触发共享 raw 全扫描。
- 回归：通过 `raw_loader` 适配复用现有查询，现有实体约束与证据校验全部通过。
- 代码所有权：`cwk_wiki_query.py` 的 Broker/raw-loader 适配由本 RT 独占。
- 回滚：关闭 Broker feature flag；不改变索引或数据。
- Agent：`agent-rt022-impl` / `agent-rt022-verify`。

## 18. RT-023：沙箱传输、客户端与真实空间集成

**目标**：让沙箱 Agent 只能通过受控通道查询自己的知识空间，不能持有 AppKey 或访问宿主机路径。

- 依赖：RT-011 的传输/身份结论、RT-021、RT-022。
- 输出：经确认的 OpenClaw 受控 Tool 或 UDS adapter、沙箱 query client/Skill、peer identity 映射、真实 SpaceIndexProvider，以及受身份约束的 `list_spaces`/slug→opaque `space_id` 解析接口。
- 范围内：传输协议、客户端、可信身份到 Broker 的不可伪造映射、真实空间查询。
- 非目标：沙箱内 collector/store、loopback HTTP + 用户提供 agent ID 的过渡实现。
- 关键门禁：协议无 agent/tenant/mirror/raw path 参数；身份不可由沙箱伪造；沙箱无 AppKey/shared raw/其他 tenant/宿主路径；敌意 raw 指令不能触发越权工具；销毁沙箱不影响宿主机采集。
- 阻塞规则：若 Gateway 不能提供可信身份或受控传输，必须 fail closed并阻塞试点，不允许降级自报身份。
- 回滚：卸载客户端/禁用 adapter；Broker 与宿主机数据保持关闭状态。
- Agent：`agent-rt023-impl` / `agent-rt023-verify`。

## 19. VG-D：真实沙箱查询门禁

必须在真实沙箱身份链上证明：用户不能选择 tenant/space 路径，双 ACL 均生效，撤权竞态拒绝，证据按 canonical SHA 回读，沙箱不可见密钥、共享对象目录或其他 tenant 数据。

## 20. RT-024：安全审计、可观测性与容量基准

**目标**：建立可回放的安全审计与租户级运行指标，并用合成负载冻结首个真实性能基线。

- 依赖：RT-018、RT-020～RT-023，且 VG-D 已通过。
- 输出：追加式审计、tenant health、成本/队列/锁/授权/路由/query 指标、日志脱敏、10 tenant × 10,000 report 合成基准报告。
- 范围内：可观测性、事件关联、故障诊断、Broker core 与真实沙箱端到端 P50/P95、容量/配额实测。
- 非目标：备份、切换、试点启用或预设 SLA。
- 关键门禁：日志无 raw、AppKey、完整 query、临时 URL、宿主机敏感路径；tenant 仅见自身摘要；binding/profile/grant/query 可回放；单租户指标故障不影响数据面。
- 基线原则：记录机器配置、数据规模、并发、缓存状态与测量方法；没有实测不得写目标数字。
- 回滚：关闭指标 exporter，不删除审计事实；数据面不依赖观测面可用性。
- Agent：`agent-rt024-impl` / `agent-rt024-verify`。

## 21. RT-025：加密备份与 Clean-room 恢复

**目标**：在全新目录中恢复共享证据、租户权限、Profile 和派生状态，并证明撤权不被恢复绕过。

- 依赖：RT-012～RT-015、RT-019～RT-021、RT-024。
- 输出：加密 backup manifest、密钥分离接口、分阶段恢复工具、恢复验证报告与实测 RTO/RPO。
- 范围内：canonical/catalog、binding、grant/tombstone、profile/route/space 元数据和可重建派生物。
- 非目标：恢复 AppKey 明文、自动开放 Broker、生产部署。
- 关键门禁：仅恢复 A 不生成 B 索引；撤权墓碑仍有效；`profile_sha256` 一致；Profile 的 `space_id` 集合与 `knowledge-spaces/<space_id>/` 一一对应，缺失/多余进入 review且不得静默改名；不依赖原机绝对路径；无 AppKey 明文；恢复后 Broker 默认关闭。
- 开放条件：恢复目录必须重新通过 ACL、跨租户、撤权和 SHA 回读 receipt，才允许启用查询。
- 回滚：销毁 clean-room 目录；源备份与生产数据不变。
- Agent：`agent-rt025-impl` / `agent-rt025-verify`。

## 22. VG-E：恢复一致性门禁

必须证明 clean-room 恢复前后 allow/deny/query 结果一致、撤权历史可回放、A-only restore 不泄漏 B、所有派生索引可从权威状态重建。

## 23. RT-026：试点准备、影子切换与回滚工具

**目标**：在默认关闭真实 tenant 的前提下，交付可执行的受控试点、影子对账、切换与回滚工具。

- 依赖：RT-016、RT-018、RT-023、RT-025，以及 VG-A～VG-E 全通过。
- 输出：tenant allowlist、独立试点 schedule、legacy/new 数据与查询双读差异报告、统一 feature switch、rollback runbook、go/no-go evaluator、install/doctor/兼容入口。
- 范围内：试点可执行性、影子读、数据与查询差异、回滚演练、现有单用户兼容。
- 非目标：自动启用真实用户、修改现有生产 cron、直接进入全员 GA。
- 关键门禁：合成双租户 E2E 覆盖共享去重、视角差异、Profile、路由、多空间、冷归档重路由、撤权、故障隔离、备份恢复和 legacy 回滚；完整现有单测与 smoke 通过。
- 代码所有权：仅本 RT 可修改 legacy `cwk_nightly_pipeline.py`、安装入口和统一 feature flag。
- CLI 扩展：本 RT 只新增 `cwk_tenant_cmd_release.py` provider，不修改共享 dispatcher。
- 发布活动：2～3 人 14 天与 5～10 人 30 天是本计划后的独立 release gate，不能用短 smoke 替代，也不在本 RT 自动执行。
- 回滚：一键关闭新 feature flag并恢复 legacy read path；不删除新证据或审计记录。
- Agent：`agent-rt026-impl` / `agent-rt026-verify`。

## 24. Gate、Migration 与 Verification 三轴映射

三条轴不可合并：`G0～G7` 是发布门禁，`M0～M5` 是迁移阶段，`VG-A～VG-E` 是波次集成 receipt。

发布门禁：

- **G0**：本轮 PRD、DESIGN、开发计划经第四轮独立 Claude Code Opus 复审无 Blocker/Major；receipt 为 `../reviews/审核报告-r4.md`。G0 是 RT-011 前的文档发布门禁，不属于 VG-A～E。
- **G1**：RT-011 冻结 v1 契约、安全默认、身份/传输 ADR 与能力探针；真实 transport 合规留到 G5。
- **G2**：RT-012～RT-013 的路径、tenant、binding、credential 测试通过。
- **G3**：RT-014～RT-016 的共享对象、授权基础与 legacy 数据级迁移对账通过；VG-A 是前置 receipt，不能替代 RT-016。
- **G4**：RT-019～RT-021 + VG-C 的 Profile、路由、多空间及派生清理通过。
- **G5**：RT-022～RT-023 + VG-D 的 Broker、可信 transport、双 ACL、撤权和沙箱越权测试通过。
- **G6**：RT-024～RT-026 + VG-E、完整回归、恢复演练和最终独立 Claude Code 验收通过。
- **G7**：RT-026 后由用户另行授权，才允许部署、注入真实密钥或切换 cron。

迁移阶段：

- **M0**：RT-011 契约与探针。
- **M1**：RT-012～RT-015 租户、身份、共享证据与授权基础。
- **M2**：RT-016 影子导入共享对象。
- **M3**：RT-016 完成数据级 crosswalk 对账；RT-026 在 Broker 可用后完成 legacy/new 查询 diff，二者共同闭合 M3。
- **M4**：仅在 RT-026、VG-A～E、G6 均通过且获得 G7 授权后，对 allowlist 的 2～3 个真实 tenant 启用独立试点 Broker/调度。
- **M5**：真实试点通过后才进入扩大切换与回滚窗口；不属于本开发计划自动执行范围。

VG-A～VG-E 的定义见 §2、§8、§12、§16、§19、§22；它们只证明跨 RT 集成，不替代任何 G 或 M 的业务/发布决策。

## 26. 单个 RT 的标准交付包

每个 `RT/RT-0xx/` 至少包含：

```text
rt-intake.md
specs/需求契约.md
specs/技术方案.md
tasks/开发任务.md
reports/实现记录.md
reports/独立验收报告.md
reports/交付验证报告.md
```

验收报告必须列出：需求逐条映射、正常/异常/恶意测试、实际命令和结果摘要、修改文件、回滚验证、剩余风险、是否允许进入下一 RT。未经独立验收明确 `PASS`，不得以“实现完成”替代交付完成。

## 27. 试点与生产边界
